## 장 개요

제12~19장에서는 Transformer의 모든 부품을 직접 만들고, 같은 구조의 작은 모델 Qwen2-Tiny까지 조립했습니다. 이 장에서는 다시 실제 Qwen2.5-0.5B-Instruct로 돌아가, 지금까지 직접 만든 지도와 실제 모델을 **마지막으로 한 번 더 겹쳐 봅니다.**

이번에는 바깥에서 봅니다. Hugging Face가 모델을 어떻게 불러오는지, 모델 안의 중간값을 어떻게 꺼내는지(Forward Hook), 생성할 때 어떤 설정이 다음 토큰을 고르는지(Sampling), 그리고 긴 문장을 빠르게 생성하게 해 주는 KV Cache가 메모리를 얼마나 쓰는지를 확인합니다. 마지막에 Qwen2-Tiny와 실제 모델의 차이를 표로 정리하며 제2부를 마무리합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 실제 모델의 내부를 어떻게 들여다보고, 생성 단계는 무엇이 결정하는가 |
| 실습 결과물 | 계층·Shape 목록, Hook 출력과 직접 구현 비교, Sampling 분포 변화, KV Cache 계산값과 측정값 |
| 실습 파일 | `examples/ch20/`의 `inspect_qwen.py`, `hook_check.py`, `sampling_kv.py`, `test_ch20.py` |
| 선수 장 | 제07장(자기회귀 생성), 제14장(Causal Mask), 제15장(GQA), 제18~19장(Decoder Layer, Qwen2-Tiny) |

## AutoConfig, AutoTokenizer, AutoModel

지금까지 `common/qwen.py`의 함수로 모델을 불러왔습니다. 그 안에서는 Hugging Face의 **Auto 클래스** 세 개가 일합니다.

```text
AutoConfig.from_pretrained(이름)            → config.json을 읽어 Qwen2Config
AutoTokenizer.from_pretrained(이름)         → tokenizer.json 등을 읽어 Qwen2Tokenizer
AutoModelForCausalLM.from_pretrained(이름)  → 설정으로 빈 모델을 만들고 model.safetensors를 채움
```

Auto 클래스는 `config.json`의 `model_type: "qwen2"`를 읽고 알맞은 실제 클래스를 골라 줍니다. 그래서 모델 이름 하나만 바꾸면 Llama든 Gemma든 같은 코드로 불러올 수 있습니다. 제19장에서 Qwen2-Tiny를 `save_pretrained`로 저장했을 때도 같은 `config.json`이 만들어졌으므로, `AutoModelForCausalLM`은 Qwen2-Tiny도 똑같이 불러옵니다.

이 교재는 모든 실습에서 두 가지를 고정합니다. 첫째, **Revision**(저장소의 특정 시점)을 고정해 모델이 갱신되어도 같은 파일을 받습니다. 둘째, `dtype=torch.float32`로 불러와 CPU와 GT 1030에서 같은 계산을 합니다(제02장).

## 계층 이름과 가중치 Shape

`model.named_parameters()`는 모든 가중치의 이름과 텐서를 차례로 내놓습니다. 24개 계층은 번호만 다르므로, 번호를 `N`으로 바꾸면 계층 하나의 설계도가 됩니다. 실습 1의 출력은 제11장에서 그린 구조도와 정확히 대응합니다.

| 이름(계층 N) | Shape | 다룬 장 |
|---|---|---|
| `embed_tokens` | 151936 × 896 | 제10장 |
| `q_proj`, `k_proj`, `v_proj` | 896 × 896, 128 × 896 | 제12장, 제15장 |
| `o_proj` | 896 × 896 | 제15장 |
| `gate_proj`, `up_proj`, `down_proj` | 4864 × 896, 896 × 4864 | 제17장 |
| `input_layernorm` 등 | 896 | 제18장 |

`k_proj`의 출력이 128인 것은 KV 헤드 2개 × head_dim 64이기 때문입니다(GQA, 제15장). 이 숫자가 아래 KV Cache의 크기를 정합니다.

## Forward Hook

모델을 실행하면 계층 사이의 값은 계산이 끝나는 즉시 사라집니다. **Forward Hook**은 특정 모듈이 계산을 마칠 때마다 불리는 함수로, 그 모듈의 입력과 출력을 가로채 저장할 수 있게 해 줍니다.

```python
handle = module.register_forward_hook(hook)   # hook(module, 입력, 출력)
model(ids)                                    # 실행 중에 hook이 불린다
handle.remove()                               # 반드시 뗀다
```

Hook에는 두 가지 주의점이 있습니다.

- **출력의 형태가 모듈마다 다릅니다.** Qwen2의 `self_attn`은 `(출력, Attention 가중치)` 튜플을 내놓으므로 첫 번째 원소만 꺼냅니다.
- **반드시 떼야 합니다.** 떼지 않으면 다음 실행에도 계속 불려 메모리를 쌓습니다. 실습 코드는 `try … finally`로 오류가 나도 떼도록 했습니다.

제14·15장에서는 `output_hidden_states`로 계층 경계의 값만 볼 수 있었습니다. Hook을 쓰면 계층 **안**의 RMSNorm, Attention, FFN 출력을 각각 따로 꺼낼 수 있습니다. 앞으로 LoRA(제3부)나 양자화(제4부)가 모델 내부를 어떻게 바꾸는지 확인할 때도 이 도구를 씁니다.

## Sampling과 생성 설정

모델이 내놓는 것은 다음 토큰의 점수(Logits)일 뿐, 어떤 토큰을 고를지는 **생성 설정**이 정합니다.

| 설정 | 하는 일 |
|---|---|
| Greedy | 언제나 1등 토큰. 같은 입력이면 같은 출력 |
| Temperature T | Logits를 T로 나눈 뒤 Softmax. T < 1이면 1등이 더 두드러지고, T > 1이면 고르게 퍼진다 |
| Top-k | 확률 상위 k개만 남기고 나머지는 버린다 |
| Top-p | 확률을 큰 순서로 더해 p에 닿을 때까지의 토큰만 남긴다 |
| repetition_penalty | 이미 나온 토큰의 점수를 깎아 반복을 줄인다 |

Qwen2.5-0.5B-Instruct의 `generation_config.json`에는 `do_sample=True`, Temperature 0.7, Top-k 20, Top-p 0.8, repetition_penalty 1.1이 기본값으로 들어 있습니다. `generate()`를 그냥 부르면 이 값으로 **무작위 추출**을 하므로 실행할 때마다 답이 달라집니다.

이 교재는 재현성을 위해 비교 실험에서 **Greedy로 고정**합니다(`do_sample=False`). 파인튜닝 전후를 비교할 때 무작위성이 섞이면, 답이 달라진 이유가 학습 때문인지 운 때문인지 구별할 수 없기 때문입니다. Temperature는 순위를 바꾸지 않는다는 점도 기억해 둡시다. 확률의 **모양**만 날카롭거나 평평하게 바꿉니다.

## KV Cache 메모리

제07장의 자기회귀 생성은 토큰을 하나 만들 때마다 문장 전체를 다시 넣었습니다. 그런데 Causal Mask(제14장) 때문에 앞 토큰의 K와 V는 뒤에 무엇이 오든 바뀌지 않습니다. 그렇다면 한 번 계산한 K·V를 저장해 두고, 새 토큰 하나의 Q·K·V만 계산하면 됩니다. 이것이 **KV Cache**입니다.

```text
캐시 없음: 매 단계 [전체 문장] → 모든 위치의 Q·K·V를 다시 계산
캐시 사용: 첫 단계만 [문장], 이후는 [새 토큰 1개] → 새 K·V를 캐시에 덧붙임
```

대가는 메모리입니다. 토큰 하나마다 모든 계층의 K와 V를 저장해야 합니다.

```text
토큰당 크기 = 2(K·V) × 계층 24 × KV 헤드 2 × head_dim 64 × 자료형 바이트
           = 6,144 × 2바이트(BF16) = 12,288B = 12KiB
32,768토큰 = 12KiB × 32,768 = 384MiB
```

GQA가 여기서 빛납니다. KV 헤드가 Query 헤드처럼 14개였다면 캐시는 7배인 84KiB/토큰, 32K 문맥에서 2.6GiB가 되어 GT 1030의 2GB를 혼자 넘어섭니다. 이 교재처럼 FP32로 계산하면 토큰당 24KiB로 두 배가 됩니다.

## Qwen2-Tiny와 실제 모델 비교

제2부에서 만든 Qwen2-Tiny와 실제 모델을 나란히 놓으면, **다른 것은 크기뿐**입니다.

| 요소 | Qwen2-Tiny | Qwen2.5-0.5B |
|---|---|---|
| QKV 편향, o_proj 편향 | 있음, 없음 | 있음, 없음 |
| Weight Tying | 있음 | 있음 |
| GQA(Query : KV) | 4 : 1 | 14 : 2 = 7 : 1 |
| rope_theta | 1e6 | 1e6 |
| Final Norm | RMSNorm | RMSNorm |
| 파라미터 | 약 4,190만 | 약 4억 9,400만 |
| Embedding 비중 | 92.8% | 27.6% |
| FP32 KV Cache | 토큰당 2KiB | 토큰당 24KiB |

Qwen2-Tiny의 KV Cache는 2 × 4계층 × KV 헤드 1 × 64 × 4바이트 = 2,048B = 2KiB/토큰입니다. 구조가 같으므로 같은 공식이 그대로 적용됩니다. 제3부부터는 이 두 모델을 나란히 두고, 작은 모델로 원리를 빠르게 확인한 뒤 실제 모델에서 같은 현상을 관찰하는 방식으로 진행합니다.

```python
# 제20장 실습 1: Auto 클래스로 불러온 실제 Qwen2.5-0.5B의 설정·계층 이름·Shape·생성 설정 살펴보기
#
# 실행: python examples/ch20/inspect_qwen.py

import json
import re
import sys
from collections import OrderedDict
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[1]))

from common.models import qwen_file  # noqa: E402
from common.qwen import load_config, load_model, load_tokenizer  # noqa: E402


def layer_table(model) -> "OrderedDict[str, tuple]":
    """계층 번호를 N으로 바꿔 24개 계층을 한 줄로 묶는다."""
    table = OrderedDict()
    for name, p in model.named_parameters():
        key = re.sub(r"layers\.\d+\.", "layers.N.", name)
        table.setdefault(key, (tuple(p.shape), 0))
        table[key] = (table[key][0], table[key][1] + 1)
    return table


def main() -> None:
    config, tok, model = load_config(), load_tokenizer(), load_model()

    print("── 1. Auto 클래스가 고른 실제 클래스 ──")
    print(f"  설정 {type(config).__name__} / 토크나이저 {type(tok).__name__} / 모델 {type(model).__name__}")
    print(f"  config.json의 model_type: {config.model_type}, architectures: {config.architectures}")

    print("\n── 2. 계층 이름과 Shape(N = 0~23) ──")
    for key, (shape, n) in layer_table(model).items():
        print(f"  {key:<48}{str(shape):<14}×{n}")
    print(f"  lm_head.weight는 embed_tokens.weight와 같은 텐서: "
          f"{model.lm_head.weight is model.model.embed_tokens.weight}")

    print("\n── 3. generation_config.json(생성 기본값) ──")
    gen = json.loads(Path(qwen_file("generation_config.json")).read_text())
    for k in ("do_sample", "temperature", "top_k", "top_p", "repetition_penalty", "eos_token_id"):
        print(f"  {k:<20}{gen[k]}")


if __name__ == "__main__":
    main()
```

### 실습 2. Hook으로 0번 계층 들여다보기

0번 계층 안의 네 모듈에 Hook을 걸어 출력을 꺼내고, 제16~18장에서 직접 만든 함수로 같은 값을 계산해 비교합니다.

파일명: `examples/ch20/hook_check.py`

```python
# 제20장 핵심 실습 1: Forward Hook으로 0번 계층 Attention·FFN 출력을 꺼내 직접 구현과 비교
#
# 실행: python examples/ch20/hook_check.py

import sys
from pathlib import Path

ROOT = Path(__file__).resolve().parents[1]
for p in (ROOT, ROOT / "ch05", ROOT / "ch03", ROOT / "ch14", ROOT / "ch15",
          ROOT / "ch16", ROOT / "ch17", ROOT / "ch18"):
    sys.path.insert(0, str(p))

import torch  # noqa: E402

from common.qwen import load_model, load_tokenizer  # noqa: E402
from decoder_layer import get, self_attention  # noqa: E402  (제18장)
from norm_residual import rms_norm  # noqa: E402            (제18장)
from rope import rope_cos_sin  # noqa: E402                 (제16장)
from swiglu import swiglu_ffn  # noqa: E402                 (제17장)

TEXT = "훅은 모델 안을 들여다보는 창문이다."


def capture(model, ids, names):
    """이름으로 고른 모듈들에 Hook을 걸어 입력과 출력을 저장하고, 끝나면 Hook을 뗀다."""
    store, handles = {}, []
    modules = dict(model.named_modules())
    for name in names:
        def hook(module, args, output, name=name):
            out = output[0] if isinstance(output, tuple) else output
            store[name] = (args[0].detach() if args else None, out.detach())
        handles.append(modules[name].register_forward_hook(hook))
    try:
        with torch.no_grad():
            model(ids)
    finally:
        for h in handles:
            h.remove()                                    # 떼지 않으면 다음 실행에도 계속 걸린다
    return store


def main() -> None:
    model, tok = load_model(), load_tokenizer()
    ids = tok(TEXT, return_tensors="pt").input_ids
    layer = model.model.layers[0]
    names = ["model.layers.0.input_layernorm", "model.layers.0.self_attn",
             "model.layers.0.post_attention_layernorm", "model.layers.0.mlp"]
    got = capture(model, ids, names)

    print("── 1. Hook으로 꺼낸 값 ──")
    for n in names:
        print(f"  {n:<40}출력 {tuple(got[n][1].shape)}")
    print(f"  Hook 해제 후 남은 Hook 수: {len(layer.self_attn._forward_hooks)}")

    cos, sin = rope_cos_sin(ids.shape[1], 64, 1e6)
    with torch.no_grad():
        x = model.model.embed_tokens(ids)                 # 0번 계층의 입력
        n1 = rms_norm(x, get(layer.input_layernorm, "weight"))
        attn = self_attention(layer.self_attn, n1, cos, sin)
        h = x + attn
        n2 = rms_norm(h, get(layer.post_attention_layernorm, "weight"))
        m = layer.mlp
        ffn = swiglu_ffn(n2, get(m.gate_proj, "weight"), get(m.up_proj, "weight"),
                         get(m.down_proj, "weight"))

    print("\n── 2. 직접 구현(제13~18장)과 비교 ──")
    for label, mine, n in (("RMSNorm 1", n1, names[0]), ("Attention", attn, names[1]),
                           ("RMSNorm 2", n2, names[2]), ("FFN", ffn, names[3])):
        ref = got[n][1]
        print(f"  {label:<10}최대 오차 {(mine - ref).abs().max().item():.1e}, "
              f"상대 오차 {((mine - ref).norm() / ref.norm()).item():.1e}")


if __name__ == "__main__":
    main()
```

```text
  RMSNorm 2 최대 오차 1.8e-05, 상대 오차 2.2e-06
  FFN       최대 오차 8.1e-06, 상대 오차 2.0e-06
```

네 부품 모두 상대 오차 1e-5 미만으로 일치합니다. 두 번째 RMSNorm의 최대 오차가 상대적으로 큰 것은, 0번 계층의 입력(Embedding 벡터)이 크기가 작아(제18장) 정규화할 때 크게 확대되면서 Attention의 작은 오차(6e-7)도 함께 확대되었기 때문입니다. 상대 오차는 다른 부품과 같은 수준입니다. 제2부에서 직접 만든 부품이 실제 모델 안의 부품과 같은 함수라는 것을, 계층 경계가 아니라 부품 하나하나의 단위에서 확인했습니다.

### 실습 3. Sampling과 KV Cache

같은 Logits에 Temperature, Top-k, Top-p를 적용해 보고, KV Cache의 크기를 공식으로 계산한 뒤 실제 캐시 텐서를 재어 비교합니다.

파일명: `examples/ch20/sampling_kv.py`

```python
# 제20장 핵심 실습 2: Sampling 설정이 확률 분포를 바꾸는 모습과 KV Cache의 크기·효과 측정
#
# 실행: python examples/ch20/sampling_kv.py

import sys
import time
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[1]))

import torch  # noqa: E402

from common.qwen import load_config, load_model, load_tokenizer  # noqa: E402

PROMPT = "대한민국의 수도는"


def kv_bytes_per_token(cfg, bytes_per: int) -> int:
    """K와 V(2) × 계층 × KV 헤드 × head_dim × 자료형 바이트"""
    head_dim = cfg.hidden_size // cfg.num_attention_heads
    return 2 * cfg.num_hidden_layers * cfg.num_key_value_heads * head_dim * bytes_per


def filter_top_k(probs, k):
    keep = torch.zeros_like(probs, dtype=torch.bool)
    keep[probs.topk(k).indices] = True
    return keep


def filter_top_p(probs, p):
    """누적 확률이 p에 처음 닿는 토큰까지 남긴다(1등은 항상 남는다)."""
    sorted_p, idx = probs.sort(descending=True)
    before = sorted_p.cumsum(0) - sorted_p                # 자기 앞까지의 누적
    keep = torch.zeros_like(probs, dtype=torch.bool)
    keep[idx[before < p]] = True
    return keep


@torch.no_grad()
def greedy(model, ids, n, use_cache):
    """KV Cache를 쓰면 두 번째 단계부터 새 토큰 하나만 넣는다."""
    out, cache, x = [], None, ids
    for _ in range(n):
        r = model(x, past_key_values=cache, use_cache=use_cache)
        nxt = r.logits[:, -1].argmax(-1, keepdim=True)
        out.append(nxt.item())
        if use_cache:
            cache, x = r.past_key_values, nxt
        else:
            x = torch.cat([x, nxt], dim=1)                # 매번 전체 문장을 다시 계산
    return out, cache


def main() -> None:
    cfg, tok, model = load_config(), load_tokenizer(), load_model()
    ids = tok(PROMPT, return_tensors="pt").input_ids
    with torch.no_grad():
        logits = model(ids).logits[0, -1]

    print(f"── 1. Temperature: '{PROMPT}' 다음 토큰 상위 3개 확률 ──")
    top = logits.topk(3).indices
    for t in (0.3, 0.7, 1.0, 1.5):
        p = torch.softmax(logits / t, dim=-1)
        row = ", ".join(f"{tok.decode(int(i))!r} {p[i].item():.3f}" for i in top)
        print(f"  T={t:<4}{row}")

    print("\n── 2. Top-k·Top-p로 남는 후보 수(T=0.7) ──")
    p = torch.softmax(logits / 0.7, dim=-1)
    k20, p08 = filter_top_k(p, 20), filter_top_p(p, 0.8)
    print(f"  Top-k 20: {int(k20.sum())}개 / Top-p 0.8: {int(p08.sum())}개 / "
          f"둘 다 적용: {int((k20 & p08).sum())}개")

    print("\n── 3. KV Cache 크기: 계산 ──")
    for label, b in (("BF16·FP16", 2), ("FP32", 4)):
        per = kv_bytes_per_token(cfg, b)
        print(f"  {label:<10}토큰당 {per:,}B = {per / 1024:.0f}KiB, "
              f"32,768토큰 {per * 32768 / 2**20:,.0f}MiB")

    print("\n── 4. KV Cache 크기: 측정(FP32, Greedy 20토큰) ──")
    t0 = time.perf_counter()
    with_cache, cache = greedy(model, ids, 20, use_cache=True)
    t1 = time.perf_counter()
    no_cache, _ = greedy(model, ids, 20, use_cache=False)
    t2 = time.perf_counter()
    stored = cache.get_seq_length()
    measured = sum(layer.keys.numel() * layer.keys.element_size()
                   + layer.values.numel() * layer.values.element_size() for layer in cache.layers)
    print(f"  캐시에 저장된 토큰 {stored}개, 실제 텐서 {measured:,}B "
          f"= 계산값 {kv_bytes_per_token(cfg, 4) * stored:,}B")
    print(f"  K 텐서 하나의 Shape {tuple(cache.layers[0].keys.shape)}  [배치, KV 헤드, 토큰, head_dim]")
    print(f"  생성 결과 같음: {with_cache == no_cache}")
    print(f"  → {tok.decode(with_cache)!r}")
    print(f"  시간: 캐시 사용 {t1 - t0:.2f}초 / 미사용 {t2 - t1:.2f}초(환경마다 다름)")


if __name__ == "__main__":
    main()
```

## 핵심 정리

- Auto 클래스는 `config.json`의 `model_type`을 읽어 알맞은 설정·토크나이저·모델 클래스를 골라 줍니다. 이 교재는 Revision과 FP32를 고정합니다.
- 실제 모델의 계층 이름과 Shape는 제2부의 구조도와 하나하나 대응하며, 제19장의 Qwen2-Tiny와 이름까지 같습니다.
- Forward Hook은 모듈의 입출력을 가로채는 도구입니다. 출력 형태를 확인해 꺼내고, 쓰고 나면 반드시 뗍니다.
- 다음 토큰은 생성 설정이 고릅니다. 기본값은 무작위 추출이지만, 이 교재는 비교 실험을 위해 Greedy로 고정합니다.
- KV Cache는 앞 토큰의 K·V를 저장해 생성을 빠르게 합니다. Qwen2.5-0.5B는 BF16 기준 토큰당 12KiB, 32K 문맥에서 384MiB이며, GQA 덕분에 7분의 1로 줄어든 크기입니다.

**다음 장 연결:** 제2부에서 모델이 **어떻게 계산하는지**를 모두 확인했습니다. 제3부에서는 모델이 **어떻게 배우는지**로 넘어갑니다. 제21장에서는 사전학습·전이학습·파인튜닝의 관계와 Base·Instruct 모델의 차이를 정리하고, 이후 실험 전체에서 쓸 고정 데이터셋을 준비합니다.
