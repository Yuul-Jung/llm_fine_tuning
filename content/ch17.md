## 장 개요

Transformer Block에는 두 개의 큰 부품이 있습니다. 제12~16장에서 완성한 Attention이 **토큰 사이**에서 정보를 주고받는다면, 이 장의 FFN(Feed Forward Network, 순방향 신경망)은 **토큰 각자**가 모아 온 정보를 가공합니다. Attention이 회의라면 FFN은 회의가 끝난 뒤 각자 자리에서 하는 생각 정리입니다.

FFN은 구조가 단순하지만 모델에서 차지하는 비중은 압도적입니다. Qwen2.5-0.5B 파라미터의 63.5%가 FFN에 있습니다. 이 장은 Qwen이 쓰는 SwiGLU 방식의 FFN을 직접 구현해 실제 모델의 0번·23번 계층 출력과 비교하고, 그 파라미터와 연산량을 계산합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | FFN은 무엇을 하며, SwiGLU의 게이트는 어떤 역할을 하는가 |
| 실습 결과물 | SwiGLU FFN 직접 구현과 실제 모델 비교, 토큰별 독립성 확인, 파라미터·연산량 |
| 실습 파일 | `examples/ch17/`의 `swiglu.py`, `test_ch17.py` |
| 선수 장 | 제04장(원소별 곱), 제05장(Linear), 제06장(SiLU) |

```text
x [.., 896] ─┬─ gate_proj ─▶ [.., 4864] ─▶ SiLU ─┐
             │                                     ⊙ (원소별 곱)  ─▶ down_proj ─▶ [.., 896]
             └─ up_proj   ─▶ [.., 4864] ──────────┘
```

## FFN의 역할

FFN은 두 가지 점에서 Attention과 정반대입니다.

| 구분 | Attention | FFN |
|---|---|---|
| 정보의 흐름 | 토큰 사이(가로) | 토큰 각자(세로) |
| 계산 단위 | 모든 토큰 쌍 | 토큰 하나씩 |
| 다른 토큰의 영향 | 받는다 | 받지 않는다 |
| 파라미터 비중(Qwen2.5-0.5B) | 약 9% | 약 63.5% |

FFN은 같은 가중치로 모든 토큰을 **따로따로** 계산합니다. 문장 안의 토큰 16개를 한꺼번에 넣든 하나씩 넣든 결과가 같습니다. 핵심 실습 3번에서 확인합니다.

토큰 사이의 정보 교환은 Attention이 이미 끝냈으므로, FFN은 각 토큰이 모아 온 정보를 바탕으로 표현을 다듬는 데 집중합니다. 학습된 지식의 상당 부분이 이 FFN의 가중치에 저장된다고 여겨집니다. 이 교재의 LoRA 실습(제30·48장)에서 Attention뿐 아니라 FFN에도 Adapter를 붙여 보는 이유입니다.

## Gate·Up·Down Projection

Qwen2.5의 FFN은 Linear 세 개로 이루어집니다. 모두 편향이 없습니다.

| 이름 | 가중치 모양 `[out, in]` | 하는 일 |
|---|---|---|
| `gate_proj` | `[4864, 896]` | 각 칸을 얼마나 통과시킬지 정할 게이트 값 |
| `up_proj` | `[4864, 896]` | 넓은 공간으로 펼친 특징 |
| `down_proj` | `[896, 4864]` | 다시 원래 크기로 모으기 |

`intermediate_size` 4,864는 hidden 896의 약 5.4배입니다. FFN은 표현을 일단 넓은 공간으로 펼쳐 다양한 특징을 만든 뒤, 필요한 것만 골라 원래 크기로 다시 접습니다. 입력과 출력의 모양이 같으므로(`[.., 896]`) 잔차 연결로 블록의 입력에 더할 수 있습니다(제18장).

## SiLU와 SwiGLU

고전적인 FFN은 Linear → 활성화 함수 → Linear의 두 층이었습니다. SwiGLU는 여기에 **게이트**를 하나 더합니다.

```text
고전 FFN:  down( ReLU( up(x) ) )
SwiGLU:    down( SiLU( gate(x) ) ⊙ up(x) )
                 └─── 게이트 ───┘   └ 내용 ┘
```

`up(x)`가 내용이고, `SiLU(gate(x))`가 그 내용을 칸마다 얼마나 통과시킬지 정하는 문입니다. 두 값을 **원소별로 곱하므로**(`⊙`, 제04장의 `*`), 게이트가 0에 가까운 칸은 내용이 거의 막히고 게이트가 큰 칸은 내용이 그대로 또는 증폭되어 지나갑니다. 핵심 실습 4번에서 게이트가 거의 닫힌 칸의 비율을 측정합니다.

이름의 Swi는 SiLU의 다른 이름인 Swish에서, GLU는 Gated Linear Unit(게이트 달린 선형 단위)에서 왔습니다.

### 원소별 곱과 행렬곱의 구분

SwiGLU 수식에는 두 종류의 곱셈이 함께 있습니다. 제04장에서 강조한 구분이 실제로 중요해지는 곳입니다.

```text
gate(x), up(x), down(…)    행렬곱(@)       Linear 세 번
SiLU(gate) ⊙ up            원소별 곱(*)     모양이 같은 [.., 4864] 두 개를 칸끼리
```

코드에서 원소별 곱 자리에 `@`를 쓰면 모양이 맞지 않아 오류가 나지만, 거꾸로 실수하는 경우는 모양에 따라 오류 없이 엉뚱한 결과가 나올 수 있습니다. 그래서 이 장도 실제 모델 출력과 비교해 검증합니다.

## 연산량과 파라미터

FFN 하나의 파라미터는 Linear 세 개의 가중치 합입니다.

```text
3 × 896 × 4,864 = 13,074,432개   (계층 1개)
× 24계층       = 313,786,368개   (전체 494,032,768개의 63.5%)
```

제11장의 블록별 표와 비교하면, 계층 하나에서 FFN(약 1,307만)은 Attention(약 184만)의 7배가 넘습니다. 모델 파라미터는 Embedding(27.6%)과 FFN(63.5%)이 대부분이고, Attention과 정규화는 나머지 약 9%입니다.

연산량도 비슷한 비율입니다. Linear 하나는 파라미터 하나당 곱셈과 덧셈 한 번씩, 토큰 하나에 대해 `2 × 파라미터 수`의 연산을 합니다. 토큰 하나가 24개 계층의 FFN을 지나는 데 약 0.63 GFLOP이 듭니다. 제02장에서 측정한 CPU 성능(약 300 GFLOPS)으로 나누면, 계산량만 보면 FFN에만 토큰 하나당 약 2밀리초가 드는 셈입니다(실제로는 메모리에서 가중치를 읽어 오는 시간이 더해집니다).

## 핵심 실습

0번 계층 `mlp`에 Hook을 걸어 입력과 출력을 붙잡고, 같은 입력으로 SwiGLU FFN을 직접 계산해 비교합니다. 제05장의 `linear_forward()`와 제06장의 `silu()`를 다시 씁니다.

파일명: `examples/ch17/swiglu.py`

```python
# 제17장 핵심 실습: SwiGLU FFN을 직접 구현해 Qwen2.5 0번 계층 MLP 출력과 비교
#
# 실행: python examples/ch17/swiglu.py
#
# FFN(x) = down( silu(gate(x)) ⊙ up(x) )     ⊙: 원소별 곱(제04장)

import sys
from pathlib import Path

ROOT = Path(__file__).resolve().parents[1]
for p in (ROOT, ROOT / "ch05", ROOT / "ch06"):
    sys.path.insert(0, str(p))

import torch  # noqa: E402

from activations import silu  # noqa: E402  (제06장)
from common.qwen import load_model, load_tokenizer  # noqa: E402
from linear_scratch import linear_forward  # noqa: E402  (제05장)

TEXT = "언어 모델은 다음 토큰을 예측한다."


def swiglu_ffn(x, w_gate, w_up, w_down):
    """x: [..., hidden] → [..., hidden]. 세 Linear 모두 편향 없음."""
    gate = linear_forward(x, w_gate)              # [..., intermediate]
    up = linear_forward(x, w_up)                  # [..., intermediate]
    return linear_forward(silu(gate) * up, w_down)  # 원소별 곱 → 다시 hidden으로


def capture_mlp(model, ids) -> dict:
    """0번 계층 mlp의 입력과 출력을 Hook으로 붙잡는다."""
    cap = {}
    handle = model.model.layers[0].mlp.register_forward_hook(
        lambda mod, inp, out: cap.update(x=inp[0].detach(), y=out.detach()))
    with torch.no_grad():
        model(ids)
    handle.remove()
    return cap


def ffn_weights(model, layer: int = 0) -> tuple:
    mlp = model.model.layers[layer].mlp
    return tuple(getattr(mlp, n).weight.detach() for n in ("gate_proj", "up_proj", "down_proj"))


def main() -> None:
    model, tok = load_model(), load_tokenizer()
    w_gate, w_up, w_down = ffn_weights(model)

    print("── 1. 세 Projection의 모양 ──")
    for name, w in (("gate_proj", w_gate), ("up_proj", w_up), ("down_proj", w_down)):
        print(f"  {name:<10} {tuple(w.shape)}")

    cap = capture_mlp(model, tok(TEXT, return_tensors="pt").input_ids)
    print("\n── 2. 직접 구현과 모델 내부 출력 비교 ──")
    mine = swiglu_ffn(cap["x"], w_gate, w_up, w_down)
    print(f"  입력 {tuple(cap['x'].shape)} → 출력 {tuple(mine.shape)}")
    print(f"  최대 절대오차: {(mine - cap['y']).abs().max().item():.1e}")

    print("\n── 3. FFN은 토큰마다 따로 계산된다 ──")
    one_by_one = torch.cat([swiglu_ffn(cap["x"][:, t:t + 1], w_gate, w_up, w_down)
                            for t in range(cap["x"].shape[1])], dim=1)
    print(f"  토큰을 하나씩 넣은 결과 = 한꺼번에 넣은 결과: {torch.allclose(one_by_one, mine, atol=1e-5)}")

    print("\n── 4. 게이트의 효과: SiLU(gate) 값의 분포 ──")
    g = torch.nn.functional.silu(linear_forward(cap["x"], w_gate))
    near_zero = (g.abs() < 0.05).float().mean().item()
    print(f"  |SiLU(gate)| < 0.05 인 칸의 비율: {near_zero:.1%}  (이 칸들의 up 값은 거의 통과하지 못함)")

    print("\n── 5. 파라미터와 연산량 ──")
    per_layer = sum(w.numel() for w in (w_gate, w_up, w_down))
    total = 494_032_768
    print(f"  계층 1개 FFN 파라미터: {per_layer:,}  (3 × 896 × 4,864)")
    print(f"  24계층 FFN 합계: {24 * per_layer:,} = 전체의 {24 * per_layer / total:.1%}")
    print(f"  토큰 1개당 FFN 연산(24계층): 약 {2 * 24 * per_layer / 1e9:.2f} GFLOP")


if __name__ == "__main__":
    main()
```


**핵심 코드 풀이**

- `swiglu_ffn()`은 03절의 수식 그대로 세 줄입니다. `silu(gate) * up`의 `*`가 원소별 곱이고, 나머지는 모두 `linear_forward()`(행렬곱)입니다. 세 Linear 모두 편향이 없으므로 가중치만 넘깁니다.
- `capture_mlp()`의 Hook은 `mlp`의 입력(`inp[0]`)과 출력을 함께 붙잡습니다. `mlp`의 입력은 `post_attention_layernorm`을 거친 값입니다(제11장 구조도).
- 2번에서 직접 구현과 모델 내부 출력의 최대 오차는 `4.8e-07`입니다. 테스트에서는 마지막 계층(23번)으로도 같은 비교를 해, 모든 계층이 같은 구조임을 확인합니다.
- 3번은 01절의 성질입니다. 토큰을 하나씩 잘라 넣고 이어 붙인 결과가 한꺼번에 넣은 결과와 같습니다. FFN이 토큰 사이를 전혀 섞지 않는다는 뜻입니다.
- 4번은 게이트의 효과입니다. `SiLU(gate)`의 약 14%가 0.05보다 작아, 그 칸의 내용(`up`)은 거의 통과하지 못합니다. 입력 토큰에 따라 어떤 칸을 열고 닫을지가 달라지며, 이것이 게이트가 고정된 활성화 함수보다 유연한 이유입니다.
- 5번은 04절의 계산을 코드로 확인합니다.

```python
from pathlib import Path

import pytest
import torch
import torch.nn.functional as F

from swiglu import swiglu_ffn  # noqa: E402


def test_hand_example():
    # hidden 2, intermediate 2: gate·up·down을 단위행렬로 두면 FFN(x) = silu(x) ⊙ x
    eye = torch.eye(2)
    x = torch.tensor([[1.0, -2.0]])
    expected = F.silu(x) * x
    torch.testing.assert_close(swiglu_ffn(x, eye, eye, eye), expected)


def test_shapes_and_tokenwise():
    torch.manual_seed(0)
    wg, wu, wd = torch.randn(12, 4), torch.randn(12, 4), torch.randn(4, 12)
    x = torch.randn(2, 5, 4)
    y = swiglu_ffn(x, wg, wu, wd)
    assert y.shape == (2, 5, 4)
    torch.testing.assert_close(y[:, 3], swiglu_ffn(x[:, 3], wg, wu, wd))


def test_matches_reference_formula():
    torch.manual_seed(1)
    wg, wu, wd = torch.randn(12, 4), torch.randn(12, 4), torch.randn(4, 12)
    x = torch.randn(3, 4)
    ref = F.linear(F.silu(F.linear(x, wg)) * F.linear(x, wu), wd)
    torch.testing.assert_close(swiglu_ffn(x, wg, wu, wd), ref)


def test_parameter_share():
    per_layer = 3 * 896 * 4864
    assert per_layer == 13_074_432
    assert round(24 * per_layer / 494_032_768, 3) == 0.635

        pytest.skip("Qwen 모델이 아직 내려받아지지 않음(swiglu.py를 먼저 실행)")


@pytest.mark.parametrize("layer", [0, 23])
```

## 핵심 정리

- FFN은 토큰마다 따로, 같은 가중치로 표현을 가공합니다. 토큰 사이의 정보 교환은 Attention의 몫입니다.
- Qwen2.5의 FFN은 SwiGLU입니다: `down(SiLU(gate(x)) ⊙ up(x))`. 게이트가 내용의 각 칸을 얼마나 통과시킬지 정합니다.
- 세 Linear는 편향이 없고, hidden 896을 4,864로 펼쳤다가 다시 896으로 접습니다.
- FFN은 Qwen2.5-0.5B 파라미터의 63.5%, 토큰 하나당 약 0.63 GFLOP을 차지하는 가장 큰 부품입니다.

**다음 장 연결:** Attention과 FFN, 두 큰 부품이 모두 준비되었습니다. 제18장에서는 둘을 감싸는 RMSNorm과 잔차 연결을 구현하고, 모든 부품을 조립해 Decoder Layer 하나를 완성합니다.
