## 장 개요

제3·4부에서는 고정된 일반 문장으로 학습의 원리를 확인했습니다. 제5부에서는 실제 목적을 가진 학습으로 넘어갑니다. 목표는 **FPGA와 디지털 설계에 관한 질문에 정확하고 일관된 형식으로 답하는 모델**입니다. 그 첫걸음은 코드가 아니라 데이터입니다.

이 장은 지도 미세조정(SFT)이 무엇을 가르치는지 정리하고, 학습 데이터의 세 가지 구조를 비교한 뒤, 좋은 데이터의 기준과 출처·라이선스 기록 원칙을 세웁니다. 그리고 FPGA 질의응답 50개를 설계표에 맞춰 직접 작성하고, 기준에 맞는지 코드로 검사합니다. 제5부의 나머지 장(제42~50장)은 모두 이 데이터로 진행합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | SFT 데이터는 어떤 구조여야 하며, 어떤 기준으로 설계·검사하는가 |
| 실습 결과물 | 설계표, FPGA 질의응답 50개, 데이터 설명서, 설계 기준 검사 결과, 세 가지 구조 변환 |
| 실습 파일 | `datasets/fpga_qa/fpga_qa.json`, `datasets/fpga_qa/README.md`, `examples/ch41/`의 `check_dataset.py`, `test_ch41.py` |
| 선수 장 | 제21장(Base와 Instruct, 프롬프트·RAG·파인튜닝), 제22장(Loss Masking 기초) |

```text
설계표(분류·목표 수) → 질의응답 작성 → 설계 기준 검사 → 데이터 설명서·라이선스 기록
                                                     → 제42장: JSONL·Datasets로 변환
```

## SFT와 Instruction Tuning

**SFT**(Supervised Fine-tuning, 지도 미세조정)는 "이런 입력에는 이렇게 답하라"는 모범 답안을 보여 주며 학습하는 것입니다. 학습 원리는 제3부와 같은 다음 토큰 예측이지만, 데이터가 질문과 모범 답변의 **쌍**으로 되어 있다는 점이 다릅니다. 지시문(Instruction)을 다양하게 담은 SFT를 특히 **Instruction Tuning**이라 부르며, 제21장의 Instruct 모델이 이렇게 만들어졌습니다.

제21장에서 정리한 대로, SFT가 가장 잘 가르치는 것은 **대답하는 방식**입니다. 답의 형식, 길이, 말투, 용어 사용, 모를 때의 태도입니다. 이 장의 데이터도 이 점을 중심에 둡니다. 50개 질의응답으로 모델에게 FPGA의 모든 지식을 넣을 수는 없지만, "FPGA 질문에는 정확한 용어로, 존댓말 서술형으로, 1~4문장 안에 핵심부터 답한다"는 방식은 가르칠 수 있습니다.

## 데이터 구조

같은 질의응답도 세 가지 구조로 담을 수 있습니다.

```text
Instruction·Input·Output  {"instruction": 지시문, "input": 추가 자료(코드 등), "output": 답}
Prompt-Completion         {"prompt": 지시문 + 추가 자료, "completion": 답}
대화형(messages)          {"messages": [{"role": "user", …}, {"role": "assistant", …}]}
```

```text
Instruction 구조     지시와 자료가 나뉘어 있어 작성·검토가 쉽다     데이터 작성 원본(이 장)
Prompt-Completion    무엇을 학습할지(Completion)가 분명하다        Completion-only 학습(제45장)
대화형               Chat Template(제44장)에 그대로 들어간다       Instruct 모델의 SFT(제46장 이후)
```

세 구조는 서로 바꿀 수 있습니다. 이 교재는 **사람이 쓰고 검토하기 쉬운 Instruction·Input·Output으로 원본을 작성**하고, 학습 단계에서 필요한 구조로 변환합니다. 원본을 하나로 두어야 수정할 때 여러 파일이 어긋나지 않습니다.

## 데이터 품질

SFT의 결과는 데이터의 양보다 **품질**에 크게 좌우됩니다. 모델은 데이터에 있는 것을 그대로 따라 하기 때문입니다. 틀린 답이 있으면 틀린 답을, 형식이 제각각이면 제각각인 형식을 배웁니다.

| 기준 | 이 데이터의 규칙 | 지키지 않으면 |
|---|---|---|
| 정확성 | 답의 모든 문장이 사실이다. 제품마다 다른 내용(핀 번호 등)은 일반화하거나 "회로도에서 확인"으로 안내한다 | 그럴듯한 오답을 자신 있게 말한다 |
| 일관성 | 같은 개념은 같은 용어로, 존댓말 서술형으로 끝맺는다 | 답마다 말투와 용어가 흔들린다 |
| 형식 통일 | 답은 1~4문장, 핵심을 첫 문장에 둔다. 코드는 input에 둔다 | 길이와 구조가 제멋대로인 답을 낸다 |
| 다양성 | 설계표의 분류별 목표 수를 지킨다 | 한 유형만 잘하고 나머지는 못한다 |
| 중복 없음 | 같은 질문을 두 번 넣지 않는다 | 특정 질문만 외운다 |

이 중 기계로 검사할 수 있는 것(필수 항목, 중복, 분류별 개수, 끝맺음 형식, 코드 질문의 input 유무)은 코드로 검사하고, 정확성처럼 사람이 판단해야 하는 것은 작성할 때와 검토할 때 확인합니다. 제43장에서 정제와 평가 지표를 더 다룹니다.

## 출처와 라이선스

배포할 데이터에는 **어디서 왔고 어떤 조건으로 쓸 수 있는지**를 반드시 기록합니다. 웹 문서나 다른 데이터셋, 책의 문장을 가져오면 그 원본의 이용 조건을 따라야 하고, 조건에 따라 배포가 금지될 수도 있습니다. 다른 모델이 생성한 답을 데이터로 쓸 때도 그 모델의 이용 약관을 확인해야 합니다.

이 교재의 FPGA 데이터는 외부 문서를 인용하지 않고 **새로 작성**했습니다. 그 사실을 데이터 옆의 설명서(`README.md`, 흔히 Dataset Card라 부릅니다)와 저장소 전체의 데이터 목록(`datasets/LICENSES.md`)에 함께 적었습니다. 설명서에는 파일, 샘플 수, 형식, 문체, 출처, 라이선스, 검증 방법, 설계표를 담습니다. 1년 뒤의 나나 데이터를 받은 다른 사람이 이 데이터가 무엇인지 설명서만 보고 알 수 있어야 합니다.

## 전자·반도체·FPGA 도메인 설계

데이터를 쓰기 전에 **설계표**를 만듭니다. 이 분야의 학습자와 실무자가 실제로 묻는 질문을 유형별로 나누고, 유형마다 몇 개를 쓸지 정합니다.

| 분류 | 목표 수 | 질문 유형 |
|---|---|---|
| 개념 | 10 | FPGA 구조(LUT, BRAM, DSP)와 설계 단계의 용어 |
| Verilog 문법 | 10 | 문법 요소의 의미, 짧은 코드 해석 |
| 설계 기법 | 8 | 래치, FSM, 카운터, 파이프라인, 리셋, 디바운싱, 고정소수점 |
| 타이밍 | 8 | 셋업·홀드, 슬랙, 임계 경로, 클럭 도메인, 클럭 제약 |
| 도구와 흐름 | 7 | 설계 흐름, 테스트벤치, 제약 파일, 보고서, 디버깅 도구 |
| 디버깅 | 7 | 오류·경고의 원인, 확인 순서, 코드 속 버그 찾기 |

질문 형식도 섞었습니다. 대부분은 설명을 요청하지만, 5개는 Verilog 코드를 input에 주고 해석하거나 버그를 찾게 합니다. 실제 질문에는 코드가 함께 오는 경우가 많기 때문입니다. 제31·34장의 2의 보수, 고정소수점처럼 이 교재에서 다룬 주제와 이어지는 질문도 넣었습니다.

작성한 데이터의 예를 보면 다음과 같습니다.


### 설계 기준 검사와 구조 변환

파일명: `examples/ch41/check_dataset.py`

```python
# 제41장 핵심 실습: FPGA 질의응답 데이터셋을 설계 기준으로 검사하고, 세 가지 데이터 구조로 바꿔 본다
#
# 실행: python examples/ch41/check_dataset.py

import json
import sys
from collections import Counter
from pathlib import Path

ROOT = Path(__file__).resolve().parents[2]
sys.path.insert(0, str(ROOT / "examples"))

DATA = ROOT / "datasets" / "fpga_qa" / "fpga_qa.json"
FIELDS = ("id", "category", "instruction", "input", "output")
PLAN = {"개념": 10, "Verilog 문법": 10, "설계 기법": 8, "타이밍": 8, "도구와 흐름": 7, "디버깅": 7}


def load(path: Path = DATA) -> list:
    return json.loads(path.read_text(encoding="utf-8"))


def problems(rows: list) -> list:
    """설계 기준 위반 목록. 비어 있으면 통과."""
    out = []
    ids, questions = Counter(r.get("id") for r in rows), Counter(r.get("instruction") for r in rows)
    for r in rows:
        rid = r.get("id", "?")
        for f in FIELDS:
            if f not in r:
                out.append(f"{rid}: '{f}' 항목 없음")
            elif f != "input" and not str(r[f]).strip():
                out.append(f"{rid}: '{f}' 비어 있음")
        if r.get("category") not in PLAN:
            out.append(f"{rid}: 설계표에 없는 분류 '{r.get('category')}'")
        out_text = r.get("output", "").strip()
        if not out_text.endswith("다."):
            out.append(f"{rid}: 답변이 '~다.'로 끝나지 않음")
        if "아래 코드" in r.get("instruction", "") and not r.get("input"):
            out.append(f"{rid}: 코드를 가리키는 질문인데 input이 비어 있음")
    out += [f"{k}: id 중복 {v}회" for k, v in ids.items() if v > 1]
    out += [f"질문 중복 {v}회: {k[:20]}" for k, v in questions.items() if v > 1]
    counts = Counter(r.get("category") for r in rows)
    out += [f"분류 '{c}' {counts[c]}개(목표 {n}개)" for c, n in PLAN.items() if counts[c] != n]
    return out


def to_structures(r: dict) -> dict:
    """같은 샘플의 세 가지 구조(02절)"""
    prompt = r["instruction"] + (f"\n\n{r['input']}" if r["input"] else "")
    return {
        "instruction": {k: r[k] for k in ("instruction", "input", "output")},
        "prompt_completion": {"prompt": prompt, "completion": r["output"]},
        "messages": {"messages": [{"role": "user", "content": prompt},
                                  {"role": "assistant", "content": r["output"]}]},
    }


def main() -> None:
    rows = load()
    print(f"── 1. 설계 기준 검사({len(rows)}개) ──")
    found = problems(rows)
    print(f"  위반 {len(found)}건" + "".join(f"\n    {p}" for p in found))

    print("\n── 2. 설계표 대비 분류별 개수 ──")
    counts = Counter(r["category"] for r in rows)
    for c, n in PLAN.items():
        print(f"  {c:<12}{counts[c]:>3} / {n}")
    print(f"  코드가 있는 샘플(input 사용) {sum(1 for r in rows if r['input'])}개")

    print("\n── 3. 길이(글자 수, 토큰 수) ──")
    try:
        from common.qwen import load_tokenizer
        tok = load_tokenizer()
        q = [len(tok(r["instruction"] + r["input"]).input_ids) for r in rows]
        a = [len(tok(r["output"]).input_ids) for r in rows]
        print(f"  질문 토큰 평균 {sum(q) / len(q):.0f}, 최대 {max(q)} / 답변 토큰 평균 {sum(a) / len(a):.0f}, "
              f"최대 {max(a)}, 전체 {sum(q) + sum(a):,}")
    except Exception as e:
        print(f"  토크나이저 없음({type(e).__name__}), 글자 수만 계산")
    chars = [len(r["output"]) for r in rows]
    print(f"  답변 글자 평균 {sum(chars) / len(chars):.0f}, 최소 {min(chars)}, 최대 {max(chars)}")

    print("\n── 4. 같은 샘플(fpga-013)의 세 가지 구조 ──")
    sample = next(r for r in rows if r["id"] == "fpga-013")
    for name, s in to_structures(sample).items():
        print(f"  [{name}]\n  {json.dumps(s, ensure_ascii=False)}")


if __name__ == "__main__":
    main()
```

```python
import copy

from pathlib import Path

from check_dataset import PLAN, load, problems, to_structures  # noqa: E402

ROWS = load()


def test_dataset_passes_all_rules():
    assert len(ROWS) == 50 and problems(ROWS) == []


def test_checker_catches_violations():
    bad = copy.deepcopy(ROWS)
    del bad[0]["output"]                              # 필수 항목 누락
    bad[1]["category"] = "기타"                       # 설계표에 없는 분류
    bad[2]["output"] = "답변 끝맺음 없음"             # 문체 위반
    bad[3]["id"] = bad[4]["id"]                       # id 중복
    found = " ".join(problems(bad))
    for word in ("항목 없음", "설계표에 없는 분류", "끝나지 않음", "id 중복"):
        assert word in found


def test_three_structures_carry_same_content():
    r = next(x for x in ROWS if x["input"])
    s = to_structures(r)
    assert s["prompt_completion"]["completion"] == s["messages"]["messages"][1]["content"] == r["output"]
    assert r["input"] in s["prompt_completion"]["prompt"]
    assert [m["role"] for m in s["messages"]["messages"]] == ["user", "assistant"]


def test_license_and_card_recorded():
    root = Path(__file__).resolve().parents[2]
    lic = (root / "datasets" / "LICENSES.md").read_text(encoding="utf-8")
    card = (root / "datasets" / "fpga_qa" / "README.md").read_text(encoding="utf-8")
    assert "fpga_qa.json" in lic and "출처" in card and "라이선스" in card
    assert all(c in card for c in PLAN)
```

## 핵심 정리

- SFT는 질문과 모범 답변의 쌍으로 다음 토큰 예측을 학습해, 모델에게 **대답하는 방식**을 가르칩니다.
- 데이터는 Instruction·Input·Output, Prompt-Completion, 대화형 구조로 담을 수 있습니다. 원본은 작성·검토가 쉬운 구조 하나로 두고 필요할 때 변환합니다.
- 품질 기준은 정확성, 일관성, 형식 통일, 다양성, 중복 없음입니다. 기계로 검사할 수 있는 것은 코드로 검사합니다.
- 배포 데이터는 출처와 라이선스를 데이터 설명서와 데이터 목록에 기록합니다. 이 교재의 FPGA 데이터는 새로 작성한 50개입니다.
- 쓰기 전에 설계표로 분류와 목표 수를 정하고, 검사로 설계표와의 일치를 확인합니다.
