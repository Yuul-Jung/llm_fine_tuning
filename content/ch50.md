## 장 개요

제48·49장의 학습은 도메인 PPL을 크게 낮췄지만 핵심어 기준을 통과하지 못했습니다. 이제 "왜 실패했는가"를 묻고, 답에 맞춰 무엇을 바꿀지 정하고, 바꾼 결과를 다시 재야 합니다. 이 순환이 파인튜닝 작업의 대부분을 차지합니다.

이 장은 제5부의 마지막 장으로, 평가와 개선의 한 바퀴를 끝까지 돕니다. 틀린 답을 유형별로 나누고, 학습·검증 손실로 과적합을 판정하며, 원인에 맞춰 데이터를 보강하고 학습 길이를 바꾼 후보들을 **validation으로만** 비교합니다. 마지막으로 확정한 모델을 test로 **한 번만** 평가하고, 그 결과로 모델을 다시 고르지 않습니다. 개선이 실패하면 실패도 결과로 기록합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 무엇이 틀렸는지 어떻게 나누고, 무엇을 바꿔야 하며, 최종 성능은 어떻게 한 번에 확정하는가 |
| 실습 결과물 | 오답 유형표, 질문 변형 보강 데이터, 과적합 판정, 후보 4개 비교표, 확정 모델의 test 평가 |
| 실습 파일 | `examples/ch50/`의 `improve.py`, `test_ch50.py`, `runs.json`, `final_test.json`, 보강 데이터 `augment_v1.json` |
| 선수 장 | 제43장(기준), 제47장(기준값), 제48장(LoRA 학습) |

```text
제48장 LoRA 답 ─사람이 분류─▶ 오답 유형표 ─원인 가설─▶ (1) 과적합 → 15단계에서 멈춤 (2) 반복 부족 → 질문 변형 보강
   후보: 원본-15, 원본-30, 보강-15, 보강-30 ─validation, 제43장 기준─▶ 규칙으로 하나 확정
   확정 모델 ─test(한 번만)─▶ 최종 결과(다시 고르지 않음)
```

## 기준값과 학습 모델 비교

모든 비교는 제47장의 기준값과 **같은 validation 데이터, 같은 측정 함수**로 합니다. 제48장의 LoRA는 도메인 PPL을 17.64에서 12.55로 낮추고 일반 PPL을 21.89로 유지했지만, 핵심어 적중률(0.04)과 형식 준수율(0.67)이 기준에 못 미쳤습니다.

| 지표 | 무엇을 말하는가 | 제48장 LoRA |
|---|---|---|
| 도메인 PPL | 정답 문장을 얼마나 예측하기 쉬워졌나 | 크게 좋아짐 |
| 일반 PPL | 원래 능력을 잃지 않았나 | 유지 |
| 핵심어 | 답에 정답의 핵심 개념이 들어 있나 | 거의 없음 |
| 형식 | 짧은 존댓말 평서문인가 | 여섯 중 넷 |

도메인 PPL과 핵심어가 반대로 움직인다는 것이 첫 단서입니다. 모델은 정답 문장의 **말투와 단어 분포**를 배워 PPL은 낮아졌지만, 질문마다 다른 **사실**은 배우지 못했습니다.

## 과적합과 과소적합

학습 손실과 검증 손실을 함께 보면 학습 상태를 판정할 수 있습니다.

| 상태 | 학습 손실 | 검증 손실 |
|---|---|---|
| 과소적합 | 높게 머문다 | 높게 머문다 |
| 적절 | 내려간다 | 함께 내려간다 |
| 과적합 | 계속 내려간다 | 바닥을 찍고 오른다 |

제48장의 학습은 15단계 이후 학습 손실만 내려가고 검증 손실은 2.49에서 2.53으로 올랐습니다. train 38개를 여러 번 보며 **문장 자체를 외우기 시작한** 과적합입니다. 대응은 검증 손실이 가장 낮은 지점에서 멈추는 것(Early Stopping)입니다. 이 장은 같은 학습에서 15단계와 30단계의 Adapter를 모두 저장해 비교합니다.

## 하이퍼파라미터 조정

학습률, 묶음 크기, Rank, Target Modules, 단계 수 같은 설정은 **validation으로만** 고릅니다. test를 보고 설정을 고르면 test가 설정 선택에 쓰여, 마지막 평가가 실제보다 좋게 나옵니다. 제47~49장에서 핵심어·형식을 test로 재다가 이 문제를 발견해 기준 파일을 version 2로 고친 것도 같은 이유입니다(제43장).

후보가 여럿이면 **선택 규칙도 미리 정합니다.** 이 장의 규칙은 "제43장 기준 합격 수가 많은 것, 같으면 핵심어 적중률이 높은 것, 그래도 같으면 도메인 PPL이 낮은 것"입니다. 규칙을 먼저 적어 두면 결과를 본 뒤 마음에 드는 후보를 고르는 일을 막을 수 있습니다. 검증 문항이 6개뿐이므로 지표의 작은 차이는 우연일 수 있다는 점도 함께 기억합니다.

## 환각과 파국적 망각

학습 후에 나빠질 수 있는 두 가지를 따로 잽니다.

| 현상 | 무엇인가 | 이 교재의 측정 |
|---|---|---|
| 환각(Hallucination) | 그럴듯하지만 사실이 아닌 내용을 만든다 | 핵심어 적중률과 사람이 읽은 오답 유형 |
| 파국적 망각(Catastrophic Forgetting) | 새 데이터를 배우며 원래 능력을 잃는다 | 고정 eval 문장의 일반 PPL |

두 현상은 서로 다른 데이터로 재야 합니다. 환각은 도메인 질문(validation)에서, 망각은 도메인과 무관한 일반 문장에서 드러납니다. 도메인 PPL 하나로는 둘 다 보이지 않습니다. 제48장 학습에서 일반 PPL은 2% 오르는 데 그쳐 망각은 작았지만, 답은 거의 모두 환각이었습니다.

## 오답 분석과 재학습

틀린 답을 하나씩 읽고 유형을 나눕니다. 이 장은 세 가지를 기록합니다. 어떤 유형인가, 무엇이 틀렸는가, **train에 그 지식이 있는가**입니다. 마지막 질문이 가장 중요합니다. 학습 데이터에 없는 지식은 파인튜닝으로 생기지 않기 때문입니다.

| 유형 | 뜻 | 대응 |
|---|---|---|
| 사실 오류 | 개념을 지어내거나 틀리게 설명 | 지식이 train에 있으면 반복 노출, 없으면 데이터 추가 |
| 질문 오해 | 묻는 것과 다른 것에 답함 | 같은 유형의 질문 예시 추가 |
| 형식 위반 | 권유형, 목록, 잘림 | 과적합 억제, 형식이 일정한 예시 |

이 장의 보강은 **질문 변형**입니다(`datasets/fpga_qa/`의 `augment_v1.json`). train 38개마다 답은 그대로 두고 질문만 다르게 쓴 문항 하나를 더해 76개로 만듭니다. 같은 사실을 다른 질문으로 두 번 보게 해 "질문의 표현"이 아니라 "답의 내용"에 연결되도록 하려는 것입니다. 보강 문항은 원본과 같은 그룹이므로 모두 train에 두고, validation·test와 비슷하지 않은지 제43장의 누출 검사로 확인합니다.

## 최종 Test 평가

후보 비교가 끝나면 규칙으로 고른 모델 하나를 test로 한 번 평가합니다. 이 결과는 **보고만 하고, 모델을 다시 고르는 데 쓰지 않습니다.** test 결과가 기대보다 나빠도 다른 후보를 test로 다시 재지 않습니다. 그렇게 하면 test가 또 하나의 validation이 되어, 처음 보는 질문에 대한 성능을 아무도 모르게 됩니다. 결과가 나쁘면 그 사실을 기록하고, 다음 개선은 새 데이터와 새 test로 합니다.

## 핵심 실습

파일명: `examples/ch50/improve.py`

```python
# 제50장 핵심 실습: 오답 유형을 나누고, 데이터를 보강해 다시 학습한 뒤, 확정 모델을 test로 한 번만 평가한다
#
# 실행: python examples/ch50/improve.py   (교재 검증 환경 CPU 약 40분, 중간 결과는 runs.json에 저장되어 이어서 실행 가능)
#
# 만드는 파일: examples/ch50/runs.json, examples/ch50/final_test.json, models/ch50/(Adapter)

import gc
import json
import sys
from pathlib import Path

HERE = Path(__file__).resolve().parent
ROOT = HERE.parents[1]
for p in (HERE.parent, HERE.parent / "ch41", HERE.parent / "ch43", HERE.parent / "ch46",
          HERE.parent / "ch47", HERE.parent / "ch48"):
    sys.path.insert(0, str(p))

import torch  # noqa: E402
from transformers.utils import logging  # noqa: E402

from baseline import measure  # noqa: E402                    (제47장)
from check_dataset import load  # noqa: E402                   (제41장)
from clean_split import NGRAM_T, jaccard, ngrams  # noqa: E402  (제43장)
from criteria import judge, load_criteria  # noqa: E402        (제43장)
from lora_sft import SCOPES, lora_config  # noqa: E402         (제48장)
from sft_loop import SFTDataset, split_rows  # noqa: E402      (제46장)
from sft_trainer import SAME_AS_CH46, to_hf_dataset  # noqa: E402   (제47장)

logging.disable_progress_bar()
logging.set_verbosity_error()
RUNS = HERE / "runs.json"
FINAL = HERE / "final_test.json"
MODELS = ROOT / "models" / "ch50"

# 제48장 LoRA의 validation 답을 사람이 읽고 분류한 결과(유형, 근거, train에 관련 지식이 있는가)
ERRORS = {
    "fpga-005": ("사실 오류", "DSP를 '디지털 소규모 프로그래밍'으로 풀어 지어냄", False),
    "fpga-019": ("사실 오류", "generate를 '합성할 때 재사용하는 블록'으로 설명", False),
    "fpga-024": ("질문 오해", "몇까지 세야 하는지 계산하지 않고 '어렵다'고 답함", False),
    "fpga-033": ("사실 오류", "메타안정성을 '같은 값으로 유지되는 기능'으로 설명", True),
    "fpga-041": ("사실 오류", "ILA를 설계 파일 비교 도구처럼 설명, 권유형으로 끝남", False),
    "fpga-049": ("질문 오해", "래치를 찾지 못하고 'q가 d보다 클 때'를 문제로 짚음", True),
}
RELATED = {"fpga-033": "fpga-032(클럭 도메인 사이 동기화)", "fpga-049": "fpga-021(래치가 생기는 원인)"}


def augmented_rows() -> list:
    """train 38개 + 질문만 바꾼 변형 38개(답·입력·분류는 원본)"""
    src = {r["id"]: r for r in load()}
    aug = json.loads((ROOT / "datasets/fpga_qa/augment_v1.json").read_text(encoding="utf-8"))["rows"]
    return split_rows("train") + [dict(src[a["source_id"]], id=a["id"], instruction=a["instruction"]) for a in aug]


def leak_check(rows: list) -> float:
    """보강 데이터가 validation·test 문항과 비슷하지 않은지(제43장 기준)"""
    held = split_rows("validation") + split_rows("test")
    g = {r["id"]: ngrams(r["instruction"] + " " + r["input"]) for r in rows + held}
    return max(jaccard(g[a["id"]], g[h["id"]]) for a in rows for h in held)


def history(name: str) -> tuple:
    """Trainer가 Checkpoint에 남긴 기록에서 학습·검증 손실을 읽는다"""
    log = json.loads((MODELS / name / "checkpoint-30" / "trainer_state.json").read_text())["log_history"]
    return [(r["step"], r["loss"]) for r in log if "loss" in r], \
        [(r["step"], r["eval_loss"]) for r in log if "eval_loss" in r]


def train_run(name: str, rows: list, tok) -> tuple:
    """30단계 학습, 15단계와 30단계 Adapter를 저장한다(15단계 = 제48장의 검증 손실 최저 지점)"""
    from common.qwen import load_model
    from trl import SFTConfig, SFTTrainer
    if (MODELS / name / "checkpoint-30" / "trainer_state.json").exists():
        return history(name)                                     # 이미 학습했으면 기록만 읽는다
    torch.manual_seed(0)
    model = load_model()
    tr, va = SFTDataset(tok, rows), SFTDataset(tok, split_rows("validation"))
    cfg = {**SAME_AS_CH46, "learning_rate": 2e-4, "save_strategy": "steps", "save_steps": 15,
           "disable_tqdm": True}
    trainer = SFTTrainer(model=model, args=SFTConfig(output_dir=str(MODELS / name), use_cpu=True, **cfg),
                         processing_class=tok, peft_config=lora_config(SCOPES["모든 Linear"]),
                         train_dataset=to_hf_dataset(tr), eval_dataset=to_hf_dataset(va))
    trainer.train()
    del trainer, model
    gc.collect()                                                 # 메모리 7GB 환경: 다음 모델 전에 비운다
    return history(name)


def load_adapter(name: str, step: int):
    from common.qwen import load_model
    from peft import PeftModel
    return PeftModel.from_pretrained(load_model(), MODELS / name / f"checkpoint-{step}").eval()


def summary(m: dict, base: dict, c: dict) -> dict:
    hits, fmts = list(m["keyword_hit"].values()), list(m["format_ok"].values())
    v = judge(c, domain_ratio=m["domain_ppl"] / base["domain_ppl"],
              general_ratio=m["general_ppl"] / base["general_ppl"], hits=hits, fmts=fmts)
    return {"domain_ppl": m["domain_ppl"], "general_ppl": m["general_ppl"], "keyword": sum(hits) / len(hits),
            "format": sum(fmts) / len(fmts), "passed": sum(v.values()), "verdict": v}


def main() -> None:
    from common.qwen import load_tokenizer
    tok = load_tokenizer()
    c = load_criteria()
    base = json.loads((ROOT / "examples/ch47/baseline.json").read_text(encoding="utf-8"))

    print("── 1. 오답 유형표(제48장 LoRA, validation 6문항) ──")
    for i, (kind, why, covered) in ERRORS.items():
        print(f"  {i}  {kind:<6} train 관련 지식 {'있음' if covered else '없음'}  {why}")
    kinds = {k: sum(1 for v in ERRORS.values() if v[0] == k) for k in sorted({v[0] for v in ERRORS.values()})}
    print(f"  유형별: {kinds}, train에 관련 지식이 있는 문항: {[f'{k} ← {v}' for k, v in RELATED.items()]}")

    rows = augmented_rows()
    print(f"\n── 2. 데이터 보강: train {len(split_rows('train'))} + 질문 변형 {len(rows) - 38} = {len(rows)}개 ──")
    print(f"  보강 데이터와 validation·test의 최대 3-gram 유사도 {leak_check(rows):.2f} < {NGRAM_T}")

    runs = json.loads(RUNS.read_text(encoding="utf-8")) if RUNS.exists() else {}
    for name, data in (("원본", split_rows("train")), ("보강", rows)):
        if name not in runs:
            train, val = train_run(name, data, tok)
            runs[name] = {"train": train, "val": val}
            RUNS.write_text(json.dumps(runs, ensure_ascii=False, indent=1) + "\n", encoding="utf-8")
        for step in (15, 30):
            key = f"{name}-{step}"
            if key not in runs:
                model = load_adapter(name, step)
                runs[key] = summary(measure(tok, model), base, c)
                del model
                gc.collect()
            RUNS.write_text(json.dumps(runs, ensure_ascii=False, indent=1) + "\n", encoding="utf-8")

    print("\n── 3. 과적합 판정: 학습·검증 손실(샘플 평균) ──")
    for name in ("원본", "보강"):
        tr, va = dict(runs[name]["train"]), dict(runs[name]["val"])
        best = min(va, key=va.get)
        print(f"  {name}: " + "  ".join(f"{s}단계 {tr[s]:.2f}/{va[s]:.2f}" for s in sorted(va, key=int))
              + f"  → 검증 최저 {best}단계")

    print("\n── 4. 후보 비교(validation, 제43장 기준) ──")
    print("  후보      도메인PPL  일반PPL  핵심어  형식   합격")
    cands = ["원본-15", "원본-30", "보강-15", "보강-30"]
    for k in cands:
        r = runs[k]
        print(f"  {k:<8}{r['domain_ppl']:>9.2f}{r['general_ppl']:>9.2f}{r['keyword']:>8.2f}{r['format']:>6.2f}"
              f"   {r['passed']}/4")
    chosen = max(cands, key=lambda k: (runs[k]["passed"], runs[k]["keyword"], -runs[k]["domain_ppl"]))
    print(f"  선택 규칙: 합격 수 → 핵심어 → 도메인 PPL 순. 확정 모델: {chosen}")

    print("\n── 5. 최종 test 평가(확정 모델, 한 번만) ──")
    if not FINAL.exists():
        name, step = chosen.split("-")
        m = measure(tok, load_adapter(name, int(step)), split="test")
        FINAL.write_text(json.dumps({"chosen": chosen, "result": m}, ensure_ascii=False, indent=1) + "\n",
                         encoding="utf-8")
    final = json.loads(FINAL.read_text(encoding="utf-8"))
    m = final["result"]
    hits, fmts = list(m["keyword_hit"].values()), list(m["format_ok"].values())
    v = judge(c, domain_ratio=m["domain_ppl"] / base["domain_ppl"],
              general_ratio=m["general_ppl"] / base["general_ppl"], hits=hits, fmts=fmts)
    print(f"  {final['chosen']}: 핵심어 {sum(hits) / len(hits):.2f}, 형식 {sum(fmts) / len(fmts):.2f}"
          f"(test), 도메인 PPL {m['domain_ppl']:.2f}, 일반 PPL {m['general_ppl']:.2f}")
    print(f"  판정 {v} → {sum(v.values())}/4")
    for i, a in m["answers"].items():
```

**결과 읽기**

- **1번** 오답 유형표에서 6개 중 4개가 사실 오류, 2개가 질문 오해입니다. 더 중요한 것은 오른쪽 열입니다. DSP 블록, generate 문, 1Hz 카운터 계산, ILA는 train에 관련 문항이 **하나도 없습니다.** 메타안정성(fpga-032의 동기화)과 래치(fpga-021)만 관련 지식이 train에 있습니다. 넷은 처음부터 배울 수 없는 질문이었습니다.
- **2번**에서 보강 데이터 76개는 validation·test와 3-gram 유사도가 최대 0.33으로 누출이 없습니다.
- **3번**에서 원본은 15단계, 보강은 20단계에서 검증 손실이 가장 낮습니다. 보강 데이터는 같은 30단계 동안 각 문항을 덜 반복하므로(76개를 약 3번) 과적합이 늦게 옵니다.
- **4번** 후보 비교에서 15단계에서 멈춘 두 후보와 보강-30이 3/4 합격입니다. 형식 준수율이 0.67에서 1.00이 되어 합격했고, 도메인 PPL도 30단계보다 낮습니다. 과적합 전에 멈추는 것은 효과가 있었습니다. 그러나 **핵심어는 네 후보 모두 0.00~0.04로 그대로**입니다. 질문 변형 보강은 핵심어를 높이지 못했습니다. 이 개선은 실패했고, 그대로 기록합니다.
- 규칙에 따라 원본-15(합격 3, 핵심어 0.00, 도메인 PPL 12.06)가 보강-15(12.16)를 도메인 PPL 차이로 앞서 확정되었습니다. 차이는 작으며, 6문항 검증으로는 두 후보를 구별하기 어렵다는 것이 정직한 해석입니다.
- **5번**에서 확정 모델을 test로 한 번 평가했습니다. 형식 1.00, 핵심어 0.08로 test에서도 3/4 합격, 핵심어 불합격입니다(PPL 두 값은 test가 아니라 기준 정의대로 validation과 고정 eval로 잰 값입니다). 핵심어를 맞힌 것은 fpga-010의 "위치·연결" 두 개뿐이고, 임계 경로·FSM·X 값은 그럴듯한 틀린 설명입니다. 이 결과로 다른 후보를 다시 test하지 않습니다.
- 정리하면, 이 데이터 38개로 한 파인튜닝은 **말투와 형식은 가르쳤지만 지식은 가르치지 못했습니다.** 다음 개선은 질문 변형이 아니라 validation에서 드러난 빈 주제(DSP, generate, ILA 같은)를 다루는 **새 문항**을 train에 더하는 것이고, 그 결과는 새로 만든 test로 확인해야 합니다. 모델이 모르는 사실을 답하게 하는 다른 길(검색 결과를 함께 넣어 주는 RAG)도 있습니다.

```python
from pathlib import Path

HERE = Path(__file__).resolve().parent

from improve import ERRORS, FINAL, NGRAM_T, RUNS, augmented_rows, leak_check  # noqa: E402


def test_augmented_data_is_train_only_and_leak_free():
    rows = augmented_rows()
    split = json.loads((HERE.parents[1] / "datasets/fpga_qa/split_v1.json").read_text(encoding="utf-8"))["split"]
    assert len(rows) == 76 and len({r["id"] for r in rows}) == 76
    assert all(split[r["id"].removesuffix("-p1")] == "train" for r in rows)      # 원본이 모두 train

def test_error_table_covers_validation():
    split = json.loads((HERE.parents[1] / "datasets/fpga_qa/split_v1.json").read_text(encoding="utf-8"))["split"]
    assert sorted(ERRORS) == sorted(i for i, s in split.items() if s == "validation")


def test_candidates_recorded_and_final_once():
    runs = json.loads(RUNS.read_text(encoding="utf-8"))
    cands = ["원본-15", "원본-30", "보강-15", "보강-30"]
    assert all(k in runs and set(runs[k]["verdict"]) == {"domain_ppl", "keyword_hit", "format_ok", "general_ppl"}
               for k in cands)
    final = json.loads(FINAL.read_text(encoding="utf-8"))
    best = max(cands, key=lambda k: (runs[k]["passed"], runs[k]["keyword"], -runs[k]["domain_ppl"]))
    assert final["chosen"] == best                                             # validation 규칙으로 고른 모델
    assert final["result"]["split"] == "test" and len(final["result"]["answers"]) == 6

    runs = json.loads(RUNS.read_text(encoding="utf-8"))
    ch48 = json.loads((HERE.parent / "ch48" / "domain.json").read_text(encoding="utf-8"))
    assert abs(runs["원본-30"]["domain_ppl"] - ch48["after"]["domain_ppl"]) < 0.05   # 같은 설정 = 같은 결과
```

## 핵심 정리

- 학습 전후는 같은 데이터·같은 측정 함수로 비교하고, 도메인 PPL이 좋아져도 핵심어·답 읽기로 사실을 따로 확인합니다.
- 학습 손실은 내려가는데 검증 손실이 오르면 과적합입니다. 검증 손실이 가장 낮은 지점에서 멈추면 형식과 PPL이 함께 좋아졌습니다.
- 설정과 후보는 validation으로만, 미리 정한 규칙으로 고릅니다. 환각은 도메인 질문으로, 망각은 일반 문장으로 따로 잽니다.
- 오답을 유형별로 나누고 train에 그 지식이 있는지 확인합니다. 학습 데이터에 없는 지식은 파인튜닝으로 생기지 않으며, 질문 변형 보강은 핵심어를 높이지 못했습니다.
- 확정 모델은 test로 한 번만 평가하고, 결과가 나빠도 다시 고르지 않습니다. 실패한 개선도 결과로 기록합니다.
