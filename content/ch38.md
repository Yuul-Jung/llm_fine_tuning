## 장 개요

제37장에서 Qwen2.5-0.5B를 4비트로 불러오니 파라미터 메모리가 약 696MiB로 줄었습니다. 그 위에 LoRA를 붙여 학습하면 **QLoRA**(Quantized LoRA)입니다. 그러나 학습에는 가중치 말고도 메모리가 필요합니다. 역전파를 위해 저장하는 중간값(Activation), Gradient, Optimizer 상태, 그리고 어휘 15만 개짜리 Logits입니다. GT 1030의 2GB에 이 모두가 들어가야 합니다.

이 장은 QLoRA의 구성을 정리하고, 학습 메모리를 항목별로 나눠 계산·측정합니다. 그리고 가장 큰 항목인 Activation을 줄이는 Gradient Checkpointing을 켜고 끄며 효과를 재고, 메모리가 부족할 때 Optimizer 상태를 옮기는 Paged Optimizer의 원리를 봅니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | QLoRA 학습은 메모리를 어디에 얼마나 쓰며, 무엇을 줄여 2GB에 맞추는가 |
| 실습 결과물 | QLoRA 모델 구성, 학습 메모리 분해표, Gradient Checkpointing 전후의 저장 텐서·시간·손실 비교 |
| 실습 파일 | `examples/ch38/`의 `qlora_memory.py`, `test_ch38.py` |
| 선수 장 | 제23장(Gradient 메모리), 제24장(Optimizer 상태), 제30장(PEFT), 제37장(4비트 로딩) |

```text
QLoRA = 4비트 원본(동결) + FP32 LoRA(학습)
학습 메모리 = 원본 가중치 + LoRA(가중치·Gradient·AdamW) + Activation + Logits(+ Gradient) + 실행 환경
                 696MiB          8MiB                    ↑ 가장 크고 줄일 수 있다
```

## QLoRA의 구성

QLoRA는 지금까지 만든 두 가지를 겹친 것입니다.

| 부분 | 형식 | 학습 | 근거 |
|---|---|---|---|
| 원본 Linear 168개 | NF4 4비트 + 이중 양자화 | 동결 | 제36·37장 |
| Embedding, RMSNorm | FP32 | 동결 | 제37장 |
| LoRA A·B(q·v_proj, r = 8) | FP32 | 학습 | 제28~30장 |

순전파에서 4비트 Linear는 계산 직전에만 가중치를 FP32로 복원하고(제35장), LoRA 경로를 더합니다. 역전파에서 Gradient는 4비트 원본을 **지나가지만**(제29장의 "동결은 신호를 막지 않는다") 원본에는 쌓이지 않고, A·B에만 생깁니다. 원본이 4비트로 줄었고 Gradient와 Optimizer 상태가 LoRA 54만 개에만 붙으므로, 가중치 관련 메모리는 704MiB 남짓입니다.

PEFT의 `prepare_model_for_kbit_training()`은 4비트 모델을 학습할 준비를 해 줍니다. 입력 쪽 Gradient를 켜 Gradient Checkpointing과 함께 쓸 수 있게 하고, 정밀도가 중요한 계층의 자료형을 FP32로 맞춥니다. 이 교재는 처음부터 FP32이므로 주로 Checkpointing 준비 역할을 합니다.

## 학습 메모리 분해

학습에 필요한 메모리를 항목별로 나눕니다(Batch 1, 시퀀스 256, FP32).

```text
항목          크기를 정하는 것          계산
원본 가중치   모델 크기와 양자화        4비트 Linear 176MiB + Embedding 519MiB
LoRA          학습 파라미터 수          540,672개 × 16바이트(가중치·Gradient·AdamW)
Logits        시퀀스 × 어휘             256 × 151,936 × 4바이트 = 148MiB, Gradient도 같은 크기
Activation    시퀀스 × hidden × 계층    측정(실습)
실행 환경     GPU 드라이버·CUDA         GPU에서만, 수백 MiB
```

Logits가 큰 것은 Qwen의 어휘가 15만 개이기 때문입니다. 설계서가 "메모리가 부족하면 Batch보다 시퀀스 길이를 먼저 줄인다"고 정한 이유입니다. 시퀀스를 절반으로 줄이면 Logits와 Activation이 함께 절반이 됩니다.

**Activation**은 순전파에서 역전파를 위해 저장해 두는 중간값입니다. 크기는 구현에 따라 달라 공식으로 정확히 계산하기 어려우므로, 이 장은 직접 잽니다. PyTorch의 `saved_tensors_hooks`를 쓰면 역전파용으로 저장되는 모든 텐서를 하나하나 볼 수 있습니다. 실습은 이 기능으로 **새로 저장된** 텐서의 바이트만 셉니다. 가중치 자체(예: LM Head가 저장하는 Embedding 텐서)는 이미 메모리에 있으므로 빼고, 같은 저장 공간을 여러 번 가리키는 텐서는 한 번만 셉니다. 측정 대상을 정확히 정의하지 않으면 같은 메모리를 두 번 세게 됩니다.

## Gradient Checkpointing

Gradient Checkpointing은 **메모리를 시간과 바꾸는** 방법입니다.

```text
끔:  순전파에서 계층마다 중간값을 모두 저장 → 역전파에서 그대로 꺼내 쓴다
켬:  순전파에서 계층의 입력만 저장 → 역전파 때 그 계층의 순전파를 다시 계산해 중간값을 만든다
```

계층 안의 중간값(Attention 점수, FFN의 4,864차원 값 등)은 버리고 계층 경계의 입력 하나만 남기므로, Activation 메모리는 대략 "계층 수 × 입력 크기"로 줄어듭니다. 대가는 순전파를 한 번 더 하는 시간입니다. 흔히 학습 시간이 20~40% 늘어납니다. 계산 결과는 같으므로 손실과 Gradient는 바뀌지 않습니다.

Transformers에서는 두 가지로 켭니다.

```python
model.gradient_checkpointing_enable()
model = prepare_model_for_kbit_training(model, use_gradient_checkpointing=True)   # 4비트 모델
```

주의할 점이 있습니다. Checkpointing은 **학습 모드**(`model.train()`)에서만 동작합니다. 평가 모드에서는 켜 두어도 아무 일이 일어나지 않아, 측정 결과가 "효과 없음"으로 나옵니다. 이 장의 측정 함수가 `model.train()`을 먼저 부르는 이유입니다.

## Paged Optimizer

Optimizer 상태는 가중치마다 붙으므로(제24장), Full FT에서는 메모리의 큰 몫을 차지합니다. **Paged Optimizer**는 GPU 메모리가 순간적으로 모자랄 때 Optimizer 상태를 CPU 메모리로 잠시 옮겼다가(Paging) 필요할 때 다시 가져옵니다. 운영체제가 RAM이 부족할 때 디스크를 쓰는 것과 같은 원리이며, CUDA의 통합 메모리 기능을 씁니다. QLoRA 논문은 긴 시퀀스에서 메모리가 순간적으로 치솟을 때 학습이 멈추지 않도록 이 방법을 함께 썼습니다.

QLoRA에서는 Optimizer 상태가 LoRA 파라미터에만 붙어 4MiB 남짓으로 작습니다. 그래서 이 교재의 설정에서 Paged Optimizer의 이득은 크지 않으며, 원리만 정리하고 사용하지 않습니다. bitsandbytes의 Paged Optimizer를 GT 1030에서 실행하는 것은 교재 검증 환경에서 확인하지 않았습니다(미검증).

## 핵심 실습

4비트 Qwen2.5-0.5B에 PEFT LoRA(q·v_proj, r = 8)를 붙여 QLoRA 모델을 만들고, 고정 학습 데이터를 256토큰 블록으로 잘라 학습 한 단계를 실행합니다. Gradient Checkpointing을 끈 경우와 켠 경우의 저장 텐서·시간·손실을 비교합니다.

파일명: `examples/ch38/qlora_memory.py`

```python
# 제38장 핵심 실습: QLoRA(4비트 원본 + LoRA)의 학습 메모리를 분해하고 Gradient Checkpointing 효과를 잰다
#
# 실행: python examples/ch38/qlora_memory.py
#
# Activation은 "역전파를 위해 저장되는 텐서"의 바이트를 saved_tensors_hooks로 직접 센다(장치와 무관).

import sys
import time
from pathlib import Path

HERE = Path(__file__).resolve().parent
for p in (HERE.parent, HERE.parent / "ch22", HERE.parent / "ch37"):
    sys.path.insert(0, str(p))

import torch  # noqa: E402
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training  # noqa: E402

from common.fixed_data import load_blocks  # noqa: E402
from common.qwen import load_tokenizer  # noqa: E402
from load_4bit import hardware, load_nf4, memory_parts  # noqa: E402   (제37장)

MiB = 2 ** 20
SEQ = 256                                                   # GT 1030 QLoRA 기준 시퀀스(설계서 1.2절)


def build_qlora(device: str, checkpointing: bool) -> tuple:
    """(QLoRA 모델, LoRA를 붙이기 전 원본의 메모리 분해)"""
    model = load_nf4(device)
    parts = memory_parts(model)
    model = prepare_model_for_kbit_training(model, use_gradient_checkpointing=checkpointing,
                                            gradient_checkpointing_kwargs={"use_reentrant": False})
    cfg = LoraConfig(r=8, lora_alpha=16, target_modules=["q_proj", "v_proj"], lora_dropout=0.0,
                     bias="none", task_type="CAUSAL_LM")
    return get_peft_model(model, cfg), parts


def saved_bytes_of_step(model, ids) -> tuple:
    """순전파 동안 역전파용으로 새로 저장된 텐서의 바이트와 한 단계(순전파+역전파) 시간.

    파라미터와 같은 저장 공간을 쓰는 텐서(가중치 자체)는 빼고, 같은 저장 공간은 한 번만 센다.
    """
    params = {p.untyped_storage().data_ptr() for p in model.parameters()}
    seen, total = set(), [0]

    def pack(t):
        s = t.untyped_storage()
        if s.data_ptr() not in params and s.data_ptr() not in seen:
            seen.add(s.data_ptr())
            total[0] += s.nbytes()
        return t

    model.train()                                            # Checkpointing은 학습 모드에서만 동작한다
    t0 = time.perf_counter()
    with torch.autograd.graph.saved_tensors_hooks(pack, lambda t: t):
        loss = model(input_ids=ids, labels=ids).loss
    loss.backward()
    return total[0], time.perf_counter() - t0, loss.item()


def main() -> None:
    hw = hardware()
    tok = load_tokenizer()
    blocks = load_blocks(tok, "train", seq_len=SEQ)
    ids = blocks[:1].to(hw["device"])
    print(f"장치 {hw['name']}, 입력 [1, {SEQ}]\n")

    results = {}
    for ckpt in (False, True):
        torch.manual_seed(0)
        model, parts = build_qlora(hw["device"], ckpt)
        saved, sec, loss = saved_bytes_of_step(model, ids)
        trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)
        results[ckpt] = (saved, sec, loss, trainable, parts)
        del model

    saved0, sec0, loss0, trainable, parts = results[False]
    saved1, sec1, loss1, _, _ = results[True]
    base = sum(parts.values())
    lora_state = trainable * (4 + 4 + 8)                     # 가중치 + Gradient + AdamW 상태(FP32)
    logits = SEQ * 151_936 * 4

    print("── 1. QLoRA 구성 ──")
    print(f"  4비트 원본(동결) + Embedding 등: {base / MiB:7.1f}MiB, 학습 파라미터(LoRA) {trainable:,}개")

    print("\n── 2. 학습 메모리 분해(Batch 1, 시퀀스 256, FP32) ──")
    rows = [("원본 가중치(4비트 + Embedding)", base), ("LoRA 가중치·Gradient·AdamW", lora_state),
            ("Logits 하나(256 × 151,936 × 4)", logits),
            ("Activation(저장 텐서), Checkpointing 끔", saved0),
            ("Activation(저장 텐서), Checkpointing 켬", saved1)]
    for label, v in rows:
        print(f"  {label:<38}{v / MiB:8.1f}MiB")

    print("\n── 3. Gradient Checkpointing 비교 ──")
    print(f"  저장 텐서 {saved0 / MiB:.0f}MiB → {saved1 / MiB:.0f}MiB ({saved1 / saved0:.0%})")
    print(f"  한 단계 시간 {sec0:.2f}초 → {sec1:.2f}초 ({sec1 / sec0:.2f}배, 환경마다 다름)")
    print(f"  손실 같음: {abs(loss0 - loss1) < 1e-4}  ({loss0:.4f} / {loss1:.4f})")


if __name__ == "__main__":
    main()
```

실행(4비트 모델을 두 번 불러오므로 교재 검증 환경에서 약 1분):

```bash
python examples/ch38/qlora_memory.py
```

실제 실행 결과(교재 검증 환경, CPU 경로):

```text

── 2. 학습 메모리 분해(Batch 1, 시퀀스 256, FP32) ──
  원본 가중치(4비트 + Embedding)                  695.6MiB
  LoRA 가중치·Gradient·AdamW                    8.2MiB
  Logits 하나(256 × 151,936 × 4)             148.4MiB
  Activation(저장 텐서), Checkpointing 끔       602.3MiB
  Activation(저장 텐서), Checkpointing 켬       170.3MiB

── 3. Gradient Checkpointing 비교 ──
```

**결과 읽기**

- **1번**에서 QLoRA 모델의 학습 파라미터는 540,672개로, 제28장에서 q·v_proj 24계층에 r = 8을 붙일 때 계산한 값과 같습니다.
- **2번**에서 Checkpointing을 끄면 Activation(새로 저장된 텐서)이 602MiB로 원본 가중치와 맞먹습니다. 켜면 170MiB로 줄어듭니다. 남은 170MiB는 손실 계산을 위해 저장한 Logits(148MiB)와 24개 계층의 입력(24 × 256 × 896 × 4바이트 ≈ 21MiB)입니다. 계층 안의 중간값이 모두 사라졌습니다.
- **3번**에서 저장 텐서가 28%로 줄었고, 한 단계 시간은 1.3배 정도 늘었습니다. 손실은 두 경우가 같습니다. 같은 계산을 다시 한 것뿐이기 때문입니다.
- 이 숫자로 GT 1030의 학습 메모리를 추정하면 원본 696MiB + LoRA 8MiB + Activation 170MiB + Logits Gradient 148MiB에 CUDA 실행 환경(수백 MiB)과 역전파 중 다시 계산하는 한 계층의 중간값이 더해져, 설계 예산인 약 1.5GB 안팎입니다. 실제 값은 제39장에서 GPU로 측정해야 하며, 교재 검증 환경에서는 미검증입니다.

| 항목(Checkpointing 켬) | 크기 |
|---|---|
| 원본 가중치 | 695.6MiB |
| LoRA 가중치·Gradient·AdamW | 8.2MiB |
| Activation(Logits 포함) | 170.3MiB |
| Logits Gradient | 148.4MiB |
| 합계(실행 환경 제외) | 약 1,023MiB |

```python
# 제38장 검증 테스트
#
# 실행: python -m pytest examples/ch38 -q

import sys
from pathlib import Path

import pytest
import torch

HERE = Path(__file__).resolve().parent
for p in (HERE, HERE.parent, HERE.parent / "ch19", HERE.parent / "ch22", HERE.parent / "ch37"):
    sys.path.insert(0, str(p))

pytest.importorskip("peft")
pytest.importorskip("bitsandbytes")

from qlora_memory import saved_bytes_of_step  # noqa: E402


def tiny():
    """어휘를 512개로 줄인 Qwen2-Tiny 구조(Logits가 Activation 비교를 가리지 않게)"""
    from tiny_model import TINY
    from transformers import Qwen2Config, Qwen2ForCausalLM
    torch.manual_seed(0)
    return Qwen2ForCausalLM(Qwen2Config(**{**TINY, "vocab_size": 512}, tie_word_embeddings=True))


def test_checkpointing_saves_memory_same_loss():
    ids = torch.randint(0, 512, (1, 128))
    a = tiny()
    saved0, _, loss0 = saved_bytes_of_step(a, ids)
    b = tiny()
    b.gradient_checkpointing_enable(gradient_checkpointing_kwargs={"use_reentrant": False})
    saved1, _, loss1 = saved_bytes_of_step(b, ids)
    assert saved1 < 0.6 * saved0
    assert loss1 == pytest.approx(loss0, abs=1e-5)
    for pa, pb in zip(a.parameters(), b.parameters()):        # 같은 Gradient
        torch.testing.assert_close(pa.grad, pb.grad, atol=1e-5, rtol=1e-4)


def test_parameters_not_counted_as_activation():
    lin = torch.nn.Linear(1000, 1000)
    x = torch.randn(1, 1000, requires_grad=True)

    class Wrap(torch.nn.Module):
        def __init__(self):
            super().__init__()
            self.lin = lin

        def forward(self, input_ids, labels):
            return type("O", (), {"loss": self.lin(x).sum()})()

    saved, _, _ = saved_bytes_of_step(Wrap(), None)
    assert saved < 1000 * 1000 * 4                           # 가중치(4MB)는 세지 않는다


def test_qlora_trainable_count():
    try:
        from qlora_memory import build_qlora
        model, parts = build_qlora("cpu", checkpointing=True)
    except Exception:
        pytest.skip("Qwen 모델이 아직 내려받아지지 않음")
    assert sum(p.numel() for p in model.parameters() if p.requires_grad) == 540_672   # 제28장 계산
    assert parts["Embedding(= LM Head)"] == 151_936 * 896 * 4
```

## 핵심 정리

- QLoRA는 4비트로 얼린 원본 위에 FP32 LoRA를 붙여 학습합니다. Gradient와 Optimizer 상태는 LoRA에만 생깁니다.
- 학습 메모리는 원본 가중치, LoRA, Activation, Logits와 그 Gradient, 실행 환경으로 나뉩니다. Qwen의 큰 어휘 때문에 Logits가 시퀀스 256에서 148MiB나 됩니다.
- Gradient Checkpointing은 계층 안의 중간값을 버리고 역전파 때 다시 계산해, Activation을 602MiB에서 170MiB로 줄였습니다. 시간은 늘고 결과는 같습니다. 학습 모드에서만 동작합니다.
- Paged Optimizer는 Optimizer 상태를 CPU 메모리로 옮겨 순간적인 부족을 견디는 방법이며, Optimizer 상태가 작은 QLoRA에서는 이득이 작습니다.
