## 장 개요

제28장에서 LoRA의 수식 `y = W x + (α/r)·B(A x)`를 손으로 확인했습니다. 이 장에서는 이 수식을 PyTorch 계층으로 옮깁니다. 기존 `nn.Linear`를 감싸 원본은 얼리고 A·B만 학습하는 `LoRALinear`를 만들고, 사전학습한 Qwen2-Tiny(제25장)의 계층을 바꿔 끼워 학습한 뒤, 학습이 끝나면 원본에 병합합니다.

라이브러리(PEFT, 제30장)를 쓰기 전에 직접 구현하는 이유는, 라이브러리가 하는 일을 하나도 빠짐없이 알기 위해서입니다. 직접 만든 LoRA로 Gradient가 어디로 흐르는지, 원본이 정말 그대로인지, 병합이 정말 같은 결과를 내는지 확인하고 나면, 제30장의 PEFT 결과도 같은 기준으로 검증할 수 있습니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | LoRA를 코드로 어떻게 구현하며, 실제 모델에 붙였을 때 학습·동결·병합이 의도대로 동작하는가 |
| 실습 결과물 | `LoRALinear` 계층, Gradient 흐름 확인, 대상·학습률별 학습 결과, 병합 전후 Logits 비교 |
| 실습 파일 | `examples/ch29/`의 `lora_linear.py`, `lora_tiny.py`, `test_ch29.py` |
| 선수 장 | 제25장(학습 루프, 사전학습 모델), 제26장(동결·부분 학습), 제28장(LoRA 수식) |

```text
q_proj: nn.Linear(256, 256)
   ↓ apply_lora()
q_proj: LoRALinear
          ├── base:   nn.Linear(256, 256)   동결(원래 가중치·편향)
          ├── lora_A: [8, 256]               학습, 작은 난수
          └── lora_B: [256, 8]               학습, 0
   ↓ merge_lora()
q_proj: nn.Linear(256, 256)   W' = W + (α/r)·BA
```

## LoRALinear 설계

`LoRALinear`는 원래의 `nn.Linear`를 버리지 않고 `base`라는 이름으로 품습니다. 그래서 원래 가중치와 편향이 그대로 남고, 순전파는 `base(x)`에 LoRA 경로를 더하는 것으로 끝납니다.

| 설계 결정 | 이유 |
|---|---|
| 원래 Linear를 `base`로 품는다 | 편향까지 포함한 원래 계산을 그대로 재사용하고, 병합할 때 꺼내 쓴다 |
| 생성할 때 `base`의 모든 파라미터를 동결 | 실수로 원본이 학습되는 일을 막는다 |
| A는 `nn.Linear`와 같은 방식의 작은 난수, B는 0 | 시작 출력이 원본과 같고, 첫 단계에 B부터 움직인다(제28장) |
| A·B를 `base`와 같은 장치·자료형으로 | GPU 경로에서도 그대로 동작한다 |

모델에 붙이는 `apply_lora()`는 두 단계로 일합니다. 먼저 모델 전체를 동결하고, 그다음 이름이 대상 목록(`q_proj`, `v_proj` 등)과 같은 Linear만 `LoRALinear`로 바꿉니다. 이렇게 하면 학습 가능한 파라미터는 A·B뿐입니다. A의 난수는 `seed`로 고정해, 같은 설정이면 언제나 같은 초기값에서 학습이 시작되게 했습니다.

## 순전파와 역전파

`LoRALinear`는 보통의 PyTorch 계층이므로 Autograd(제23장)가 역전파를 알아서 처리합니다. 확인할 것은 두 가지입니다.

```text
원본 base.weight:  requires_grad=False  →  .grad = None       (Gradient도, Optimizer 상태도 없음)
lora_A, lora_B:    requires_grad=True   →  .grad 생성         (첫 단계에서 A의 Gradient는 0)
```

Gradient는 손실에서 출발해 모든 계층을 거쳐 거꾸로 흐르지만, 원본 가중치에서 멈춥니다. 다만 Gradient가 **지나가는** 길은 막히지 않습니다. 0번 계층의 LoRA까지 신호가 닿으려면 1~3번 계층의 원본 가중치를 지나야 하는데, 원본이 동결되어 있어도 그 계층의 입력 쪽으로 Gradient를 전달하는 계산은 그대로 합니다. 동결은 "이 가중치를 바꾸지 않는다"는 뜻이지 "신호를 막는다"는 뜻이 아닙니다.

## Qwen2-Tiny에 적용

LoRA를 처음 제안한 논문은 Attention의 Query와 Value Projection에 LoRA를 붙이는 설정을 주로 실험했습니다. 이 교재도 q_proj·v_proj를 기본으로 하고, 비교를 위해 일곱 Linear 전부(q, k, v, o, gate, up, down)에 붙이는 설정도 학습합니다.

| 설정 | 학습 파라미터(r = 8) | 비율 |
|---|---|---|
| q·v_proj | 4계층 × (4,096 + 2,560) = 26,624 | 0.063% |
| 7종 전부 | 151,552 | 0.36% |
| (참고) 제26장 마지막 Block | 754,560 | 1.8% |

학습 데이터·단계·학습률 일정은 제26장과 같게 했습니다(자전거 정비 데이터, 60단계). 학습률은 Full FT와 같은 3e-4와, LoRA에서 흔히 쓰는 더 큰 값 2e-3을 비교합니다. 제26장의 "RMSNorm만" 실험에서 보았듯, 학습 파라미터가 적을수록 더 큰 학습률이 필요할 수 있기 때문입니다.

## 가중치 병합

학습이 끝나면 `merge_lora()`가 모든 `LoRALinear`를 `W' = W + (α/r)·BA`를 담은 보통의 `nn.Linear`로 되돌립니다. 병합한 모델은 처음의 Qwen2-Tiny와 계층 구조·파라미터 수가 똑같으므로, 제25장과 같은 방식으로 `save_pretrained`해 어떤 도구에서도 쓸 수 있습니다.

병합 전후의 출력은 같아야 하지만, 비트 하나까지 같지는 않습니다. `W x + s·B(A x)`와 `(W + s·BA) x`는 수학적으로 같아도 부동소수점 계산 순서가 다르기 때문입니다. 그래서 병합은 허용 오차 안의 일치로 판정합니다.

## 핵심 실습

### LoRALinear

파일명: `examples/ch29/lora_linear.py`

```python
# 제29장: 기존 Linear를 감싸 원본은 동결하고 A·B만 학습하는 LoRALinear
#
# y = base(x) + (α/r) · B (A x)            base: 원래 nn.Linear(동결, 편향 포함)

import math

import torch
from torch import nn


class LoRALinear(nn.Module):
    def __init__(self, base: nn.Linear, r: int = 8, alpha: float = 16.0):
        super().__init__()
        self.base, self.r, self.scale = base, r, alpha / r
        for p in self.base.parameters():
            p.requires_grad_(False)                                   # 원본 동결
        device, dtype = base.weight.device, base.weight.dtype
        self.lora_A = nn.Parameter(torch.empty(r, base.in_features, device=device, dtype=dtype))
        self.lora_B = nn.Parameter(torch.zeros(base.out_features, r, device=device, dtype=dtype))
        nn.init.kaiming_uniform_(self.lora_A, a=math.sqrt(5))         # nn.Linear와 같은 방식의 작은 난수

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return self.base(x) + self.scale * ((x @ self.lora_A.T) @ self.lora_B.T)

    @torch.no_grad()
    def merged(self) -> nn.Linear:
        """W' = W + (α/r)·BA를 담은 보통의 nn.Linear를 새로 만들어 돌려준다(원본은 그대로)."""
        out = nn.Linear(self.base.in_features, self.base.out_features, bias=self.base.bias is not None,
                        device=self.base.weight.device, dtype=self.base.weight.dtype)
        out.weight.copy_(self.base.weight + self.scale * (self.lora_B @ self.lora_A))
        if self.base.bias is not None:
            out.bias.copy_(self.base.bias)
        return out


ALL_LINEAR = ("q_proj", "k_proj", "v_proj", "o_proj", "gate_proj", "up_proj", "down_proj")


def apply_lora(model: nn.Module, targets=("q_proj", "v_proj"), r: int = 8, alpha: float = 16.0,
               seed: int = 0) -> list:
    """모델 전체를 동결한 뒤, 이름이 targets인 Linear를 LoRALinear로 바꾼다. A의 난수는 seed로 고정한다."""
    torch.manual_seed(seed)
    for p in model.parameters():
        p.requires_grad_(False)
    replaced = []
    for name, module in list(model.named_modules()):
        for child_name, child in list(module.named_children()):
            if child_name in targets and isinstance(child, nn.Linear):
                setattr(module, child_name, LoRALinear(child, r, alpha))
                replaced.append(f"{name}.{child_name}")
    return replaced


def merge_lora(model: nn.Module) -> int:
    """모든 LoRALinear를 병합한 nn.Linear로 되돌린다. 바꾼 개수를 돌려준다."""
    count = 0
    for module in list(model.modules()):
        for child_name, child in list(module.named_children()):
            if isinstance(child, LoRALinear):
                setattr(module, child_name, child.merged())
                count += 1
    return count


def trainable_count(model: nn.Module) -> int:
    return sum(p.numel() for p in model.parameters() if p.requires_grad)
```

### Qwen2-Tiny에 LoRA 붙이기, 학습, 병합

파일명: `examples/ch29/lora_tiny.py`

```python
# 제29장 핵심 실습: 사전학습 Qwen2-Tiny의 q_proj·v_proj에 직접 만든 LoRA를 붙여 학습하고 병합한다
#
# 실행: python examples/ch29/lora_tiny.py   (먼저 제25장 pretrain_tiny.py로 사전학습 모델을 만든다)

import math
import sys
from pathlib import Path

HERE = Path(__file__).resolve().parent
for p in (HERE, HERE.parent, HERE.parent / "ch24", HERE.parent / "ch25", HERE.parent / "ch26"):
    sys.path.insert(0, str(p))

import torch  # noqa: E402
from transformers import Qwen2ForCausalLM  # noqa: E402
from transformers.utils import logging  # noqa: E402

from common.device import select_device  # noqa: E402
from common.fixed_data import load_blocks  # noqa: E402
from common.qwen import load_tokenizer  # noqa: E402
from lora_linear import ALL_LINEAR, LoRALinear, apply_lora, merge_lora, trainable_count  # noqa: E402
from partial_ft import snapshot  # noqa: E402         (제26장)
from trainer import eval_loss, train  # noqa: E402     (제25장)

logging.disable_progress_bar()
PRETRAINED = HERE.parents[1] / "models" / "qwen2-tiny-pretrained"


def ppl(model, blocks, device) -> float:
    return math.exp(eval_loss(model, blocks, device))


def main() -> None:
    device, _ = select_device()
    tok = load_tokenizer()
    data = {s: load_blocks(tok, s) for s in ("eval", "domain_train", "domain_eval")}

    print("── 1. LoRALinear 붙이기(r = 8, α = 16) ──")
    model = Qwen2ForCausalLM.from_pretrained(PRETRAINED, dtype=torch.float32).to(device)
    probe = data["domain_eval"][:, :32].to(device)
    with torch.no_grad():
        before_logits = model(probe).logits
    replaced = apply_lora(model)
    with torch.no_grad():
        same = torch.equal(model(probe).logits, before_logits)
    total = sum(p.numel() for p in model.parameters())
    print(f"  바꾼 계층 {len(replaced)}개: {replaced[0]}, {replaced[1]}, …")
    print(f"  학습 파라미터 {trainable_count(model):,} / {total:,} ({trainable_count(model) / total:.3%})")
    print(f"  붙인 직후 Logits가 원본과 완전히 같음(B = 0): {same}")

    print("\n── 2. 역전파: Gradient는 A·B에만 ──")
    x = data["domain_train"][:1].to(device)
    model(input_ids=x, labels=x).loss.backward()
    lora = model.model.layers[0].self_attn.q_proj
    print(f"  원본 q_proj.weight.grad: {lora.base.weight.grad}")
    print(f"  lora_A.grad 0 아닌 원소 {torch.count_nonzero(lora.lora_A.grad).item()}개, "
          f"lora_B.grad 0 아닌 원소 {torch.count_nonzero(lora.lora_B.grad).item()}개")
    model.zero_grad(set_to_none=True)

    print("\n── 3. 대상과 학습률별 도메인 학습(60단계, 제26장과 같은 데이터·단계) ──")
    base_ppl = (ppl(model, data["domain_eval"], device), ppl(model, data["eval"], device))
    print(f"  학습 전{'':<18}도메인 PPL {base_ppl[0]:6.1f}, 일반 PPL {base_ppl[1]:6.1f}")
    results = {}
    for label, targets, lr in (("q·v, lr 3e-4", ("q_proj", "v_proj"), 3e-4),
                               ("q·v, lr 2e-3", ("q_proj", "v_proj"), 2e-3),
                               ("7종 전부, lr 2e-3", ALL_LINEAR, 2e-3)):
        m = Qwen2ForCausalLM.from_pretrained(PRETRAINED, dtype=torch.float32)
        apply_lora(m, targets)
        frozen = {n: p for n, p in snapshot(m).items() if "lora_" not in n}
        train(m, data["domain_train"], {}, steps=60, lr=lr, warmup=5, device=device, log_every=60)
        kept = all(torch.equal(p, snapshot(m)[n].cpu()) for n, p in frozen.items())
        results[label] = m
        print(f"  {label:<22}도메인 PPL {ppl(m, data['domain_eval'], device):6.1f}, "
              f"일반 PPL {ppl(m, data['eval'], device):6.1f}, 학습 {trainable_count(m):>7,}개, "
              f"원본 그대로 {kept}")

    print("\n── 4. 병합: LoRALinear → 보통의 Linear ──")
    m = results["7종 전부, lr 2e-3"].eval()
    with torch.no_grad():
        lora_logits = m(probe).logits
    n = merge_lora(m)
    with torch.no_grad():
        merged_logits = m(probe).logits
    left = sum(isinstance(mod, LoRALinear) for mod in m.modules())
    print(f"  병합한 계층 {n}개, 남은 LoRALinear {left}개, 파라미터 {sum(p.numel() for p in m.parameters()):,}개")
    print(f"  병합 전후 Logits 최대 차이 {(lora_logits - merged_logits).abs().max().item():.1e}")
    print(f"  병합 모델 도메인 PPL {ppl(m, data['domain_eval'], device):.1f}")


if __name__ == "__main__":
    main()
```

**결과 읽기**

- **1번**에서 LoRA를 붙인 직후의 Logits가 원본과 비트 하나까지 같습니다. B가 0이므로 LoRA 경로가 정확히 0을 더하기 때문입니다. 학습 파라미터는 전체의 0.063%인 26,624개입니다.
- **2번**에서 원본 가중치의 `.grad`는 `None`이고, 첫 역전파에서 A의 Gradient는 0, B의 Gradient만 0이 아닙니다. 제28장의 손계산과 같은 결과를 실제 모델에서 확인했습니다.
- **3번**에서 q·v_proj에 학습률 3e-4를 쓰면 60단계 동안 도메인 PPL이 거의 줄지 않습니다(884.9 → 858.0). 학습률을 2e-3으로 올리면 735.9까지 내려갑니다. 2만 6천 개의 파라미터에는 더 큰 학습률이 필요합니다.
- **7종 전부**에 붙이면 도메인 PPL이 397.7까지 내려가, 다섯 배 많은 파라미터를 쓴 제26장의 "마지막 Block"(477.0)보다 잘 배웠습니다. 모든 계층에 조금씩 손을 대는 방식이 한 계층을 통째로 고치는 것보다 효율적일 수 있다는 뜻입니다.
- 그러나 일반 PPL은 342.8 → 442.3으로 크게 올라, 제25장의 Full FT(399.2)보다도 많이 잊었습니다. 원본을 동결했다고 망각이 사라지는 것은 아닙니다. 높은 학습률로 모든 계층의 출력을 바꾸면, 원본 가중치가 그대로여도 모델의 행동은 크게 바뀝니다.
- 세 설정 모두 학습 후 원본 가중치가 학습 전과 완전히 같습니다(`원본 그대로 True`). 바뀐 것은 A·B뿐입니다.
- **4번**에서 병합 후 `LoRALinear`가 모두 사라지고 파라미터 수가 원래 Qwen2-Tiny의 41,914,112개로 돌아옵니다. 병합 전후 Logits 차이는 8.6e-06으로 계산 순서 차이 수준이며, 도메인 PPL도 같습니다.

제3부의 질문, "적은 파라미터로 망각 없이 새 분야를 배울 수 있는가"에 대한 이 장의 답은 "설정에 달렸다"입니다. 대상 계층, r, 학습률이 학습 효과와 망각의 균형을 정합니다. 제30장에서 PEFT 라이브러리로 같은 실험을 재현하고, 제40장에서 Full FT·LoRA·QLoRA를 같은 조건으로 비교합니다.

## 핵심 정리

- `LoRALinear`는 원래 Linear를 `base`로 품어 동결하고, A(작은 난수)와 B(0)만 학습합니다. 순전파는 `base(x) + (α/r)·B(A x)`입니다.
- 원본 가중치에는 Gradient가 생기지 않지만, Gradient가 원본 계층을 지나 앞 계층의 LoRA까지 전달되는 것은 막히지 않습니다.
- Qwen2-Tiny의 q·v_proj에 r = 8을 붙이면 학습 파라미터는 0.063%입니다. 적은 파라미터에는 큰 학습률이 필요했고, 7종 전부에 붙이면 마지막 Block 학습보다 적은 파라미터로 더 잘 배웠습니다.
- 원본을 동결해도 학습률이 높으면 망각이 생깁니다. 대상·r·학습률이 학습 효과와 망각의 균형을 정합니다.
- 병합하면 `LoRALinear`가 보통의 Linear로 돌아가고, 출력은 허용 오차 안에서 같습니다.

**다음 장 연결:** 제30장에서는 Hugging Face의 PEFT 라이브러리로 같은 LoRA를 적용합니다. 라이브러리의 설정(`LoraConfig`)이 이 장의 직접 구현과 어떻게 대응하는지 확인하고, 직접 구현과 같은 결과가 나오는지 비교합니다.
