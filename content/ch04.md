## 장 개요

제03장이 텐서의 모양을 다뤘다면, 이 장은 텐서끼리의 **계산**을 다룹니다. LLM이 하는 계산의 대부분은 놀랄 만큼 단순한 두 연산, 내적과 행렬곱의 반복입니다. 이 둘을 손으로 계산할 수 있으면 Attention도 FFN도 더 이상 마법이 아닙니다.

이 장에서는 행렬곱을 반복문으로 직접 만들어 라이브러리가 하는 일을 눈으로 확인합니다. 그리고 내적 결과의 분산이 차원 수에 비례해 커진다는 사실을 실험으로 측정합니다. 이 측정값은 제13장에서 Attention 점수를 `√dₖ`로 나누는 이유의 근거가 됩니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 행렬곱은 무엇을 계산하며, 내적 값은 차원이 커질수록 어떻게 변하는가 |
| 실습 결과물 | 반복문 행렬곱과 PyTorch 결과 비교, 차원별 내적 분산 측정표 |
| 실습 파일 | `examples/ch04/`의 `matmul_loop.py`, `dot_variance.py`, `test_ch04.py` |
| 선수 장 | 제02장(행렬곱 연산 수), 제03장(모양과 축) |

```text
[내적] 두 벡터 → 같은 위치끼리 곱해 더하기 → 숫자 하나(닮은 정도)
   ↓
[통계] 평균·분산 → 내적의 분산은 d에 비례 → √d로 나누면 1
   ↓
[행렬곱] 원소별 곱과 구분 → 차원 규칙 [m,k]×[k,n]=[m,n] → Broadcasting·Batch
   ↓
[핵심 실습] 반복문 구현 = PyTorch 결과, 측정 분산 ≈ d
```

## 벡터의 내적

내적(Dot Product)은 길이가 같은 두 벡터를 **같은 위치끼리 곱한 뒤 모두 더한** 값입니다.

```text
u = [1, 2, 3]
v = [4, 5, 6]
u · v = 1×4 + 2×5 + 3×6 = 4 + 10 + 18 = 32
```

결과는 숫자 하나지만, 그 안에는 두 벡터의 관계가 담겨 있습니다.

| 두 벡터의 관계 | 내적 값 | 예 |
|---|---|---|
| 같은 방향을 가리킨다 | 크고 양수 | `[1, 2] · [2, 4] = 10` |
| 직각을 이룬다(관계없음) | 0 | `[1, 0] · [0, 1] = 0` |
| 반대 방향을 가리킨다 | 크고 음수 | `[1, 2] · [-1, -2] = -5` |

LLM은 이 성질을 그대로 이용합니다. 제13장 Attention에서 "이 토큰이 저 토큰을 얼마나 참고할까"를 정하는 점수가 바로 두 벡터(Query와 Key)의 내적입니다. 내적이 클수록 두 토큰이 서로 관련 있다고 판단합니다.

## 평균과 분산

내적 값이 "크다"고 말하려면 기준이 필요합니다. 그 기준이 평균과 분산입니다.

| 통계량 | 뜻 | 계산 |
|---|---|---|
| 평균(Mean) | 값들의 중심 | 모두 더해 개수로 나눈다 |
| 분산(Variance) | 값들이 중심에서 퍼진 정도 | 평균과의 차이를 제곱해 평균한다 |
| 표준편차(Std) | 퍼진 정도를 원래 단위로 | 분산의 제곱근 |

### 내적의 분산은 차원에 비례한다

다음 세 가지를 **가정**합니다. 두 벡터의 각 원소가 ① 서로 독립이고, ② 평균이 0이며, ③ 분산이 1이라고 합시다. 신경망의 초기 가중치와 정규화된 값은 대략 이 조건을 따릅니다.

이 가정 아래에서 내적 `q · k = q₁k₁ + q₂k₂ + … + q_d k_d`의 각 항 `qᵢkᵢ`는 평균 0, 분산 1입니다. 서로 독립인 값의 분산은 더하면 그대로 더해지므로, 항이 `d`개인 내적의 분산은 다음과 같습니다.

```text
Var(q · k) = 1 + 1 + … + 1 (d개) = d          표준편차 = √d
Var(q · k / √d) = d / d = 1                     ← 차원과 관계없이 일정
```

차원이 64인 벡터의 내적은 표준편차가 8이고, 1024차원이면 32입니다. 차원이 커질수록 내적 값이 크게 출렁입니다. 이 값을 그대로 Softmax에 넣으면 한 칸만 확률이 1에 가깝고 나머지는 0이 되는 쏠림이 생깁니다(제13장). 그래서 Attention은 내적을 `√d`로 나눠 분산을 1로 되돌립니다. 이 장의 핵심 실습 2가 이 이론을 숫자로 확인합니다.

## 원소별 곱과 행렬곱

모양이 같은 두 행렬을 곱하는 방법은 두 가지이며, 결과가 완전히 다릅니다.

```text
x = [[1, 2],      y = [[10, 20],
     [3, 4]]           [30, 40]]

원소별 곱 x * y = [[1×10, 2×20],     = [[ 10,  40],
                   [3×30, 4×40]]        [ 90, 160]]

행렬곱   x @ y = [[1×10+2×30, 1×20+2×40],   = [[ 70, 100],
                  [3×10+4×30, 3×20+4×40]]      [150, 220]]
```

원소별 곱은 Hadamard Product(하다마드 곱), 행렬곱은 Matrix Multiplication이라고 부릅니다.

| 구분 | 원소별 곱 | 행렬곱 |
|---|---|---|
| PyTorch 기호 | `*` | `@`, `matmul` |
| 계산 | 같은 위치끼리 곱한다 | 행과 열의 내적 |
| 모양 조건 | 같은 모양(또는 Broadcasting 가능) | 앞 행렬의 열 수 = 뒤 행렬의 행 수 |
| LLM에서 | SwiGLU의 게이트 곱(제17장), 마스크 적용 | 모든 Linear 계층, Attention 점수 |

코드에서 `*`와 `@` 한 글자 차이가 전혀 다른 계산이 됩니다. 제17장 SwiGLU 수식 `down(silu(gate(x)) ⊙ up(x))`에는 두 연산이 함께 등장하므로, 지금 확실히 구분해 두어야 합니다.

## 행렬곱의 차원 규칙

행렬곱 결과의 `(i, j)` 칸은 **앞 행렬의 i번째 행과 뒤 행렬의 j번째 열의 내적**입니다. 내적은 길이가 같은 벡터끼리만 할 수 있으므로, 모양에 관한 규칙 하나가 생깁니다.

```text
[m, k] × [k, n] = [m, n]
     └─┬─┘
   안쪽 차원 k가 같아야 곱할 수 있고, 곱한 뒤에는 사라진다
   바깥 차원 m과 n이 결과의 모양이 된다
```

| 계산 | 모양 | 결과 |
|---|---|---|
| 손계산 예제 | `[2, 3] × [3, 2]` | `[2, 2]` |
| 토큰 표현 × 가중치 | `[4, 896] × [896, 128]` | `[4, 128]` (Qwen의 K Projection) |
| Query × Key의 전치 | `[4, 64] × [64, 4]` | `[4, 4]` (Attention 점수) |
| 곱할 수 없는 경우 | `[2, 3] × [2, 3]` | 오류: 안쪽 차원 3 ≠ 2 |

이 규칙 하나면 모델의 어느 계층이든 입력 모양만 보고 출력 모양을 예측할 수 있습니다. 제2부에서 계층을 조립할 때마다 이 예측을 먼저 하고 코드로 확인합니다.

## Broadcasting과 Batch 행렬곱

실제 LLM 코드의 텐서는 2차원보다 큽니다. PyTorch는 두 가지 규칙으로 고차원 계산을 간결하게 만들어 줍니다.

### Broadcasting: 모양 자동 확장

모양이 다른 두 텐서를 계산할 때, 길이 1이거나 없는 축을 상대에 맞춰 **복사한 것처럼** 늘려 계산합니다. 실제로 메모리에 복사하지는 않습니다.

```text
h @ w + bias
[2, 4, 8] @ [8, 3]  →  [2, 4, 3]      가중치 w는 모든 문장·토큰이 함께 쓴다
             + [3]  →  [2, 4, 3]      bias [3]이 [2, 4, 3]으로 늘어나 더해진다
```

Linear 계층의 편향(Bias)이 문장·토큰마다 따로 저장되지 않고 하나만 있어도 되는 이유가 Broadcasting입니다. 제03장에서 본 마스크 `[2, 1, 1, 4]`도 같은 규칙으로 Attention 점수 `[2, 2, 4, 4]`에 맞춰집니다.

### Batch 행렬곱: 묶음 단위로 한 번에

3차원 이상의 텐서에 `@`를 쓰면, 마지막 두 축으로 행렬곱을 하고 앞의 축들은 **묶음 번호**로 취급합니다.

```text
q @ k.transpose(1, 2)
[2, 4, 8] @ [2, 8, 4] = [2, 4, 4]
 └ 문장 0: [4, 8] × [8, 4] = [4, 4]
 └ 문장 1: [4, 8] × [8, 4] = [4, 4]   ← 두 문장을 반복문 없이 한 번에 계산
```

이것이 제13장 Attention 점수 계산의 실제 모양입니다. 제03장에서 익힌 `transpose`로 Key를 뒤집고, Batch 행렬곱으로 모든 문장의 점수를 한 번에 구합니다.

## 반복문 행렬곱 직접 구현

라이브러리의 `@` 한 글자 뒤에서 무슨 일이 일어나는지, 정의 그대로 반복문으로 구현해 봅니다. 결과의 칸마다 내적 하나를 계산하면 됩니다.

```text
for i in 결과의 행:            ← m번
    for j in 결과의 열:        ← n번
        c[i, j] = 내적(a의 i행, b의 j열)   ← 내적 안에서 k번 곱하고 더함
총 곱셈 m × n × k번 = n×n 행렬이면 n³번(제02장의 2n³ 중 곱셈 몫)
```

구현은 다음 절의 실습 코드 `matmul_loop()`에 있습니다. 같은 계산을 PyTorch는 최적화된 수학 라이브러리로 수백 배 빠르게 처리합니다. 반복문 구현의 목적은 속도가 아니라 **정의를 확인하는 것**이며, 앞으로 직접 구현과 라이브러리 결과를 비교하는 이 교재의 검증 방식이 여기서 시작됩니다.

## 핵심 실습

### 실습 1. 반복문 행렬곱과 PyTorch 비교

파일명: `examples/ch04/matmul_loop.py`

```python
# 제04장 핵심 실습 1: 내적과 행렬곱을 반복문으로 직접 구현하고 PyTorch와 비교
#
# 실행: python examples/ch04/matmul_loop.py

import time

import torch


def dot(u: torch.Tensor, v: torch.Tensor) -> float:
    """두 벡터의 내적: 같은 위치끼리 곱해 모두 더한다."""
    assert u.shape == v.shape, "내적은 길이가 같은 두 벡터에서만 정의된다"
    total = 0.0
    for i in range(u.shape[0]):
        total += u[i].item() * v[i].item()
    return total


def matmul_loop(a: torch.Tensor, b: torch.Tensor) -> torch.Tensor:
    """[m, k] × [k, n] = [m, n]: 결과의 (i, j) 칸은 a의 i행과 b의 j열의 내적이다."""
    m, k = a.shape
    k2, n = b.shape
    assert k == k2, f"안쪽 차원이 달라 곱할 수 없음: {tuple(a.shape)} × {tuple(b.shape)}"
    c = torch.zeros(m, n, dtype=a.dtype)
    for i in range(m):
        for j in range(n):
            c[i, j] = dot(a[i, :], b[:, j])
    return c


def main() -> None:
    print("── 1. 손계산 예제 ──")
    a = torch.tensor([[1., 2., 3.],
                      [4., 5., 6.]])          # [2, 3]
    b = torch.tensor([[7., 8.],
                      [9., 10.],
                      [11., 12.]])            # [3, 2]
    print("반복문 결과:\n", matmul_loop(a, b))
    print("torch 결과:\n", a @ b)

    print("\n── 2. 무작위 행렬 비교 ──")
    torch.manual_seed(0)
    a = torch.randn(16, 32)
    b = torch.randn(32, 8)
    loop_c = matmul_loop(a, b)
    torch_c = a @ b
    print(f"모양: {tuple(a.shape)} × {tuple(b.shape)} = {tuple(torch_c.shape)}")
    print(f"최대 절대오차: {(loop_c - torch_c).abs().max().item():.2e}")

    print("\n── 3. 원소별 곱과 행렬곱 ──")
    x = torch.tensor([[1., 2.], [3., 4.]])
    y = torch.tensor([[10., 20.], [30., 40.]])
    print("x * y (원소별 곱):\n", x * y)
    print("x @ y (행렬곱):\n", x @ y)

    print("\n── 4. Broadcasting과 Batch 행렬곱 ──")
    h = torch.randn(2, 4, 8)            # [batch, seq, hidden]
    w = torch.randn(8, 3)               # 모든 문장이 공유하는 가중치
    bias = torch.randn(3)               # [3] → [2, 4, 3]으로 자동 확장
    print(f"[2, 4, 8] @ [8, 3] + [3] = {tuple((h @ w + bias).shape)}")
    q = torch.randn(2, 4, 8)
    k = torch.randn(2, 4, 8)
    scores = q @ k.transpose(1, 2)      # 문장마다 [4, 8] × [8, 4]
    print(f"Batch 행렬곱 [2, 4, 8] @ [2, 8, 4] = {tuple(scores.shape)}")
    same = torch.allclose(scores[1], q[1] @ k[1].T)
    print(f"묶음 안 문장 1의 결과 = 따로 계산한 결과: {same}")

    print("\n── 5. 속도 비교(64×64) ──")
    a = torch.randn(64, 64)
    b = torch.randn(64, 64)
    start = time.perf_counter()
    matmul_loop(a, b)
    loop_s = time.perf_counter() - start
    start = time.perf_counter()
    a @ b
    torch_s = time.perf_counter() - start
    print(f"반복문 {loop_s * 1e3:.1f} ms, torch {torch_s * 1e3:.3f} ms")


if __name__ == "__main__":
    main()
```

```bash
python examples/ch04/matmul_loop.py
```

**핵심 코드 풀이**

- `dot()`은 정의 그대로 같은 위치끼리 곱해 더합니다. `matmul_loop()`은 결과의 칸마다 `dot(a[i, :], b[:, j])`를 부릅니다. 행렬곱이 "내적의 표"라는 사실이 코드 구조에 그대로 드러납니다.
- `assert k == k2`는 차원 규칙을 코드로 옮긴 것입니다. 안쪽 차원이 다르면 계산을 시작하기 전에 멈춥니다.
- 1번 손계산 예제의 첫 칸 58은 `1×7 + 2×9 + 3×11`입니다. 나머지 세 칸도 직접 계산해 출력과 맞춰 보세요.
- 2번의 최대 절대오차 `3.81e-06`은 0이 아닙니다. 반복문과 PyTorch가 덧셈 순서를 다르게 하기 때문인데, FP32에서는 더하는 순서가 바뀌면 마지막 자리가 달라질 수 있습니다. 그래서 이 교재는 부동소수점 비교에 "완전 일치" 대신 **허용 오차**를 씁니다(설계서 7.1절).
- 4번 마지막 줄은 Batch 행렬곱이 문장마다 따로 계산한 결과와 같음을 확인합니다.
- 5번은 반복문이 PyTorch보다 수백 배 느리다는 것을 보여 줍니다. PyTorch 시간에는 첫 호출의 준비 시간이 섞여 있어, 정확한 비교는 제02장의 측정 방식(워밍업·반복·중앙값)을 따라야 합니다.

### 실습 2. 내적 분산 측정

파일명: `examples/ch04/dot_variance.py`

```python
# 제04장 핵심 실습 2: 내적 결과의 분산은 차원 수 d에 비례하는가
#
# 실행: python examples/ch04/dot_variance.py
#
# 가정: 두 벡터의 각 원소가 서로 독립이고, 평균 0·분산 1인 정규분포를 따른다.
# 이론: Var(q·k) = d,  Var(q·k / √d) = 1   → 제13장 Attention의 √dₖ 나누기 근거

import math

import torch

DIMS = [4, 16, 64, 256, 1024]
SAMPLES = 20000


def dot_statistics(d: int, samples: int = SAMPLES, seed: int = 0) -> tuple:
    """길이 d인 무작위 벡터 쌍을 samples개 만들어 내적의 평균과 분산을 구한다."""
    generator = torch.Generator().manual_seed(seed)
    q = torch.randn(samples, d, generator=generator)
    k = torch.randn(samples, d, generator=generator)
    dots = (q * k).sum(dim=-1)          # 쌍마다 내적 하나 → [samples]
    return dots.mean().item(), dots.var().item()


def main() -> None:
    print(f"{'d':>6}{'평균':>10}{'분산':>12}{'이론 분산':>10}{'√d로 나눈 뒤 분산':>18}")
    for d in DIMS:
        mean, var = dot_statistics(d)
        # q·k를 √d로 나누면 분산은 1/d배가 된다: Var(X / c) = Var(X) / c²
        print(f"{d:>6}{mean:>10.3f}{var:>12.1f}{d:>10}{var / d:>18.3f}")
    print("\n√d로 나누면 차원과 관계없이 분산이 약 1로 유지된다.")
    print(f"예) d = 64(Qwen2.5-0.5B의 head_dim): 표준편차 √64 = {math.sqrt(64):.0f} → 나눈 뒤 1")


if __name__ == "__main__":
    main()
```

**핵심 코드 풀이**

- `torch.randn(samples, d)`는 평균 0, 분산 1인 정규분포에서 값을 뽑습니다. 02절에서 세운 세 가지 가정을 코드로 만든 것입니다.
- `(q * k).sum(dim=-1)`은 원소별 곱 뒤에 마지막 축을 따라 더합니다. 20,000쌍의 내적을 반복문 없이 한 번에 계산하는 방법으로, 03절의 원소별 곱과 제03장의 축 연산이 함께 쓰였습니다.
- 측정 분산(4.0, 16.0, 63.2, 252.1, 1031.5)이 이론값 `d`와 거의 같습니다. 표본이 유한하므로 몇 퍼센트 차이는 자연스러운 오차입니다.
- 마지막 열은 `√d`로 나눈 뒤의 분산입니다. 차원이 4에서 1024로 256배 커져도 모두 1 근처에 머뭅니다. 제13장 Attention이 점수를 `√dₖ`로 나누는 이유를 숫자로 확인한 것입니다.
- 난수 생성기(`Generator`)의 시작값을 `manual_seed(seed)`로 고정해, 다시 실행해도 같은 표가 나옵니다.

```python
import sys

import torch

from dot_variance import dot_statistics  # noqa: E402
from matmul_loop import dot, matmul_loop  # noqa: E402


def test_dot_hand_calculation():
    # 1×4 + 2×5 + 3×6 = 32
    assert dot(torch.tensor([1., 2., 3.]), torch.tensor([4., 5., 6.])) == 32.0


def test_matmul_hand_calculation():
    a = torch.tensor([[1., 2., 3.], [4., 5., 6.]])
    b = torch.tensor([[7., 8.], [9., 10.], [11., 12.]])
    expected = torch.tensor([[58., 64.], [139., 154.]])
    assert torch.equal(matmul_loop(a, b), expected)


def test_matmul_matches_torch():
    torch.manual_seed(0)
    a, b = torch.randn(16, 32), torch.randn(32, 8)
    torch.testing.assert_close(matmul_loop(a, b), a @ b, atol=1e-5, rtol=1e-5)


def test_inner_dimension_mismatch():
    with pytest.raises(AssertionError):
        matmul_loop(torch.zeros(2, 3), torch.zeros(2, 3))


def test_hadamard_is_not_matmul():
    x = torch.tensor([[1., 2.], [3., 4.]])
    y = torch.tensor([[10., 20.], [30., 40.]])
    assert torch.equal(x * y, torch.tensor([[10., 40.], [90., 160.]]))
    assert torch.equal(x @ y, torch.tensor([[70., 100.], [150., 220.]]))


def test_broadcast_and_batch_shapes():
    assert (torch.randn(2, 4, 8) @ torch.randn(8, 3) + torch.randn(3)).shape == (2, 4, 3)
    q, k = torch.randn(2, 4, 8), torch.randn(2, 4, 8)
    scores = q @ k.transpose(1, 2)
    assert scores.shape == (2, 4, 4)
    torch.testing.assert_close(scores[1], q[1] @ k[1].T)


@pytest.mark.parametrize("d", [16, 64, 256])
def test_dot_variance_close_to_d(d):
    # 표본 20,000개의 분산 추정 오차를 고려해 이론값 d의 ±5% 이내를 통과로 본다.
    mean, var = dot_statistics(d)
    assert abs(mean) < 0.1 * d ** 0.5
    assert abs(var / d - 1) < 0.05
```

## 핵심 정리

- 내적은 같은 위치끼리 곱해 더한 값으로, 두 벡터가 얼마나 같은 방향인지를 나타냅니다. Attention 점수의 정체입니다.
- 독립·평균 0·분산 1인 원소로 된 `d`차원 벡터의 내적은 분산이 `d`이며, `√d`로 나누면 분산이 1로 돌아옵니다.
- 원소별 곱(`*`)과 행렬곱(`@`)은 전혀 다른 계산입니다. 행렬곱의 각 칸은 행과 열의 내적입니다.
- `[m, k] × [k, n] = [m, n]`: 안쪽 차원이 같아야 곱할 수 있고, 바깥 차원이 결과의 모양이 됩니다.
- Broadcasting은 모양을 자동으로 맞추고, Batch 행렬곱은 앞쪽 축을 묶음 번호로 보고 한 번에 계산합니다.
