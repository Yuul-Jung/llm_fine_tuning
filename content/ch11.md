## 장 개요

제1부에서 우리는 Transformer의 입구(토크나이저·Embedding)와 출구(Logits·Softmax·생성)를 만들었습니다. 제2부는 그 사이, 896차원 벡터들이 서로 정보를 주고받으며 문맥을 쌓아 가는 **Transformer 본체**를 다룹니다.

이 장은 제2부의 지도입니다. 부품을 하나씩 만들기 전에 전체 구조를 한 장의 그림으로 고정하고, 그 그림이 실제 Qwen2.5-0.5B의 계층 이름·모양·파라미터 수와 정확히 맞는지 확인합니다. 지도와 실제 지형이 일치한다는 것을 확인해 두면, 제12~20장에서 어떤 부품을 만들든 지금 어디에 있는지 잃지 않습니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | Transformer는 어떤 블록으로 이루어지며, 데이터는 어떤 경로로 흐르는가 |
| 실습 결과물 | 순차·병렬 처리 비교, Qwen2.5-0.5B 계층 지도와 블록별 파라미터 표, Shape 추적 |
| 실습 파일 | `examples/ch11/`의 `rnn_vs_attention.py`, `model_map.py`, `test_ch11.py`와 공통 모듈 `examples/common/qwen.py` |
| 선수 장 | 제05장(Linear), 제06장(활성화·Softmax), 제10장(Embedding·Weight Tying) |

```text
[역사] RNN의 순차 처리 → Attention의 병렬 처리
   ↓
[구조] Encoder · Decoder · Decoder-only → LLM은 Decoder-only
   ↓
[반복 단위] Norm → Attention → 더하기 → Norm → FFN → 더하기 (× 24)
   ↓
[핵심 실습] 구조도 ↔ Qwen2.5-0.5B 실제 계층 이름·모양·파라미터 수 대조
```

## RNN에서 Transformer로

Transformer 이전의 언어 모델은 주로 RNN(Recurrent Neural Network, 순환 신경망)이었습니다. RNN은 문장을 **한 토큰씩 순서대로** 읽으며, 지금까지 읽은 내용을 상태 벡터 하나에 요약해 다음 단계로 넘깁니다.

```text
RNN:   h₁ ← x₁        h₂ ← (x₂, h₁)        h₃ ← (x₃, h₂)   …   위치마다 이전 결과를 기다림
Attention: 모든 위치 쌍의 점수를 행렬곱 한 번으로 동시에 계산
```

| 구분 | RNN | Transformer(Self-Attention) |
|---|---|---|
| 처리 순서 | 위치마다 순서대로 | 모든 위치를 한꺼번에 |
| 순차 단계 수 | 시퀀스 길이만큼 | 계층 수만큼(길이와 무관) |
| 먼 토큰의 정보 | 상태 벡터를 여러 번 거치며 희미해짐 | 직접 연결(점수 한 칸) |
| GPU 활용 | 기다림이 많아 낮음 | 행렬곱 위주라 높음 |

RNN은 1,024개 토큰을 읽으려면 1,024번을 순서대로 계산해야 합니다. 앞 단계가 끝나야 다음 단계를 시작할 수 있어, 제02장에서 본 GPU의 수많은 코어를 놀리게 됩니다. 또 첫 토큰의 정보가 마지막까지 가려면 상태 벡터를 천 번 넘게 거쳐야 하므로 점점 희미해집니다.

Transformer의 Self-Attention은 모든 토큰 쌍의 관계를 제04장의 Batch 행렬곱 한 번으로 계산합니다. 시퀀스가 길어져도 순차 단계는 늘지 않고, 첫 토큰과 마지막 토큰이 점수 한 칸으로 직접 연결됩니다. 다만 다음 토큰을 맞히도록 학습하는 모델은 정답인 미래 토큰을 미리 보면 안 되므로, 미래 위치를 가리는 마스크를 씁니다(제14장). 핵심 실습 1에서 이 차이를 직접 확인합니다.

## Encoder, Decoder, Decoder-only

2017년 처음 발표된 Transformer는 번역을 위한 **Encoder-Decoder** 구조였습니다. 이후 용도에 따라 한쪽만 쓰는 구조가 갈라져 나왔습니다.

| 구조 | 하는 일과 보는 범위 | 대표 모델 |
|---|---|---|
| Encoder-only | 문장을 이해해 표현 벡터로 만든다. 앞뒤 모든 토큰을 본다 | BERT |
| Encoder-Decoder | 입력을 이해(Encoder)한 뒤 출력을 생성(Decoder)한다. Decoder는 과거 토큰과 Encoder 출력을 본다 | T5 |
| Decoder-only | 앞의 토큰으로 다음 토큰을 생성한다. 과거 토큰만 본다 | GPT, Llama, **Qwen** |

오늘날 LLM이 Decoder-only를 택한 이유는 제07장에서 배운 학습 방식과 맞아떨어지기 때문입니다. 문장의 모든 위치에서 "다음 토큰 맞히기"를 동시에 학습할 수 있고, 학습한 그대로 한 토큰씩 생성하면 됩니다. 질문과 답변을 나누지 않고 하나의 긴 토큰열로 다루므로 구조도 단순합니다. 이 교재가 다루는 Qwen2.5도 Decoder-only입니다.

## Transformer Block 구성

Decoder-only Transformer는 같은 모양의 블록(Decoder Layer)을 여러 번 쌓은 것입니다. Qwen2.5-0.5B는 이 블록을 24번 반복합니다. 블록 하나의 구조는 다음과 같습니다.

```text
입력 x [batch, seq, 896]
  │
  ├──────────────────────────┐
  ▼                          │ (지름길)
RMSNorm   input_layernorm    │
  ▼                          │
Self-Attention  self_attn    │   토큰끼리 정보를 주고받음
  ▼                          │
  + ◀────────────────────────┘   잔차 연결(Residual)
  │
  ├──────────────────────────┐
  ▼                          │
RMSNorm   post_attention_layernorm
  ▼                          │
FFN       mlp                │   토큰마다 특징을 변환
  ▼                          │
  + ◀────────────────────────┘
  │
출력 [batch, seq, 896]   ← 입력과 같은 모양이라 그대로 다음 블록에 들어감
```

| 부품 | 역할 | 구현 장 |
|---|---|---|
| RMSNorm | 값의 크기를 일정하게 맞춤 | 제18장 |
| Self-Attention | 다른 토큰의 정보를 가져옴 | 제12~16장 |
| 잔차 연결 | 블록의 입력을 출력에 더해 줌 | 제18장 |
| FFN | 토큰별로 특징을 변환 | 제17장 |

실제 계층 이름은 다음과 같습니다.

```text
RMSNorm         input_layernorm, post_attention_layernorm
Self-Attention  self_attn  (q_proj, k_proj, v_proj, o_proj)
잔차 연결        별도 계층 없음(코드의 + 연산)
FFN             mlp        (gate_proj, up_proj, down_proj)
```

블록의 출력 모양이 입력과 똑같다는 점이 핵심입니다. 그래서 같은 블록을 원하는 만큼 쌓을 수 있습니다. Attention은 "토큰 사이"의 일을, FFN은 "토큰 각자"의 일을 맡아, 둘이 번갈아 가며 24번 반복됩니다.

## Qwen2 계열의 데이터 흐름

블록을 쌓은 본체에 제1부의 입구와 출구를 붙이면 전체 모델이 됩니다.

```text
Token ID              [batch, seq]                     토크나이저(제08장)
  │ model.embed_tokens                                  Embedding(제10장)
벡터                   [batch, seq, 896]
  │ model.layers[0] … model.layers[23]                  Decoder Layer × 24(제12~19장)
벡터                   [batch, seq, 896]
  │ model.norm                                          Final Norm(제18장)
벡터                   [batch, seq, 896]
  │ lm_head  (= embed_tokens와 같은 텐서)                 LM Head(제10장 Weight Tying)
Logits                [batch, seq, 151936]
  │ 마지막 위치 → Softmax → 선택                           생성(제06·07장)
다음 토큰
```

위치 정보를 넣는 RoPE(제16장)는 별도의 가중치 없이 Attention 안에서 Query와 Key를 회전시키는 계산이라, 구조도에는 `self_attn` 안에 포함됩니다. 실제 모델에는 회전 각도를 미리 계산해 두는 `rotary_emb` 모듈이 있지만, 학습되는 파라미터는 없습니다.

이 그림이 제2부 전체의 지도입니다. 제12장부터 각 화살표와 상자를 하나씩 직접 구현하고, 제19장에서 모두 조립해 같은 구조의 작은 모델 Qwen2-Tiny를 완성합니다.

## 핵심 실습

### 실습 1. 순차 처리와 병렬 처리

파일명: `examples/ch11/rnn_vs_attention.py`

```python
# 제11장 실습 1: 순차 처리(RNN)와 병렬 처리(Self-Attention)의 계산 순서 비교
#
# 실행: python examples/ch11/rnn_vs_attention.py

import torch


def rnn_forward(x: torch.Tensor, w_x: torch.Tensor, w_h: torch.Tensor) -> tuple:
    """h_t = tanh(x_t W_xᵀ + h_(t-1) W_hᵀ): 이전 결과가 있어야 다음을 계산할 수 있다."""
    seq, hidden = x.shape[0], w_h.shape[0]
    h = torch.zeros(hidden)
    outputs, steps = [], 0
    for t in range(seq):                       # 위치마다 한 번씩, 순서대로
        h = torch.tanh(x[t] @ w_x.T + h @ w_h.T)
        outputs.append(h)
        steps += 1
    return torch.stack(outputs), steps


def attention_forward(x: torch.Tensor) -> tuple:
    """모든 위치 쌍의 점수를 행렬곱 한 번으로 계산하고, 미래 위치는 가린다."""
    seq = x.shape[0]
    scores = x @ x.T / x.shape[1] ** 0.5            # [seq, seq]: 한 번에 계산
    future = torch.triu(torch.ones(seq, seq, dtype=torch.bool), diagonal=1)
    weights = torch.softmax(scores.masked_fill(future, float("-inf")), dim=-1)
    return weights @ x, 1                            # 행렬곱 단계: 위치 수와 무관


def main() -> None:
    torch.manual_seed(0)
    for seq in (4, 64, 1024):
        x = torch.randn(seq, 8)
        _, rnn_steps = rnn_forward(x, torch.randn(8, 8) * 0.3, torch.randn(8, 8) * 0.3)
        _, attn_steps = attention_forward(x)
        print(f"시퀀스 {seq:>5}: RNN 순차 단계 {rnn_steps:>5}번, Attention 순차 단계 {attn_steps}번")

    print("\n앞 위치의 결과는 뒤 토큰이 바뀌어도 변하지 않는가?")
    x = torch.randn(6, 8)
    y = x.clone()
    y[-1] = torch.randn(8)                              # 마지막 토큰만 교체
    w_x, w_h = torch.randn(8, 8) * 0.3, torch.randn(8, 8) * 0.3
    rnn_same = torch.allclose(rnn_forward(x, w_x, w_h)[0][:-1], rnn_forward(y, w_x, w_h)[0][:-1])
    att_same = torch.allclose(attention_forward(x)[0][:-1], attention_forward(y)[0][:-1])
    print(f"  RNN: {rnn_same},  Attention(미래 가림): {att_same}")


if __name__ == "__main__":
    main()
```

```bash
python examples/ch11/rnn_vs_attention.py
```

실제 실행 결과(교재 검증 환경):

```text
시퀀스     4: RNN 순차 단계     4번, Attention 순차 단계 1번
시퀀스    64: RNN 순차 단계    64번, Attention 순차 단계 1번
시퀀스  1024: RNN 순차 단계  1024번, Attention 순차 단계 1번

앞 위치의 결과는 뒤 토큰이 바뀌어도 변하지 않는가?
  RNN: True,  Attention(미래 가림): True
```

**핵심 코드 풀이**

- `rnn_forward()`의 `for t in range(seq)`가 RNN의 본질입니다. `h`를 계산하려면 직전의 `h`가 있어야 하므로, 이 반복은 병렬로 바꿀 수 없습니다. 시퀀스가 1,024면 1,024번을 차례로 계산합니다.
- `attention_forward()`는 `x @ x.T` 한 번으로 모든 위치 쌍의 점수 `[seq, seq]`를 만듭니다. 반복문이 없으므로 시퀀스 길이와 관계없이 순차 단계는 1번입니다. 점수 계산의 자세한 의미는 제13장에서 다룹니다.
- `torch.triu(..., diagonal=1)`로 만든 마스크는 각 위치가 자기보다 뒤의 위치를 보지 못하게 가립니다. 마지막 토큰을 바꿔도 앞 위치의 결과가 그대로인 것(`True`)이 그 증거입니다. RNN은 구조상 원래 과거만 보므로 역시 `True`입니다. 마스크의 원리는 제14장에서 자세히 봅니다.

### 실습 2. Qwen2.5-0.5B 구조 지도 대조

실제 모델을 불러와 설정값, 계층 이름과 모양, 블록별 파라미터 수, 데이터 흐름의 Shape를 앞 절의 구조도와 하나씩 맞춥니다. 모델을 불러오는 함수는 공통 모듈로 만들어, 이후 장에서 계속 씁니다.

파일명: `examples/common/qwen.py`

```python
# 실제 Qwen2.5-0.5B-Instruct 모델과 토크나이저를 불러오는 공통 함수
#
# 교재 원칙: Revision 고정, FP32로 불러와 CPU에서 계산(GT 1030은 VRAM 2GB라 FP32 전체 모델을 올릴 수 없음)

import torch
from transformers import AutoConfig, AutoModelForCausalLM, AutoTokenizer

from common.models import QWEN_ID, QWEN_REVISION


def load_config(local_only: bool = False):
    return AutoConfig.from_pretrained(QWEN_ID, revision=QWEN_REVISION,
                                      local_files_only=local_only)


def load_tokenizer(local_only: bool = False):
    return AutoTokenizer.from_pretrained(QWEN_ID, revision=QWEN_REVISION,
                                         local_files_only=local_only)


def load_model(local_only: bool = False):
    """FP32로 불러와 평가 모드(eval)로 돌려준다. 약 2GB의 시스템 RAM이 필요하다."""
    model = AutoModelForCausalLM.from_pretrained(

        local_files_only=local_only)
    return model.eval()
```

파일명: `examples/ch11/model_map.py`

```python
# 제11장 핵심 실습: Qwen2.5-0.5B의 설정·계층 구조·데이터 흐름을 구조도와 대조
#
# 실행: python examples/ch11/model_map.py
# 필요: 시스템 RAM 약 3GB(FP32 모델 2GB + 여유)

import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[1]))

import torch  # noqa: E402

from common.qwen import load_config, load_model, load_tokenizer  # noqa: E402

CONFIG_KEYS = ["hidden_size", "num_hidden_layers", "num_attention_heads",
               "num_key_value_heads", "intermediate_size", "vocab_size",
               "hidden_act", "rms_norm_eps", "rope_theta", "tie_word_embeddings"]


def count(module) -> int:
    return sum(p.numel() for p in module.parameters())


def block_table(model) -> dict:
    """구조도의 블록별 파라미터 수(공유 텐서는 한 번만)."""
    layer = model.model.layers[0]
    return {
        "Embedding": count(model.model.embed_tokens),
        "Attention(계층 1개)": count(layer.self_attn),
        "FFN(계층 1개)": count(layer.mlp),
        "RMSNorm 2개(계층 1개)": count(layer.input_layernorm) + count(layer.post_attention_layernorm),
        "Final Norm": count(model.model.norm),
    }


def main() -> None:
    config = load_config()
    print("── 1. config.json 핵심 값 ──")
    for key in CONFIG_KEYS:
        value = getattr(config, key, None)
        if value is None and key == "rope_theta":
            value = config.rope_parameters["rope_theta"]
        print(f"  {key:<22} {value}")

    model = load_model()
    tok = load_tokenizer()

    print("\n── 2. 최상위 구조 ──")
    for name, child in model.named_children():
        print(f"  {name}: {type(child).__name__}")
    for name, child in model.model.named_children():
        size = len(child) if isinstance(child, torch.nn.ModuleList) else ""
        print(f"    model.{name}: {type(child).__name__} {size}")

    print("\n── 3. Decoder Layer 하나의 내부(layers.0) ──")
    for name, p in model.model.layers[0].named_parameters():
        print(f"  {name:<34} {str(tuple(p.shape)):<12}")

    print("\n── 4. 블록별 파라미터 수 ──")
    blocks = block_table(model)
    for name, n in blocks.items():
        print(f"  {name:<20} {n:>12,}")
    per_layer = blocks["Attention(계층 1개)"] + blocks["FFN(계층 1개)"] + blocks["RMSNorm 2개(계층 1개)"]
    total = blocks["Embedding"] + 24 * per_layer + blocks["Final Norm"]
    print(f"  계산 합계: {total:,}  /  모델 집계: {count(model):,}")
    tied = model.lm_head.weight is model.model.embed_tokens.weight
    print(f"  LM Head와 Embedding이 같은 텐서: {tied}")

    print("\n── 5. 데이터 흐름(Shape 추적) ──")
    ids = tok("언어 모델은 다음 토큰을 예측한다.", return_tensors="pt").input_ids
    with torch.no_grad():
        out = model(ids, output_hidden_states=True)
    hs = out.hidden_states
    print(f"  Token ID           {tuple(ids.shape)}")
    print(f"  Embedding 출력      {tuple(hs[0].shape)}")
    print(f"  Decoder Layer 출력  {tuple(hs[1].shape)} × {len(hs) - 1}개")
    print(f"  Logits             {tuple(out.logits.shape)}")
    next_id = int(out.logits[0, -1].argmax())
    print(f"  마지막 위치의 다음 토큰 예측: {tok.decode([next_id])!r}")


if __name__ == "__main__":
    main()
```

**핵심 코드 풀이**

- `load_model()`은 `dtype=torch.float32`로 모델을 불러오고 `eval()`로 평가 모드로 바꿉니다. FP32 모델은 약 2GB라 GT 1030의 VRAM에는 들어가지 않으므로, 이 장의 분석은 두 경로 모두 CPU에서 합니다.
- 1번의 설정값은 제02~10장에서 계산에 써 온 숫자 그대로입니다. `rope_theta`는 최신 Transformers에서 `rope_parameters` 안으로 옮겨져 있어, 코드에서 그 위치를 함께 확인합니다.
- 2번의 최상위 구조가 04절 그림의 세로축입니다. `model.embed_tokens` → `model.layers`(24개) → `model.norm` → `lm_head` 순서이며, `rotary_emb`는 학습 파라미터가 없는 회전 계산 모듈입니다.
- 3번은 블록 하나에 든 파라미터 12개입니다. 이름이 03절 표와 정확히 일치하고, 모양은 제05장의 규약 `[out, in]`을 따릅니다. `k_proj`와 `v_proj`의 출력이 128인 것은 KV 헤드가 2개(2 × 64)이기 때문입니다(제15장).
- 4번에서 블록별 파라미터를 더한 값과 모델 전체 집계가 494,032,768로 같습니다. 계층 하나에서 FFN(약 1,307만)이 Attention(약 184만)의 7배가 넘는다는 점도 눈여겨보세요. 0.5B 모델의 파라미터는 Embedding을 빼면 대부분 FFN에 있습니다.
- 5번은 실제 문장을 넣어 데이터 흐름을 추적합니다. `output_hidden_states=True`로 받은 중간 결과 25개(Embedding 출력 + 계층 24개) 모두 `(1, 16, 896)`이고, Logits는 `(1, 16, 151936)`입니다. Transformers는 마지막 중간 결과에 Final Norm까지 적용한 값을 돌려줍니다.
- 마지막 줄의 예측은 줄바꿈(`'\n'`)입니다. 대화 형식 없이 문장 하나만 주면, 이 모델은 문장이 끝났다고 보고 줄을 바꾸려 합니다. Instruct 모델에 질문하는 올바른 형식은 제44장 Chat Template에서 다룹니다.

## 핵심 정리

- RNN은 위치마다 순서대로 계산하지만, Self-Attention은 모든 위치 쌍을 행렬곱 한 번으로 계산합니다. 먼 토큰도 직접 연결됩니다.
- LLM은 다음 토큰 예측에 맞는 Decoder-only 구조를 씁니다. Qwen2.5도 Decoder-only입니다.
- Decoder Layer 하나는 RMSNorm → Attention → 잔차 더하기 → RMSNorm → FFN → 잔차 더하기이며, 입력과 출력 모양이 같아 그대로 쌓을 수 있습니다.
- Qwen2.5-0.5B는 Embedding → Decoder Layer × 24 → Final Norm → LM Head(Embedding과 공유) 순서로 데이터가 흐르며, 실제 계층 이름·모양·파라미터 수가 구조도와 정확히 일치합니다.

**다음 장 연결:** 지도를 손에 쥐었으니 첫 번째 부품으로 들어갑니다. 제12장에서는 Self-Attention의 출발점인 Query·Key·Value를 만드는 세 개의 Linear를 직접 구현하고, 실제 모델의 Projection 가중치와 편향으로 같은 결과를 재현합니다.
