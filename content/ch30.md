## 장 개요

제29장에서 LoRA를 직접 구현해 Qwen2-Tiny에 붙이고, 학습하고, 병합했습니다. 실무에서는 같은 일을 Hugging Face의 **PEFT** 라이브러리로 합니다. 설정 몇 줄로 어떤 모델에든 LoRA를 붙이고, 학습 결과를 원본과 분리된 작은 Adapter 파일로 저장해 주기 때문입니다.

이 장의 목표는 PEFT를 "믿고 쓰는" 것이 아니라 "확인하고 쓰는" 것입니다. PEFT의 설정 이름이 직접 구현의 어디에 대응하는지 연결하고, **같은 출발점과 같은 조건**으로 두 구현을 학습해 결과가 같은지 비교합니다. 그리고 Adapter를 저장·재로딩·병합하며 제3부를 마무리합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | PEFT의 LoRA는 직접 구현과 같은 계산을 하는가, Adapter는 무엇을 담는가 |
| 실습 결과물 | 설정 대응표, Target Modules별 파라미터 수, 두 구현의 학습 결과 비교, Adapter 파일 구조와 재로딩 확인 |
| 실습 파일 | `examples/ch30/`의 `peft_lora.py`, `test_ch30.py` |
| 선수 장 | 제25장(사전학습 모델, 학습 루프), 제28장(LoRA 수식), 제29장(직접 구현) |

```text
사전학습 Qwen2-Tiny ──get_peft_model(LoraConfig)──▶ PeftModel ──학습──▶ save_pretrained
                                                                         │
                     adapter_config.json + adapter_model.safetensors(약 106KB) ◀┘
원본(168MB) + Adapter ──PeftModel.from_pretrained──▶ 같은 출력 ──merge_and_unload──▶ 보통 모델
```

## LoraConfig와 get_peft_model

PEFT에서 LoRA는 설정 객체 `LoraConfig`와 함수 `get_peft_model` 두 가지로 붙입니다.

```python
cfg = LoraConfig(r=8, lora_alpha=16, target_modules=["q_proj", "v_proj"],
                 lora_dropout=0.0, bias="none", task_type="CAUSAL_LM")
peft_model = get_peft_model(model, cfg)       # 원본 동결 + 대상 Linear에 LoRA
```

설정 이름은 제29장의 직접 구현과 하나씩 대응합니다.

```text
PEFT 설정           직접 구현(제29장)       의미
r                   r                       A·B 사이의 차원(Rank)
lora_alpha          alpha                   배율 α/r의 α
target_modules      targets                 LoRA를 붙일 Linear의 이름
lora_dropout        없음(0)                 LoRA 경로 입력의 Dropout(이 교재는 비교를 위해 0)
bias="none"         원본 편향 동결          편향은 학습하지 않는다
기본 초기화         A Kaiming 균등, B 0     두 구현이 같은 방식(PEFT 소스에서 확인)
```

PEFT는 `lora_A`, `lora_B`를 각각 편향 없는 작은 `nn.Linear`로 만듭니다. 그 가중치 모양은 `lora_A`가 `[r, in]`, `lora_B`가 `[out, r]`로 직접 구현의 A·B와 정확히 같습니다. 이름에는 접두어 `base_model.model.`과 Adapter 이름 `default`가 붙습니다.

```text
PEFT:      base_model.model.model.layers.0.self_attn.q_proj.lora_A.default.weight   [8, 256]
직접 구현:                   model.layers.0.self_attn.q_proj.lora_A                  [8, 256]
```

## Target Modules

`target_modules`에는 계층의 **이름**을 적습니다. 그래서 모델의 계층 이름을 알아야 하며, 제20장에서 정리한 Qwen2의 이름(q·k·v·o_proj, gate·up·down_proj)이 여기서 쓰입니다. 같은 이름의 Linear는 모든 계층에서 한꺼번에 대상이 됩니다.

| 대상 | Qwen2-Tiny 학습 파라미터(r = 8) |
|---|---|
| q·v_proj | 26,624 |
| Attention 4종(q·k·v·o) | 53,248 |
| 7종 전부 | 151,552 |

이 숫자는 제28장의 `r × (in + out)` 공식으로 미리 계산할 수 있고, 실습에서 PEFT가 센 값과 직접 구현이 센 값이 같은지 확인합니다. 계층 이름을 잘못 적으면 PEFT는 대상이 없다는 오류를 내므로, 다른 모델에 적용할 때는 먼저 `named_modules()`로 이름을 확인합니다.

## Qwen2-Tiny PEFT 학습

두 구현이 같은 계산을 하는지 확인하는 가장 엄격한 방법은, **같은 출발점에서 같은 조건으로** 학습해 결과를 비교하는 것입니다.

| 조건 | 맞추는 방법 |
|---|---|
| 원본 가중치 | 같은 사전학습 모델(제25장)을 각각 불러온다 |
| A 초기값 | 직접 구현의 A(seed 0)를 PEFT 쪽에 복사한다. B는 둘 다 0 |
| 학습 | 같은 `train()`(제25장), 같은 데이터·단계·학습률·묶음 순서 |

PEFT 모델도 보통의 PyTorch 모델이므로 제25장의 학습 루프를 그대로 씁니다. `requires_grad=True`인 파라미터만 학습하는 `train()`의 설계(제25장)가 여기서 빛을 봅니다. 제5부에서는 이 자리를 TRL의 `SFTTrainer`가 대신합니다.

## Adapter 저장과 재로딩

PEFT 모델의 `save_pretrained`는 원본 가중치를 저장하지 않고 **Adapter만** 저장합니다.

```text
models/qwen2-tiny-bike-lora/
  adapter_config.json          LoraConfig 내용(r, lora_alpha, target_modules, …)과 원본 모델 위치
  adapter_model.safetensors    lora_A·lora_B 가중치만
  README.md                    PEFT가 만드는 모델 설명서 틀
```

Adapter는 26,624개 × 4바이트 ≈ 106KB로, 원본 168MB의 0.06%입니다. 다시 쓸 때는 원본 모델을 먼저 불러온 뒤 `PeftModel.from_pretrained(원본, Adapter 폴더)`로 덧붙입니다. 원본 하나에 과제별 Adapter를 바꿔 끼울 수 있다는 PEFT의 장점(제26장)이 파일 구조로 드러납니다.

`merge_and_unload()`는 제29장의 `merge_lora()`와 같은 일을 합니다. ΔW를 원본에 더하고 LoRA 계층을 걷어 내, 보통의 `Qwen2ForCausalLM`을 돌려줍니다. 병합한 모델을 `save_pretrained`하면 제25장과 같은 전체 모델 폴더가 되어, 제6부의 GGUF 변환에 그대로 쓸 수 있습니다.

`adapter_config.json`에는 원본 모델의 위치(`base_model_name_or_path`)가 기록됩니다. 내 컴퓨터의 폴더 경로가 그대로 들어가므로, Adapter를 다른 사람과 공유할 때는 이 값을 공개 모델 이름으로 바꾸거나 지웁니다.

## 핵심 실습

파일명: `examples/ch30/peft_lora.py`

```python
# 제30장 핵심 실습: PEFT 라이브러리 LoRA를 직접 구현(제29장)과 같은 조건으로 학습해 비교하고,
#                   Adapter를 저장·재로딩·병합한다
#
# 실행: python examples/ch30/peft_lora.py   (먼저 제25장 pretrain_tiny.py로 사전학습 모델을 만든다)

import math
import sys
from pathlib import Path

HERE = Path(__file__).resolve().parent
for p in (HERE.parent, HERE.parent / "ch24", HERE.parent / "ch25", HERE.parent / "ch29"):
    sys.path.insert(0, str(p))

import torch  # noqa: E402
from peft import LoraConfig, PeftModel, get_peft_model  # noqa: E402
from transformers import Qwen2ForCausalLM  # noqa: E402
from transformers.utils import logging  # noqa: E402

from common.device import select_device  # noqa: E402
from common.fixed_data import load_blocks  # noqa: E402
from common.qwen import load_tokenizer  # noqa: E402
from lora_linear import ALL_LINEAR, apply_lora, trainable_count  # noqa: E402   (제29장)
from trainer import eval_loss, train  # noqa: E402                             (제25장)

logging.disable_progress_bar()
ROOT = HERE.parents[1]
PRETRAINED = ROOT / "models" / "qwen2-tiny-pretrained"
ADAPTER = ROOT / "models" / "qwen2-tiny-bike-lora"
STEPS, LR = 60, 2e-3


def config(targets=("q_proj", "v_proj")) -> LoraConfig:
    """제29장 apply_lora(r=8, alpha=16)와 같은 설정"""
    return LoraConfig(r=8, lora_alpha=16, target_modules=list(targets), lora_dropout=0.0,
                      bias="none", task_type="CAUSAL_LM")


def load_pretrained():
    return Qwen2ForCausalLM.from_pretrained(PRETRAINED, dtype=torch.float32)


def copy_A_from(mine, peft_model) -> int:
    """직접 구현의 A 초기값을 PEFT 쪽에 복사해, 두 구현이 같은 출발점에서 학습하게 한다."""
    n = 0
    for name, module in mine.named_modules():
        if hasattr(module, "lora_A") and isinstance(module.lora_A, torch.nn.Parameter):
            target = peft_model.get_submodule("base_model.model." + name)
            with torch.no_grad():
                target.lora_A["default"].weight.copy_(module.lora_A)
            n += 1
    return n


def main() -> None:
    device, _ = select_device()
    tok = load_tokenizer()
    data = {s: load_blocks(tok, s) for s in ("eval", "domain_train", "domain_eval")}

    print("── 1. LoraConfig + get_peft_model ──")
    peft_model = get_peft_model(load_pretrained(), config())
    names = [(n, tuple(p.shape)) for n, p in peft_model.named_parameters() if p.requires_grad]
    print(f"  학습 파라미터 {trainable_count(peft_model):,}개, 텐서 {len(names)}개")
    for n, s in names[:2]:
        print(f"  {n}  {s}")
    mine = load_pretrained()
    apply_lora(mine, seed=0)
    print(f"  직접 구현(제29장)  {trainable_count(mine):,}개, "
          f"이름 예 model.layers.0.self_attn.q_proj.lora_A  {tuple(mine.model.layers[0].self_attn.q_proj.lora_A.shape)}")

    print("\n── 2. Target Modules별 학습 파라미터 ──")
    for label, targets in (("q·v", ("q_proj", "v_proj")), ("Attention 4종", ALL_LINEAR[:4]),
                           ("7종 전부", ALL_LINEAR)):
        m = get_peft_model(load_pretrained(), config(targets))
        print(f"  {label:<14}{trainable_count(m):>9,}개")

    print(f"\n── 3. 같은 출발점·같은 조건 학습(q·v, r 8, α 16, lr {LR:.0e}, {STEPS}단계) ──")
    print(f"  A 초기값 복사: {copy_A_from(mine, peft_model)}개 계층")
    for label, m in (("직접 구현", mine), ("PEFT", peft_model)):
        train(m, data["domain_train"], {}, steps=STEPS, lr=LR, warmup=5, device=device, log_every=STEPS)
        ppl_d = math.exp(eval_loss(m, data["domain_eval"], device))
        ppl_g = math.exp(eval_loss(m, data["eval"], device))
        print(f"  {label:<10}도메인 PPL {ppl_d:.2f}, 일반 PPL {ppl_g:.2f}")
    b_mine = mine.model.layers[2].self_attn.v_proj.lora_B.detach().cpu()
    b_peft = peft_model.get_submodule("base_model.model.model.layers.2.self_attn.v_proj").lora_B["default"].weight
    print(f"  학습된 B(2번 계층 v_proj) 최대 차이 {(b_mine - b_peft.detach().cpu()).abs().max().item():.1e}")

    print("\n── 4. Adapter 저장 → 재로딩 → 병합 ──")
    peft_model.save_pretrained(ADAPTER)
    files = {f.name: f.stat().st_size for f in ADAPTER.iterdir()}
    print(f"  저장 파일 {files}")
    print(f"  원본 model.safetensors {(PRETRAINED / 'model.safetensors').stat().st_size:,}바이트와 비교")
    probe = data["domain_eval"][:, :32].to(device)
    with torch.no_grad():
        trained = peft_model.eval()(probe).logits
    reloaded = PeftModel.from_pretrained(load_pretrained(), ADAPTER).to(device).eval()
    with torch.no_grad():
        again = reloaded(probe).logits
    merged = reloaded.merge_and_unload()
    with torch.no_grad():
        after_merge = merged(probe).logits
    print(f"  재로딩 후 Logits 완전히 같음: {torch.equal(trained, again)}")
    print(f"  merge_and_unload 후 최대 차이 {(after_merge - trained).abs().max().item():.1e}, "
          f"모델 종류 {type(merged).__name__}")


if __name__ == "__main__":
    main()
```

**결과 읽기**

- **1번**에서 PEFT가 센 학습 파라미터 26,624개가 직접 구현과 같습니다. 텐서 16개는 q·v_proj 8개 계층마다 A·B 두 개씩입니다. A `(8, 256)`, B `(256, 8)`의 모양도 같습니다.
- **2번**의 대상별 파라미터 수는 02절의 표, 그리고 제28장의 공식과 일치합니다.
- **3번**이 이 장의 결론입니다. 같은 출발점에서 같은 조건으로 학습한 두 구현이 소수점 둘째 자리까지 같은 PPL(735.90, 361.69)을 냈고, 학습된 B의 차이는 0입니다. PEFT의 LoRA는 제29장에서 직접 만든 LoRA와 **똑같은 계산**을 합니다. 이 값은 제29장의 "q·v, lr 2e-3" 결과와도 같습니다.
- **4번**에서 Adapter 파일은 약 106KB로, 원본 가중치 파일(약 168MB)의 0.06%입니다. 원본에 Adapter를 다시 붙이면 학습 직후와 Logits가 비트 하나까지 같고, 병합한 뒤에도 차이가 8.1e-06(계산 순서 차이)에 그칩니다. 병합 결과는 보통의 `Qwen2ForCausalLM`입니다.

# 제30장 검증 테스트

import sys
from pathlib import Path

import pytest
import torch

HERE = Path(__file__).resolve().parent
for p in (HERE, HERE.parent, HERE.parent / "ch19", HERE.parent / "ch24", HERE.parent / "ch25",
          HERE.parent / "ch29"):

peft = pytest.importorskip("peft")

from lora_linear import ALL_LINEAR, apply_lora, trainable_count  # noqa: E402
from peft_lora import config, copy_A_from  # noqa: E402


@pytest.fixture()
def tiny_pair():
    from hf_compat import to_hf
    from tiny_model import Qwen2Tiny, init_weights
    return to_hf(init_weights(Qwen2Tiny(), seed=0)), to_hf(init_weights(Qwen2Tiny(), seed=0))


def test_trainable_counts_match_scratch(tiny_pair):
    a, b = tiny_pair
    pm = peft.get_peft_model(a, config(ALL_LINEAR))
    apply_lora(b, ALL_LINEAR)
    assert trainable_count(pm) == trainable_count(b) == 151_552


def test_names_and_shapes_correspond(tiny_pair):
    a, b = tiny_pair
    pm = peft.get_peft_model(a, config())
    apply_lora(b)
    ours = {n: tuple(p.shape) for n, p in b.named_parameters() if p.requires_grad}
    theirs = {n.replace("base_model.model.", "").replace(".default.weight", ""): tuple(p.shape)
              for n, p in pm.named_parameters() if p.requires_grad}
    assert ours == theirs                       # 같은 이름(접두어·접미어 제외), 같은 Shape


def test_same_start_same_training(tiny_pair):
    from trainer import train
    a, b = tiny_pair
    pm = peft.get_peft_model(a, config())
    apply_lora(b, seed=0)
    copy_A_from(b, pm)
    ids = torch.randint(0, 3000, (4, 24))
    with torch.no_grad():
        torch.testing.assert_close(pm(ids[:1]).logits, b(ids[:1]).logits)
    train(pm, ids, {}, steps=5, lr=1e-2, warmup=1, log_every=5)
    train(b, ids, {}, steps=5, lr=1e-2, warmup=1, log_every=5)
    with torch.no_grad():
        torch.testing.assert_close(pm(ids[:1]).logits, b(ids[:1]).logits, atol=1e-4, rtol=1e-4)


def test_adapter_save_reload(tiny_pair, tmp_path):
    a, b = tiny_pair
    pm = peft.get_peft_model(a, config())
    with torch.no_grad():
        pm.get_submodule("base_model.model.model.layers.0.self_attn.q_proj").lora_B["default"].weight.normal_()
    pm.save_pretrained(tmp_path)
    assert {"adapter_config.json", "adapter_model.safetensors"} <= {f.name for f in tmp_path.iterdir()}
    again = peft.PeftModel.from_pretrained(b, tmp_path)
    ids = torch.randint(0, 3000, (1, 10))
    with torch.no_grad():
        assert torch.equal(pm(ids).logits, again(ids).logits)

| 검증 항목 | 판정 기준 | 교재 검증 결과 |
|---|---|---|
| 학습 파라미터 수 | 7종 전부에서 PEFT = 직접 구현 = 151,552 | 통과 |
| 이름·Shape 대응 | 접두어·접미어를 뺀 이름과 Shape가 모두 같음 | 통과 |
| 같은 조건 학습 | 같은 A에서 시작해 5단계 학습 후 Logits 일치 | 통과 |
| Adapter 저장·재로딩 | 두 파일이 생기고, 재로딩한 출력이 완전히 같음 | 통과 |

이 장의 실습은 CPU에서 실행합니다. GT 1030 경로에서는 `select_device()`가 GPU를 고르며, 같은 결과(반올림 범위)가 나와야 합니다(교재 검증 환경 미검증). GT 1030 경로의 PEFT 설치·실행도 미검증입니다.

**완료 기준:** `target_modules`를 Attention 4종으로 바꿔 학습하고 도메인·일반 PPL을 제29장의 결과표에 한 줄로 더하고, `adapter_config.json`을 열어 `r`, `lora_alpha`, `target_modules`가 설정과 같은지 확인하며, 테스트 4개를 모두 통과하면 이 장을 마친 것입니다.

## 핵심 정리

- PEFT의 `LoraConfig`(r, lora_alpha, target_modules, lora_dropout, bias)는 제29장 직접 구현의 설정과 하나씩 대응하고, `get_peft_model`이 원본 동결과 LoRA 부착을 한 번에 합니다.
- `target_modules`에는 계층 이름을 적습니다. 학습 파라미터 수는 `r × (in + out)` 공식으로 미리 계산해 맞춰 봅니다.
- 같은 출발점·같은 조건에서 PEFT LoRA와 직접 구현 LoRA는 같은 결과를 냅니다. 라이브러리의 계산을 직접 구현으로 검증했습니다.
- Adapter는 `adapter_config.json`과 `adapter_model.safetensors`로 저장되며, 원본의 0.06% 크기입니다. 원본에 다시 붙이면 같은 출력이 나오고, `merge_and_unload`로 보통 모델로 합칠 수 있습니다.

**다음 장 연결:** 제3부에서 LoRA로 **학습할 파라미터**를 줄였습니다. 그래도 0.5B 모델은 FP32 원본 가중치만 약 2GB라 GT 1030에 올라가지 않습니다. 제4부에서는 **원본을 저장하는 비트 수**를 줄이는 양자화를 다룹니다. 제31장에서는 그 출발점, 컴퓨터가 수를 표현하는 방법부터 봅니다.
