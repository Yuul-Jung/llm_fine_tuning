## 장 개요

제54장의 F32 GGUF는 1.9GB로, GT 1030의 2GB에 들어가지 않습니다. 추론용으로 배포할 때는 가중치를 더 적은 비트로 줄이는 **양자화**를 합니다. 제33~36장에서 INT8·INT4·NF4를 직접 구현했다면, 이 장은 로컬 실행 도구의 표준 형식인 Q8_0과 Q4_0을 같은 눈으로 읽고, 실제 병합 모델을 양자화해 크기와 품질을 함께 비교합니다.

양자화는 크기를 줄이는 대신 품질을 잃을 수 있습니다. 그래서 "얼마나 작아졌는가"만이 아니라 제43장의 기준으로 **품질이 유지되었는가**를 같은 측정 함수로 판정한 뒤, 기준을 통과한 형식 중에서 GT 1030에 들어가는 것을 고릅니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 추론용 양자화 형식은 어떤 구조이며, 어떤 형식이 품질을 지키면서 GT 1030에 들어가는가 |
| 실습 결과물 | Q8_0·Q4_0 직접 구현과 라이브러리 비교, F32·F16·Q8_0·Q4_0 GGUF, 형식별 PPL·정답률·답 일치, GT 1030 판정 |
| 실습 파일 | `examples/ch55/`의 `quant_compare.py`, `test_ch55.py`, `quant.json`(변환기는 제54장 `to_gguf.py`) |
| 선수 장 | 제33~36장(양자화), 제43장(기준), 제54장(GGUF), 제58장(장치별 판정) |

```text
병합 모델 ─to_gguf(F32·F16·Q8_0·Q4_0)─▶ GGUF 4개
   ─다시 읽기(FP32로 풀기)─▶ 제47장 measure: 도메인 PPL · 일반 PPL · 핵심어 · 형식(validation)
   ─제43장 기준 판정─▶ 기준 통과 형식 중 GT 1030 메모리에 들어가는 가장 작은 것
```

## PTQ와 QAT

| 방식 | 하는 일 | 특징 |
|---|---|---|
| PTQ(학습 후 양자화) | 학습이 끝난 가중치를 그대로 양자화한다 | 빠르고 학습 데이터가 필요 없다. 낮은 비트에서 품질이 떨어질 수 있다 |
| QAT(양자화 인식 학습) | 학습 중에 양자화 오차를 흉내 내어 모델이 적응하게 한다 | 낮은 비트에서도 품질을 지키지만 다시 학습해야 한다 |

로컬 실행 도구의 GGUF 양자화는 PTQ입니다. 제49장의 QLoRA는 4비트 원본 위에서 LoRA를 학습했으므로 QAT와 비슷해 보이지만, 원본 가중치는 학습하지 않고 Adapter만 4비트 원본에 맞췄다는 점이 다릅니다. 이 장은 PTQ로 양자화하고, 품질이 기준을 지키는지로 판정합니다.

## GGUF 양자화 형식

두 형식 모두 32개 값을 한 블록으로 묶고, 블록마다 FP16 Scale 하나를 둡니다(그룹 양자화, 제34장).

| 형식 | 블록 구조 | 제33~36장과의 대응 |
|---|---|---|
| Q8_0 | Scale d = 블록 최대 절댓값 / 127, 값 = round(x / d) | 대칭 INT8, 그룹 크기 32 |
| Q4_0 | 절댓값이 가장 큰 원소 m으로 d = m / −8, 값 = ⌊x / d + 8.5⌋ ∈ 0~15 | 4비트, 그룹 32. 0~15에서 8을 빼 −8~7로 쓴다 |

Q4_0은 가장 큰 원소의 **부호까지** Scale에 담아, 그 원소가 정확히 −8 칸에 오게 합니다. 대칭 INT4(−7~7)보다 한 칸을 더 쓰는 방법입니다. 두 형식 모두 Scale이 FP16이라 평균 비트가 8.5와 4.5입니다. 이보다 정교한 K-quant 형식(Q4_K 등)은 블록을 다시 큰 묶음으로 모아 Scale까지 양자화하는데, 제36장의 이중 양자화와 같은 생각입니다.

실습에서는 두 형식을 numpy로 직접 구현해 gguf 라이브러리(llama.cpp의 기준 구현과 비트 단위로 같도록 만든 것)의 결과와 비교합니다. 반올림 방식(0.5를 0에서 먼 쪽으로)과 Scale을 FP16으로 저장하는 순서까지 맞아야 값이 정확히 같아집니다.

## 성능 지표

| 지표 | 무엇을 보는가 | 이 장의 측정 |
|---|---|---|
| 파일 크기 | 저장·내려받기·VRAM에 올릴 가중치 | 측정 |
| 도메인 PPL, 일반 PPL | 품질과 망각(제43장) | 측정(FP32로 풀어 계산) |

품질은 GGUF를 Transformers로 다시 읽어 잽니다. 이때 양자화된 값을 FP32로 풀어 계산하므로 **품질은 양자화 형식 그대로의 값**이지만, 속도와 메모리는 실행 도구가 양자화된 채로 계산할 때와 다릅니다. 그래서 이 장은 속도 지표를 재지 않고 미검증으로 남깁니다.

## GT 1030 탑재 판정

제58장의 방법으로 판정합니다. 가중치 크기에 KV Cache(FP16, 2,048토큰)와 연산 버퍼를 더해, 2GB의 75% 안에 들어가는지 봅니다. 연산 버퍼는 실행 도구와 설정에 따라 다르므로 300MiB로 가정했고, 실제 값은 GT 1030에서 실행 도구가 보고하는 사용량으로 확인해야 합니다. 형식 선택 순서는 이렇습니다.

1. 제43장 기준에서 F32와 같은 수준을 지키는 형식만 남긴다.
2. 그중 GT 1030 예산에 들어가는 형식을 남긴다.
3. 남은 것 중 가장 작은 형식을 고른다.

import numpy as np  # noqa: E402
import torch  # noqa: E402
from gguf import GGMLQuantizationType, quants  # noqa: E402
from transformers.utils import logging  # noqa: E402

from baseline import measure  # noqa: E402                    (제47장)

logging.set_verbosity_error()

GGUF = ROOT / "models" / "gguf"
OUT = HERE / "quant.json"
FORMATS = ["F32", "F16", "Q8_0", "Q4_0"]

def q8_0_by_hand(x: np.ndarray) -> np.ndarray:
    """32개 블록마다 d = max|x| / 127, q = round(x / d)(0.5는 0에서 먼 쪽으로) → 복원 q × fp16(d) (제33장의 대칭 INT8)"""
    b = x.reshape(-1, 32)
    d = np.abs(b).max(axis=1, keepdims=True) / 127
    q = np.trunc(b / d + np.copysign(0.5, b / d))
    return (q * d.astype(np.float16).astype(np.float32)).reshape(x.shape)


def q4_0_by_hand(x: np.ndarray) -> np.ndarray:
    """32개 블록마다 절댓값이 가장 큰 원소 m으로 d = m / -8, q = ⌊x / d + 8.5⌋ ∈ [0, 15] → 복원 (q - 8) × fp16(d)"""
    b = x.reshape(-1, 32)
    m = b[np.arange(len(b)), np.abs(b).argmax(axis=1)][:, None]
    d = m / -8
    q = np.clip(np.trunc(b / d + 8.5), 0, 15)
    return ((q - 8) * d.astype(np.float16).astype(np.float32)).reshape(x.shape)


def load_gguf(name: str):
    from transformers import AutoModelForCausalLM, AutoTokenizer
    t0 = time.time()
    model = AutoModelForCausalLM.from_pretrained(GGUF, gguf_file=f"{name}.gguf", dtype=torch.float32).eval()
    model.generation_config.repetition_penalty = 1.1          # 원본 생성 설정을 옮긴다(제54장)
    tok = AutoTokenizer.from_pretrained(MERGED)
    return tok, model, time.time() - t0


def main() -> None:
    from common.fixed_data import load_blocks
    from trainer import eval_loss
    rec = json.loads(OUT.read_text(encoding="utf-8")) if OUT.exists() else {}

    print("── 1. 블록 양자화 구조: 직접 구현 ↔ gguf 라이브러리 ──")
    x = np.random.default_rng(0).standard_normal((8, 896)).astype(np.float32)
    for q, fn, size in (("Q8_0", q8_0_by_hand, 34), ("Q4_0", q4_0_by_hand, 18)):
        lib = quants.dequantize(quants.quantize(x, GGMLQuantizationType[q]), GGMLQuantizationType[q])
        print(f"  {q}: 블록 32개 = {size}바이트({size * 8 / 32}비트/값), 직접 구현과 최대 차이 "
              f"{np.abs(fn(x) - lib).max():.1e}, 복원 오차(평균 제곱) {np.mean((lib - x) ** 2):.2e}")

    print("\n── 2. 형식별 GGUF 만들기 ──")
    for f in FORMATS:
        path = GGUF / f"fpga-{f.lower()}.gguf"
        if not path.exists():
            t0 = time.time()
            convert(MERGED, path, f)
            print(f"  {f}: 변환 {time.time() - t0:.0f}초")
        rec.setdefault(f, {})["size_mib"] = path.stat().st_size / MiB
    print("  " + ", ".join(f"{f} {rec[f]['size_mib']:.0f}MiB" for f in FORMATS))

    print("\n── 3. 형식별 품질(validation, 제43장 기준) ──")
    c = load_criteria()
    base = json.loads((ROOT / "examples/ch47/baseline.json").read_text(encoding="utf-8"))
    for f in FORMATS:
        if "domain_ppl" in rec[f]:
            continue
        tok, model, load_s = load_gguf(f"fpga-{f.lower()}")
        m = measure(tok, model)
        hits, fmts = list(m["keyword_hit"].values()), list(m["format_ok"].values())
        v = judge(c, domain_ratio=m["domain_ppl"] / base["domain_ppl"],
                  general_ratio=m["general_ppl"] / base["general_ppl"], hits=hits, fmts=fmts)
        rec[f].update(load_s=load_s, domain_ppl=m["domain_ppl"], general_ppl=m["general_ppl"],
                      keyword=sum(hits) / len(hits), format=sum(fmts) / len(fmts), passed=sum(v.values()),
                      answers=m["answers"])
        OUT.write_text(json.dumps(rec, ensure_ascii=False, indent=1) + "\n", encoding="utf-8")
        del model
        gc.collect()
    print("  형식   크기MiB  도메인PPL  일반PPL  핵심어  형식   합격  F32와 같은 답")
    for f in FORMATS:
        r = rec[f]
        same = sum(r["answers"][i] == rec["F32"]["answers"][i] for i in r["answers"])
        print(f"  {f:<6}{r['size_mib']:>7.0f}{r['domain_ppl']:>10.2f}{r['general_ppl']:>9.2f}"
              f"{r['keyword']:>7.2f}{r['format']:>6.2f}   {r['passed']}/4   {same}/6")

    print("\n── 4. GT 1030 탑재 판정(가중치 + FP16 KV Cache 2048토큰 + 연산 버퍼 가정 300MiB) ──")
    from transformers import AutoConfig
    cfg = AutoConfig.from_pretrained(MERGED)
    for f in FORMATS:
        need = rec[f]["size_mib"] + kv_mib(cfg, 2048, 2) + 300
        print(f"  {f:<6}{need:>7.0f}MiB → 2GB의 75% 이내 {fits(need, DEVICES['GT 1030'])}")
    OUT.write_text(json.dumps(rec, ensure_ascii=False, indent=1) + "\n", encoding="utf-8")


if __name__ == "__main__":
    main()

**결과 읽기**

- **1번**에서 직접 구현한 Q8_0·Q4_0이 라이브러리와 차이 0으로 같습니다. 같은 무작위 값의 복원 오차는 Q4_0이 Q8_0보다 약 260배 큽니다.
- **2번**에서 크기는 F32 1,890MiB → F16 948 → Q8_0 506 → Q4_0 271MiB입니다. Q8_0은 F32의 27%, Q4_0은 14%입니다. 1차원 텐서(편향·RMSNorm)는 모든 형식에서 F32로 두었습니다.
- **3번**에서 F16과 Q8_0은 PPL이 F32와 거의 같고(일반 PPL 21.37 → 21.46), 제43장 판정도 F32와 같은 3/4입니다. 다만 Q8_0은 Greedy 답 6개 중 5개가 F32와 다릅니다. 작은 점수 차이가 한 토큰을 바꾸면 그 뒤 문장이 모두 달라지기 때문입니다. 답의 수준(핵심어 0, 형식 1.00)은 같지만, **"양자화해도 같은 답이 나온다"고 가정하면 안 됩니다.**
- Q4_0은 도메인 PPL 15.74, 일반 PPL 31.16으로 크게 나빠졌고, 형식 준수율도 0.33으로 떨어져 0/4입니다. 0.5B 모델에 블록 단위 4비트는 너무 거칩니다. 크기만 보고 Q4_0을 고르면 기준을 통과하지 못하는 모델을 배포하게 됩니다.
- **4번**에서 F32는 GT 1030에 들어가지 않고, 나머지 셋은 들어갑니다. 위의 순서대로 고르면 기준을 지키는 F16·Q8_0 중 더 작은 **Q8_0**이 GT 1030용 형식입니다. 제56장은 이 파일로 Ollama 모델을 만듭니다.

# 제55장 검증 테스트
#
# 실행: python -m pytest examples/ch55 -q

import json
import sys
from pathlib import Path

HERE = Path(__file__).resolve().parent
sys.path.insert(0, str(HERE))

import numpy as np  # noqa: E402
import pytest  # noqa: E402

pytest.importorskip("gguf")

from gguf import GGMLQuantizationType, quants  # noqa: E402

from quant_compare import OUT, q4_0_by_hand, q8_0_by_hand  # noqa: E402


@pytest.mark.parametrize("name, fn, nbytes", [("Q8_0", q8_0_by_hand, 34), ("Q4_0", q4_0_by_hand, 18)])
def test_hand_implementation_matches_library(name, fn, nbytes):
    x = np.random.default_rng(1).standard_normal((4, 64)).astype(np.float32)
    q = GGMLQuantizationType[name]
    packed = quants.quantize(x, q)
    assert packed.shape == (4, 2 * nbytes)                                  # 64개 = 블록 2개
    assert np.array_equal(fn(x), quants.dequantize(packed, q))


def test_recorded_comparison():
    r = json.loads(OUT.read_text(encoding="utf-8"))
    sizes = [r[f]["size_mib"] for f in ("F32", "F16", "Q8_0", "Q4_0")]
    assert sizes == sorted(sizes, reverse=True)
    assert abs(r["F32"]["domain_ppl"] - 12.0587) < 0.01                    # F32 GGUF = 병합 모델(제52장)
    assert r["F16"]["passed"] == r["Q8_0"]["passed"] == r["F32"]["passed"] > r["Q4_0"]["passed"]
    assert r["Q4_0"]["general_ppl"] > 1.3 * r["F32"]["general_ppl"]

## 핵심 정리

- GGUF 양자화는 학습 후 양자화(PTQ)입니다. Q8_0은 그룹 32의 대칭 INT8, Q4_0은 가장 큰 원소의 부호까지 Scale에 담는 4비트입니다.
- 크기는 Q8_0이 F32의 27%, Q4_0이 14%입니다. 품질은 F16·Q8_0이 F32와 같은 수준을 지켰고, Q4_0은 기준을 하나도 통과하지 못했습니다.
- 양자화하면 품질 지표가 같아도 Greedy 답은 달라질 수 있습니다.
- 형식은 기준을 지키는 것 중에서 장치 예산에 들어가는 가장 작은 것으로 고릅니다. 이 교재의 GT 1030용 형식은 Q8_0입니다.
