## 장 개요

제22장에서 손실을 잴 수 있게 되었습니다. 무작위 Qwen2-Tiny의 손실은 약 12였습니다. 이제 이 숫자를 줄여야 합니다. 그런데 Qwen2-Tiny에는 4,190만 개의 가중치가 있습니다. 어느 가중치를 어느 방향으로 얼마나 바꿔야 손실이 줄어들까요?

그 답이 **Gradient**(기울기)입니다. 가중치마다 "이 값을 조금 키우면 손실이 얼마나 변하는가"를 알려 주는 숫자입니다. 4,190만 개의 Gradient를 하나씩 따로 구하면 순전파를 4,190만 번 해야 하지만, **역전파**(Backpropagation)는 순전파 한 번과 거꾸로 한 번의 계산으로 전부 구합니다. 이 장은 그 원리와, 계산이 맞는지 확인하는 방법을 다룹니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 수천만 개 가중치의 Gradient를 어떻게 한 번에 구하며, 그 값이 맞는지 어떻게 확인하는가 |
| 실습 결과물 | 손계산·수치 미분·Autograd 비교표, `gradcheck` 결과, Qwen2-Tiny 부품별 Gradient 크기 |
| 실습 파일 | `examples/ch23/`의 `grad_basics.py`, `grad_flow.py`, `test_ch23.py` |
| 선수 장 | 제05장(Linear), 제06장(Softmax), 제22장(Cross Entropy) |

```text
순전파:  가중치 ─▶ 계산 ─▶ 계산 ─▶ 손실        (계산 과정을 그래프로 기록)
역전파:  가중치 ◀─ 계산 ◀─ 계산 ◀─ dL/dL = 1   (연쇄법칙으로 거꾸로 곱해 나감)
결과:    가중치마다 .grad = dL/d가중치
```

## 미분과 연쇄법칙

미분은 "입력을 아주 조금 바꿨을 때 출력이 얼마나 바뀌는가"의 비율입니다. 가중치 w에 대한 손실 L의 미분 `dL/dw`가 3이면, w를 0.001 키울 때 손실이 약 0.003 커집니다. 그러니 손실을 줄이려면 w를 **반대 방향으로**, 즉 조금 줄이면 됩니다. 이것이 제24장 경사하강법의 전부입니다.

신경망은 계산을 여러 단계로 이어 붙인 것입니다. 단계마다의 미분은 쉽지만, 가중치에서 손실까지 여러 단계를 거칩니다. **연쇄법칙**(Chain Rule)은 이렇게 이어진 계산의 미분을 단계별 미분의 곱으로 구합니다.

```text
y = w·x + b,   L = (y − t)²
dL/dw = dL/dy × dy/dw = 2(y − t) × x
w = 3, x = 2, b = 1, t = 5  →  y = 7,  dL/dw = 2 × 2 × 2 = 8
```

"출력의 변화가 각 가중치에 얼마씩 책임이 있는가"를 손실 쪽에서부터 거꾸로 나눠 주는 셈입니다. 손실에 가까운 단계의 미분을 먼저 구하고, 그 값을 앞 단계로 넘겨 곱해 나갑니다. 그래서 **역**전파입니다.

### Cross Entropy의 Gradient

언어 모델의 마지막 단계, Logits z에 대한 Cross Entropy(제22장)의 미분은 놀랄 만큼 간단합니다.

```text
dL/dz = softmax(z) − 정답 원-핫
```

모델이 준 확률에서 정답 자리만 1을 뺀 것입니다. 정답 토큰의 점수는 올리고(미분이 음수), 나머지 토큰의 점수는 자기가 받은 확률만큼 내리라는 뜻입니다. 이 식은 어휘의 **모든** 토큰에 0이 아닌 값을 줍니다. 실습 2에서 이 사실이 Weight Tying과 만나 흥미로운 결과를 낳습니다.

Linear `z = Wx + b`까지 거슬러 올라가면, 연쇄법칙으로 다음을 얻습니다.

```text
dL/db = dL/dz                 [어휘]
dL/dW = dL/dz × xᵀ            [어휘, 입력]   바깥곱
```

## 계산 그래프와 Autograd

PyTorch는 `requires_grad=True`인 텐서로 계산하면, 어떤 연산을 어떤 순서로 했는지를 **계산 그래프**로 기록해 둡니다. 그리고 `loss.backward()`를 부르면 그 그래프를 거꾸로 따라가며 연쇄법칙을 자동으로 적용해, 각 텐서의 `.grad`에 결과를 넣습니다. 이 기능이 **Autograd**(자동 미분)입니다.

| 단계 | 하는 일 |
|---|---|
| `requires_grad=True` | 이 텐서에 대한 Gradient가 필요하다고 표시(모델 가중치는 기본값) |
| 순전파 | 계산하면서 그래프를 기록 |
| `loss.backward()` | 그래프를 거꾸로 따라 모든 가중치의 Gradient 계산 |
| `.grad` | 결과가 저장되는 곳(가중치와 같은 모양) |

Autograd 덕분에 제2부에서 만든 어떤 부품을 조립하든, 역전파 코드를 따로 쓸 필요가 없습니다. 대가는 메모리입니다. 역전파에 필요한 중간값을 순전파 동안 저장해 두어야 하고, `.grad`는 가중치와 같은 크기의 메모리를 하나 더 차지합니다. 제24장의 Optimizer 상태까지 더하면 학습에는 추론보다 훨씬 많은 메모리가 듭니다.

## Gradient 누적과 초기화

`backward()`는 `.grad`를 **덮어쓰지 않고 더합니다.** 같은 손실로 두 번 역전파하면 Gradient가 두 배가 됩니다.

```text
loss.backward()   →  .grad = g
loss.backward()   →  .grad = g + g = 2g     ← 초기화하지 않으면 계속 쌓인다
.grad = None      →  초기화(optimizer.zero_grad()가 하는 일)
```

이 설계는 실수가 아니라 기능입니다. 메모리가 부족해 한 번에 큰 묶음을 계산할 수 없을 때, 작은 묶음 여러 개의 Gradient를 차례로 더해 큰 묶음의 효과를 내는 **Gradient Accumulation**에 이 성질을 씁니다(제25장). 다만 학습 반복마다 초기화를 잊으면 이전 단계의 Gradient가 섞여 학습이 엉망이 되므로, 매 단계 시작에서 반드시 초기화합니다.

## 수치 미분 검증

Gradient를 직접 구현했거나 새로운 부품을 만들었다면, 그 값이 맞는지 어떻게 알까요? 미분의 정의로 돌아가면 됩니다. 가중치 하나를 아주 조금 올렸다 내렸다 하며 손실의 변화를 재는 **수치 미분**입니다.

```text
dL/dθ ≈ ( L(θ + h) − L(θ − h) ) ÷ 2h          중앙 차분, h = 10⁻⁶
```

수치 미분은 가중치 하나당 순전파를 두 번 해야 하므로 큰 모델에는 쓸 수 없지만, 작은 예제에서 정답지 역할을 합니다. 이때 반드시 **FP64**(64비트 부동소수점)로 계산합니다. h가 아주 작아 L(θ + h)와 L(θ − h)의 차이가 미세하므로, FP32로는 반올림 오차가 차이 자체를 덮어 버리기 때문입니다.

PyTorch의 `torch.autograd.gradcheck`는 이 비교를 자동으로 해 줍니다. FP64 입력에 대해 수치 미분과 Autograd 결과가 허용 오차 안에서 같으면 `True`를 돌려줍니다.

## 핵심 실습

### 실습 1. 세 방법으로 구한 Gradient 비교

어휘 3개, 입력 3차원의 작은 Linear 분류기로, 01절의 식(손계산), 중앙 차분(수치 미분), `backward()`(Autograd) 세 방법의 Gradient를 비교합니다.

파일명: `examples/ch23/grad_basics.py`

```python
# 제23장 핵심 실습: 작은 Linear 분류기의 Gradient를 손계산·수치 미분·Autograd로 비교한다
#
# 실행: python examples/ch23/grad_basics.py
#
# 모델: z = W x + b (어휘 3개짜리 점수), 손실 = Cross Entropy(z, 정답) (제22장)

import torch
import torch.nn.functional as F

X = torch.tensor([1.0, -2.0, 0.5], dtype=torch.float64)       # 입력 3차원
TARGET = 2                                                    # 정답 토큰
W0 = torch.tensor([[0.2, -0.1, 0.4],
                   [0.0, 0.3, -0.2],
                   [-0.3, 0.1, 0.1]], dtype=torch.float64)    # [출력 3, 입력 3]
B0 = torch.tensor([0.1, 0.0, -0.1], dtype=torch.float64)


def loss_fn(w: torch.Tensor, b: torch.Tensor) -> torch.Tensor:
    z = w @ X + b
    return F.cross_entropy(z.unsqueeze(0), torch.tensor([TARGET]))


def grad_by_hand(w: torch.Tensor, b: torch.Tensor) -> tuple:
    """연쇄법칙: dL/dz = softmax(z) − 정답 원-핫,  dL/dW = (dL/dz) xᵀ,  dL/db = dL/dz"""
    p = torch.softmax(w @ X + b, dim=0)
    dz = p.clone()
    dz[TARGET] -= 1.0
    return torch.outer(dz, X), dz


def grad_numeric(w: torch.Tensor, b: torch.Tensor, h: float = 1e-6) -> tuple:
    """중앙 차분: (L(θ + h) − L(θ − h)) / 2h 를 원소마다 계산한다(FP64)."""
    gw, gb = torch.zeros_like(w), torch.zeros_like(b)
    for g, param in ((gw, w), (gb, b)):
        flat, gflat = param.view(-1), g.view(-1)
        for i in range(flat.numel()):
            old = flat[i].item()
            flat[i] = old + h
            up = loss_fn(w, b).item()
            flat[i] = old - h
            down = loss_fn(w, b).item()
            flat[i] = old
            gflat[i] = (up - down) / (2 * h)
    return gw, gb


def grad_autograd(w: torch.Tensor, b: torch.Tensor) -> tuple:
    w, b = w.clone().requires_grad_(True), b.clone().requires_grad_(True)
    loss_fn(w, b).backward()                                   # 계산 그래프를 거꾸로
    return w.grad, b.grad


def main() -> None:
    print("── 1. 연쇄법칙 한 줄 예: L = (w·x + b − t)², w=3, x=2, b=1, t=5 ──")
    w = torch.tensor(3.0, requires_grad=True)
    y = w * 2.0 + 1.0                       # 7
    loss = (y - 5.0) ** 2                   # 4
    loss.backward()
    print(f"  손계산 dL/dw = dL/dy × dy/dw = 2(y − t) × x = 2×2×2 = 8,  Autograd {w.grad.item():.1f}")

    print("\n── 2. Linear 분류기 Gradient 세 방법 비교(FP64) ──")
    hw, hb = grad_by_hand(W0, B0)
    nw, nb = grad_numeric(W0.clone(), B0.clone())
    aw, ab = grad_autograd(W0, B0)
    print(f"  손실 {loss_fn(W0, B0).item():.6f}, 확률 {[round(v, 4) for v in torch.softmax(W0 @ X + B0, 0).tolist()]}")
    print(f"  dL/db  손계산 {[round(v, 6) for v in hb.tolist()]}")
    print(f"         Autograd {[round(v, 6) for v in ab.tolist()]}")
    print(f"  dL/dW 첫 행 손계산 {[round(v, 6) for v in hw[0].tolist()]}")
    for name, (gw, gb) in (("수치 미분", (nw, nb)), ("Autograd", (aw, ab))):
        err = max((gw - hw).abs().max().item(), (gb - hb).abs().max().item())
        print(f"  손계산과의 최대 차이({name}): {err:.1e}")

    print("\n── 3. gradcheck(FP64 수치 미분 vs 자동 미분) ──")
    w = W0.clone().requires_grad_(True)
    b = B0.clone().requires_grad_(True)
    print(f"  통과: {torch.autograd.gradcheck(loss_fn, (w, b))}")

    print("\n── 4. .grad는 더해진다 ──")
    w = W0.clone().requires_grad_(True)
    loss_fn(w, B0).backward()
    once = w.grad.clone()
    loss_fn(w, B0).backward()                                  # 초기화 없이 한 번 더
    print(f"  두 번째 backward 후 / 첫 번째: {(w.grad / once)[0, 0].item():.1f}배")
    w.grad = None                                              # optimizer.zero_grad()와 같은 일
    loss_fn(w, B0).backward()
    print(f"  초기화 후 다시 계산: 첫 번째와 같음 {torch.equal(w.grad, once)}")


if __name__ == "__main__":
    main()
```

실행:

```bash
python examples/ch23/grad_basics.py
```

```text
  손계산 dL/dw = dL/dy × dy/dw = 2(y − t) × x = 2×2×2 = 8,  Autograd 8.0

── 2. Linear 분류기 Gradient 세 방법 비교(FP64) ──
  손실 1.677293, 확률 [0.6523, 0.1608, 0.1869]
  dL/db  손계산 [0.652272, 0.160848, -0.813121]
         Autograd [0.652272, 0.160848, -0.813121]
  dL/dW 첫 행 손계산 [0.652272, -1.304545, 0.326136]
  손계산과의 최대 차이(수치 미분): 2.2e-10
  손계산과의 최대 차이(Autograd): 2.2e-16

── 3. gradcheck(FP64 수치 미분 vs 자동 미분) ──
  통과: True

── 4. .grad는 더해진다 ──
  두 번째 backward 후 / 첫 번째: 2.0배
  초기화 후 다시 계산: 첫 번째와 같음 True
```

| 방법 | 손계산과의 최대 차이 | 해석 |
|---|---|---|
| Autograd | 2e-16 | FP64의 마지막 자리 차이, 사실상 같다 |
| 수치 미분 | 2e-10 | 차분 근사의 오차, h를 작게 할수록 줄지만 반올림 한계가 있다 |

- 1번은 01절의 예제 그대로입니다. Autograd가 손계산과 같은 8을 냅니다.
- 2번에서 확률 `[0.65, 0.16, 0.19]`에 정답은 2번이므로, `dL/db`는 `[0.65, 0.16, 0.19 − 1]`입니다. 정답 자리만 음수라 정답 점수는 올라가고 나머지는 내려갑니다. 세 값의 합은 1 − 1 = 0입니다.
- `dL/dW`의 첫 행은 `dL/db`의 첫 값 0.65에 입력 `[1, −2, 0.5]`를 곱한 것입니다. 바깥곱 공식을 그대로 보여 줍니다.
- 3번의 `gradcheck` 통과는 같은 비교를 PyTorch가 독립적으로 확인한 결과입니다.
- 4번에서 초기화 없이 두 번 역전파하면 Gradient가 정확히 2배가 되고, 초기화하면 처음 값으로 돌아옵니다.

### 실습 2. Qwen2-Tiny의 Gradient 흐름

제19장의 Qwen2-Tiny에 고정 학습 데이터(제21장)의 블록 하나를 넣고 역전파를 한 번 합니다. 부품별 Gradient 크기를 막대로 그려, 손실 하나에서 출발한 신호가 모든 계층에 닿는 것을 확인합니다. 이 장부터 학습 실습은 `select_device()`가 고른 장치에서 계산합니다.

파일명: `examples/ch23/grad_flow.py`

```python
# 제23장 실습 2: Qwen2-Tiny에서 역전파 한 번이 모든 가중치에 Gradient를 남기는 모습 관찰
#
# 실행: python examples/ch23/grad_flow.py

import re
import sys
from collections import OrderedDict
from pathlib import Path

HERE = Path(__file__).resolve().parent
for p in (HERE.parent, HERE.parent / "ch19"):
    sys.path.insert(0, str(p))

import torch  # noqa: E402

from common.device import select_device  # noqa: E402
from common.fixed_data import load_blocks  # noqa: E402
from common.qwen import load_tokenizer  # noqa: E402
from hf_compat import to_hf  # noqa: E402            (제19장)
from tiny_model import Qwen2Tiny, init_weights  # noqa: E402


def group_of(name: str) -> str:
    """파라미터 이름을 '어느 계층의 어느 부품'으로 묶는다."""
    m = re.match(r"model\.layers\.(\d+)\.(self_attn|mlp|input_layernorm|post_attention_layernorm)", name)
    if m:
        part = {"self_attn": "Attention", "mlp": "FFN"}.get(m.group(2), "RMSNorm")
        return f"Block {m.group(1)} {part}"
    return {"model.embed_tokens.weight": "Embedding(= LM Head)", "model.norm.weight": "Final Norm"}[name]


def grad_table(model) -> "OrderedDict[str, float]":
    sq = OrderedDict()
    for name, p in model.named_parameters():               # 공유 텐서는 한 번만 나온다
        g = group_of(name)
        sq[g] = sq.get(g, 0.0) + p.grad.float().pow(2).sum().item()
    return OrderedDict((k, v ** 0.5) for k, v in sq.items())


def main() -> None:
    device, _ = select_device()
    tok = load_tokenizer()
    block = load_blocks(tok, "train")[:1].to(device)
    model = to_hf(init_weights(Qwen2Tiny(), seed=0)).to(device).train()

    loss = model(input_ids=block, labels=block).loss
    print(f"── 1. 순전파 손실 {loss.item():.4f} → loss.backward() 한 번 ──")
    print(f"  역전파 전 .grad: {model.model.layers[0].mlp.up_proj.weight.grad}")
    loss.backward()

    print("\n── 2. 부품별 Gradient 크기(L2 노름) ──")
    table = grad_table(model)
    top = max(table.values())
    for g, v in table.items():
        print(f"  {g:<20}{v:9.4f}  {'█' * max(1, round(20 * v / top))}")

    print("\n── 3. Embedding(= LM Head)이 받은 Gradient ──")
    emb = model.model.embed_tokens.weight.grad
    rows = (emb.abs().sum(dim=1) > 0).sum().item()
    print(f"  Gradient가 0이 아닌 행 {rows:,} / {emb.shape[0]:,}  (입력 토큰 종류 {block.unique().numel()}개)")
    alone = torch.nn.Embedding(*emb.shape).to(device)        # 공유하지 않는 표라면?
    alone(block).sum().backward()
    rows_alone = (alone.weight.grad.abs().sum(dim=1) > 0).sum().item()
    print(f"  공유하지 않은 Embedding 표만 따로 역전파하면: {rows_alone}행")

    n = sum(p.numel() for p in model.parameters())
    print(f"\n── 4. Gradient 메모리: 파라미터 {n:,}개 × 4바이트 = {n * 4 / 2**20:.1f}MiB(가중치와 같은 크기) ──")


if __name__ == "__main__":
    main()
```

## 핵심 정리

- Gradient는 가중치를 조금 바꿨을 때 손실이 변하는 비율입니다. 손실을 줄이려면 Gradient의 반대 방향으로 가중치를 움직입니다.
- 역전파는 연쇄법칙으로 손실 쪽에서부터 단계별 미분을 곱해 나가, 모든 가중치의 Gradient를 한 번에 구합니다.
- Cross Entropy의 Logits Gradient는 `softmax − 정답 원-핫`이며, 어휘 전체에 값을 줍니다.
- PyTorch Autograd는 순전파를 계산 그래프로 기록했다가 `backward()`로 역전파합니다. `.grad`는 더해지므로 매 단계 초기화합니다.
- 구현이 맞는지는 FP64 수치 미분(`gradcheck`)과 비교해 확인합니다.

**다음 장 연결:** Gradient로 "어느 방향"인지는 알았습니다. 제24장에서는 그 방향으로 "얼마나" 움직일지 정하는 Optimizer(SGD, Adam, AdamW)를 비교하고, Optimizer가 추가로 쓰는 메모리를 계산합니다.
