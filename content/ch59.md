## 장 개요

이 장은 선택 장입니다. FPGA를 다루는 학습자를 위해, LLM 추론의 핵심 계산을 하드웨어 회로로 옮기는 첫걸음을 다룹니다.

LLM이 토큰 하나를 만들 때 하는 계산의 대부분은 **행렬과 벡터의 곱**입니다. 행렬곱은 곱하고 더하는 일(MAC, Multiply-Accumulate)의 반복이므로, NPU나 GPU 같은 가속기는 결국 MAC를 많이, 빠르게 하는 회로입니다. 이 장은 제53장에서 꺼낸 k_proj 가중치를 INT8로 양자화해 Basys3 보드(XC7A35T)의 메모리에 맞춰 보고, 정수 MAC 블록을 Verilog로 설계하며, 파이썬 정수 기준값(Golden)과 비교할 Testbench를 만듭니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | LLM의 한 층을 FPGA에서 계산하려면 어떤 크기·자료형·누산기가 필요하고, 결과가 맞는지 어떻게 확인하는가 |
| 실습 결과물 | BRAM 탑재 판정, 누산기 비트 계산, INT8 타일과 기준값 HEX, MAC RTL과 Testbench, 사이클 단위 동작 모델 |
| 실습 파일 | `examples/ch59/`의 `golden.py`, `rtl_model.py`, `test_ch59.py`, `rtl/mac_matmul.v`, `rtl/tb_mac_matmul.v` |
| 선수 장 | 제31장(2의 보수), 제33장(INT8 양자화), 제53장(가중치 추출과 HEX) |

```text
k_proj 0층의 앞 8행(8 × 896, FP32) ─행마다 대칭 INT8─▶ w.hex      입력 x(896) ─INT8─▶ x.hex
파이썬 정수 곱셈·누산 ─▶ expected.hex(32비트)
mac_matmul.v(MAC 1개, 2단 파이프라인) + tb_mac_matmul.v ─$readmemh─▶ 결과를 expected와 비트 단위 비교
```

## LLM 연산과 NPU

Decoder 층 하나에는 Attention의 투영 4개와 FFN의 투영 3개가 있고(제20장), 각각이 행렬-벡터 곱입니다. 0.5B 모델이 토큰 하나를 만드는 데 필요한 곱셈은 대략 파라미터 수(약 5억 번)와 같습니다. 그래서 추론 속도는 MAC를 초당 몇 번 할 수 있는지와, 가중치를 메모리에서 얼마나 빨리 가져오는지로 정해집니다.

| 장치 | MAC를 늘리는 방법 |
|---|---|
| CPU | SIMD 명령으로 한 번에 여러 개 |
| GPU | 수천 개의 코어가 동시에 |
| NPU·FPGA | 곱셈기와 누산기를 회로로 직접 배치(정수 연산이면 더 작고 빠르다) |

이 장의 회로는 가장 단순한 형태인 MAC 1개짜리입니다. 한 사이클에 곱셈 하나를 하며, 구조를 이해한 뒤 MAC 개수를 늘리는 것이 다음 단계입니다.

## Basys3 자원과 탑재 범위

Basys3의 XC7A35T에는 36Kb 블록 RAM이 50개, 합쳐 1,800Kb(225KiB) 있습니다. 가중치를 INT8로 줄여도 0.5B 모델의 한 층조차 모두 담기 어렵습니다.

| 가중치 | INT8 크기 | BRAM 225KiB |
|---|---|---|
| q_proj(896 × 896) | 784KiB | 불가 |
| k_proj(128 × 896) | 112KiB | 이론상 가능 |

그래서 이 장은 k_proj에서 8행을 떼어 낸 **타일**(8 × 896, 7KiB)로 설계를 검증합니다. 같은 회로를 타일마다 반복하면 큰 행렬도 계산할 수 있으며, 그때는 외부 메모리에서 타일을 차례로 가져오는 일이 중요해집니다.

## 정수 MAC와 누산기

INT8 두 개의 곱은 최대 크기가 128 × 128 = 16,384로 16비트에 들어가지만, 896개를 더하면 커집니다. 누산기가 넘치지 않으려면 최악의 합을 담을 수 있어야 합니다.

```text
최악의 합 = 896 × 128 × 128 = 14,680,064 < 2²⁴
→ 크기 24비트 + 부호 1비트 = 최소 25비트, 이 장의 설계는 여유를 두어 32비트
```

입력 x도 INT8로 양자화하므로, 정수 결과에 가중치 Scale(행마다)과 입력 Scale을 곱해야 원래 크기의 값이 됩니다(역양자화, 제33장). 회로는 정수 누산까지만 하고, Scale 곱셈은 회로 밖에서 하거나 고정소수점 곱셈기를 더해 처리합니다.

## RTL MatMul과 Testbench

설계는 2단 파이프라인입니다. 1단은 행·열 번호를 세며 메모리에서 W와 x를 읽고(동기 읽기라 BRAM으로 합성될 수 있는 형태), 2단은 읽은 두 값을 곱해 누산기에 더합니다. 행의 마지막 열에서는 결과를 내보내고 누산기를 비웁니다.

검증의 기준은 **파이썬의 정수 계산**입니다. 같은 INT8 값으로 64비트 정수 곱셈·누산을 해서 기대값을 만들고, Testbench가 RTL의 결과와 비트 단위로 비교합니다. 부동소수점이 아니므로 허용 오차 없이 정확히 같아야 합니다.

교재 검증 환경에는 Verilog 시뮬레이터와 합성 도구가 없어, RTL 시뮬레이션과 합성(자원·타이밍 보고)은 실행하지 못했습니다(미검증). 대신 RTL과 같은 순서로 레지스터를 바꾸는 **사이클 단위 파이썬 모델**을 만들어, 설계의 순서(파이프라인, 행 끝 처리, 사이클 수)가 맞는지 먼저 확인합니다. 이 모델은 RTL 자체의 검증을 대신하지 않습니다.

```python
# 제59장 핵심 실습(선택): k_proj 타일을 INT8로 만들고, RTL MatMul의 정수 기준값(Golden)과 HEX 파일을 만든다
#
# 실행: python examples/ch59/golden.py   (제52장의 병합 모델 필요, CPU 약 20초)
#
# 만드는 파일: examples/ch59/rtl/w.hex, x.hex, expected.hex (Testbench가 $readmemh로 읽는다)
# RTL 시뮬레이션과 Basys3 합성은 교재 검증 환경에 도구가 없어 실행하지 않았다(미검증).

import sys
from pathlib import Path

HERE = Path(__file__).resolve().parent
ROOT = HERE.parents[1]
sys.path.insert(0, str(HERE.parent))

import numpy as np  # noqa: E402
import torch  # noqa: E402

MERGED = ROOT / "models" / "fpga_merged_v1"
RTL = HERE / "rtl"
ROWS, COLS = 8, 896                    # 타일: k_proj 출력 8개 × 입력 896개
BRAM_KIB = 50 * 36 / 8                 # XC7A35T: 36Kb 블록 50개 = 225KiB


def quant_rows(w: np.ndarray) -> tuple:
    """행(출력)마다 대칭 INT8: q = round(w / s), s = max|w| / 127 (제33장)"""
    s = np.abs(w).max(axis=1, keepdims=True) / 127
    return np.clip(np.round(w / s), -127, 127).astype(np.int8), s.astype(np.float32)


def quant_vec(x: np.ndarray) -> tuple:
    s = np.abs(x).max() / 127
    return np.clip(np.round(x / s), -127, 127).astype(np.int8), np.float32(s)


def acc_bits(n: int, a_max: int = 128, b_max: int = 128) -> int:
    """부호 있는 누산기가 넘치지 않는 최소 비트: |합| ≤ n × a_max × b_max"""
    worst = n * a_max * b_max
    return int(np.ceil(np.log2(worst + 1))) + 1


def to_hex(values, bits: int) -> list:
    mask = (1 << bits) - 1
    return [f"{int(v) & mask:0{bits // 4}x}" for v in values]          # 2의 보수(제31장)


def main() -> None:
    from transformers import AutoModelForCausalLM
    model = AutoModelForCausalLM.from_pretrained(MERGED, dtype=torch.float32).eval()
    layer = model.get_submodule("model.layers.0.self_attn.k_proj")      # 제53장과 같은 층

    print("── 1. Basys3 자원과 탑재 범위(INT8) ──")
    for name in ("q_proj", "k_proj"):
        w = model.get_submodule(f"model.layers.0.self_attn.{name}").weight
        kib = w.numel() / 1024
        print(f"  {name} {tuple(w.shape)}: {kib:.0f}KiB  BRAM {BRAM_KIB:.0f}KiB 안에 {'가능' if kib <= BRAM_KIB else '불가'}")

    print("\n── 2. 정수 MAC와 누산기 ──")
    print(f"  INT8 × INT8 곱 896개 합의 최악값 896 × 128 × 128 = {896 * 128 * 128:,} → 최소 {acc_bits(896)}비트"
          f"(부호 포함), 설계는 32비트")

    print(f"\n── 3. 타일 {ROWS} × {COLS}의 정수 기준값 ──")
    torch.manual_seed(0)
    x = torch.randn(COLS)
    wq, ws = quant_rows(layer.weight[:ROWS].detach().numpy())
    xq, xs = quant_vec(x.numpy())
    acc = wq.astype(np.int64) @ xq.astype(np.int64)                     # 정수 기준값(넘침 없는 64비트)
    assert np.abs(acc).max() < 2 ** 31
    y_int = acc * ws[:, 0] * xs                                          # 역양자화
    y_fp = (layer.weight[:ROWS] @ x).detach().numpy()                    # 편향 제외 W x
    rel = np.abs(y_int - y_fp).max() / np.abs(y_fp).max()
    print(f"  누산 결과 범위 {acc.min():,} ~ {acc.max():,}(32비트 안)")
    print(f"  INT8 결과(역양자화)와 FP32 W x의 최대 상대 오차 {rel:.2%}")

    RTL.mkdir(exist_ok=True)
    (RTL / "w.hex").write_text("\n".join(to_hex(wq.ravel(), 8)) + "\n")     # 행 우선, 한 줄에 8비트
    (RTL / "x.hex").write_text("\n".join(to_hex(xq, 8)) + "\n")
    (RTL / "expected.hex").write_text("\n".join(to_hex(acc, 32)) + "\n")
    print(f"  파일: w.hex {ROWS * COLS}줄, x.hex {COLS}줄, expected.hex {ROWS}줄(32비트 2의 보수)")
    print(f"  첫 기대값 {acc[0]:,} = {to_hex(acc[:1], 32)[0]}")


if __name__ == "__main__":
    main()
```

파일명: `examples/ch59/rtl/mac_matmul.v`

```verilog
// 제59장(선택): INT8 행렬-벡터 곱 MAC 블록 (y[r] = Σ W[r][c] · x[c], 32비트 누산)
//
// 구조: 2단 파이프라인
//   1단: 메모리에서 W[r][c], x[c]를 읽는다(동기 읽기, BRAM으로 합성되는 형태)
//   2단: 곱해서 누산기에 더한다. 행의 마지막 열이면 결과를 내보내고 누산기를 비운다
// 한 사이클에 곱셈 하나(MAC 1개). ROWS × COLS 사이클 + 파이프라인 2사이클이 걸린다.

module mac_matmul #(
    parameter ROWS   = 8,
    parameter COLS   = 896,
    parameter W_FILE = "w.hex",          // 행 우선, 한 줄에 INT8 하나(2의 보수 HEX)
    parameter X_FILE = "x.hex"
) (
    input  wire               clk,
    input  wire               rst,       // 동기 리셋
    input  wire               start,     // 한 사이클 펄스
    output reg                out_valid, // out_row, out_acc가 유효한 사이클
    output reg  [7:0]         out_row,
    output reg  signed [31:0] out_acc,
    output reg                done       // 마지막 행의 결과를 낸 뒤 1
);
    reg signed [7:0] w_mem [0:ROWS*COLS-1];
    reg signed [7:0] x_mem [0:COLS-1];
    initial begin
        $readmemh(W_FILE, w_mem);
        $readmemh(X_FILE, x_mem);
    end

    // 1단: 주소 생성과 메모리 읽기
    reg        running;
    reg [7:0]  row;
    reg [15:0] col;
    reg signed [7:0] w_q, x_q;
    reg        rd_valid, rd_last;
    reg [7:0]  rd_row;

    always @(posedge clk) begin
        if (rst) begin
            running  <= 1'b0;
            row      <= 8'd0;
            col      <= 16'd0;
            rd_valid <= 1'b0;
            rd_last  <= 1'b0;
        end else begin
            rd_valid <= 1'b0;
            rd_last  <= 1'b0;
            if (start && !running) begin
                running <= 1'b1;
                row     <= 8'd0;
                col     <= 16'd0;
            end else if (running) begin
                w_q      <= w_mem[row * COLS + col];
                x_q      <= x_mem[col];
                rd_valid <= 1'b1;
                rd_row   <= row;
                rd_last  <= (col == COLS - 1);
                if (col == COLS - 1) begin
                    col <= 16'd0;
                    if (row == ROWS - 1)
                        running <= 1'b0;
                    else
                        row <= row + 8'd1;
                end else begin
                    col <= col + 16'd1;
                end
            end
        end
    end

    // 2단: 곱셈과 누산(부호 있는 8비트 × 8비트 → 32비트로 부호 확장해 더한다)
    reg signed [31:0] acc;

    always @(posedge clk) begin
        if (rst) begin
            acc       <= 32'sd0;
            out_valid <= 1'b0;
            done      <= 1'b0;
        end else begin
            out_valid <= 1'b0;
            if (start)
                done <= 1'b0;
            if (rd_valid) begin
                if (rd_last) begin
                    out_acc   <= acc + w_q * x_q;
                    out_row   <= rd_row;
                    out_valid <= 1'b1;
                    acc       <= 32'sd0;
                    if (rd_row == ROWS - 1)
                        done <= 1'b1;
                end else begin
                    acc <= acc + w_q * x_q;
                end
            end
        end
    end
endmodule
```

// 제59장(선택): mac_matmul Testbench — Python 정수 기준값(expected.hex)과 비트 단위로 비교한다
//
// 실행 예(Icarus Verilog, 교재 검증 환경에서는 미검증):
//   iverilog -o tb tb_mac_matmul.v mac_matmul.v && vvp tb

`timescale 1ns / 1ps

module tb_mac_matmul;
    localparam ROWS = 8, COLS = 896;

    reg clk = 1'b0, rst = 1'b1, start = 1'b0;
    wire out_valid, done;
    wire [7:0] out_row;
    wire signed [31:0] out_acc;

    reg [31:0] expected [0:ROWS-1];
    integer errors = 0, received = 0, cycles = 0;

    mac_matmul #(.ROWS(ROWS), .COLS(COLS)) dut (
        .clk(clk), .rst(rst), .start(start),
        .out_valid(out_valid), .out_row(out_row), .out_acc(out_acc), .done(done)
    );

    always #5 clk = ~clk;                         // 100MHz

    always @(posedge clk) begin
        cycles <= cycles + 1;
        if (out_valid) begin
            received <= received + 1;
            if (out_acc !== $signed(expected[out_row])) begin
                errors <= errors + 1;
                $display("FAIL row %0d: got %0d, expected %0d", out_row, out_acc, $signed(expected[out_row]));
            end else begin
                $display("ok   row %0d: %0d", out_row, out_acc);
            end
        end
    end

    initial begin
        $readmemh("expected.hex", expected);
        repeat (3) @(posedge clk);
        rst <= 1'b0;
        @(posedge clk) start <= 1'b1;
        @(posedge clk) start <= 1'b0;
        wait (done);
        @(posedge clk);
        $display("%s: %0d rows, %0d errors, %0d cycles", (errors == 0 && received == ROWS) ? "PASS" : "FAIL",
                 received, errors, cycles);
        $finish;
    end

    initial begin
        #(20 * ROWS * COLS * 10);                  // 시간 초과 보호
        $display("FAIL: timeout");
        $finish;
    end
endmodule

```python
# 제59장(선택): mac_matmul.v의 동작을 사이클 단위로 흉내 내는 파이썬 모델
#
# RTL 시뮬레이터가 없는 환경에서 설계의 순서(2단 파이프라인, 행 끝 처리)가 맞는지 먼저 확인하는 용도다.
# 레지스터는 사이클마다 "현재 값으로 다음 값을 계산한 뒤 한꺼번에 바꾼다"(Verilog의 <=와 같음).
# 이 모델이 맞아도 RTL 자체의 검증을 대신하지는 않는다.
#
# 실행: python examples/ch59/rtl_model.py   (golden.py가 만든 HEX 파일 필요)

from pathlib import Path

RTL = Path(__file__).resolve().parent / "rtl"


def read_hex(path: Path, bits: int) -> list:
    """2의 보수 HEX를 부호 있는 정수로(제31장)"""
    out = []
    for line in path.read_text().split():
        v = int(line, 16)
        out.append(v - (1 << bits) if v >> (bits - 1) else v)
    return out


def simulate(w: list, x: list, rows: int, cols: int, max_cycles: int = 10 ** 7) -> tuple:
    s = {"running": 0, "row": 0, "col": 0, "w_q": 0, "x_q": 0, "rd_valid": 0, "rd_last": 0, "rd_row": 0,
         "acc": 0}
    results, cycle, start = {}, 0, 1
    while cycle < max_cycles:
        n = dict(s)                                                  # 다음 상태(모두 현재 값으로 계산)
        n["rd_valid"], n["rd_last"] = 0, 0
        if start and not s["running"]:                               # 1단
            n.update(running=1, row=0, col=0)
        elif s["running"]:
            r, c = s["row"], s["col"]
            n.update(w_q=w[r * cols + c], x_q=x[c], rd_valid=1, rd_row=r, rd_last=int(c == cols - 1))
            if c == cols - 1:
                n["col"] = 0
                if r == rows - 1:
                    n["running"] = 0
                else:
                    n["row"] = r + 1
            else:
                n["col"] = c + 1
        done = False
        if s["rd_valid"]:                                            # 2단
            total = s["acc"] + s["w_q"] * s["x_q"]
            if s["rd_last"]:
                results[s["rd_row"]] = total
                n["acc"] = 0
                done = s["rd_row"] == rows - 1
            else:
                n["acc"] = total
        s, start, cycle = n, 0, cycle + 1
        if done:
            return [results[r] for r in range(rows)], cycle
    raise RuntimeError("끝나지 않음")


if __name__ == "__main__":
    w, x, exp = read_hex(RTL / "w.hex", 8), read_hex(RTL / "x.hex", 8), read_hex(RTL / "expected.hex", 32)
    rows, cols = len(exp), len(x)
    got, cycles = simulate(w, x, rows, cols)
    for r, (g, e) in enumerate(zip(got, exp)):
        print(f"  행 {r}: 모델 {g:>8,}  기대값 {e:>8,}  {'일치' if g == e else '불일치'}")
    print(f"  {cycles:,}사이클(= {rows} × {cols} + 2), 100MHz라면 {cycles / 100:.1f}마이크로초")
```

**결과 읽기**

- **1번**에서 q_proj(784KiB)는 BRAM 225KiB에 들어가지 않고 k_proj(112KiB)는 들어갑니다. 실제로는 다른 회로도 BRAM을 쓰므로 k_proj 전체도 빠듯합니다.
- **2번**에서 896개 누산의 최악값은 14,680,064이고 최소 25비트가 필요합니다. 32비트 누산기는 충분합니다.
- **3번**의 실제 누산값은 −94,846 ~ 66,987로 최악값보다 훨씬 작습니다. 가중치와 입력의 부호가 섞여 서로 상쇄되기 때문이지만, 설계는 최악값을 기준으로 해야 어떤 입력에도 넘치지 않습니다. INT8로 계산해 역양자화한 결과와 FP32 결과의 최대 상대 오차는 0.51%입니다.
- 기대값은 32비트 2의 보수 HEX로 저장했습니다. 31,416은 00007ab8이고, 음수는 ff로 시작합니다.
- 사이클 모델의 결과 8개가 기대값과 모두 일치하고, 걸린 사이클은 8 × 896 + 2 = 7,170입니다(시작 1사이클, 파이프라인 끝 1사이클). 100MHz로 동작한다면 약 72마이크로초입니다. k_proj 전체(128행)라면 MAC 1개로 약 115만 사이클, 약 1.1밀리초가 걸리므로, MAC를 여러 개 두는 병렬화가 필요합니다.

import sys
from pathlib import Path

HERE = Path(__file__).resolve().parent
sys.path.insert(0, str(HERE))

import numpy as np  # noqa: E402

from golden import BRAM_KIB, COLS, ROWS, acc_bits, quant_rows, to_hex  # noqa: E402
from rtl_model import RTL, read_hex, simulate  # noqa: E402


def test_accumulator_and_bram():
    assert acc_bits(896) == 25 and 896 * 128 * 128 < 2 ** 24
    assert BRAM_KIB == 225 and 128 * 896 / 1024 <= BRAM_KIB < 896 * 896 / 1024


def test_hex_twos_complement_roundtrip(tmp_path):
    vals = [-128, -1, 0, 1, 127]
    (tmp_path / "a.hex").write_text("\n".join(to_hex(vals, 8)))
    assert to_hex(vals, 8) == ["80", "ff", "00", "01", "7f"] and read_hex(tmp_path / "a.hex", 8) == vals


def test_quant_range():
    q, s = quant_rows(np.array([[0.5, -1.0, 0.25]], dtype=np.float32))
    assert q.tolist() == [[64, -127, 32]] and abs(s[0, 0] - 1 / 127) < 1e-7


def test_rtl_model_matches_golden_files():
    w, x = read_hex(RTL / "w.hex", 8), read_hex(RTL / "x.hex", 8)
    exp = read_hex(RTL / "expected.hex", 32)
    got, cycles = simulate(w, x, ROWS, COLS)
    assert got == exp == (np.array(w).reshape(ROWS, COLS) @ np.array(x)).tolist()
    assert cycles == ROWS * COLS + 2                                    # 시작 1 + MAC ROWS×COLS + 마지막 누산 1

## 핵심 정리

- LLM 추론의 대부분은 행렬-벡터 곱이며, 가속기는 MAC를 많이 빠르게 하는 회로입니다.
- Basys3의 BRAM은 225KiB라 INT8로도 한 층 전체를 담기 어렵고, 타일로 나눠 계산합니다.
- INT8 × INT8을 n번 누산하려면 최악의 합을 담을 비트가 필요합니다(896번이면 최소 25비트).
- 검증 기준은 파이썬 정수 계산이며, 정수 연산은 허용 오차 없이 비트 단위로 같아야 합니다.
- 시뮬레이터가 없으면 사이클 단위 모델로 설계 순서를 먼저 확인하되, RTL 시뮬레이션과 합성은 따로 해야 합니다.
