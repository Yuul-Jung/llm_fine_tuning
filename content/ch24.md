## 장 개요

제23장에서 Gradient로 "손실이 커지는 방향"을 알아냈습니다. 학습은 그 반대 방향으로 가중치를 조금씩 옮기는 일을 수천 번 되풀이하는 것입니다. 이때 "얼마나, 어떻게" 옮길지를 정하는 것이 **Optimizer**입니다.

이 장은 가장 단순한 SGD에서 출발해 Momentum, Adam, AdamW로 발전해 온 이유를 따라가고, 같은 문제를 다섯 가지 설정으로 풀어 손실 곡선을 비교합니다. 그리고 Optimizer가 가중치마다 저장하는 상태가 메모리를 얼마나 쓰는지 계산해, 0.5B 모델을 GT 1030에서 통째로 학습할 수 없는 이유를 숫자로 확인합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | Gradient를 가중치 갱신으로 바꾸는 규칙은 무엇이며, 그 대가로 메모리를 얼마나 쓰는가 |
| 실습 결과물 | 다섯 가지 Optimizer 설정의 손실 비교표, Optimizer 상태 메모리 측정, Full Fine-tuning 메모리 예산 |
| 실습 파일 | `examples/ch24/`의 `optim_compare.py`, `optim_memory.py`, `test_ch24.py` |
| 선수 장 | 제07장(Bigram), 제22장(손실), 제23장(Gradient와 초기화) |

```text
학습 반복 한 단계
  ① 묶음 꺼내기 → ② 순전파·손실 → ③ zero_grad → ④ backward → ⑤ optimizer.step
                                                                    └ 이 장의 주제
```

## 경사하강법과 SGD

가장 기본적인 규칙은 Gradient의 반대 방향으로, 학습률(Learning Rate)만큼 이동하는 것입니다.

```text
θ ← θ − lr × g          θ: 가중치, g: Gradient(dL/dθ), lr: 학습률
예) θ = [1, −2], L = θ₁² + θ₂²,  g = 2θ = [2, −4],  lr = 0.1
    θ ← [1 − 0.2, −2 + 0.4] = [0.8, −1.6]       손실 5 → 3.2
```

이것이 **경사하강법**(Gradient Descent)입니다. 데이터 전체가 아니라 무작위로 고른 작은 묶음(Mini-batch)으로 Gradient를 구해 매번 조금씩 이동하는 방식을 **SGD**(Stochastic Gradient Descent, 확률적 경사하강법)라 부릅니다. 묶음마다 Gradient가 조금씩 다르므로 경로가 흔들리지만, 평균적으로는 손실이 줄어드는 방향으로 갑니다.

## Momentum, Adam, AdamW

SGD는 단순하지만 두 가지 약점이 있습니다. 묶음마다 방향이 흔들려 같은 자리를 맴돌기 쉽고, 모든 가중치에 같은 학습률을 쓰므로 Gradient가 작은 가중치는 거의 움직이지 않습니다. 제23장에서 부품마다 Gradient 크기가 수십 배 달랐던 것을 떠올려 보세요.

| 방법 | 아이디어 | 기억하는 것 |
|---|---|---|
| Momentum | 지난 이동 방향을 관성처럼 이어 간다. 흔들림은 상쇄되고 일관된 방향은 가속된다 | 이동 방향의 평균 m |
| Adam | Momentum에 더해, 가중치마다 Gradient 크기의 평균으로 나눠 이동 폭을 고르게 맞춘다 | m과 Gradient 제곱의 평균 v |
| AdamW | Adam에 Weight Decay를 **따로** 적용한다 | m, v |

```text
Adam:   m ← 0.9 m + 0.1 g             방향의 이동 평균
        v ← 0.999 v + 0.001 g²         크기의 이동 평균
        θ ← θ − lr × m̂ ÷ (√v̂ + ε)     m̂, v̂: 초기 편향을 보정한 값
AdamW:  θ ← θ − lr × wd × θ  를 추가로   Weight Decay(가중치 감쇠)
```

Adam의 핵심은 `÷ √v`입니다. Gradient가 큰 가중치는 크게 나누고 작은 가중치는 작게 나누므로, 모든 가중치가 비슷한 폭으로 움직입니다. 그래서 학습률을 하나만 정해도 부품마다 크기가 다른 Transformer를 고르게 학습할 수 있고, 오늘날 LLM 학습의 표준이 되었습니다.

**Weight Decay**는 매 단계 가중치를 조금씩 0 쪽으로 당겨, 가중치가 지나치게 커지는 것을 막습니다. 가중치가 작을수록 모델은 학습 데이터의 세세한 우연까지 외우기 어려워집니다. AdamW는 이 감쇠를 Adam의 `÷ √v` 보정과 섞지 않고 따로 적용한다는 점에서 Adam과 다릅니다. 손실 Gradient가 0이어도 가중치가 정확히 `lr × wd` 비율만큼 줄어드는 것을 테스트에서 확인합니다.

## Learning Rate, Batch, Epoch

| 용어 | 뜻 | 작을 때 / 클 때 |
|---|---|---|
| Learning Rate | 한 번에 이동하는 폭 | 거의 배우지 못한다 / 손실이 튀거나 발산한다(NaN) |
| Batch | 한 번의 Gradient 계산에 쓰는 묶음 크기 | Gradient가 많이 흔들린다 / 메모리가 부족하다 |
| Epoch | 학습 데이터 전체를 한 번 다 보는 단위 | 덜 배운다 / 학습 데이터를 외운다(과적합) |

학습률에는 정답이 없고 Optimizer마다 알맞은 범위가 다릅니다. 실습 1에서 SGD는 학습률 0.1로는 거의 움직이지 않고 10은 되어야 손실이 줄지만, Adam은 0.1로 빠르게 줄어듭니다. Adam의 이동 폭은 Gradient 크기와 거의 상관없이 학습률 정도로 정해지기 때문입니다.

이 장의 실습은 학습 블록 25개에서 묶음 4개씩 300단계를 학습하므로 약 48 Epoch에 해당합니다. 같은 데이터를 48번 보았으니 외우기 쉬운 조건입니다. 그래서 **학습 손실과 함께 평가 손실**을 봐야 합니다(제21장의 학습·평가 분리).

## Optimizer State와 메모리

Momentum과 Adam이 "기억하는 것"은 공짜가 아닙니다. 가중치마다 값을 저장해야 합니다.

| Optimizer | 가중치당 상태 | FP32 바이트 |
|---|---|---|
| SGD | 없음 | 0 |
| SGD + Momentum | m | 4 |
| Adam, AdamW | m, v | 8 |

학습에 필요한 고정 메모리는 가중치(4바이트) + Gradient(4바이트, 제23장) + AdamW 상태(8바이트)로, **가중치 하나당 16바이트**입니다. 순전파 중간값(활성값)은 묶음 크기와 문장 길이에 따라 그 위에 더해집니다.

```text
Qwen2-Tiny     41,914,112 × 16바이트 ≈ 640MiB      GT 1030(2GiB)에서 학습 가능
Qwen2.5-0.5B  494,032,768 × 16바이트 ≈ 7.4GiB      GT 1030에서 불가능
```

모든 가중치를 학습하는 **Full Fine-tuning**은 0.5B 모델조차 우리 장비에서 할 수 없습니다. 제26장부터 다루는 LoRA는 이 문제를, 대부분의 가중치를 얼려 Gradient와 Optimizer 상태를 아예 만들지 않는 방법으로 풉니다.

## Scheduler, Accumulation, Clipping 개념

실제 학습에서는 세 가지 기법을 함께 씁니다. 이 장에서는 목적만 정리하고, 제25장에서 Qwen2-Tiny 학습에 실제로 적용합니다.

| 기법 | 목적 | 방법 |
|---|---|---|
| Scheduler | 처음에는 조심스럽게, 끝에는 세밀하게 | 학습률을 단계마다 바꾼다. Warmup(0에서 서서히 올림) 후 Cosine(코사인 곡선으로 내림) |
| Gradient Accumulation | 메모리는 작게, 효과는 큰 묶음처럼 | 작은 묶음 여러 개의 Gradient를 더한 뒤 한 번 갱신한다(제23장의 누적 원리) |
| Gradient Clipping | 한 번의 큰 Gradient가 학습을 망치지 않게 | Gradient 전체의 노름이 기준을 넘으면 비율을 유지한 채 줄인다 |

Accumulation에서는 손실을 묶음 수로 나눠 더해야 큰 묶음 하나로 계산한 Gradient와 정확히 같아집니다. 테스트에서 묶음 8개를 한 번에 계산한 Gradient와 2개씩 4번 나눠 더한 Gradient가 같은 것을 확인합니다.

## 핵심 실습

### 실습 1. 같은 문제, 다섯 가지 Optimizer

제07장의 Bigram 모델을, 이번에는 개수를 세는 대신 **경사하강법으로 학습**합니다. 앞 토큰을 보고 다음 토큰의 점수를 내는 점수표 `[어휘, 어휘]` 하나가 모델의 전부입니다. 어휘는 고정 학습 데이터에 나온 718개 토큰으로 줄였습니다. 모든 설정은 같은 초기값, 같은 묶음 순서로 학습합니다.

파일명: `examples/ch24/optim_compare.py`

```python
# 제24장 핵심 실습: 같은 Bigram 학습 문제를 SGD·Adam·AdamW로 풀어 손실 곡선을 비교한다
#
# 실행: python examples/ch24/optim_compare.py
#
# 문제: 고정 학습 데이터(제21장)에서 "앞 토큰 → 다음 토큰" 점수표를 경사하강법으로 학습한다.
# 제07장의 Bigram을 세는 대신 Gradient로 배운다. 어휘는 데이터에 나온 토큰만 남겨 줄인다.

import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[1]))

import torch  # noqa: E402
import torch.nn.functional as F  # noqa: E402

from common.device import select_device  # noqa: E402
from common.fixed_data import load_blocks  # noqa: E402
from common.qwen import load_tokenizer  # noqa: E402

STEPS, BATCH, SEED = 300, 4, 0
CHECKPOINTS = (0, 10, 30, 100, 300)


def compact(train: torch.Tensor, evals: torch.Tensor) -> tuple:
    """학습 데이터에 나온 토큰만 0, 1, 2, …로 번호를 다시 매긴다. 처음 보는 평가 토큰은 −1."""
    vocab = train.unique()
    lookup = torch.full((151_936,), -1, dtype=torch.long)
    lookup[vocab] = torch.arange(len(vocab))
    return lookup[train], lookup[evals], len(vocab)


def eval_loss(table, evals: torch.Tensor, v: int) -> float:
    """처음 보는 토큰이 낀 위치는 −100으로 빼고(제22장) 평균 손실을 잰다."""
    x, y = evals[:, :-1], evals[:, 1:].clone()
    y[(x < 0) | (y < 0)] = -100
    with torch.no_grad():
        return F.cross_entropy(table(x.clamp(min=0)).reshape(-1, v), y.reshape(-1),
                               ignore_index=-100).item()


def train(blocks: torch.Tensor, evals: torch.Tensor, v: int, make_opt, device: str) -> tuple:
    """점수표 [v, v]를 학습하고 (기록된 학습 손실, 평가 손실, 최종 가중치 노름)을 돌려준다."""
    torch.manual_seed(SEED)
    table = torch.nn.Embedding(v, v).to(device)            # 행 = 앞 토큰, 열 = 다음 토큰의 점수
    opt = make_opt(table.parameters())
    g = torch.Generator().manual_seed(SEED)                 # 모든 Optimizer가 같은 묶음 순서
    blocks, evals = blocks.to(device), evals.to(device)
    log = {}
    for step in range(STEPS + 1):
        idx = torch.randint(0, len(blocks), (BATCH,), generator=g)
        x = blocks[idx]
        loss = F.cross_entropy(table(x[:, :-1]).reshape(-1, v), x[:, 1:].reshape(-1))
        if step in CHECKPOINTS:
            log[step] = loss.item()
        if step == STEPS:
            break
        opt.zero_grad()                                      # 제23장: .grad 초기화
        loss.backward()
        opt.step()                                           # 가중치 갱신
    return log, eval_loss(table, evals, v), table.weight.norm().item()


def main() -> None:
    device, _ = select_device()
    tok = load_tokenizer()
    blocks, evals, v = compact(load_blocks(tok, "train"), load_blocks(tok, "eval"))
    print(f"학습 블록 {tuple(blocks.shape)}, 줄인 어휘 {v}개, 점수표 파라미터 {v * v:,}개, "
          f"묶음 {BATCH}, {STEPS}단계\n")

    runs = {
        "SGD lr=0.1": lambda p: torch.optim.SGD(p, lr=0.1),
        "SGD lr=10": lambda p: torch.optim.SGD(p, lr=10),
        "SGD+Momentum lr=10": lambda p: torch.optim.SGD(p, lr=10, momentum=0.9),
        "Adam lr=0.1": lambda p: torch.optim.Adam(p, lr=0.1),
        "AdamW lr=0.1 wd=0.1": lambda p: torch.optim.AdamW(p, lr=0.1, weight_decay=0.1),
    }
    print(f"── 1. 단계별 손실(처음 값 ln {v} = {torch.log(torch.tensor(float(v))).item():.2f} 근처) ──")
    print("  " + f"{'Optimizer':<22}" + "".join(f"{s:>7}" for s in CHECKPOINTS) + "   평가   노름")
    for name, make in runs.items():
        log, ev, norm = train(blocks, evals, v, make, device)
        print("  " + f"{name:<22}" + "".join(f"{log[s]:>7.2f}" for s in CHECKPOINTS)
              + f"{ev:>7.2f}{norm:>7.0f}")
    print("  (0~300: 학습 묶음 손실, 평가: 학습 후 평가 데이터 손실, 노름: 점수표 가중치 L2 노름)")


if __name__ == "__main__":
    main()
```

```bash
python examples/ch24/optim_compare.py
```

**결과 읽기**

- **SGD lr=0.1**은 300단계 동안 손실이 거의 줄지 않았습니다. Bigram 점수표의 Gradient는 한 칸 한 칸이 아주 작아서, 학습률 0.1로는 움직이는 폭이 너무 작습니다.
- **SGD lr=10**으로 100배 키우면 비로소 손실이 내려갑니다. **Momentum**을 더하면 같은 학습률에서 훨씬 빨리 내려갑니다(2.05). 관성이 일관된 방향을 가속한 결과입니다.
- **Adam**은 학습률 0.1로도 가장 빨리, 가장 낮게(1.74) 내려갑니다. 그러나 평가 손실은 5.83으로 Momentum(4.81)보다 나쁩니다. 학습 데이터를 48번 보며 외운 것입니다. 가중치 노름이 4,181로 가장 큰 것도 외우기의 흔적입니다.
- **AdamW**는 학습 손실(2.18)은 Adam보다 조금 높지만 평가 손실(4.69)이 가장 낮습니다. Weight Decay가 가중치를 2,677로 억제해 덜 외우고 더 일반적인 규칙을 배웠습니다. LLM 학습이 AdamW를 기본으로 쓰는 이유입니다.
- 0단계의 손실 6.99가 ln 718 = 6.58보다 조금 큰 것은, 점수표를 표준정규분포로 초기화해 처음부터 점수가 고르지 않기 때문입니다.

### 실습 2. Optimizer 상태 메모리

Qwen2-Tiny를 세 Optimizer로 한 단계씩 학습한 뒤, Optimizer가 실제로 저장한 상태 텐서의 크기를 잽니다. 그리고 FP32 Full Fine-tuning의 고정 메모리를 두 모델에 대해 계산합니다.

파일명: `examples/ch24/optim_memory.py`

```python
# 제24장 실습 2: Optimizer 상태 메모리를 계산하고 Qwen2-Tiny에서 실제 텐서 크기로 확인한다
#
# 실행: python examples/ch24/optim_memory.py

import math
import sys
from pathlib import Path

HERE = Path(__file__).resolve().parent
for p in (HERE.parent, HERE.parent / "ch19"):
    sys.path.insert(0, str(p))

import torch  # noqa: E402

from tiny_model import Qwen2Tiny, init_weights  # noqa: E402  (제19장)

MiB = 2 ** 20
STATE_BYTES = {"SGD": 0, "SGD+Momentum": 4, "AdamW": 8}     # FP32 기준 파라미터당 추가 바이트


def state_bytes(opt) -> int:
    return sum(v.numel() * v.element_size() for s in opt.state.values()
               for v in s.values() if torch.is_tensor(v) and v.dim() > 0)


def full_ft_budget(n_params: int, opt: str) -> dict:
    """FP32 Full Fine-tuning의 고정 메모리(활성값 제외): 가중치 + Gradient + Optimizer 상태"""
    return {"가중치": 4 * n_params, "Gradient": 4 * n_params, "상태": STATE_BYTES[opt] * n_params}


def warmup_cosine(step: int, warmup: int, total: int) -> float:
    """학습률 배율: 처음 warmup단계는 0→1로 올리고, 이후 코사인으로 0까지 내린다(제25장에서 사용)."""
    if step < warmup:
        return (step + 1) / warmup
    return 0.5 * (1 + math.cos(math.pi * (step - warmup) / max(1, total - warmup)))


def main() -> None:
    model = init_weights(Qwen2Tiny(), seed=0)
    n = sum(p.numel() for p in model.parameters())
    ids = torch.tensor([[9707, 11, 1879, 0, 1234, 42, 7, 7]])

    print(f"── 1. Qwen2-Tiny({n:,}개)에서 한 단계 학습 후 Optimizer 상태 측정 ──")
    for name, make in (("SGD", lambda p: torch.optim.SGD(p, lr=0.01)),
                       ("SGD+Momentum", lambda p: torch.optim.SGD(p, lr=0.01, momentum=0.9)),
                       ("AdamW", lambda p: torch.optim.AdamW(p, lr=1e-3))):
        opt = make(model.parameters())
        logits = model(ids)
        loss = torch.nn.functional.cross_entropy(logits[0, :-1], ids[0, 1:])
        opt.zero_grad()
        loss.backward()
        opt.step()
        got = state_bytes(opt)
        print(f"  {name:<13}측정 {got / MiB:7.1f}MiB  계산 {STATE_BYTES[name] * n / MiB:7.1f}MiB "
              f"(파라미터당 {got / n:.0f}바이트)")

    print("\n── 2. FP32 Full Fine-tuning 고정 메모리(활성값 제외) ──")
    for label, count in (("Qwen2-Tiny", n), ("Qwen2.5-0.5B", 494_032_768)):
        b = full_ft_budget(count, "AdamW")
        total = sum(b.values())
        parts = ", ".join(f"{k} {v / MiB:,.0f}" for k, v in b.items())
        print(f"  {label:<13}{parts} → 합계 {total / MiB:,.0f}MiB ({total / 2**30:.2f}GiB)")
    print("  GT 1030 VRAM 2GiB, 0.5B 모델은 Full Fine-tuning 불가 → 제26장부터 LoRA")

    print("\n── 3. Warmup + Cosine 학습률 배율(총 100단계, Warmup 10) ──")
    steps = (0, 4, 9, 10, 30, 55, 80, 99)
    print("  " + "  ".join(f"{s}:{warmup_cosine(s, 10, 100):.2f}" for s in steps))


if __name__ == "__main__":
    main()
```

## 핵심 정리

- 경사하강법은 Gradient의 반대 방향으로 학습률만큼 이동합니다. 작은 묶음으로 이를 반복하는 것이 SGD입니다.
- Momentum은 이동 방향의 평균을, Adam은 여기에 Gradient 크기의 평균까지 기억해 가중치마다 이동 폭을 맞춥니다. AdamW는 Weight Decay를 따로 적용해 과적합을 줄입니다.
- 학습 손실만 보면 외운 것과 배운 것을 구별할 수 없습니다. 평가 손실을 함께 봅니다.
- AdamW는 가중치당 8바이트의 상태를 저장합니다. FP32 Full Fine-tuning은 가중치당 16바이트가 필요해, 0.5B 모델은 7.4GiB로 GT 1030에 들어가지 않습니다.
- Scheduler는 학습률을 단계마다 바꾸고, Accumulation은 작은 묶음으로 큰 묶음의 효과를 내며, Clipping은 큰 Gradient를 제한합니다.
