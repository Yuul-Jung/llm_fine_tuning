## 장 개요

제13·14장의 Attention은 헤드가 하나였습니다. 896차원 벡터 전체로 점수를 한 번 계산하면, 토큰 쌍마다 "닮은 정도"가 하나만 나옵니다. 하지만 언어의 관계는 하나가 아닙니다. 어떤 단어는 문법적으로, 어떤 단어는 의미적으로, 어떤 단어는 가까운 위치라서 중요합니다.

Multi-Head Attention은 벡터를 여러 조각(헤드)으로 나눠, 조각마다 따로 Attention을 계산합니다. 그리고 Qwen2.5는 여기서 한 걸음 더 나아가, Key·Value 헤드를 Query보다 적게 두는 **GQA**(Grouped Query Attention)를 씁니다. 이 장은 MHA·GQA·MQA를 하나의 함수로 구현하고, 지금까지 만든 부품을 조립해 실제 Qwen2.5-0.5B 0번 계층의 Attention 출력을 그대로 재현합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 왜 여러 헤드로 나누며, Key·Value 헤드를 줄이면 무엇을 얻는가 |
| 실습 결과물 | MHA·GQA·MQA 비교, KV 메모리 계산, 실제 모델 Attention 출력 재현 |
| 실습 파일 | `examples/ch15/`의 `mha_gqa.py`, `qwen_rebuild.py`, `test_ch15.py` |
| 선수 장 | 제03장(헤드 분할), 제12장(Q·K·V), 제14장(Causal Attention) |

```text
Q [batch, seq, 896] ──split──▶ [batch, 14, seq, 64] ─┐
K [batch, seq, 128] ──split──▶ [batch,  2, seq, 64] ─┼─ repeat_kv(×7) ─▶ 헤드 14개 각각 Causal Attention
V [batch, seq, 128] ──split──▶ [batch,  2, seq, 64] ─┘                         │
                                                       merge ◀────────────────────┘
                                          [batch, seq, 896] ──o_proj──▶ 출력
```

## 여러 헤드가 필요한 이유

헤드가 하나면 토큰 `i`가 토큰 `j`를 볼 때 기준이 하나뿐입니다. "고양이가 쥐를 쫓는다"에서 "쫓는다"는 주어 "고양이"와 목적어 "쥐"를 서로 다른 이유로 참고해야 하지만, 점수가 하나라면 두 관계를 한꺼번에 섞어 버립니다.

Multi-Head Attention은 hidden 벡터를 여러 조각으로 나눠, 조각마다 **독립된 Attention**을 계산하게 합니다. 각 헤드는 자기 몫의 Q·K·V로 자기만의 점수 행렬을 만들므로, 서로 다른 관계에 주목할 수 있습니다.

| 구분 | 헤드 1개 | 헤드 14개(Qwen2.5-0.5B) |
|---|---|---|
| 헤드당 차원 | 896 | 64 |
| 점수 행렬 | `[seq, seq]` 1개 | `[seq, seq]` 14개 |
| 계산량 | 같다 | 같다(조각을 나눴을 뿐) |
| 볼 수 있는 관계 | 한 가지 | 헤드마다 다른 관계 |

헤드를 나눠도 전체 계산량은 거의 같습니다. 896차원 내적 한 번이 64차원 내적 14번으로 바뀔 뿐입니다. 같은 비용으로 여러 관점을 얻는 셈입니다. 헤드마다 실제로 어떤 관계를 배우는지는 학습이 정하며, 사람이 미리 지정하지 않습니다.

## 헤드 분할과 결합

헤드로 나누고 다시 합치는 연산은 제03장에서 이미 만들었습니다.

```text
split_heads:  [batch, seq, 896] → view → [batch, seq, 14, 64] → transpose → [batch, 14, seq, 64]
Attention:    헤드 축을 묶음처럼 취급해 [seq, 64] 행렬끼리 계산(제13장의 마지막 두 축 원칙)
merge_heads:  [batch, 14, seq, 64] → transpose → [batch, seq, 14, 64] → reshape → [batch, seq, 896]
o_proj:       [batch, seq, 896] × [896, 896]ᵀ → [batch, seq, 896]
```

제13·14장에서 Attention 함수를 "마지막 두 축만 다루도록" 구현해 둔 덕분에, 헤드 축이 앞에 붙어도 코드를 고칠 필요가 없습니다. 헤드 14개가 Batch 행렬곱(제04장)으로 한 번에 계산됩니다.

헤드별 결과를 합친 뒤에는 `o_proj`(Output Projection)를 한 번 거칩니다. 헤드마다 따로 모은 정보를 다시 섞어 하나의 896차원 표현으로 만드는 단계입니다. 제11장에서 본 대로 `o_proj`에는 Bias가 없습니다.

## MQA와 GQA

Attention에서 Key와 Value는 특별한 비용이 있습니다. 생성할 때 이미 계산한 토큰들의 Key·Value를 저장해 두고 재사용하는데(KV Cache, 제20장), 이 저장량이 문맥 길이에 비례해 커집니다. 제14장에서 확인한 "미래가 과거에 영향을 주지 않는다"는 성질 덕분에 재사용이 가능하지만, 메모리는 피할 수 없습니다.

그래서 Key·Value 헤드 수를 줄이는 방법이 등장했습니다.

| 구조 | Query 헤드 | KV 헤드 | 특징 |
|---|---|---|---|
| MHA(Multi-Head) | 14 | 14 | Query 헤드마다 자기 KV |
| GQA(Grouped Query) | 14 | 2 | Query 헤드 7개가 KV 하나를 공유 |
| MQA(Multi-Query) | 14 | 1 | 모든 Query 헤드가 KV 하나를 공유 |

MQA는 메모리를 가장 많이 아끼지만 품질이 떨어질 수 있고, MHA는 품질은 좋지만 메모리를 많이 씁니다. GQA는 그 사이에서 균형을 잡습니다. Qwen2.5-0.5B는 Query 14 : KV 2, 즉 7:1의 GQA입니다.

핵심 실습 3번에서 계산하듯, Qwen2.5-0.5B 크기에서 GQA의 KV Cache는 MHA의 1/7입니다. 토큰 하나, 계층 하나에 FP16 기준 512바이트이며, 24개 계층을 합치면 토큰당 12KiB입니다. 이 값은 제20장과 제58장에서 문맥 길이별 메모리를 계산하는 기준이 됩니다.

## MHA·GQA 구현

GQA를 계산하는 방법은 간단합니다. 적은 수의 KV 헤드를 **복제해** Query 헤드 수에 맞춘 뒤, MHA와 똑같이 계산합니다.

```text
KV 헤드 2개:      [kv0, kv1]
repeat_kv(×7):   [kv0, kv0, kv0, kv0, kv0, kv0, kv0, kv1, kv1, kv1, kv1, kv1, kv1, kv1]
Query 헤드 14개:  [q0,  q1,  q2,  q3,  q4,  q5,  q6,  q7,  q8,  q9,  q10, q11, q12, q13]
                  └──── Query 헤드 0~6은 kv0 ────┘  └──── Query 헤드 7~13은 kv1 ────┘
```

복제 순서가 중요합니다. `repeat_interleave`는 각 KV 헤드를 **연속으로** 반복해, 앞쪽 Query 헤드 7개가 첫 번째 KV를, 뒤쪽 7개가 두 번째 KV를 쓰게 합니다. 순서를 잘못 맞추면(`[kv0, kv1, kv0, kv1, …]`) 계산은 오류 없이 끝나지만 결과가 실제 모델과 달라집니다. 이런 오류는 실제 모델 출력과 비교해야만 잡을 수 있습니다.

이 장의 `grouped_attention()` 하나가 KV 헤드 수만 바꾸면 MHA·GQA·MQA를 모두 계산합니다. KV 헤드 수가 Query 헤드 수와 같으면 복제 배수가 1이 되어 그대로 MHA입니다.

## 핵심 실습

### 실습 1. MHA·GQA·MQA 비교

파일명: `examples/ch15/mha_gqa.py`

```python
# 제15장 실습 1: Multi-Head Attention, GQA, MQA를 같은 함수로 구현하고 비교
#
# 실행: python examples/ch15/mha_gqa.py

import sys
from pathlib import Path

ROOT = Path(__file__).resolve().parents[1]
sys.path.insert(0, str(ROOT / "ch03"))
sys.path.insert(0, str(ROOT / "ch14"))

import torch  # noqa: E402
import torch.nn.functional as F  # noqa: E402

from causal_attention import causal_attention  # noqa: E402  (제14장)
from head_split import merge_heads, split_heads  # noqa: E402  (제03장)


def repeat_kv(x: torch.Tensor, n_rep: int) -> torch.Tensor:
    """[batch, kv_heads, seq, d] → [batch, kv_heads × n_rep, seq, d]
    KV 헤드 하나를 연속된 Query 헤드 n_rep개가 함께 쓰도록 복제한다."""
    return x.repeat_interleave(n_rep, dim=1)


def grouped_attention(q, k, v, n_heads: int, n_kv: int, rope=None):
    """q: [batch, seq, n_heads×d], k·v: [batch, seq, n_kv×d] → [batch, seq, n_heads×d]"""
    q, k, v = split_heads(q, n_heads), split_heads(k, n_kv), split_heads(v, n_kv)
    if rope is not None:
        q, k = rope(q, k)                          # 위치 회전(제16장)
    k, v = repeat_kv(k, n_heads // n_kv), repeat_kv(v, n_heads // n_kv)
    out, _ = causal_attention(q, k, v)             # 헤드마다 독립 계산
    return merge_heads(out)


def kv_numbers(hidden: int, n_heads: int, n_kv: int, bytes_per: int = 2) -> tuple:
    """K·V Projection 파라미터 수(편향 제외)와 토큰·계층당 KV Cache 크기(FP16, 바이트)."""
    head_dim = hidden // n_heads
    params = 2 * hidden * n_kv * head_dim
    cache = 2 * n_kv * head_dim * bytes_per
    return params, cache


def main() -> None:
    torch.manual_seed(0)
    batch, seq, hidden, n_heads = 1, 6, 16, 4
    x = torch.randn(batch, seq, hidden)
    wq = torch.randn(hidden, hidden)

    print("── 1. 같은 입력, KV 헤드 수만 다르게 ──")
    results = {}
    for name, n_kv in (("MHA", 4), ("GQA", 2), ("MQA", 1)):
        kv_dim = n_kv * hidden // n_heads
        wk, wv = torch.randn(kv_dim, hidden), torch.randn(kv_dim, hidden)
        q, k, v = x @ wq.T, x @ wk.T, x @ wv.T
        out = grouped_attention(q, k, v, n_heads, n_kv)
        ref = F.scaled_dot_product_attention(
            split_heads(q, n_heads), split_heads(k, n_kv), split_heads(v, n_kv),
            is_causal=True, enable_gqa=True)
        error = (out - merge_heads(ref)).abs().max().item()
        results[name] = (k.shape[-1], out.shape)
        print(f"{name}: Query 헤드 {n_heads}, KV 헤드 {n_kv} → K {tuple(k.shape)}, "
              f"출력 {tuple(out.shape)}, PyTorch와 차이 {error:.1e}")

    print("\n── 2. repeat_kv: KV 헤드 2개 → Query 헤드 4개용 ──")
    kv = torch.arange(2).float().view(1, 2, 1, 1).expand(1, 2, 3, 1)   # 헤드 번호를 값으로
    print("복제 전 헤드 번호:", kv[0, :, 0, 0].tolist())
    print("복제 후 헤드 번호:", repeat_kv(kv, 2)[0, :, 0, 0].tolist())

    print("\n── 3. Qwen2.5-0.5B 크기의 K·V 비교(계층 1개, FP16 KV Cache) ──")
    print(f"{'구조':<6}{'KV 헤드':>8}{'K·V 가중치 수':>16}{'토큰당 KV Cache':>18}")
    for name, n_kv in (("MHA", 14), ("GQA", 2), ("MQA", 1)):
        params, cache = kv_numbers(896, 14, n_kv)
        print(f"{name:<6}{n_kv:>8}{params:>16,}{cache:>15,} B")


if __name__ == "__main__":
    main()
```

**핵심 코드 풀이**

- `grouped_attention()`은 지금까지의 부품을 순서대로 부릅니다. 제03장의 `split_heads`로 나누고, (있으면) 위치 회전을 적용하고, `repeat_kv`로 KV를 맞추고, 제14장의 `causal_attention`으로 계산한 뒤, `merge_heads`로 합칩니다.
- 1번에서 KV 헤드 수가 4·2·1로 줄면 K의 크기가 16·8·4로 줄지만, 출력 모양은 모두 `(1, 6, 16)`으로 같습니다. 세 구조 모두 PyTorch 공식 Attention 함수(GQA 옵션 `enable_gqa` 사용)와 반올림 수준으로 일치합니다.
- 2번은 `repeat_kv`의 순서를 확인합니다. KV 헤드 번호 `[0, 1]`이 `[0, 0, 1, 1]`로, 각 헤드가 연속으로 복제됩니다.
- 3번은 Qwen2.5-0.5B 크기에서의 차이입니다. GQA의 K·V 가중치는 MHA의 1/7(229,376 대 1,605,632)이고, 토큰당 KV Cache도 1/7(512바이트 대 3,584바이트)입니다.

### 실습 2. 실제 모델 Attention 출력 재현

이 장의 진짜 목표입니다. 제03·12·14장과 이 장에서 직접 만든 부품으로 0번 계층의 Self-Attention 전체를 조립하고, 모델 내부에서 Hook으로 꺼낸 실제 출력과 비교합니다. 위치 회전(RoPE)만은 제16장에서 직접 구현하므로 이번에는 Transformers의 함수를 빌립니다.

파일명: `examples/ch15/qwen_rebuild.py`

```python
# 제15장 핵심 실습: 직접 만든 부품으로 Qwen2.5-0.5B 0번 계층 Self-Attention 출력을 재현
#
# 실행: python examples/ch15/qwen_rebuild.py
#
# 사용 부품: split_heads·merge_heads(제03장), causal_attention(제14장), repeat_kv(이 장)
# 위치 회전(RoPE)은 제16장에서 직접 구현하므로, 이 장에서는 Transformers의 함수를 빌려 쓴다.

import sys
from pathlib import Path

ROOT = Path(__file__).resolve().parents[1]
sys.path.insert(0, str(ROOT))
sys.path.insert(0, str(Path(__file__).resolve().parent))

import torch  # noqa: E402
from transformers.models.qwen2.modeling_qwen2 import apply_rotary_pos_emb  # noqa: E402

from common.qwen import load_model, load_tokenizer  # noqa: E402
from mha_gqa import grouped_attention  # noqa: E402

TEXT = "언어 모델은 다음 토큰을 예측한다."


def capture_layer0(model, ids) -> dict:
    """0번 계층 RMSNorm 출력(Attention 입력)과 self_attn 출력을 Hook으로 붙잡는다."""
    layer, cap = model.model.layers[0], {}
    h1 = layer.input_layernorm.register_forward_hook(
        lambda mod, inp, out: cap.__setitem__("x", out.detach()))
    h2 = layer.self_attn.register_forward_hook(
        lambda mod, inp, out: cap.__setitem__("attn", out[0].detach()))
    with torch.no_grad():
        model(ids)
    h1.remove()
    h2.remove()
    return cap


def rebuild_attention(model, x: torch.Tensor) -> torch.Tensor:
    """q·k·v_proj → 헤드 분할 → RoPE → GQA Causal Attention → 헤드 결합 → o_proj"""
    attn = model.model.layers[0].self_attn
    positions = torch.arange(x.shape[1])[None]
    cos, sin = model.model.rotary_emb(x, positions)

    def rope(q, k):
        return apply_rotary_pos_emb(q, k, cos, sin)

    with torch.no_grad():
        q, k, v = attn.q_proj(x), attn.k_proj(x), attn.v_proj(x)
        merged = grouped_attention(q, k, v, n_heads=14, n_kv=2, rope=rope)
        return attn.o_proj(merged)


def main() -> None:
    model, tok = load_model(), load_tokenizer()
    ids = tok(TEXT, return_tensors="pt").input_ids
    cap = capture_layer0(model, ids)

    mine = rebuild_attention(model, cap["x"])
    print(f"입력(RMSNorm 출력) {tuple(cap['x'].shape)}")
    print(f"직접 조립한 Attention 출력 {tuple(mine.shape)}")
    print(f"모델 내부 Attention 출력   {tuple(cap['attn'].shape)}")
    print(f"최대 절대오차: {(mine - cap['attn']).abs().max().item():.1e}")


if __name__ == "__main__":
    main()
```

```bash
python examples/ch15/qwen_rebuild.py
```

```text

직접 조립한 Attention 출력 (1, 16, 896)
모델 내부 Attention 출력   (1, 16, 896)
최대 절대오차: 3.0e-08
```

**핵심 코드 풀이**

- `capture_layer0()`은 제12장의 방식대로 Hook 두 개를 걸어, Attention에 들어간 입력(RMSNorm 출력)과 Attention이 내놓은 출력을 붙잡습니다. `self_attn`은 출력과 Attention 가중치를 묶어 돌려주므로 첫 번째 값(`out[0]`)만 씁니다.
- `rebuild_attention()`은 장 개요의 그림 그대로입니다. q·k·v_proj로 Q·K·V를 만들고, `grouped_attention()`에 헤드 14개, KV 헤드 2개, 그리고 위치 회전 함수를 넘긴 뒤, `o_proj`를 적용합니다.
- `model.model.rotary_emb(x, positions)`는 위치마다 회전 각도의 `cos`·`sin` 값을 만들고, `apply_rotary_pos_emb`가 Q·K를 회전시킵니다. 이 두 줄이 제16장에서 직접 구현할 부분입니다.
- 최대 절대오차 `3.0e-08`은 사실상 0입니다. 헤드 분할, GQA 복제 순서, Causal Mask, `√dₖ` 나누기, 헤드 결합까지 모든 부품이 실제 모델과 정확히 같게 동작한다는 증거입니다. 이 중 하나만 어긋나도 오차는 눈에 띄게 커집니다.

## 핵심 정리

- Multi-Head Attention은 hidden을 여러 헤드로 나눠 헤드마다 독립된 Attention을 계산합니다. 계산량은 같고 볼 수 있는 관계는 늘어납니다.
- 헤드별 결과는 합친 뒤 `o_proj`로 다시 섞습니다.
- GQA는 Query 헤드 여러 개가 Key·Value 헤드 하나를 공유합니다. Qwen2.5-0.5B는 14:2(7:1)이며, KV Cache가 MHA의 1/7입니다.
- GQA는 KV 헤드를 연속으로 복제(`repeat_interleave`)한 뒤 MHA와 같이 계산합니다. 복제 순서가 틀리면 오류 없이 다른 결과가 나옵니다.
- 직접 만든 부품으로 실제 모델 0번 계층의 Attention 출력을 오차 3×10⁻⁸로 재현했습니다.

**다음 장 연결:** 이번 재현에서 위치 회전만은 라이브러리를 빌렸습니다. 제16장에서는 그 마지막 부품, 토큰의 위치를 Query·Key의 회전으로 알려 주는 RoPE를 직접 구현해, 빌린 함수를 우리 코드로 바꿉니다.
