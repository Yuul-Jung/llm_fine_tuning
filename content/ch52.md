## 장 개요

제51장의 Adapter는 원본 모델 없이는 쓸 수 없습니다. 추론할 때마다 원본을 불러와 Adapter를 붙여야 하고, 층마다 원본 계산과 LoRA 계산을 따로 해야 합니다. **병합(Merge)** 은 LoRA가 더하는 변화량을 원본 가중치에 미리 더해, Adapter가 없는 하나의 독립 모델로 만드는 일입니다. 병합한 모델은 원본과 구조가 같으므로 다음 장들의 변환·배포 도구가 그대로 다룰 수 있습니다.

이 장은 병합 수식을 직접 계산해 라이브러리 결과와 맞춰 보고, 병합 전후의 Logits로 순수 병합 오차를 잽니다. 그리고 4비트 원본으로 학습한 QLoRA Adapter를 병합할 때의 함정을 세 모델(A·B·C)로 나누어 확인한 뒤, 배포용 Adapter를 CPU에서 FP32로 병합해 저장합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 병합은 출력을 바꾸지 않는가, QLoRA Adapter를 병합하면 무엇이 달라지는가 |
| 실습 결과물 | 수식과 라이브러리 병합 비교, 병합 전후 Logits 차이, A·B·C 세 모델의 PPL과 Logits 비교, 병합 모델(1.9GB) |
| 실습 파일 | `examples/ch52/`의 `merge.py`, `test_ch52.py`, `merge.json` |
| 선수 장 | 제28·29장(LoRA 수식), 제49장(QLoRA), 제51장(배포용 Adapter) |

```text
병합:  W' = W + (α / r) · B · A        (층마다 한 번 계산, 이후 LoRA 계산 없음)
A: 4비트 원본 + Adapter(학습 때와 같은 조건)
B: FP32 원본 + 같은 Adapter         A↔B 차이 = 원본 정밀도의 차이
C: B를 병합한 독립 모델             B↔C 차이 = 순수 병합 오차
```

## 병합 수식과 merge_and_unload

LoRA 층의 출력은 원본 출력에 저랭크 변화량을 더한 것입니다(제28장).

```text
y = W x + (α / r) · B (A x) = (W + (α / r) · B A) x = W' x
```

행렬 곱의 결합 법칙에 따라 B·A를 먼저 곱해 W에 더하면, 같은 출력을 내는 가중치 W'가 나옵니다. PEFT의 `merge_and_unload()`는 대상 모듈마다 이 계산을 하고 LoRA 층을 걷어 내, 원래 모델 클래스(Qwen2ForCausalLM)를 돌려줍니다. 병합한 모델은 파라미터 수가 원본과 같고, 추론 속도도 원본과 같습니다.

| 형태 | 장점 | 단점 |
|---|---|---|
| Adapter로 유지 | 파일이 작고(수십 MiB), 원본 하나에 여러 Adapter를 바꿔 끼운다 | 추론 때 원본과 Adapter를 함께 불러야 한다 |
| 병합한 모델 | 독립 모델이라 일반 도구로 변환·배포한다 | 원본 크기의 파일이 하나 더 생긴다 |

## Qwen2-Tiny 병합

수학적으로 같은 계산이지만 실제 결과는 아주 조금 다를 수 있습니다. 병합 전에는 W x와 B(A x)를 따로 계산해 더하고, 병합 후에는 W'x 하나를 계산합니다. 부동소수점 덧셈은 순서에 따라 마지막 자리가 달라지므로 Logits에 1e-6~1e-4 정도의 차이가 생깁니다. 이것이 **순수 병합 오차**이며, 이보다 큰 차이가 나면 병합이 잘못된 것입니다.

작은 Qwen2-Tiny(제30장의 자전거 정비 Adapter)로 먼저 확인합니다. 가중치 수준에서는 직접 계산한 W'와 라이브러리 결과가 정확히 같아야 하고, Logits 수준에서는 위의 작은 오차만 있어야 합니다.

## QLoRA Adapter 병합

QLoRA Adapter는 **4비트로 양자화한 원본** 위에서 학습되었습니다. 이 Adapter를 FP32 원본에 병합하면, 학습 때와 다른 원본에 붙이는 셈이 됩니다. 원인을 나누려면 세 모델을 비교합니다.

| 비교 | 차이의 원인 | 기대 |
|---|---|---|
| A ↔ B | 원본이 4비트인가 FP32인가 | 클 수 있다 |
| B ↔ C | 병합 계산 자체 | 순수 병합 오차 수준 |

병합 결과(C)는 B와 같아야 합니다. 따라서 "병합했더니 품질이 달라졌다"면 원인은 병합이 아니라 A와 B의 차이, 곧 원본 정밀도입니다. 4비트 원본에 병합하는 방법도 있지만, 4비트 가중치에 변화량을 더하면 다시 양자화해야 해서 오차가 한 번 더 생깁니다. 이 교재는 FP32 원본에 병합해 독립 모델을 만들고, A↔B 차이는 따로 기록합니다.

## CPU에서 병합

0.5B 모델의 병합은 FP32 원본 전체(약 1.9GB)를 메모리에 올려야 하므로 GT 1030의 2GB VRAM으로는 할 수 없습니다. 병합은 학습과 달리 한 번만 하는 계산이고 시간도 짧으므로, **CPU에서 FP32로** 합니다. 시스템 메모리는 원본, Adapter, 병합 과정의 임시 텐서를 담을 만큼 필요하며, 이 실습은 메모리 8GB의 교재 검증 환경에서 실행했습니다.

병합한 모델은 토크나이저와 함께 저장해, 다음 장부터 원본 대신 독립 모델로 씁니다. 병합 전후의 PPL과 Logits를 비교해 병합이 출력을 바꾸지 않았음을 확인한 뒤에 저장합니다.

## 핵심 실습

파일명: `examples/ch52/merge.py`

```python
# 제52장 핵심 실습: LoRA를 원본에 병합하고, 세 모델 A·B·C의 Logits와 PPL로 차이의 원인을 나눈다
#
# 실행: python examples/ch52/merge.py   (CPU 약 3분, 교재 검증 환경은 메모리 8GB)
#
# 만드는 파일: models/fpga_merged_v1/(병합한 독립 모델, 약 2GB), examples/ch52/merge.json

import json
import math
import sys
import time
from pathlib import Path

HERE = Path(__file__).resolve().parent
ROOT = HERE.parents[1]
for p in (HERE.parent, HERE.parent / "ch37", HERE.parent / "ch46", HERE.parent / "ch51"):
    sys.path.insert(0, str(p))

import torch  # noqa: E402
from peft import PeftModel  # noqa: E402
from transformers import AutoModelForCausalLM, AutoTokenizer  # noqa: E402
from transformers.utils import logging  # noqa: E402

from common.device import select_device  # noqa: E402
from common.models import QWEN_ID, QWEN_REVISION  # noqa: E402
from load_4bit import load_nf4  # noqa: E402                     (제37장)
from save_load import FINAL, load_base, logits_of  # noqa: E402   (제51장)
from sft_loop import SFTDataset, split_rows, validate  # noqa: E402   (제46장)

logging.disable_progress_bar()
TINY = ROOT / "models" / "qwen2-tiny-pretrained"
TINY_LORA = ROOT / "models" / "qwen2-tiny-bike-lora"           # 제30장
QLORA = ROOT / "models" / "ch49_qlora"                          # 제49장
MERGED = ROOT / "models" / "fpga_merged_v1"
OUT = HERE / "merge.json"


def merge_by_hand(layer) -> torch.Tensor:
    """W' = W + (alpha / r) B A"""
    a, b = layer.lora_A["default"].weight, layer.lora_B["default"].weight
    return layer.base_layer.weight + layer.scaling["default"] * (b @ a)


def diff(x: torch.Tensor, y: torch.Tensor) -> float:
    return (x - y).abs().max().item()


def ppl(model, va) -> float:
    return validate(model, va)["val_ppl"]


def main() -> None:
    device, _ = select_device()
    rec = {}

    print("── 1. 병합 수식(Qwen2-Tiny 제30장 Adapter, 0층 q_proj) ──")
    tok_t = AutoTokenizer.from_pretrained(TINY)
    tiny = PeftModel.from_pretrained(AutoModelForCausalLM.from_pretrained(TINY, dtype=torch.float32),
                                     TINY_LORA).to(device).eval()
    layer = tiny.base_model.model.model.layers[0].self_attn.q_proj
    by_hand = merge_by_hand(layer).detach().clone()
    print(f"  r {layer.r['default']}, alpha {layer.lora_alpha['default']}, "
          f"scaling = alpha / r = {layer.scaling['default']}")
    before = logits_of(tiny, tok_t, device)

    print("\n── 2. Qwen2-Tiny 병합 전후 ──")
    merged_tiny = tiny.merge_and_unload()
    w = merged_tiny.model.layers[0].self_attn.q_proj.weight
    after = logits_of(merged_tiny, tok_t, device)
    print(f"  병합 후 모델 종류: {type(merged_tiny).__name__}(LoRA 층 없음: "
          f"{not any('lora' in n for n, _ in merged_tiny.named_modules())})")
    print(f"  merge_and_unload 가중치와 수식 계산의 최대 차이 {diff(w, by_hand):.2e}")
    print(f"  병합 전후 Logits 최대 차이 {diff(before, after):.2e}(순수 병합 오차)")
    rec["tiny"] = {"weight_diff": diff(w, by_hand), "logits_diff": diff(before, after)}
    del tiny, merged_tiny

    print("\n── 3. QLoRA Adapter(제49장): 세 모델로 차이의 원인 나누기 ──")
    tok = AutoTokenizer.from_pretrained(QWEN_ID, revision=QWEN_REVISION)
    va = SFTDataset(tok, split_rows("validation"))
    b = PeftModel.from_pretrained(load_base(device), QLORA).eval()      # B: FP32 원본 + Adapter
    lb, pb = logits_of(b, tok, device), ppl(b, va)
    c = b.merge_and_unload()                                            # C: B를 병합한 독립 모델
    lc, pc = logits_of(c, tok, device), ppl(c, va)
    del b, c
    a = PeftModel.from_pretrained(load_nf4(device), QLORA).eval()      # A: 학습 때와 같은 4비트 원본 + Adapter
    la, pa = logits_of(a, tok, device), ppl(a, va)
    del a
    print("  모델                     도메인 PPL   Logits 최대 차이")
    print(f"  A 4비트 원본 + Adapter    {pa:>9.2f}   A↔B {diff(la, lb):.2f}(원본 정밀도 차이)")
    print(f"  B FP32 원본 + Adapter     {pb:>9.2f}   B↔C {diff(lb, lc):.2e}(순수 병합 오차)")
    print(f"  C B를 병합한 모델          {pc:>9.2f}")
    rec["qlora"] = {"ppl": {"A": pa, "B": pb, "C": pc}, "A_B": diff(la, lb), "B_C": diff(lb, lc)}

    print("\n── 4. CPU에서 FP32 병합(제51장 배포용 Adapter) ──")
    t0 = time.time()
    m = PeftModel.from_pretrained(load_base("cpu"), FINAL).eval()       # 원본 2GB + 병합: GT 1030 VRAM 초과
    l0, p0 = logits_of(m, tok, "cpu"), ppl(m, va)
    merged = m.merge_and_unload()
    l1, p1 = logits_of(merged, tok, "cpu"), ppl(merged, va)
    merged.save_pretrained(MERGED)
    tok.save_pretrained(MERGED)
    secs = time.time() - t0
    size = sum(f.stat().st_size for f in MERGED.glob("*.safetensors")) / 2 ** 20
    n_params = sum(p.numel() for p in merged.parameters())
    print(f"  병합 전 PPL {p0:.4f}, 병합 후 PPL {p1:.4f}, Logits 최대 차이 {diff(l0, l1):.2e}")
    print(f"  병합 모델 파라미터 {n_params:,}개(원본과 같음), 저장 {size:.0f}MiB, 걸린 시간 {secs:.0f}초")
    rec["final"] = {"ppl_before": p0, "ppl_after": p1, "logits_diff": diff(l0, l1), "params": n_params,
                    "size_mib": round(size)}
    OUT.write_text(json.dumps(rec, indent=1) + "\n", encoding="utf-8")


if __name__ == "__main__":
    torch.manual_seed(0)
    main()
```

## 검증과 완료 기준

파일명: `examples/ch52/test_ch52.py`

```python
# 제52장 검증 테스트
#
# 실행: python -m pytest examples/ch52 -q

import json
import sys
from pathlib import Path

HERE = Path(__file__).resolve().parent
sys.path.insert(0, str(HERE))

import torch  # noqa: E402

from merge import OUT  # noqa: E402

TOL = 1e-3                                         # 병합 허용 오차(Logits 최대 차이)


def test_merge_formula_on_toy_layer():
    from peft import LoraConfig, get_peft_model
    torch.manual_seed(0)
    net = torch.nn.Sequential(torch.nn.Linear(16, 12))
    peft = get_peft_model(net, LoraConfig(r=4, lora_alpha=8, target_modules=["0"], init_lora_weights=False))
    layer = peft.base_model.model[0]
    expect = layer.base_layer.weight + 2.0 * layer.lora_B["default"].weight @ layer.lora_A["default"].weight
    x = torch.randn(3, 16)
    y = peft(x)
    merged = peft.merge_and_unload()
    assert torch.allclose(merged[0].weight, expect, atol=1e-6) and torch.allclose(merged(x), y, atol=1e-5)


def test_recorded_merge_errors():
    r = json.loads(OUT.read_text())
    assert r["tiny"]["weight_diff"] < 1e-6 and r["tiny"]["logits_diff"] < TOL
    assert r["qlora"]["B_C"] < TOL and r["final"]["logits_diff"] < TOL              # B↔C 허용 오차 이내
    assert abs(r["qlora"]["ppl"]["B"] - r["qlora"]["ppl"]["C"]) < 0.01
    assert r["qlora"]["A_B"] > 100 * r["qlora"]["B_C"]                              # A↔B는 따로 기록할 큰 차이
    assert r["final"]["params"] == 494_032_768
```

| 배포용 병합 | 병합 전후 Logits 차이 1e-3 이내, 파라미터 수가 원본과 같음 | 통과(6.0e-5) |
| A ↔ B | 품질 차이를 따로 기록 | 기록(PPL 14.03 / 13.20) |

이 장의 실습은 `select_device()`로 장치를 고르지만, 0.5B 병합(4번)은 VRAM을 넘으므로 언제나 CPU에서 합니다. 교재 검증 환경은 CPU이며, GT 1030 경로에서는 1·2번(Tiny)과 3번의 A 모델만 GPU에서 실행할 수 있습니다(미검증).

**완료 기준:** 제48장의 FP32 LoRA Adapter로 같은 B↔C 비교를 해 병합 오차가 같은 수준인지 확인하고, 병합 모델을 다시 불러와 같은 입력의 Logits가 저장 전과 같은지 적으며, 테스트 2개를 모두 통과하면 이 장을 마친 것입니다.

## 핵심 정리

- 병합은 W' = W + (α / r)·B·A를 층마다 미리 계산해 LoRA 층을 걷어 내는 것이며, 결과는 원본과 같은 구조의 독립 모델입니다.
- 병합 전후 Logits 차이는 부동소수점 계산 순서에 따른 1e-6~1e-4 수준이어야 하며, 이것이 순수 병합 오차입니다.
- QLoRA Adapter의 품질 차이는 세 모델로 나눕니다. B↔C는 병합, A↔B는 원본 정밀도입니다. 이 장에서 병합은 아무것도 바꾸지 않았고, 차이는 모두 4비트 원본에서 왔습니다.
- 0.5B 병합은 GT 1030 VRAM을 넘으므로 CPU에서 FP32로 하며, 병합 전후 PPL과 Logits를 확인한 뒤 저장합니다.
