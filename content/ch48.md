## 장 개요

제41장부터 제47장까지 도메인 학습의 부품을 하나씩 만들었습니다. 데이터와 분할, 템플릿, Label Masking, 학습 루프, SFTTrainer, 그리고 평가 기준과 기준값입니다. 이 장은 여기에 제29·30장의 LoRA를 더해 **하나의 학습 스크립트로 조립하고, 처음으로 실제 모델을 도메인 데이터로 학습합니다.**

실습은 두 부분입니다. 먼저 작은 Qwen2-Tiny로 LoRA를 붙이는 범위(Target Modules)를 세 가지로 바꿔 차이를 봅니다. 다음으로 Qwen2.5-0.5B-Instruct에 FP32 LoRA를 붙여 CPU에서 학습하고, 제43장 기준으로 판정하며, 같은 Greedy 설정으로 학습 전후의 답을 나란히 읽습니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 지금까지의 부품을 조립한 학습은 기준을 통과하는가, 통과하지 못한다면 무엇이 부족한가 |
| 실습 결과물 | Target Modules 범위별 결과, Qwen2.5 LoRA 학습·검증 곡선, 네 지표 판정, 학습 전후 응답 비교 |
| 실습 파일 | `examples/ch48/`의 `lora_sft.py`, `test_ch48.py`, `scope.json`, `domain.json` |
| 선수 장 | 제29·30장(LoRA, PEFT), 제43장(기준), 제47장(SFTTrainer, 기준값) |

```text
split_v1 → 템플릿·Label Masking(제44·45장) → completion_mask 데이터(제47장)
   → SFTTrainer(SFTConfig FP32, peft_config=LoRA) → Adapter(models/ch48_lora)
   → measure(제47장) → 제43장 기준 판정 + 학습 전후 응답 비교
```

## 부품 결합

조립한 스크립트에서 새로 더한 것은 `peft_config` 인자 하나입니다. SFTTrainer에 LoRA 설정을 넘기면, Trainer가 모델을 받은 뒤 PEFT로 LoRA를 붙이고 원래 가중치는 고정합니다. 나머지는 모두 앞 장에서 만든 것을 그대로 가져옵니다.

| 부품 | 가져온 곳 | 이 장에서 바뀐 점 |
|---|---|---|
| 분할과 샘플 | 제43·45·46장 | 없음 |
| 학습 설정 | 제47장의 설정 묶음 | 학습률만 LoRA에 맞게 |
| LoRA 설정 | 제29·30장 | r 8, alpha 16, Dropout 0 |
| 평가 | 제47장 measure | 없음(학습 전과 같은 함수) |

학습 전후를 **같은 함수, 같은 데이터, 같은 생성 설정**으로 재는 것이 핵심입니다. 측정 경로가 하나라도 다르면 차이가 학습 때문인지 측정 때문인지 가릴 수 없습니다.

## Target Modules 선정

LoRA를 어느 Linear 층에 붙일지가 Target Modules입니다. 범위가 넓을수록 학습 파라미터가 늘고, 모델을 바꿀 수 있는 여지도 커집니다.

| 범위 | 대상 | 특징 |
|---|---|---|
| Attention q·v | Query, Value | LoRA 원 논문의 기본. 가장 가볍다 |
| Attention 전체 | Query, Key, Value, Output | 어떤 정보를 볼지와 무엇을 내보낼지를 함께 바꾼다 |
| 모든 Linear | Attention 4개 + FFN 3개 | 지식이 많이 저장된 FFN까지. QLoRA 논문이 권장 |

제29장의 실험에서 범위를 넓히면 도메인 손실이 더 내려갔습니다. 이 장은 SFT 데이터로 같은 비교를 하고, 0.5B 모델에는 모든 Linear를 씁니다. 새 지식(FPGA 용어와 개념)을 넣는 학습이라 FFN을 포함하는 것이 알맞기 때문입니다.

## 도메인 학습

Qwen2.5-0.5B를 FP32로 불러 LoRA를 붙이고 CPU에서 학습합니다. 모델 전체가 약 2GB라 GT 1030의 VRAM 2GB에는 FP32로 올릴 수 없으므로, 이 장의 0.5B 학습은 CPU 경로입니다. GT 1030에서는 제49장의 4비트(QLoRA) 경로로 학습합니다.

학습률은 2e-4로 정했습니다. 전체 파인튜닝보다 크게, Tiny에 쓴 2e-3보다는 작게 잡은 값입니다. 0.5B 모델은 이미 잘 학습되어 있어 큰 학습률로 크게 움직이면 기존 능력이 무너질 수 있기 때문입니다. 30단계 × 8샘플은 train 38개를 약 6번 도는 양입니다.

## 응답 비교

손실과 지표는 요약일 뿐입니다. 학습이 무엇을 바꾸었는지는 **답을 직접 읽어야** 압니다. 학습 전후의 답을 같은 질문, 같은 Greedy 설정, 같은 최대 길이로 만들어 나란히 놓고, 다음 세 가지를 봅니다.

| 볼 점 | 질문 |
|---|---|
| 형식 | 짧은 존댓말 평서문으로 바뀌었는가 |
| 맥락 | FPGA 맥락으로 답하는가 |
| 사실 | 내용이 맞는가, 그럴듯하지만 틀린 내용을 지어내지 않는가 |

## 핵심 실습

파일명: `examples/ch48/lora_sft.py`

```python
# 제48장 핵심 실습: 분할·템플릿·Label Masking·SFTTrainer·LoRA를 하나의 학습 스크립트로 조립한다
#
# 실행: python examples/ch48/lora_sft.py scope   (Qwen2-Tiny, Target Modules 세 범위 비교, CPU 약 8분)
#       python examples/ch48/lora_sft.py domain  (Qwen2.5-0.5B FP32 LoRA 도메인 학습과 평가, CPU 약 15분)
#
# 만드는 파일: examples/ch48/scope.json, examples/ch48/domain.json, models/ch48_lora/(Adapter)

import json
import sys
import time
from pathlib import Path

HERE = Path(__file__).resolve().parent
ROOT = HERE.parents[1]
for p in (HERE.parent, HERE.parent / "ch46", HERE.parent / "ch47"):
    sys.path.insert(0, str(p))

import torch  # noqa: E402
from peft import LoraConfig  # noqa: E402
from transformers.utils import logging  # noqa: E402

from baseline import measure  # noqa: E402                         (제47장)
from sft_loop import SFTDataset, setup, split_rows, validate  # noqa: E402   (제46장)
from sft_trainer import SAME_AS_CH46, to_hf_dataset  # noqa: E402  (제47장)

logging.disable_progress_bar()
logging.set_verbosity_error()
ADAPTER = ROOT / "models" / "ch48_lora"
SCOPES = {
    "Attention q·v": ["q_proj", "v_proj"],
    "Attention 전체": ["q_proj", "k_proj", "v_proj", "o_proj"],
    "모든 Linear": ["q_proj", "k_proj", "v_proj", "o_proj", "gate_proj", "up_proj", "down_proj"],
}


def lora_config(targets: list, r: int = 8) -> LoraConfig:
    return LoraConfig(r=r, lora_alpha=2 * r, target_modules=targets, lora_dropout=0.0,
                      bias="none", task_type="CAUSAL_LM")


def train_lora(model, tok, tr, va, targets: list, **overrides):
    """SFTTrainer가 peft_config를 받아 LoRA를 붙이고 학습한다. 학습된 PEFT 모델과 기록을 돌려준다."""
    from trl import SFTConfig, SFTTrainer
    torch.manual_seed(0)                                           # LoRA A 초기값 고정
    cfg = {**SAME_AS_CH46, "disable_tqdm": True, **overrides}
    trainer = SFTTrainer(model=model, args=SFTConfig(output_dir="/tmp/ch48_run", use_cpu=True, **cfg),
                         processing_class=tok, peft_config=lora_config(targets),
                         train_dataset=to_hf_dataset(tr), eval_dataset=to_hf_dataset(va))
    trainer.train()
    m = trainer.model
    n_train = sum(p.numel() for p in m.parameters() if p.requires_grad)
    return m, n_train, trainer.state.log_history


def curve(history: list) -> list:
    return [(r["step"], r["eval_loss"]) for r in history if "eval_loss" in r]


def run_scope() -> None:
    print("── Target Modules 범위 비교(Qwen2-Tiny, r 8, lr 2e-3, 30단계) ──")
    results = {}
    for name, targets in SCOPES.items():
        tok, model, tr, va = setup()
        before = validate(model, va)["val_loss"]
        t0 = time.time()
        m, n, hist = train_lora(model, tok, tr, va, targets, learning_rate=2e-3)
        results[name] = {"targets": targets, "trainable": n, "val_before": before,
                         "val_after": validate(m, va)["val_loss"], "curve": curve(hist),
                         "seconds": round(time.time() - t0)}
        r = results[name]
        print(f"  {name:<14}학습 파라미터 {n:>8,}  val {r['val_before']:.3f} → {r['val_after']:.3f}  ({r['seconds']}초)")
    (HERE / "scope.json").write_text(json.dumps(results, ensure_ascii=False, indent=1) + "\n", encoding="utf-8")


def run_domain() -> None:
    from common.qwen import load_model, load_tokenizer
    from criteria import judge, load_criteria
    tok = load_tokenizer()
    base = json.loads((ROOT / "examples/ch47/baseline.json").read_text(encoding="utf-8"))
    torch.manual_seed(0)
    model = load_model()
    tr, va = SFTDataset(tok, split_rows("train")), SFTDataset(tok, split_rows("validation"))
    print("── Qwen2.5-0.5B FP32 LoRA(모든 Linear, r 8, lr 2e-4, 30단계) ──")
    t0 = time.time()
    m, n, hist = train_lora(model, tok, tr, va, SCOPES["모든 Linear"], learning_rate=2e-4)
    secs = round(time.time() - t0)
    print(f"  학습 파라미터 {n:,}개, 학습 {secs}초")
    print("  단계   train   val(샘플 평균)")
    train = {r["step"]: r["loss"] for r in hist if "loss" in r}
    for s, v in curve(hist):
        print(f"  {s:>4}  {train[s]:.3f}   {v:.3f}  " + "█" * int(v * 20))
    m.save_pretrained(ADAPTER)
    m.eval()
    after = measure(tok, m)
    c = load_criteria()
    hits, fmts = list(after["keyword_hit"].values()), list(after["format_ok"].values())
    verdict = judge(c, domain_ratio=after["domain_ppl"] / base["domain_ppl"],
                    general_ratio=after["general_ppl"] / base["general_ppl"], hits=hits, fmts=fmts)
    print("\n── 제43장 기준으로 판정(학습 전 → 학습 후) ──")
    rows = [("도메인 PPL", base["domain_ppl"], after["domain_ppl"], "domain_ppl"),
            ("일반 PPL", base["general_ppl"], after["general_ppl"], "general_ppl"),
            ("핵심어 적중률", sum(base["keyword_hit"].values()) / 6, sum(hits) / len(hits), "keyword_hit"),
            ("형식 준수율", sum(base["format_ok"].values()) / 6, sum(fmts) / len(fmts), "format_ok")]
    for label, b, a, key in rows:
        print(f"  {label:<10}{b:>7.2f} → {a:>6.2f}   {'합격' if verdict[key] else '불합격'}")
    print("\n── 응답 비교(Greedy, 최대 160토큰, 앞부분) ──")
    for i in after["answers"]:
        print(f"  [{i}] 전: {base['answers'][i][:46].replace(chr(10), ' ')}…")
        print(f"  {'':>10}후: {after['answers'][i][:46].replace(chr(10), ' ')}…")
    out = {"trainable": n, "seconds": secs, "curve": curve(hist), "train": train,
           "after": after, "verdict": verdict}
    (HERE / "domain.json").write_text(json.dumps(out, ensure_ascii=False, indent=1) + "\n", encoding="utf-8")


if __name__ == "__main__":
    {"scope": run_scope, "domain": run_domain}[sys.argv[1]]()
```

**결과 읽기**

- **실행 1**에서 범위를 넓힐수록 학습 파라미터가 2.7만 → 5.3만 → 15.2만으로 늘고, 검증 손실도 7.98 → 7.86 → 7.58로 더 내려갑니다. 같은 30단계 동안 제46장의 전체 파인튜닝(6.24)에는 미치지 못합니다. 바꿀 수 있는 파라미터가 전체의 0.4%뿐이기 때문입니다. 학습 시간은 세 범위가 비슷합니다. Tiny에서는 시간 대부분이 큰 Embedding과 출력층 계산에 쓰이기 때문입니다.
- **실행 2**의 학습 파라미터 440만 개는 층마다 r × (입력 + 출력)을 더한 값과 정확히 같습니다(테스트에서 확인). 모델 전체 약 4억 9천만 개의 0.9%입니다.
- 학습 손실은 2.75에서 1.63으로 계속 내려가지만, **검증 손실은 15단계(2.49)에서 가장 낮고 그 뒤로 조금 오릅니다.** train 38개를 여러 번 보면서 외우기 시작했다는 신호(과적합)입니다. 제50장에서 이 지점을 기준으로 Early Stopping을 다룹니다.
- 판정은 네 지표 중 세 개가 합격입니다. 도메인 PPL은 17.64에서 12.55로 29% 내려가 합격선(14.11)을 넘었고, 일반 PPL은 21.45에서 21.89로 2% 오르는 데 그쳤습니다. 형식 준수율은 0.00에서 1.00이 되었습니다. **핵심어 적중률은 0.10에서 0.08로 불합격**입니다.
- 답을 읽으면 이유가 보입니다. 학습 후의 답은 짧은 존댓말 평서문이 되었고 FPGA 단어(신호, 클럭, 핀)를 쓰지만, 내용이 맞지 않습니다. 배치를 "클럭이 들어가는 장치의 위치를 결정하는 도구"로, 임계 경로를 "기준 시간을 초과하면 신호가 중단되는 경로"로 설명하고, fpga-040은 같은 말을 되풀이하며 무너집니다. 모델은 **답의 말투와 분위기를 배웠지만 지식은 배우지 못했습니다.** 38개의 예시는 형식을 가르치기에는 충분하지만 개념을 가르치기에는 부족합니다.
- 이것이 기준을 미리 적어 둔 이유입니다. 도메인 PPL과 형식만 보았다면 "학습 성공"으로 판단했을 것입니다. 핵심어 지표가 그럴듯하게 틀린 답을 잡아냈습니다. 기준 파일은 고치지 않고, 이 결과를 그대로 기록합니다.

## 검증과 완료 기준

파일명: `examples/ch48/test_ch48.py`

```python
# 제48장 검증 테스트
#
# 실행: python -m pytest examples/ch48 -q

import json
from pathlib import Path

HERE = Path(__file__).resolve().parent


def lora_params(c: dict, targets: list, r: int = 8) -> int:
    """LoRA 파라미터 = 층 수 × Σ r × (입력 + 출력)"""
    h, kv, i = c["hidden_size"], c["num_key_value_heads"] * (c["hidden_size"] // c["num_attention_heads"]), \
        c["intermediate_size"]
    shape = {"q_proj": (h, h), "k_proj": (h, kv), "v_proj": (h, kv), "o_proj": (h, h),
             "gate_proj": (h, i), "up_proj": (h, i), "down_proj": (i, h)}
    return c["num_hidden_layers"] * sum(r * sum(shape[t]) for t in targets)


def test_scope_results():
    s = json.loads((HERE / "scope.json").read_text(encoding="utf-8"))
    n = [v["trainable"] for v in s.values()]
    assert n == sorted(n) and len(set(n)) == 3                       # 범위가 넓을수록 파라미터가 많다
    assert all(v["val_after"] < v["val_before"] for v in s.values())
    assert [v["val_after"] for v in s.values()] == sorted((v["val_after"] for v in s.values()), reverse=True)


def test_trainable_count_matches_formula():
    qwen = {"hidden_size": 896, "num_attention_heads": 14, "num_key_value_heads": 2,
            "intermediate_size": 4864, "num_hidden_layers": 24}
    d = json.loads((HERE / "domain.json").read_text(encoding="utf-8"))
    targets = ["q_proj", "k_proj", "v_proj", "o_proj", "gate_proj", "up_proj", "down_proj"]
    assert d["trainable"] == lora_params(qwen, targets) == 4_399_104


def test_domain_verdict_recorded():
    d = json.loads((HERE / "domain.json").read_text(encoding="utf-8"))
    base = json.loads((HERE.parent / "ch47" / "baseline.json").read_text(encoding="utf-8"))
    assert set(d["verdict"]) == {"domain_ppl", "keyword_hit", "format_ok", "general_ppl"}
    assert d["after"]["domain_ppl"] < base["domain_ppl"]               # 검증 손실 감소
    assert sorted(d["after"]["answers"]) == sorted(base["answers"])     # 같은 test 문항으로 비교
    assert d["after"]["generation"] == base["generation"]               # 같은 Greedy 설정
```

## 핵심 정리

- SFTTrainer에 `peft_config`를 넘기면 LoRA가 붙고 원래 가중치는 고정됩니다. 나머지 부품은 앞 장의 것을 그대로 씁니다.
- Target Modules를 넓힐수록 학습 파라미터와 표현력이 늘어납니다. 새 지식을 넣는 학습에는 FFN을 포함한 모든 Linear가 알맞습니다.
- Qwen2.5-0.5B FP32 LoRA는 CPU 경로이며, 학습 파라미터는 전체의 0.9%입니다.
- 검증 손실이 바닥을 찍고 오르기 시작하면 과적합의 신호입니다.
- 이 학습은 형식과 도메인 PPL은 합격했지만 핵심어는 불합격입니다. 적은 데이터는 말투를 먼저 가르치고 지식은 나중에 가르칩니다. 답을 직접 읽고, 미리 정한 기준으로 판정해야 이 차이가 보입니다.

**다음 장 연결:** 제49장에서는 같은 학습을 Qwen2.5-0.5B의 4비트(NF4) 모델로 합니다. Gradient Checkpointing과 최대 길이 256으로 2GB 예산에 맞추고, 같은 데이터와 기준으로 이 장의 LoRA 결과와 비교합니다.
