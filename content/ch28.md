## 장 개요

제27장에서 LoRA의 핵심 가정을 확인했습니다. 원본 가중치는 그대로 두고, 학습으로 생길 **변화량**만 작은 행렬 두 개의 곱으로 배운다는 것입니다. 이 장은 그 생각을 수식으로 정확히 적고, 숫자 몇 개짜리 행렬로 손계산합니다.

LoRA(Low-Rank Adaptation, 저랭크 적응)의 수식은 한 줄이지만, 그 안에 세 가지 설계 결정이 들어 있습니다. B를 0으로 시작하는 이유, `α/r`라는 배율의 역할, 학습이 끝난 뒤 원본에 합치는 병합입니다. 이 장에서 셋을 하나씩 확인한 뒤, 제29장에서 PyTorch로 직접 구현합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | LoRA는 어떤 수식으로 계산되며, 초기화·배율·병합은 왜 그렇게 설계되었는가 |
| 실습 결과물 | LoRA 순전파 손계산과 병합 비교, B = 0의 효과, 배율과 학습률의 관계, 실제 계층의 파라미터 수 |
| 실습 파일 | `examples/ch28/`의 `lora_math.py`, `test_ch28.py` |
| 선수 장 | 제05장(Linear), 제23장(Gradient), 제24장(Adam), 제27장(Rank) |

```text
            ┌──── W x ────────────────┐   W [out, in]  동결
x [in] ─────┤                         (+)──▶ y [out]
            └─ A ─▶ [r] ─ B ─▶ × α/r ─┘   A [r, in], B [out, r]  학습
```

## W와 ΔW

Linear 계층(제05장)은 `y = W x`입니다. Full Fine-tuning은 W 자체를 `W + ΔW`로 바꿉니다. LoRA는 ΔW를 다음과 같이 제한합니다.

```text
ΔW = (α/r) · B A          B [out, r],  A [r, in],  r ≪ out, in
y  = W x + ΔW x = W x + (α/r) · B (A x)
```

| 기호 | 모양 | 역할 | 학습 |
|---|---|---|---|
| W | `[out, in]` | 원본 가중치 | 동결 |
| A | `[r, in]` | 입력을 r차원으로 줄인다 | 학습 |
| B | `[out, r]` | r차원을 출력 크기로 늘린다 | 학습 |
| α | 숫자 | 변화량의 배율을 정하는 상수 | 고정 |

계산 순서에 주목합시다. `B A`를 먼저 곱해 `[out, in]` 행렬을 만들지 않고, `A x`로 r개짜리 벡터를 먼저 만든 뒤 B를 곱합니다. 큰 행렬을 만들지 않으므로 계산량과 메모리가 작습니다. 학습 중에는 원본 W의 Gradient가 필요 없으므로(제26장의 동결), Gradient와 Optimizer 상태는 A와 B에만 생깁니다.

## A, B의 모양과 초기화

A는 작은 난수로, **B는 0으로** 시작합니다. 이 선택에서 두 가지가 따라 나옵니다.

```text
학습 시작:  B = 0  →  ΔW = (α/r) · 0 · A = 0  →  y = W x   (원본과 정확히 같다)
첫 역전파:  dL/dA = (α/r) · Bᵀ(…) = 0       →  A는 아직 움직이지 않는다
           dL/dB = (α/r) · (…)(A x)ᵀ ≠ 0   →  B부터 움직인다
```

첫째, 학습을 시작하는 순간의 모델은 **원본 모델과 똑같습니다**. 사전학습으로 얻은 능력을 그대로 가진 채 출발하고, 학습이 진행되며 조금씩 벗어납니다. 무작위 변화량을 얹고 시작하면 첫 단계부터 원본의 출력이 흔들립니다.

둘째, A와 B를 **둘 다 0으로 두면 안 됩니다.** 그러면 B의 Gradient에도 `A x = 0`이 곱해져 둘 다 영원히 0에 머뭅니다. 하나는 난수, 하나는 0이어야 대칭이 깨지고 학습이 시작됩니다. 첫 단계에서는 B만 움직이고, B가 0이 아니게 된 다음 단계부터 A에도 신호가 갑니다.

## Alpha와 Scaling

`α/r`는 ΔW 전체에 곱해지는 상수입니다. 그렇다면 왜 굳이 따로 둘까요? A와 B가 학습으로 알아서 크기를 맞출 텐데 말입니다.

그 답은 Optimizer에 있습니다. 제24장에서 본 것처럼 Adam은 Gradient의 크기와 거의 상관없이 각 파라미터를 학습률 정도씩 움직입니다. 그러니 A·B가 한 단계에 움직이는 폭은 학습률이 정하고, ΔW가 움직이는 폭은 거기에 `α/r`가 곱해진 만큼입니다. **α를 두 배로 하는 것은 학습률을 두 배로 하는 것과 비슷한 효과**를 냅니다. 실습 3번에서 첫 단계의 ΔW가 정확히 같아지는 것을 확인합니다.

LoRA를 제안한 논문(Hu 외, 2021)은 이 성질을 이용해, α를 처음 시도한 r 값으로 정해 두고 따로 조정하지 않았다고 밝혔습니다. 이 교재도 같은 원칙을 씁니다.

| 실무 원칙 | 이유 |
|---|---|
| α는 정해 두고 학습률을 조정한다 | 두 값이 같은 역할을 하므로 하나만 조정하면 된다 |
| r을 바꿀 때 α를 고정하면 배율 α/r이 바뀐다 | r을 두 배로 하면 배율은 절반이 된다. 비교 실험에서는 이 점을 기록한다 |
| 흔한 설정: r = 8, α = 16(배율 2) | 제29·30장의 기본값 |

## 파라미터 수 계산

LoRA가 추가하는 파라미터는 행렬 하나에 `r × (in + out)`개입니다(제27장). Qwen2.5-0.5B 한 계층의 일곱 Linear에 모두 r = 8을 붙이면 원본의 1.23%이고, 24계층 전체로는 약 440만 개로 모델 전체의 0.89%입니다. Query와 Value(q_proj, v_proj)에만 붙이면 0.11%로 더 줄어듭니다.

어디에 붙일지는 r만큼 중요한 선택입니다. 제26장에서 "어떤 파라미터를 학습하느냐"가 결과를 갈랐듯, LoRA도 대상 계층에 따라 효과가 달라집니다. 제29장에서는 q_proj·v_proj와 일곱 Linear 전부에 붙여 학습 결과를 비교하고, 제30장에서는 PEFT로 대상별 학습 파라미터 수를 확인합니다.

학습한 결과물은 A와 B뿐입니다. r = 8, q·v_proj만이라면 FP32로 약 2MiB입니다. 원본 2GB를 그대로 두고, 과제마다 2MiB짜리 파일을 바꿔 끼울 수 있습니다.

### 병합

학습이 끝나면 ΔW를 원본에 더해 하나의 가중치로 합칠 수 있습니다.

```text
W' = W + (α/r) · B A          →          y = W' x
```

병합한 모델은 원래 모델과 모양이 같고 계산량도 같습니다. LoRA 경로의 추가 계산이 사라지므로 추론 속도가 원본과 같습니다. 이것이 Adapter 같은 다른 PEFT 방법(제26장)에 비한 LoRA의 장점입니다. 대신 병합하면 A·B를 따로 바꿔 끼우는 유연성은 사라지므로, 원본과 A·B를 따로 보관해 두는 것이 원칙입니다.

## 핵심 실습

작은 숫자 행렬로 LoRA 순전파와 병합을 손계산하고, B = 0 초기화의 효과, 배율과 학습률의 관계, 실제 모델의 파라미터 수를 확인합니다.

파일명: `examples/ch28/lora_math.py`

```python
# 제28장 핵심 실습: 작은 숫자 행렬로 LoRA 순전파를 손계산하고, 초기화·배율·병합을 확인한다
#
# 실행: python examples/ch28/lora_math.py
#
# y = W x + (α/r) · B (A x)        W: 동결, A [r, in]·B [out, r]: 학습
# 병합: W' = W + (α/r) · B A       → y = W' x  (추가 계산 없음)

import torch


def lora_forward(x, w, a, b, alpha: float, r: int):
    return x @ w.T + (alpha / r) * ((x @ a.T) @ b.T)


def merge(w, a, b, alpha: float, r: int):
    return w + (alpha / r) * (b @ a)


def lora_params(out_dim: int, in_dim: int, r: int) -> int:
    return r * (in_dim + out_dim)


def first_step_delta(r: int, alpha: float, lr: float) -> float:
    """B = 0에서 Adam 한 단계 학습한 뒤의 ‖ΔW‖ = ‖(α/r)·B A‖"""
    torch.manual_seed(0)
    out_dim, in_dim = 32, 32
    target = torch.randn(out_dim, in_dim) * 0.1
    x = torch.randn(256, in_dim)
    a = torch.nn.Parameter(torch.randn(r, in_dim) / in_dim ** 0.5)
    b = torch.nn.Parameter(torch.zeros(out_dim, r))
    opt = torch.optim.Adam([a, b], lr=lr)
    loss = ((alpha / r) * (x @ a.T) @ b.T - x @ target.T).pow(2).mean()
    loss.backward()
    opt.step()
    return ((alpha / r) * (b @ a)).norm().item()


def main() -> None:
    w = torch.tensor([[1.0, 0.0, 2.0],
                      [0.0, 1.0, -1.0]])                 # [out 2, in 3]
    x = torch.tensor([1.0, 2.0, 3.0])
    a = torch.tensor([[1.0, 1.0, 0.0]])                 # [r 1, in 3]
    b = torch.tensor([[0.5], [-1.0]])                   # [out 2, r 1]
    alpha, r = 2.0, 1

    print("── 1. 손계산(α = 2, r = 1, 배율 α/r = 2) ──")
    print("  원본  W x = [1·1 + 0·2 + 2·3, 0·1 + 1·2 − 1·3] = [7, −1]")
    print("  A x = [1 + 2 + 0] = [3]")
    print("  B (A x) = [0.5·3, −1·3] = [1.5, −3]")
    print("  y = [7, −1] + 2 × [1.5, −3] = [10, −7]")
    y = lora_forward(x, w, a, b, alpha, r)
    merged = merge(w, a, b, alpha, r)
    print(f"  PyTorch LoRA 순전파 {y.tolist()}")
    print(f"  병합 W' = W + 2·BA =\n{merged}")
    print(f"  병합 후 W' x {(x @ merged.T).tolist()}  같음: {torch.allclose(y, x @ merged.T)}")

    print("\n── 2. B = 0 초기화: 학습 첫 순간의 출력과 Gradient ──")
    torch.manual_seed(0)                                # A의 난수를 고정해 결과를 재현한다
    a0 = torch.randn(1, 3, requires_grad=True)
    b0 = torch.zeros(2, 1, requires_grad=True)
    y0 = lora_forward(x, w, a0, b0, alpha, r)
    print(f"  출력 {y0.tolist()} = 원본 W x {(x @ w.T).tolist()}")
    y0.pow(2).sum().backward()
    print(f"  dL/dA {a0.grad.tolist()}  (B가 0이라 A에는 신호가 가지 않는다)")
    print(f"  dL/dB {[round(v, 3) for v in b0.grad.flatten().tolist()]}  (B부터 움직이기 시작한다)")

    print("\n── 3. 배율 α/r은 학습률처럼 작용한다(r = 8, Adam 첫 단계 후 ‖ΔW‖) ──")
    for label, alpha_, lr in (("α = 16, lr 1e-3", 16, 1e-3), ("α = 32, lr 1e-3", 32, 1e-3),
                              ("α = 16, lr 2e-3", 16, 2e-3)):
        print(f"  {label:<18}배율 {alpha_ / 8:.0f}, ‖ΔW‖ {first_step_delta(8, alpha_, lr):.5f}")

    print("\n── 4. r = 8일 때 Qwen2.5-0.5B 한 계층의 LoRA 파라미터 ──")
    shapes = {"q_proj": (896, 896), "k_proj": (128, 896), "v_proj": (128, 896), "o_proj": (896, 896),
              "gate_proj": (4864, 896), "up_proj": (4864, 896), "down_proj": (896, 4864)}
    total_lora = total_orig = 0
    for name, (o, i) in shapes.items():
        n = lora_params(o, i, 8)
        total_lora, total_orig = total_lora + n, total_orig + o * i
        print(f"  {name:<10}{o:>5} × {i:<5}원본 {o * i:>10,}  LoRA {n:>7,}  ({n / (o * i):.2%})")
    print(f"  계층 합계: 원본 {total_orig:,}, LoRA {total_lora:,} ({total_lora / total_orig:.2%})")
    print(f"  24계층: LoRA {24 * total_lora:,}개 = 전체 494,032,768개의 {24 * total_lora / 494_032_768:.2%}")
    qv = 24 * (lora_params(896, 896, 8) + lora_params(128, 896, 8))
    print(f"  q_proj·v_proj만: {qv:,}개 ({qv / 494_032_768:.3%})")


if __name__ == "__main__":
    main()
```

## 검증과 완료 기준

파일명: `examples/ch28/test_ch28.py`

```python
# 제28장 검증 테스트
#
# 실행: python -m pytest examples/ch28 -q

import sys
from pathlib import Path

import pytest
import torch

sys.path.insert(0, str(Path(__file__).resolve().parent))

from lora_math import first_step_delta, lora_forward, lora_params, merge  # noqa: E402

W = torch.tensor([[1.0, 0.0, 2.0], [0.0, 1.0, -1.0]])
X = torch.tensor([1.0, 2.0, 3.0])
A = torch.tensor([[1.0, 1.0, 0.0]])
B = torch.tensor([[0.5], [-1.0]])


def test_hand_calculation():
    assert lora_forward(X, W, A, B, alpha=2.0, r=1).tolist() == [10.0, -7.0]


def test_merge_equals_lora_forward():
    torch.manual_seed(0)
    w, a, b, x = torch.randn(6, 5), torch.randn(3, 5), torch.randn(6, 3), torch.randn(4, 5)
    torch.testing.assert_close(x @ merge(w, a, b, 16, 3).T, lora_forward(x, w, a, b, 16, 3))


def test_zero_b_keeps_output_and_blocks_a_gradient():
    a = torch.randn(2, 3, requires_grad=True)
    b = torch.zeros(2, 2, requires_grad=True)
    y = lora_forward(X, W, a, b, alpha=8.0, r=2)
    torch.testing.assert_close(y, X @ W.T)
    y.sum().backward()
    assert torch.count_nonzero(a.grad) == 0 and torch.count_nonzero(b.grad) > 0


def test_alpha_acts_like_learning_rate_on_first_step():
    base = first_step_delta(8, 16, 1e-3)
    assert first_step_delta(8, 32, 1e-3) == pytest.approx(2 * base, rel=1e-5)
```

## 핵심 정리

- LoRA는 원본 W를 동결하고 변화량 `ΔW = (α/r)·BA`만 학습합니다. 계산은 `W x + (α/r)·B(A x)` 순서로 해 큰 행렬을 만들지 않습니다.
- A는 작은 난수, B는 0으로 시작합니다. 그래서 학습 첫 순간의 출력이 원본과 같고, 첫 단계에서는 B부터 움직입니다.
- 배율 α/r은 Adam에서 학습률과 비슷한 역할을 합니다. α는 정해 두고 학습률을 조정합니다.
- 추가 파라미터는 행렬당 `r × (in + out)`개로, 0.5B 모델 전체에 r = 8을 붙여도 0.89%입니다.
- 학습 후 `W' = W + ΔW`로 병합하면 추론 속도가 원본과 같습니다.
