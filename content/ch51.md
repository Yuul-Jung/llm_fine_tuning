## 장 개요

제5부에서 학습한 모델은 지금 학습 도구가 만든 폴더 안에 흩어져 있습니다. 배포하려면 무엇을 남기고 무엇을 버릴지, 파일이 무엇을 담고 있는지, 나중에 같은 모델을 정확히 다시 만들 수 있는지를 알아야 합니다. 제6부는 학습한 모델을 저장·병합·변환해 로컬 서비스로 내보내는 과정이며, 이 장은 그 출발점인 **저장과 복원**을 다룹니다.

이 장은 제50장에서 확정한 Adapter(원본-15)의 Checkpoint 폴더를 열어 파일마다 무엇이 들어 있는지 확인하고, Safetensors 파일의 구조를 직접 읽어 봅니다. Adapter 파일이 원본 모델의 어느 층과 연결되는지 대응시키고, 원본 모델의 Revision을 Adapter에 기록해 배포용 Adapter로 저장한 뒤, 다시 불러와 출력이 완전히 같은지 확인합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 학습 결과는 어떤 파일에 어떻게 저장되며, 저장한 모델을 정확히 같은 모델로 되살릴 수 있는가 |
| 실습 결과물 | Checkpoint 파일별 역할과 크기, Safetensors 직접 해석, Adapter와 원본 모듈 대응, 배포용 Adapter와 대응 기록 |
| 실습 파일 | `examples/ch51/`의 `save_load.py`, `test_ch51.py`, `manifest.json` |
| 선수 장 | 제30장(PEFT), 제46장(Checkpoint), 제50장(확정 모델) |

```text
models/ch50/원본/checkpoint-15 ─(학습용: 가중치 + Optimizer + Scheduler + 난수 + 기록)
   └─ 배포에 필요한 것만 ─▶ models/fpga_lora_v1(adapter_config + adapter_model, 원본 Revision 기록)
       + examples/ch51/manifest.json(원본 Revision, Adapter 해시, 데이터·기준 판, 평가 결과)
```

## state_dict와 Checkpoint

PyTorch 모델의 가중치는 **state_dict**로 저장합니다. 파라미터 이름을 열쇠로, 텐서를 값으로 하는 사전입니다. Optimizer와 Scheduler에도 각자의 state_dict가 있습니다. 제46장에서 보았듯 학습을 이어 가려면 이 셋과 데이터 위치, 난수 상태가 모두 필요하며, 이를 묶은 것이 학습 Checkpoint입니다.

| 파일 | 담고 있는 것 | 배포에 필요한가 |
|---|---|---|
| adapter_model | LoRA의 A·B 가중치 | 예 |
| adapter_config | LoRA 설정과 원본 모델 이름 | 예 |
| optimizer | AdamW 모멘트 | 아니요(학습 재개용) |
| scheduler, rng_state | 학습률 위치, 난수 상태 | 아니요(학습 재개용) |
| trainer_state, training_args | 기록과 학습 설정 | 아니요(기록으로 보관) |

학습 Checkpoint는 배포 파일보다 훨씬 큽니다. AdamW는 파라미터마다 모멘트 두 개를 저장하므로 Optimizer 파일만 LoRA 가중치의 두 배입니다. 배포할 때는 가중치와 설정만 남기고, 학습을 이어 갈 가능성이 있는 동안에만 Checkpoint 전체를 보관합니다.

## Safetensors

PyTorch의 기본 저장 형식(.pt, .bin, .pth)은 파이썬 pickle입니다. pickle은 객체를 되살리는 과정에서 **임의의 코드를 실행할 수 있어서**, 출처를 모르는 파일을 열면 위험합니다. 최근 PyTorch는 불러올 때 텐서만 허용하는 옵션을 기본으로 켜지만, 형식 자체의 위험은 남습니다.

**Safetensors**는 텐서만 저장하는 단순한 형식입니다.

| 부분 | 내용 |
|---|---|
| 처음 8바이트 | 머리말 길이(부호 없는 64비트 정수, little-endian) |
| 머리말 | JSON. 텐서마다 이름, 자료형, 모양, 본문 안의 시작·끝 위치 |
| 본문 | 텐서 바이트를 순서대로 이어 붙인 것 |

실행할 코드가 들어갈 자리가 없으므로 안전하고, 머리말만 읽으면 필요한 텐서의 위치를 알 수 있어 파일 전체를 읽지 않고 원하는 텐서만 꺼낼 수 있습니다(메모리 매핑). Hugging Face 모델과 PEFT Adapter는 이 형식을 기본으로 씁니다. 실습에서는 라이브러리 없이 머리말만으로 텐서를 꺼내 라이브러리의 결과와 비교합니다.

## Adapter 파일 구조

PEFT Adapter는 두 파일로 이루어집니다. **adapter_config.json**은 LoRA 설정(r, alpha, 대상 모듈)과 어느 원본 모델에 붙이는지를, **adapter_model.safetensors**는 A·B 가중치를 담습니다. 원본 가중치는 들어 있지 않으므로, Adapter를 쓰려면 원본 모델을 먼저 불러와야 합니다.

Adapter 텐서의 이름이 연결 고리입니다. 이름에서 PEFT가 붙인 앞부분(base_model.model)과 뒷부분(lora_A, lora_B)을 떼면 원본 모델의 모듈 이름이 남습니다. 불러올 때 PEFT는 이 이름의 모듈을 찾아 A·B를 붙입니다. 그래서 원본 모델의 구조가 다르면(층 수, 모듈 이름, 차원) Adapter를 붙일 수 없거나 모양 오류가 납니다.

## Revision과 버전 관리

adapter_config에는 원본 모델의 이름은 있지만, 실습에서 보듯 **Revision(커밋 해시)은 비어 있습니다.** 이름만으로는 원본 저장소가 나중에 갱신되었을 때 어느 판의 가중치로 학습했는지 알 수 없습니다. Adapter는 원본의 특정 판과 짝을 이루므로, 이 교재는 두 가지로 대응을 남깁니다.

| 기록 | 내용 |
|---|---|
| Adapter 설정 파일의 revision 항목 | 원본 모델 커밋 해시(불러올 때 PEFT가 참고) |
| 대응 기록 파일(manifest) | 원본 Revision, Adapter 파일 해시, 학습 데이터·분할, 기준 판, 평가 결과 |

Adapter 파일의 해시(SHA-256)를 함께 적어 두면, 나중에 받은 파일이 기록된 것과 같은 파일인지 확인할 수 있습니다. 평가 결과와 채택 여부(제50장: 실습용, 배포 후보 불채택)도 같이 적어, 이 Adapter를 쓰는 사람이 품질 수준을 알 수 있게 합니다.

## 핵심 실습

파일명: `examples/ch51/save_load.py`

```python
# 제51장 핵심 실습: Checkpoint·Safetensors·Adapter 구조를 열어 보고, Adapter를 저장·재로딩해 출력을 비교한다
#
# 실행: python examples/ch51/save_load.py   (제50장의 확정 Adapter 필요, CPU 약 1분)
#
# 만드는 파일: models/fpga_lora_v1/(배포용 Adapter), examples/ch51/manifest.json(대응 기록)

import hashlib
import json
import struct
import sys
from pathlib import Path

HERE = Path(__file__).resolve().parent
ROOT = HERE.parents[1]
sys.path.insert(0, str(HERE.parent))

import torch  # noqa: E402
from safetensors.torch import load_file  # noqa: E402

from common.device import select_device  # noqa: E402
from common.models import QWEN_ID, QWEN_REVISION  # noqa: E402

CKPT = ROOT / "models" / "ch50" / "원본" / "checkpoint-15"     # 제50장 확정 모델(원본-15)
FINAL = ROOT / "models" / "fpga_lora_v1"
MANIFEST = HERE / "manifest.json"
MiB = 2 ** 20


def read_header(path: Path) -> tuple:
    """Safetensors = [8바이트 길이(little-endian)][JSON 머리말][텐서 바이트를 이어 붙인 본문]"""
    raw = path.read_bytes()
    n = struct.unpack("<Q", raw[:8])[0]
    header = json.loads(raw[8:8 + n])
    return n, header, raw[8 + n:]


def tensor_by_hand(header: dict, body: bytes, name: str) -> torch.Tensor:
    """머리말의 자료형·모양·위치만으로 텐서 하나를 직접 꺼낸다"""
    info = header[name]
    start, end = info["data_offsets"]
    assert info["dtype"] == "F32"
    return torch.frombuffer(bytearray(body[start:end]), dtype=torch.float32).reshape(info["shape"])


def sha256(path: Path) -> str:
    return hashlib.sha256(path.read_bytes()).hexdigest()


def load_base(device: str):
    from transformers import AutoModelForCausalLM
    return AutoModelForCausalLM.from_pretrained(QWEN_ID, revision=QWEN_REVISION,
                                                dtype=torch.float32).to(device).eval()


def logits_of(model, tok, device: str) -> torch.Tensor:
    ids = tok("FPGA의 LUT는 어떤 역할을 하나요?", return_tensors="pt").input_ids.to(device)
    with torch.no_grad():
        return model(ids).logits[0].float().cpu()


def main() -> None:
    from peft import PeftModel
    from transformers import AutoTokenizer
    device, _ = select_device()                    # 병합 전 0.5B FP32 Adapter 모델: GT 1030에서는 CPU 권장
    print("── 1. 학습 Checkpoint에 들어 있는 것(제50장 원본-15) ──")
    roles = {"adapter_model.safetensors": "LoRA 가중치(A, B)", "optimizer.pt": "AdamW 1·2차 모멘트(pickle)",
             "scheduler.pt": "학습률 Scheduler 상태(pickle)", "rng_state.pth": "난수 상태(pickle)",
             "trainer_state.json": "단계·기록(log_history)", "training_args.bin": "학습 설정(pickle)",
             "adapter_config.json": "LoRA 설정과 원본 모델 이름"}
    for name, role in roles.items():
        size = (CKPT / name).stat().st_size
        text = f"{size / MiB:.2f}MiB" if size >= MiB else f"{size / 1024:.1f}KiB"
        print(f"  {name:<27}{text:>10}  {role}")
    ratio = (CKPT / "optimizer.pt").stat().st_size / (CKPT / "adapter_model.safetensors").stat().st_size
    print(f"  Optimizer 상태 / LoRA 가중치 = {ratio:.2f}배(모멘트 2개)")

    print("\n── 2. Safetensors 구조 ──")
    n, header, body = read_header(CKPT / "adapter_model.safetensors")
    names = sorted(k for k in header if k != "__metadata__")
    print(f"  머리말 {n}바이트(JSON), 텐서 {len(names)}개, 본문 {len(body) / MiB:.2f}MiB")
    for k in names[:2]:
        print(f"  {k}\n    {header[k]}")
    lib = load_file(CKPT / "adapter_model.safetensors")
    same = all(torch.equal(tensor_by_hand(header, body, k), lib[k]) for k in names)
    print(f"  머리말만으로 직접 꺼낸 텐서 = 라이브러리로 읽은 텐서: {same}")

    print("\n── 3. Adapter 파일과 원본 모델의 연결 ──")
    cfg = json.loads((CKPT / "adapter_config.json").read_text())
    print(f"  base_model_name_or_path {cfg['base_model_name_or_path']}, revision {cfg['revision']}, "
          f"r {cfg['r']}, alpha {cfg['lora_alpha']}")
    print(f"  target_modules {sorted(cfg['target_modules'])}")
    tok = AutoTokenizer.from_pretrained(QWEN_ID, revision=QWEN_REVISION)
    base = load_base(device)
    modules = {n for n, _ in base.named_modules()}
    mapped = {k.removeprefix("base_model.model.").rsplit(".lora_", 1)[0] for k in names}
    print(f"  Adapter 텐서 {len(names)}개 → 원본 모듈 {len(mapped)}개(모두 원본에 있음 {mapped <= modules})")
    print(f"  예: {names[0]}\n    → 원본의 {sorted(mapped)[0]}에 A·B 한 쌍이 붙는다")
    ref = logits_of(base, tok, device)

    print("\n── 4. 저장·재로딩과 Revision 기록 ──")
    model = PeftModel.from_pretrained(base, CKPT).eval()
    out1 = logits_of(model, tok, device)
    model.peft_config["default"].revision = QWEN_REVISION         # 원본 Revision을 Adapter 설정에 남긴다
    model.save_pretrained(FINAL)
    del model, base
    base2 = load_base(device)
    model2 = PeftModel.from_pretrained(base2, FINAL).eval()
    out2 = logits_of(model2, tok, device)
    w1, w2 = load_file(CKPT / "adapter_model.safetensors"), load_file(FINAL / "adapter_model.safetensors")
    print(f"  저장 파일: {sorted(p.name for p in FINAL.iterdir())}")
    print(f"  가중치 완전 일치: {w1.keys() == w2.keys() and all(torch.equal(w1[k], w2[k]) for k in w1)}")
    print(f"  재로딩 전후 Logits 최대 차이 {(out1 - out2).abs().max().item():.2e}")
    print(f"  Adapter 적용 전후 Logits 최대 차이 {(ref - out1).abs().max().item():.2f}(Adapter가 실제로 작동)")
    saved = json.loads((FINAL / "adapter_config.json").read_text())
    manifest = {
        "adapter": "models/fpga_lora_v1",
        "base_model": QWEN_ID, "base_revision": QWEN_REVISION,
        "adapter_sha256": sha256(FINAL / "adapter_model.safetensors"),
        "source": "제50장 원본-15(train 38, 15단계, lr 2e-4, 모든 Linear r 8)",
        "data": {"dataset": "datasets/fpga_qa/fpga_qa.json", "split": "split_v1.json"},
        "criteria_version": 2, "final_test": "3/4 합격(핵심어 불합격), 배포 후보 불채택, 실습용",
    }
    MANIFEST.write_text(json.dumps(manifest, ensure_ascii=False, indent=1) + "\n", encoding="utf-8")
    print(f"  저장된 설정의 revision {saved['revision'][:12]}…, 대응 기록 {MANIFEST.relative_to(ROOT)}")
    print(f"  Adapter 해시 {manifest['adapter_sha256'][:16]}…")


if __name__ == "__main__":
    torch.manual_seed(0)
    main()
```

**결과 읽기**

- **1번**에서 Checkpoint 약 50MiB 중 배포에 필요한 LoRA 가중치는 16.8MiB이고, Optimizer 상태가 그 2.01배(모멘트 두 개)입니다. Optimizer·Scheduler·난수·학습 설정 네 파일은 pickle 형식입니다.
- **2번**에서 Safetensors 머리말은 43,712바이트의 JSON이고, 텐서 336개의 자료형·모양·위치가 들어 있습니다. 첫 텐서는 본문 0~155,648바이트(8 × 4864 × 4바이트)를 차지합니다. 머리말의 위치만으로 꺼낸 336개 텐서가 라이브러리로 읽은 것과 모두 같습니다.
- **3번**에서 Adapter 텐서 336개는 원본 모듈 168개(24층 × 7개)에 A·B 한 쌍씩 대응하며, 모두 원본 모델에 실제로 있는 모듈입니다. 설정의 revision은 비어 있습니다.
- **4번**에서 Revision을 기록해 배포용 Adapter로 저장하고, 새로 불러온 원본에 다시 붙였습니다. 가중치는 완전히 같고, 같은 입력의 Logits 차이는 0입니다. Adapter를 붙이기 전과의 Logits 차이(최대 6.00)는 Adapter가 실제로 출력을 바꾸고 있다는 확인입니다. 저장된 설정에는 이제 원본 Revision이 들어 있습니다.

```python
# 제51장 검증 테스트
#
# 실행: python -m pytest examples/ch51 -q

import json
import struct
import sys
from pathlib import Path

HERE = Path(__file__).resolve().parent
sys.path.insert(0, str(HERE))

import pytest  # noqa: E402
import torch  # noqa: E402
from safetensors.torch import load_file, save_file  # noqa: E402

from save_load import CKPT, FINAL, MANIFEST, QWEN_REVISION, read_header, sha256, tensor_by_hand  # noqa: E402


def test_safetensors_layout_by_hand(tmp_path):
    t = {"a": torch.arange(6, dtype=torch.float32).reshape(2, 3), "b": torch.ones(4)}
    save_file(t, tmp_path / "x.safetensors")
    n, header, body = read_header(tmp_path / "x.safetensors")
    assert struct.unpack("<Q", (tmp_path / "x.safetensors").read_bytes()[:8])[0] == n
    assert header["a"]["shape"] == [2, 3] and len(body) == (6 + 4) * 4
    assert all(torch.equal(tensor_by_hand(header, body, k), t[k]) for k in t)
```

## 핵심 정리

- state_dict는 이름과 텐서의 사전이며, 학습 Checkpoint는 가중치·Optimizer·Scheduler·난수·기록을 묶은 것입니다. 배포에는 가중치와 설정만 필요합니다.
- pickle 형식은 불러올 때 코드를 실행할 수 있어 위험합니다. Safetensors는 머리말(JSON)과 텐서 바이트만 담아 안전하고, 필요한 텐서만 골라 읽을 수 있습니다.
- Adapter는 설정과 A·B 가중치뿐이며, 텐서 이름으로 원본 모듈에 연결됩니다. 원본 모델이 있어야 쓸 수 있습니다.
- adapter_config의 revision은 기본으로 비어 있습니다. 원본 Revision, Adapter 해시, 데이터·기준 판, 평가 결과를 함께 기록합니다.
- 저장·재로딩 후에는 가중치 일치와 같은 입력의 출력 일치를 확인합니다.
