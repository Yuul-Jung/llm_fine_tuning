## 장 개요

제3·4부에서 세 가지 학습 방식을 모두 해 보았습니다. 모든 가중치를 학습하는 Full Fine-tuning(제25장), 원본을 얼리고 작은 행렬만 학습하는 LoRA(제29·30장), 원본을 4비트로 줄인 위에서 LoRA를 학습하는 QLoRA(제39장)입니다. 각 장의 결과는 서로 다른 조건에서 얻은 것이라 그대로 비교할 수 없습니다.

이 장은 제4부를 마무리하며, 세 방식을 **같은 조건으로 맞춰 한 표로 비교**합니다. 비교 A는 작은 Qwen2-Tiny에서 세 방식을 모두, 비교 B는 실제 Qwen2.5-0.5B에서 QLoRA와 FP32 LoRA를 비교합니다. 그리고 결과를 바탕으로, 주어진 장비에서 어떤 방식을 고를지 판단 기준을 세웁니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 같은 조건에서 Full FT·LoRA·QLoRA는 메모리·저장 용량·품질이 어떻게 다르며, 장비에 따라 무엇을 골라야 하는가 |
| 실습 결과물 | 비교 조건 기록, 비교 A(Qwen2-Tiny 세 방식)·비교 B(0.5B QLoRA·LoRA) 결과표, 장비별 선택 기준 |
| 실습 파일 | `examples/ch40/`의 `compare_methods.py`, `test_ch40.py`, `results.json` |
| 선수 장 | 제25장(Full FT), 제29·30장(LoRA), 제37~39장(4비트, QLoRA) |

```text
비교 A  Qwen2-Tiny(사전학습, 제25장) × 자전거 정비 데이터 × 60단계 → Full FT / LoRA / QLoRA
비교 B  Qwen2.5-0.5B-Instruct × 고정 학습 데이터(시퀀스 256) × 30단계 → QLoRA / FP32 LoRA
기록    학습 파라미터 · 고정 메모리 · Activation · 저장 용량 · PPL
```

## 비교 설계

공정한 비교의 원칙은 제21장에서 세웠습니다. **바꾸는 조건 하나를 빼고 모두 같게** 합니다. 이 장에서 바꾸는 것은 학습 방식 하나이고, 나머지는 다음과 같이 고정합니다.

| 조건 | 고정한 값 |
|---|---|
| 출발 체크포인트 | 비교 A: `models/qwen2-tiny-pretrained`(제25장), 비교 B: Qwen2.5-0.5B-Instruct(Revision 고정) |
| 데이터 | 데이터 지문으로 확인(실습 출력의 비교 조건) |
| 토크나이저·Label | Qwen2.5 토크나이저, 첫 토큰을 뺀 전체 토큰을 정답으로(제22장) |
| 평가 | 128토큰 블록 독립 PPL(제22장) |
| 학습 루프 | 제25장 `train()`, AdamW, Warmup + Cosine, Clipping 1.0, seed 0 |
| LoRA | r 8, α 16, 같은 seed의 A 초기값 |

학습률만은 방식마다 다르게 둡니다. 제26·29장에서 확인했듯 학습 파라미터의 수가 크게 다르면 알맞은 학습률도 다르기 때문입니다. Full FT는 제25장의 3e-4, LoRA와 QLoRA는 2e-3(비교 A)과 제39장의 5e-4(비교 B)를 씁니다. 같은 학습률을 강요하면 한쪽에 불리한 비교가 됩니다. 대신 쓴 값을 결과와 함께 기록합니다.

측정 항목은 다섯 가지입니다.

| 항목 | 뜻 |
|---|---|
| 학습 파라미터 | `requires_grad=True`인 파라미터 수 |
| 고정 메모리 | 파라미터 메모리(4비트는 번호 + absmax) + 학습 파라미터 × 12바이트(Gradient + AdamW) |
| Activation | 학습 한 단계에서 역전파용으로 새로 저장된 텐서(제38장 방식) |
| 저장 용량 | 학습 결과로 저장하는 파일(Full FT는 모델 전체, LoRA·QLoRA는 Adapter) |
| PPL | 학습 후 평가 PPL(비교 A는 도메인과 일반 두 가지) |

## 비교 A: Qwen2-Tiny

비교 A는 세 방식을 모두 같은 모델에서 비교합니다. LoRA와 QLoRA는 일곱 Linear 전부에 붙입니다(제29장의 "7종 전부"). 4비트 Qwen2-Tiny는 제25장의 사전학습 모델을 `BitsAndBytesConfig`로 불러와 만듭니다.

Qwen2-Tiny에는 특이한 점이 하나 있습니다. 파라미터의 93%가 Embedding입니다(제19장). bitsandbytes는 Linear만 4비트로 바꾸므로, Qwen2-Tiny에서는 4비트로 줄어드는 부분이 7%뿐입니다. 비교 A에서 QLoRA의 메모리 이득이 작게 나오는 것은 방식의 한계가 아니라 이 모델 구조 때문입니다. 비교 B가 필요한 이유입니다.

## 비교 B: Qwen2.5-0.5B

비교 B는 실제 모델에서 QLoRA와 FP32 LoRA를 비교합니다. 둘 다 q·v_proj LoRA, 시퀀스 256, Batch 1 × Accumulation 4, Gradient Checkpointing으로 같고, 원본 가중치의 형식(NF4 대 FP32)만 다릅니다.

설계서는 QLoRA를 GT 1030에서, FP32 LoRA를 CPU에서 실행하도록 했습니다. 0.5B의 FP32 원본은 약 1.9GB라 GT 1030에 학습 공간까지 올릴 수 없기 때문입니다. 그래서 두 방식은 장치가 달라 **시간은 비교하지 않고** 메모리와 품질만 비교합니다. 교재 검증 환경은 두 방식 모두 CPU에서 실행했습니다.

## 하드웨어별 최적 선택

방식 선택은 "어느 것이 가장 좋은가"가 아니라 "주어진 메모리에서 무엇이 가능하고, 그중 무엇이 가장 좋은가"의 문제입니다. 이 장의 결과와 제24·38장의 메모리 계산으로 기준을 세웁니다.

```text
GT 1030(VRAM 2GB)
  Qwen2-Tiny     Full FT 가능(고정 640MiB)
  Qwen2.5-0.5B   QLoRA만 가능(고정 약 704MiB + 실행 환경)
CPU(RAM 8GB 이상)
  Qwen2-Tiny     모든 방식
  Qwen2.5-0.5B   FP32 LoRA, QLoRA(bitsandbytes CPU 경로)
                 Full FT(고정 7.4GiB)는 RAM 16GB 이상에서 가능하지만 매우 느림
최신 GPU(VRAM 16GB 이상)
  두 모델 모두   모든 방식, BF16 혼합 정밀도로 더 빠르게(제32장)
```

선택의 순서는 다음과 같습니다.

1. **메모리로 거른다.** 고정 메모리 + Activation + Logits + 실행 환경이 장비 메모리에 들어가는 방식만 남깁니다.
2. **품질을 본다.** 남은 방식 중 원본 정밀도가 높은 쪽(Full FT > FP32 LoRA > QLoRA)이 대체로 품질이 좋습니다. 이 장의 비교 B가 그 차이를 숫자로 보여 줍니다.
3. **보관과 배포를 본다.** 과제가 여러 개라면 Adapter 몇 MB씩만 보관하는 LoRA·QLoRA가 유리합니다. 추론 속도가 중요하면 학습 후 병합합니다(제29·30장).

## 핵심 실습

파일명: `examples/ch40/compare_methods.py`

```python
# 제40장 핵심 실습: Full FT·LoRA·QLoRA를 같은 조건으로 비교한다
#
# 실행: python examples/ch40/compare_methods.py          (비교 A + 비교 B, 교재 검증 환경 CPU에서 약 15분)
#       python examples/ch40/compare_methods.py --only-a  (비교 A만, 약 4분)
#
# 비교 A: 사전학습 Qwen2-Tiny(제25장) + 자전거 정비 데이터, 60단계
# 비교 B: Qwen2.5-0.5B-Instruct + 고정 학습 데이터(시퀀스 256), 30단계 — QLoRA(제39장)와 FP32 LoRA

import json
import math
import sys
import tempfile
from pathlib import Path

HERE = Path(__file__).resolve().parent
for p in (HERE.parent, HERE.parent / "ch22", HERE.parent / "ch24", HERE.parent / "ch25", HERE.parent / "ch29",
          HERE.parent / "ch37", HERE.parent / "ch38", HERE.parent / "ch39"):
    sys.path.insert(0, str(p))

import torch  # noqa: E402
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training  # noqa: E402
from transformers import AutoModelForCausalLM  # noqa: E402
from transformers.utils import logging  # noqa: E402

from common.fixed_data import fingerprint, load_blocks  # noqa: E402
from common.models import QWEN_ID, QWEN_REVISION  # noqa: E402
from common.qwen import load_tokenizer  # noqa: E402
from lora_linear import ALL_LINEAR  # noqa: E402                     (제29장)
from load_4bit import memory_parts, nf4_config  # noqa: E402        (제37장)
from qlora_memory import saved_bytes_of_step  # noqa: E402          (제38장)
from qlora_train import keep_training_layout  # noqa: E402          (제39장)
from trainer import eval_loss, train  # noqa: E402                  (제25장)

logging.disable_progress_bar()
TINY = HERE.parents[1] / "models" / "qwen2-tiny-pretrained"
MiB = 2 ** 20


def lora(model, targets=ALL_LINEAR):
    torch.manual_seed(0)                                         # A 초기값 고정
    return get_peft_model(model, LoraConfig(r=8, lora_alpha=16, target_modules=list(targets),
                                            lora_dropout=0.0, bias="none", task_type="CAUSAL_LM"))


def load(path_or_id, quant: bool, **kw):
    q = {"quantization_config": nf4_config(), "device_map": "cpu"} if quant else {}
    return AutoModelForCausalLM.from_pretrained(path_or_id, dtype=torch.float32, **q, **kw)


def weight_bytes(model) -> int:
    """파라미터 메모리(4비트는 번호 + absmax). LoRA 파라미터 포함."""
    return sum(memory_parts(model).values())


def artifact_bytes(model) -> int:
    with tempfile.TemporaryDirectory() as d:
        model.save_pretrained(d)
        return sum(f.stat().st_size for f in Path(d).iterdir() if f.suffix == ".safetensors")


def run(label, model, data, ev, steps, lr, accum, batch, seq_probe) -> dict:
    trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)
    act, _, _ = saved_bytes_of_step(model, seq_probe)            # 한 단계 저장 텐서(제38장)
    model.zero_grad(set_to_none=True)
    train(model, data, {}, steps=steps, batch=batch, accum=accum, lr=lr, warmup=5, log_every=steps)
    res = {"방식": label, "학습 파라미터": trainable,
           "고정 메모리MiB": round((weight_bytes(model) + trainable * 12) / MiB, 1),  # + Gradient·AdamW
           "Activation MiB": round(act / MiB, 1), "저장 MiB": round(artifact_bytes(model) / MiB, 2)}
    for k, blocks in ev.items():
        res[k] = round(math.exp(eval_loss(model, blocks, "cpu")), 2)
    return res


def show(rows: list) -> None:
    keys = list(rows[0])
    for k in keys:
        print(f"  {k:<14}" + "".join(f"{str(r[k]):>16}" for r in rows))


def compare_a(tok) -> list:
    d = {s: load_blocks(tok, s) for s in ("domain_train", "domain_eval", "eval")}
    ev = {"도메인 PPL": d["domain_eval"], "일반 PPL": d["eval"]}
    probe = d["domain_train"][:1]
    print(f"── 비교 A: Qwen2-Tiny, 학습 {tuple(d['domain_train'].shape)}, 60단계, Batch 2 × Accumulation 2 ──")
    base = load(TINY, quant=False)
    print("  학습 전" + "".join(f"  {k} {math.exp(eval_loss(base, b, 'cpu')):.2f}" for k, b in ev.items()))
    rows = [run("Full FT", load(TINY, False), d["domain_train"], ev, 60, 3e-4, 2, 2, probe)]
    rows.append(run("LoRA", lora(load(TINY, False)), d["domain_train"], ev, 60, 2e-3, 2, 2, probe))
    q = prepare_model_for_kbit_training(load(TINY, True), use_gradient_checkpointing=False)
    q = lora(q)
    keep_training_layout(q)
    rows.append(run("QLoRA", q, d["domain_train"], ev, 60, 2e-3, 2, 2, probe))
    show(rows)
    return rows


def compare_b(tok) -> list:
    train_blocks = load_blocks(tok, "train", seq_len=256)
    ev = {"평가 PPL": load_blocks(tok, "eval")}
    probe = train_blocks[:1]
    print(f"\n── 비교 B: Qwen2.5-0.5B-Instruct, 학습 {tuple(train_blocks.shape)}, 30단계, "
          f"Batch 1 × Accumulation 4, Checkpointing, q·v LoRA ──")
    rows = []
    for label, quant in (("QLoRA(NF4)", True), ("LoRA(FP32)", False)):
        m = load(QWEN_ID, quant, revision=QWEN_REVISION)
        m = prepare_model_for_kbit_training(m, use_gradient_checkpointing=True,
                                            gradient_checkpointing_kwargs={"use_reentrant": False}) if quant \
            else m
        if not quant:
            m.gradient_checkpointing_enable(gradient_checkpointing_kwargs={"use_reentrant": False})
            m.enable_input_require_grads()
        m = lora(m, ("q_proj", "v_proj"))
        if quant:
            keep_training_layout(m)
        rows.append(run(label, m, train_blocks, ev, 30, 5e-4, 4, 1, probe))
        del m
    show(rows)
    return rows


def main() -> None:
    tok = load_tokenizer()
    print("── 비교 조건 ──")
    print(f"  토크나이저 Qwen2.5(제08장), Label: 전체 토큰(첫 토큰 제외), 평가: 128토큰 블록 독립(제22장)")
    print(f"  데이터 지문 domain_train {fingerprint(load_blocks(tok, 'domain_train'))}, "
          f"eval {fingerprint(load_blocks(tok, 'eval'))}")
    print(f"  LoRA r 8, α 16, seed 0, AdamW, Warmup + Cosine, Clipping 1.0(제25장 train())\n")
    out = {"A": compare_a(tok)}
    if "--only-a" not in sys.argv:
        out["B"] = compare_b(tok)
    (HERE / "results.json").write_text(json.dumps(out, ensure_ascii=False, indent=1) + "\n", encoding="utf-8")


if __name__ == "__main__":
    main()
```

결과는 `examples/ch40/results.json`에 저장됩니다.

**비교 A 결과 읽기**

- **학습 파라미터와 메모리:** LoRA·QLoRA는 Full FT의 0.36%(151,552개)만 학습합니다. 고정 메모리는 Full FT 640MiB에서 LoRA 162MiB로 4분의 1이 됩니다. Gradient와 AdamW 상태가 LoRA에만 붙기 때문입니다. QLoRA는 152MiB로 LoRA보다 10MiB밖에 줄지 않습니다. 앞 절에서 설명한 대로, 4비트로 줄어드는 Linear가 Qwen2-Tiny의 7%뿐이기 때문입니다.
- **Activation:** 세 방식 모두 약 84MiB로 거의 같습니다. Activation은 모델의 계산 구조와 시퀀스 길이가 정하며, 학습 방식과는 거의 관계가 없습니다. 이것을 줄이는 것은 Gradient Checkpointing(제38장)입니다.
- **저장 용량:** Full FT는 모델 전체 160MiB, LoRA·QLoRA는 Adapter 0.58MiB로 275분의 1입니다.
- **품질:** 도메인 PPL은 Full FT가 157로 가장 많이 배웠고, LoRA 377, QLoRA 387이 뒤를 잇습니다. 학습 전 885에서 모두 크게 내려갔습니다. 일반 PPL(학습 전 343)은 세 방식 모두 396~410으로 올랐습니다. 이 설정에서는 LoRA도 Full FT만큼 망각을 일으켰습니다(제29장의 결론과 같음). 도메인 평가가 블록 1개라는 한계(제25장)도 기억해 둡니다.

**비교 B 결과 읽기**

- **메모리:** 같은 LoRA라도 원본이 NF4면 고정 메모리가 704MiB, FP32면 1,893MiB입니다. QLoRA가 2.7배 작습니다. 0.5B 모델에서는 Linear가 파라미터의 72%를 차지하므로 4비트의 효과가 큽니다. Activation(170MiB)과 Adapter(2.07MiB)는 같습니다.
- **품질:** 평가 PPL은 FP32 LoRA 14.34, QLoRA 17.71입니다. 두 방식 모두 학습 전 기준(FP32 21.45, NF4 27.90)보다 크게 좋아졌지만, FP32 LoRA가 더 낮습니다. QLoRA는 4비트로 바뀐 원본(PPL 27.90)에서 출발하므로, 같은 학습으로도 FP32 원본보다 불리한 자리에서 시작합니다. 메모리를 2.7배 아낀 대가입니다.
- QLoRA의 PPL은 제39장(17.73)과 조금 다른 17.71입니다. 이 장은 학습 전에 Activation을 재려고 순전파·역전파를 한 번 더 하므로, 계산 순서의 미세한 차이가 생깁니다.

| 결론 | 근거 |
|---|---|
| 메모리가 넉넉하면 FP32 LoRA가 QLoRA보다 품질이 좋다 | 비교 B: 14.34 대 17.71 |
| GT 1030에서 0.5B를 학습하는 유일한 방법은 QLoRA다 | 비교 B: FP32 원본만 1.9GB |
| 작은 모델에서는 QLoRA의 이득이 작다 | 비교 A: Embedding이 대부분이라 4비트 효과 10MiB |
| 학습 파라미터를 줄여도 망각은 남는다 | 비교 A: 세 방식 모두 일반 PPL 상승 |

## 핵심 정리

- 학습 방식을 비교할 때는 방식 하나만 바꾸고 체크포인트·데이터·Label·평가·학습 루프를 고정합니다. 학습률은 방식에 맞게 두되 기록합니다.
- 고정 메모리는 Full FT ≫ LoRA > QLoRA 순입니다. QLoRA의 이득은 Linear가 큰 모델에서 크고, Embedding이 대부분인 작은 모델에서는 작습니다.
- Activation은 학습 방식과 거의 무관하며, Gradient Checkpointing으로 줄입니다. 저장 용량은 Adapter가 모델 전체의 수백분의 1입니다.
- 품질은 원본 정밀도가 높을수록 좋습니다(0.5B: FP32 LoRA 14.34 < QLoRA 17.71). QLoRA는 메모리가 부족할 때 학습을 가능하게 하는 방법입니다.
- 방식 선택은 메모리로 거르고, 품질을 보고, 보관·배포를 따지는 순서로 합니다.

**다음 장 연결:** 제3·4부는 고정 데이터로 학습의 원리를 확인했습니다. 제5부에서는 실제 용도의 데이터로 옮겨 갑니다. 제41장에서는 지도 미세조정(SFT)이 무엇인지 정리하고, 질문과 답의 쌍으로 이루어진 사용자 데이터셋을 설계합니다.
