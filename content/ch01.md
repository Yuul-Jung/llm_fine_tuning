## 장 개요

이 장은 긴 여정의 출발선입니다. 앞으로 59개의 장에서 LLM의 내부를 열어 보고, 직접 학습시키고, 내 컴퓨터에 배포하게 됩니다. 그 모든 실습이 같은 환경에서 같은 결과를 내려면 출발점이 단단해야 합니다.

제01장은 두 가지를 해냅니다. 첫째, LLM이 무엇이고 이 교재가 그중 어디를 다루는지 큰 그림을 그립니다. 둘째, 그 그림을 실제로 확인할 로컬 실습 환경을 만들고 첫 번째 LLM을 실행합니다.

## AI·머신러닝·딥러닝·생성형 AI

네 용어는 서로 다른 기술이 아니라 **안쪽으로 좁아지는 동심원**입니다. 바깥 원의 성질을 안쪽 원이 모두 물려받습니다.

```text
┌─ 인공지능(AI) ─ 사람의 지적 작업을 컴퓨터로 수행하는 모든 기술
│  ┌─ 머신러닝(ML) ─ 규칙을 사람이 쓰지 않고 데이터에서 학습
│  │  ┌─ 딥러닝(DL) ─ 여러 층의 신경망으로 특징까지 스스로 학습
│  │  │  ┌─ 생성형 AI ─ 학습한 분포에서 새로운 데이터를 만들어 냄
│  │  │  │   └─ LLM ─ 대규모 텍스트로 학습한, 텍스트를 생성하는 모델
```

| 구분 | 무엇이 달라졌는가 | 예시 |
|---|---|---|
| 인공지능 | 지능적 작업을 기계에 맡긴다는 목표 | 규칙 기반 전문가 시스템, 체스 프로그램 |
| 머신러닝 | 규칙 대신 **데이터**에서 패턴을 찾는다 | 스팸 필터, 집값 예측 |
| 딥러닝 | 특징 추출까지 **신경망**이 스스로 한다 | 이미지 분류, 음성 인식 |
| 생성형 AI | 분류를 넘어 새 결과물을 **생성**한다 | 이미지 생성, 텍스트 생성 |
| LLM | 생성형 AI 가운데 **텍스트**를 다루는 대규모 모델 | Qwen, Llama, GPT 계열 |

이 교재에서 다루는 Qwen2.5는 가장 안쪽 원, LLM에 속합니다. 따라서 딥러닝의 기본 부품인 행렬·가중치·학습 원리를 먼저 익혀야 LLM을 제대로 다룰 수 있습니다. 제1~3부가 바로 그 순서로 짜여 있습니다.

## LLM이 하는 일: 다음 토큰 예측

LLM이 요약하고, 번역하고, 코드를 짜는 모습은 다채로워 보입니다. 그러나 그 속에서 일어나는 일은 단 하나입니다.

> **앞의 문맥을 보고, 다음에 올 토큰의 확률을 계산해, 하나를 고른다.**

토큰(Token, 모델이 처리하는 글자 조각)은 글자 하나일 수도, 단어 일부일 수도 있습니다. 모델은 고른 토큰을 문맥 끝에 붙이고 같은 일을 다시 반복합니다.

```text
입력 문맥: "대한민국의 수도는"
  1회차 → 확률 계산 → " 서울"  선택 → "대한민국의 수도는 서울"
  2회차 → 확률 계산 → "입니다" 선택 → "대한민국의 수도는 서울입니다"
  3회차 → 확률 계산 → "."      선택 → "대한민국의 수도는 서울입니다."
  4회차 → 확률 계산 → [종료]   선택 → 생성 끝
```

이 방식을 **자기회귀(Autoregressive, 자기 출력을 다시 입력으로 쓰는 방식) 생성**이라 부릅니다. 긴 답변도 결국 이 한 걸음을 수백 번 반복한 결과입니다. 그래서 LLM의 속도는 "초당 몇 개의 토큰을 생성하는가(tokens/s)"로 잽니다. 이 장의 마지막 실습에서 바로 이 숫자를 측정합니다.

확률을 계산하는 장치의 내부, 즉 Embedding·Attention·FFN은 제2부에서 하나씩 직접 구현합니다. 지금은 "LLM = 다음 토큰 확률 계산기"라는 한 문장만 기억하면 충분합니다.

## 사전학습·파인튜닝·추론

같은 모델도 일생의 단계에 따라 하는 일과 필요한 자원이 전혀 다릅니다.

| 단계 | 하는 일 | 데이터 | 자원 규모 | 이 교재 |
|---|---|---|---|---|
| 사전학습(Pretraining) | 방대한 텍스트로 다음 토큰 예측을 처음부터 학습 | 수조 개 토큰 | 대규모 GPU 클러스터 | 원리만 소규모로(제25장) |
| 파인튜닝(Fine-tuning) | 학습된 모델을 특정 목적·형식에 맞게 추가 학습 | 수백~수만 개 예시 | 단일 PC도 가능 | **핵심 범위**(제3~5부) |
| 추론(Inference) | 학습을 마친 모델로 답을 생성 | 사용자 입력 | 노트북·엣지 장치 | **핵심 범위**(제6부) |

사전학습이 "언어와 세상에 대한 일반 지식"을 쌓는 과정이라면, 파인튜닝은 그 지식 위에 "우리 분야의 말투와 전문성"을 입히는 과정입니다. 이 교재는 이미 공개된 사전학습 모델 Qwen2.5를 출발점으로 삼아, 파인튜닝과 추론을 내 컴퓨터 안에서 끝까지 완성하는 것을 목표로 합니다.

```text
사전학습된 모델(Qwen2.5)  →  파인튜닝(내 데이터)  →  병합·변환  →  로컬 추론(Ollama)
      공개 가중치               제3~5부                제6부           제6부
```

## 로컬 AI와 두 가지 하드웨어 경로

로컬 AI란 모델이 클라우드가 아닌 **내 컴퓨터 안에서** 실행되는 것을 말합니다. 데이터가 밖으로 나가지 않고, 사용료가 들지 않으며, 네트워크 없이도 동작합니다. 대신 내 컴퓨터의 메모리와 연산 능력이 그대로 한계가 됩니다.

이 교재는 두 가지 경로를 지원합니다.

| 항목 | CPU 경로 | GT 1030 2GB 경로 |
|---|---|---|
| 연산 장치 | 다중 코어 CPU | NVIDIA GT 1030(Pascal, Compute Capability 6.1) |
| 메모리 | 시스템 RAM(16GB 이상 권장) | VRAM 2GB |
| 연산 자료형 | FP32 | FP32 |
| 강점 | 메모리가 넉넉해 큰 모델도 불러올 수 있음 | CUDA와 4비트 QLoRA를 직접 경험 |
| 제약 | GPU 전용 기능은 체험 불가 | 2GB 안에 모든 것을 맞춰야 함 |

두 경로 모두 FP32(32비트 부동소수점)를 씁니다. CPU는 원래 FP32가 기본입니다. GT 1030은 하드웨어의 16비트 연산 능력이 32비트의 1/64에 불과해, 16비트로 계산해도 빨라지지 않습니다(제02장에서 실측). 자료형의 원리는 제32장에서 자세히 다룹니다.

GT 1030의 FP32 연산 성능은 최신 다중 코어 CPU와 큰 차이가 없습니다. 따라서 GPU 경로의 가치는 속도보다 **CUDA·VRAM·양자화를 실제 장비로 경험하는 데** 있습니다. 어느 경로를 택해도 이 교재의 핵심 결과물, 즉 직접 학습한 모델을 로컬에 배포하는 일은 똑같이 완성됩니다.

가상환경은 프로젝트마다 독립된 Python 꾸러미 공간입니다. 다른 프로젝트의 라이브러리 버전과 섞이지 않으므로, 같은 명령이 언제나 같은 결과를 냅니다. 재현성은 바로 여기서 시작됩니다.

```bash
# 저장소 루트에서 가상환경 생성 → 활성화
python3 -m venv .venv
source .venv/bin/activate

# pip 최신화
python -m pip install --upgrade pip
```

PyTorch는 경로에 따라 설치 명령이 다릅니다. 핵심은 **연산 장치에 맞는 빌드**를 고르는 것입니다.

```bash
# [CPU 경로] CPU 전용 빌드: 용량이 작고 GPU 드라이버가 필요 없음
python -m pip install -r requirements/cpu.txt
```

```bash
# [GT 1030 경로] 1) 드라이버 확인: 570 이상이어야 함
nvidia-smi

# 2) Pascal을 지원하는 CUDA 12.6 빌드의 마지막 버전(2.14)으로 고정
python -m pip install -r requirements/gt1030.txt
```

GT 1030 경로에서 버전을 고정하는 이유는 분명합니다. PyTorch는 최신 CUDA 빌드에서 Pascal 세대 지원을 제외했고, Pascal을 지원하던 CUDA 12.6 빌드도 2.15부터 배포를 멈췄습니다. 버전을 고정하지 않고 최신판을 설치하면, GPU가 있어도 PyTorch가 그 GPU를 쓰지 못합니다. 다음 절의 장치 선택 함수가 이 상황을 자동으로 잡아냅니다.

## 장치 자동 선택

같은 실습 코드가 CPU와 GT 1030 어디서든 그대로 실행되어야 합니다. 그래서 모든 장은 장치를 직접 적지 않고, 공통 함수 `select_device()`에 묻습니다.

파일명: `examples/common/device.py`

```python
# 모든 장이 공유하는 장치·연산 자료형 선택 모듈
#
# 판단 순서
#   1. GPU(CUDA)를 쓸 수 있는가
#   2. 설치된 PyTorch가 이 GPU 세대(Compute Capability)를 지원하는가
#   3. 이 GPU에서 빠르고 안전한 연산 자료형은 무엇인가

import torch


def select_device(verbose: bool = True):
    """사용할 장치 이름과 연산 자료형을 함께 돌려준다.

    반환값: (device, dtype)
        device: "cuda" 또는 "cpu"
        dtype : torch.float32 / torch.float16 / torch.bfloat16
    """
    if torch.cuda.is_available():
        major, minor = torch.cuda.get_device_capability(0)
        arch = f"sm_{major}{minor}"

        # PyTorch 빌드에 이 세대의 GPU 코드가 들어 있어야 실제 연산이 가능하다.
        if arch in torch.cuda.get_arch_list():
            if major >= 8:
                # Ampere 이후: BF16 고속 연산 지원
                return "cuda", torch.bfloat16
            if major == 7:
                # Volta·Turing: FP16 고속 연산 지원, BF16 미지원
                return "cuda", torch.float16
            # Pascal 이전(GT 1030 = sm_61): FP16이 FP32의 1/64 속도이므로 FP32 사용
            return "cuda", torch.float32

        if verbose:
            print(f"[device] {arch} GPU를 설치된 PyTorch가 지원하지 않아 CPU를 사용합니다.")

    return "cpu", torch.float32
```

함수가 내리는 판단은 세 단계입니다.

| 단계 | 질문 | 아니라면 |
|---|---|---|
| 1 | GPU를 쓸 수 있는가(`is_available`) | CPU, FP32 |
| 2 | 설치된 PyTorch가 이 GPU 세대를 지원하는가(`get_arch_list`) | 이유를 출력하고 CPU, FP32 |
| 3 | GPU 세대 번호(`major`)에 맞는 자료형은 무엇인가 | 8 이상 BF16, 7은 FP16, 그 밖은 FP32 |

두 함수는 모두 `torch.cuda` 안에 있습니다.

2단계가 이 함수의 핵심입니다. `is_available()`만 확인하면 GPU가 있다고 판단하지만, 실제 연산을 시작하는 순간 "지원하지 않는 아키텍처" 오류로 멈춥니다. GT 1030 사용자가 가장 자주 만나는 함정을 미리 막는 장치입니다.

## Ollama로 첫 로컬 LLM 실행

Ollama는 내려받은 LLM을 명령 한 줄로 실행해 주는 로컬 실행기입니다. 내부적으로 llama.cpp를 사용하며, 모델을 GGUF(가중치를 한 파일에 담는 형식) 파일로 관리합니다. 제6부에서 우리가 직접 학습한 모델도 이 길을 따라 배포됩니다.

```bash
# Ollama 설치(공식 설치 스크립트): 설치 후 백그라운드 서버가 자동 실행됨
curl -fsSL https://ollama.com/install.sh | sh

# 설치 확인
ollama --version

# 이 교재의 기본 모델 받기(약 400MB)
ollama pull qwen2.5:0.5b

# 대화형 실행: 질문을 입력하고, 끝낼 때는 /bye
ollama run qwen2.5:0.5b
```

GT 1030 사용자는 다음 명령으로 모델이 GPU에 올라갔는지 확인합니다. `PROCESSOR` 열이 `100% GPU`이면 모델 전체가 VRAM에서 실행되고 있다는 뜻입니다.

```bash
# 실행 중인 모델과 적재 위치 확인
ollama ps
```

Ollama는 실행과 동시에 `127.0.0.1:11434`에서 HTTP API(프로그램끼리 요청을 주고받는 창구) 서버를 엽니다. 대화창 대신 Python 코드로 질문을 보내면, 응답과 함께 **생성 통계**를 숫자로 받을 수 있습니다. 다음 절의 핵심 실습은 바로 이 통계를 이용합니다.

import json
import os
import platform
import sys
from pathlib import Path

# examples/common 모듈을 불러오기 위해 상위 폴더(examples)를 검색 경로에 추가한다.
sys.path.insert(0, str(Path(__file__).resolve().parents[1]))

import torch  # noqa: E402
from common.device import select_device  # noqa: E402


def read_total_ram_gib() -> float:
    """Linux의 /proc/meminfo에서 전체 메모리를 GiB 단위로 읽는다."""
    try:
        with open("/proc/meminfo", encoding="utf-8") as f:
            for line in f:
                if line.startswith("MemTotal:"):
                    kib = int(line.split()[1])
                    return round(kib / 1024 / 1024, 1)
    except OSError:
        pass
    return -1.0


def collect_report() -> dict:
    """환경 정보를 사전(dict) 하나로 모은다."""
    device, dtype = select_device(verbose=False)

    report = {
        "os": platform.platform(),
        "python": platform.python_version(),
        "torch": torch.__version__,
        "torch_cuda_build": torch.version.cuda,      # CPU 전용 빌드면 None
        "cpu_cores": os.cpu_count(),
        "ram_gib": read_total_ram_gib(),
        "device": device,
        "dtype": str(dtype).replace("torch.", ""),
        "gpu": None,
    }

    if device == "cuda":
        props = torch.cuda.get_device_properties(0)
        free_b, total_b = torch.cuda.mem_get_info(0)
        report["gpu"] = {
            "name": props.name,
            "compute_capability": f"{props.major}.{props.minor}",
            "vram_total_mib": total_b // 2**20,
            "vram_free_mib": free_b // 2**20,
            "bf16_fast": props.major >= 8,
        }
    return report


def smoke_test(device: str, dtype: torch.dtype) -> float:
    """선택한 장치에서 작은 행렬곱을 실행해 결과를 CPU FP32 계산과 비교한다."""
    torch.manual_seed(0)
    a = torch.randn(64, 64)
    b = torch.randn(64, 64)
    expected = a @ b
    actual = (a.to(device, dtype) @ b.to(device, dtype)).float().cpu()
    return (actual - expected).abs().max().item()


def main() -> None:
    report = collect_report()
    dtype = getattr(torch, report["dtype"])
    report["smoke_test_max_abs_error"] = smoke_test(report["device"], dtype)

    print("=== 로컬 실습 환경 점검 ===")
    for key, value in report.items():
        print(f"{key:>24} : {value}")

    out = Path(__file__).with_name("env_report.json")
    out.write_text(json.dumps(report, ensure_ascii=False, indent=2), encoding="utf-8")
    print(f"\n보고서 저장: {out.name}")


if __name__ == "__main__":
    main()

**핵심 코드 풀이**

- `collect_report()`는 운영체제·Python·PyTorch 버전과 `select_device()`의 판단 결과를 한 사전에 모읍니다. GPU를 쓸 때만 이름·세대·VRAM을 추가합니다.
- `torch.cuda.mem_get_info(0)`는 지금 이 순간 비어 있는 VRAM과 전체 VRAM을 바이트 단위로 돌려줍니다. 화면 출력에 GPU를 쓰고 있다면 비어 있는 양이 눈에 띄게 줄어듭니다.
- `smoke_test()`는 선택된 장치에서 64×64 행렬곱을 실제로 실행하고, CPU FP32 결과와의 최대 차이를 잽니다. 장치가 "있다"는 것을 넘어 "제대로 계산한다"는 것을 확인하는 단계입니다.
- 보고서는 `env_report.json`으로 저장됩니다. 앞으로 문제가 생기면 이 파일이 가장 먼저 확인할 기준 기록이 됩니다.

### 실습 2. 로컬 LLM 질의와 생성 속도 측정

파일명: `examples/ch01/ollama_generate.py`

```python
# 제01장 핵심 실습 2: Ollama API로 로컬 LLM에 질문하고 생성 속도 측정
#
# 준비: ollama pull qwen2.5:0.5b  (Ollama 서버가 실행 중이어야 한다)
# 실행: python examples/ch01/ollama_generate.py "질문"

import json
import sys
import urllib.error
import urllib.request

OLLAMA_URL = "http://127.0.0.1:11434/api/generate"
MODEL = "qwen2.5:0.5b"


def generate(prompt: str, url: str = OLLAMA_URL, model: str = MODEL,
             timeout: float = 120.0) -> dict:
    """프롬프트 하나를 보내고 응답 JSON 전체를 돌려준다.

    temperature 0과 고정 seed로 같은 질문에 같은 답이 나오게 한다(재현성).
    """
    payload = {
        "model": model,
        "prompt": prompt,
        "stream": False,
        "options": {"temperature": 0, "seed": 42},
    }
    request = urllib.request.Request(
        url,
        data=json.dumps(payload).encode("utf-8"),
        headers={"Content-Type": "application/json"},
    )
    with urllib.request.urlopen(request, timeout=timeout) as response:
        return json.loads(response.read().decode("utf-8"))


def tokens_per_second(result: dict) -> float:
    """생성 토큰 수(eval_count)를 생성 시간(eval_duration, 나노초)으로 나눈다."""
    duration_ns = result.get("eval_duration", 0)
    if duration_ns <= 0:
        return 0.0
    return result.get("eval_count", 0) / (duration_ns / 1e9)


def main() -> None:
    prompt = sys.argv[1] if len(sys.argv) > 1 else "LLM을 한 문장으로 설명해 주세요."
    try:
        result = generate(prompt)
    except urllib.error.URLError as error:
        print(f"Ollama 서버에 연결할 수 없습니다: {error.reason}")
        print("확인: 'ollama serve' 실행 여부, 'ollama pull qwen2.5:0.5b' 완료 여부")
        sys.exit(1)

    print("=== 응답 ===")
    print(result.get("response", "").strip())
    print("\n=== 생성 통계 ===")
    print(f"입력 토큰 수   : {result.get('prompt_eval_count', 0)}")
    print(f"생성 토큰 수   : {result.get('eval_count', 0)}")
    print(f"초당 생성 토큰 : {tokens_per_second(result):.1f} tokens/s")


if __name__ == "__main__":
    main()
```

예상 출력 형식(응답 문장과 숫자는 장치·버전에 따라 달라짐, 교재 검증 환경에서 미검증):

```text
=== 응답 ===
(모델이 생성한 한 문장)

=== 생성 통계 ===
입력 토큰 수   : (질문의 토큰 수)
생성 토큰 수   : (응답의 토큰 수)
초당 생성 토큰 : (장치별 측정값) tokens/s
```

**핵심 코드 풀이**

- `payload`의 `"stream": False`는 응답을 토큰 단위로 나눠 받지 않고 한 번에 받겠다는 뜻입니다. 토큰 단위 수신(Streaming)은 제57장에서 다룹니다.
- `"temperature": 0`과 고정 `"seed"`는 매번 가장 확률 높은 토큰을 고르게 해, 같은 질문에 같은 답이 나오도록 합니다. 결과를 비교·검증하려면 생성이 재현되어야 하기 때문입니다.
- 응답 JSON의 `eval_count`는 생성한 토큰 수, `eval_duration`은 생성에 걸린 시간(나노초)입니다. 둘을 나눈 값이 초당 생성 토큰 수입니다.
- 이 숫자가 바로 02절의 "한 걸음씩 반복하는 생성"을 눈으로 보여 주는 증거입니다. 답이 길어질수록 생성 토큰 수와 시간이 함께 늘어납니다.
- 연결에 실패하면 원인을 짐작할 수 있는 안내를 출력하고 종료합니다. 오류를 숨기지 않고 이유를 드러내는 것이 실습 코드의 기본 원칙입니다.

**확인 과제:** 짧은 질문과 "다섯 문장으로 설명해 주세요" 같은 긴 답변 요청을 각각 보내 보세요. 생성 토큰 수는 크게 달라지지만 초당 생성 토큰 수는 비슷하게 유지됩니다. 생성 속도는 문장의 길이가 아니라 **장치와 모델 크기**가 결정한다는 뜻입니다.

## 검증과 완료 기준

실습이 의도대로 동작하는지 테스트 코드로 확인합니다. 테스트는 실제 GPU나 Ollama가 없어도 실행되도록 **모의 실험(mock, 실제 대상을 흉내 내는 가짜 객체)**을 사용합니다. 장치 선택은 다섯 가지 GPU 상황을 흉내 내 판단을 검사하고, Ollama 클라이언트는 작은 가짜 서버를 띄워 요청·응답을 검사합니다.

# 제01장 검증 테스트
#
# 실행: python -m pytest examples/ch01 -q
#
# 실제 GPU나 Ollama가 없어도 실행되도록, 장치 상태와 Ollama 서버를 모의(mock)로 흉내 낸다.

import json
import sys
import threading
from http.server import BaseHTTPRequestHandler, HTTPServer
from pathlib import Path

import pytest
import torch

sys.path.insert(0, str(Path(__file__).resolve().parents[1]))
sys.path.insert(0, str(Path(__file__).resolve().parent))

from common.device import select_device  # noqa: E402
import check_env  # noqa: E402
import ollama_generate  # noqa: E402


# ── 1. 장치 선택 모의 실험 ──────────────────────────────────────────────

def fake_gpu(monkeypatch, available, capability=(6, 1), arch_list=("sm_61",)):
    """torch.cuda의 판단 함수를 바꿔 원하는 GPU 상황을 흉내 낸다."""
    monkeypatch.setattr(torch.cuda, "is_available", lambda: available)
    monkeypatch.setattr(torch.cuda, "get_device_capability", lambda i=0: capability)
    monkeypatch.setattr(torch.cuda, "get_arch_list", lambda: list(arch_list))


@pytest.mark.parametrize(
    "available, capability, arch_list, expected",
    [
        (False, (0, 0), (), ("cpu", torch.float32)),                     # GPU 없음
        (True, (6, 1), ("sm_75", "sm_80"), ("cpu", torch.float32)),      # GT 1030 + 미지원 빌드
        (True, (6, 1), ("sm_61", "sm_75"), ("cuda", torch.float32)),     # GT 1030 + cu126 빌드
        (True, (7, 5), ("sm_75",), ("cuda", torch.float16)),             # Turing
        (True, (8, 6), ("sm_86",), ("cuda", torch.bfloat16)),            # Ampere
    ],
)
def test_select_device(monkeypatch, available, capability, arch_list, expected):
    fake_gpu(monkeypatch, available, capability, arch_list)
    assert select_device(verbose=False) == expected


# ── 2. 환경 보고서 ──────────────────────────────────────────────────────

def test_report_has_required_fields():
    report = check_env.collect_report()
    for key in ("os", "python", "torch", "device", "dtype", "ram_gib"):
        assert key in report


def test_smoke_test_on_selected_device():
    device, dtype = select_device(verbose=False)
    error = check_env.smoke_test(device, dtype)
    # FP32는 거의 0, 16비트 자료형은 정밀도가 낮아 기준을 넓게 잡는다.
    limit = 1e-4 if dtype == torch.float32 else 0.5
    assert error <= limit


# ── 3. Ollama API 클라이언트(모의 서버) ─────────────────────────────────

FAKE_RESPONSE = {
    "model": "qwen2.5:0.5b",
    "response": "LLM은 다음 토큰을 예측하는 언어 모델입니다.",
    "done": True,
    "prompt_eval_count": 12,
    "eval_count": 20,
    "eval_duration": 500_000_000,   # 0.5초(나노초 단위)
}


class FakeOllama(BaseHTTPRequestHandler):
    received = {}

    def do_POST(self):
        length = int(self.headers["Content-Length"])
        FakeOllama.received = json.loads(self.rfile.read(length))
        body = json.dumps(FAKE_RESPONSE).encode("utf-8")
        self.send_response(200)
        self.send_header("Content-Type", "application/json")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def log_message(self, *args):
        pass


def test_generate_with_fake_server():
    server = HTTPServer(("127.0.0.1", 0), FakeOllama)
    thread = threading.Thread(target=server.serve_forever, daemon=True)
    thread.start()
    try:
        url = f"http://127.0.0.1:{server.server_port}/api/generate"
        result = ollama_generate.generate("테스트", url=url)
    finally:
        server.shutdown()

    # 요청: 재현성 설정(temperature 0, seed 고정)이 실제로 전송되었는가
    assert FakeOllama.received["stream"] is False
    assert FakeOllama.received["options"] == {"temperature": 0, "seed": 42}
    # 응답: 20개 토큰 / 0.5초 = 40 tokens/s
    assert result["response"] == FAKE_RESPONSE["response"]
    assert ollama_generate.tokens_per_second(result) == pytest.approx(40.0)


def test_tokens_per_second_zero_duration():
    assert ollama_generate.tokens_per_second({"eval_count": 5, "eval_duration": 0}) == 0.0

## 핵심 정리

- LLM은 앞 문맥으로 다음 토큰의 확률을 계산해 하나씩 고르는 일을 반복하는 모델입니다. 생성 속도를 tokens/s로 재는 이유도 여기에 있습니다.
- 이 교재는 공개된 사전학습 모델 위에서 **파인튜닝과 로컬 추론**을 끝까지 완성하는 데 집중합니다.
- CPU와 GT 1030 두 경로 모두 FP32로 계산하며, 공통 함수 `select_device()`가 장치와 자료형을 자동으로 고릅니다.
- 가상환경과 버전 고정은 "같은 명령, 같은 결과"를 보장하는 재현성의 출발점입니다.

**다음 장 연결:** 제02장에서는 오늘 고른 두 장치, CPU와 GPU가 행렬 연산을 어떻게 다르게 처리하는지 실측으로 비교하고, VRAM 2GB가 실제로 얼마만큼의 공간인지 측정합니다.
