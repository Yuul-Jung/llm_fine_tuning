## 장 개요

제15장에서 Attention을 재현할 때 한 부품만 라이브러리에서 빌렸습니다. 토큰의 위치를 알려 주는 RoPE입니다. 이 장은 그 마지막 부품을 직접 만듭니다.

Attention에는 뜻밖의 약점이 있습니다. 행렬곱으로 모든 토큰 쌍을 한꺼번에 계산하다 보니, **토큰의 순서를 전혀 모릅니다**. "개가 사람을 물었다"와 "사람이 개를 물었다"가 같은 토큰들로 이루어져 있다면, 위치 정보 없는 Attention에게 두 문장은 구별되지 않습니다. RoPE(Rotary Position Embedding, 회전 위치 임베딩)는 Query와 Key를 **위치만큼 회전**시켜 이 문제를 풉니다. 회전이라는 간단한 아이디어가 "두 토큰이 얼마나 떨어져 있는가"를 점수에 자연스럽게 녹여 넣는 과정을 따라가고, 직접 구현한 RoPE로 실제 모델의 Attention 출력을 다시 재현합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | Attention은 왜 순서를 모르며, 회전으로 어떻게 위치를 알려 주는가 |
| 실습 결과물 | 순서 무관성 확인, 상대 거리 성질 확인, 회전 속도표, 직접 구현 RoPE로 실제 모델 재현 |
| 실습 파일 | `examples/ch16/`의 `rope.py`, `qwen_rope.py`, `test_ch16.py` |
| 선수 장 | 제04장(내적), 제13장(Attention), 제15장(실제 모델 재현) |

```text
Q, K [batch, heads, seq, 64]
   │ 위치 p의 토큰: 64칸을 32쌍으로 묶고, 쌍마다 p × (회전 속도)만큼 회전
   ▼
회전된 Q, K   → Q·K 점수가 "두 위치의 차이"에만 의존하게 됨
   ▼
Attention(제13~15장)
```

## 위치 정보가 필요한 이유

제13장의 Attention 계산을 다시 보면, 어디에도 "몇 번째 토큰인가"가 들어가지 않습니다. 점수는 Query와 Key의 내적일 뿐이고, 내적은 두 벡터의 값만 봅니다.

그래서 입력 토큰의 순서를 섞으면 출력도 **똑같이 섞일 뿐**, 각 토큰이 받는 결과는 바뀌지 않습니다. 핵심 실습 1번에서 이 사실을 확인합니다. 순서를 섞은 입력의 출력이, 원래 출력을 같은 순서로 섞은 것과 정확히 같습니다. 이런 성질을 순열 등변성(Permutation Equivariance)이라 부릅니다.

언어에서 순서는 의미의 절반입니다. 제14장의 Causal Mask가 "앞인지 뒤인지"는 알려 주지만, "얼마나 떨어져 있는지"까지는 알려 주지 못합니다. 그래서 위치 정보를 따로 넣어 줘야 합니다.

## 절대 위치와 상대 위치

위치를 알려 주는 방법은 크게 두 가지 관점이 있습니다.

| 관점 | 알려 주는 것 | 예 |
|---|---|---|
| 절대 위치 | "나는 5번째 토큰이다" | Sinusoidal 위치 인코딩, 학습형 위치 임베딩 |
| 상대 위치 | "너와 나는 3칸 떨어져 있다" | RoPE |

### Sinusoidal 위치 인코딩

원조 Transformer는 위치마다 사인·코사인 값으로 만든 고정 벡터를 임베딩에 **더했습니다**. 위치 0, 1, 2…마다 서로 다른 무늬의 벡터가 붙으므로 모델이 위치를 구별할 수 있습니다.

하지만 더하는 방식은 위치 정보가 토큰의 의미 벡터와 섞여 버리고, 학습 때 본 길이보다 긴 문장에서는 처음 보는 위치 벡터를 만나게 됩니다. 무엇보다 언어에서 중요한 것은 대개 "5번째 토큰"이라는 절대 위치보다 "바로 앞 토큰", "세 칸 앞 토큰" 같은 **상대 거리**입니다.

## 회전 행렬과 RoPE

RoPE의 아이디어는 2차원 회전에서 출발합니다. 2차원 벡터를 각도 θ만큼 돌리는 회전 행렬은 다음과 같습니다.

```text
┌ cosθ  -sinθ ┐ ┌ x₁ ┐   =   ┌ x₁cosθ - x₂sinθ ┐
└ sinθ   cosθ ┘ └ x₂ ┘       └ x₁sinθ + x₂cosθ ┘
```

회전은 벡터의 길이를 바꾸지 않고 방향만 바꿉니다. 그리고 회전에는 중요한 성질이 있습니다. 두 벡터를 각각 α, β만큼 돌린 뒤 내적하면, 결과는 **두 각도의 차이 α − β에만** 의존합니다. 둘을 같은 만큼 더 돌려도 사이각은 그대로이기 때문입니다.

RoPE는 이 성질을 그대로 씁니다.

```text
위치 m의 Query를 m × ω만큼 회전,   위치 n의 Key를 n × ω만큼 회전
회전된 Query · 회전된 Key  =  (m − n) × ω 에만 의존하는 값
                           =  두 토큰의 상대 거리에만 의존
```

위치를 임베딩에 더하지 않고 Q·K의 방향에 새기므로, 토큰의 의미(벡터의 길이와 내용)는 건드리지 않습니다. 점수에는 "얼마나 떨어져 있는가"가 자연스럽게 반영됩니다. 핵심 실습 3번에서 (3, 1), (10, 8), (100, 98)처럼 거리가 2로 같은 위치 쌍의 점수가 정확히 같은 것을 확인합니다.

### 64차원에서의 회전: 32개의 쌍

Query와 Key는 2차원이 아니라 64차원(head_dim)입니다. RoPE는 64칸을 2칸씩 짝지어 32쌍의 2차원 벡터로 보고, 쌍마다 따로 회전시킵니다. Qwen2·Llama 계열은 앞 절반의 `i`번째 칸과 뒤 절반의 `i`번째 칸, 즉 `(i, i + 32)`를 한 쌍으로 묶습니다.

```text
칸 번호:   0  1  2 … 31 │ 32 33 34 … 63
쌍:        ①  ②  ③ … ㉜ │ ①  ②  ③ … ㉜
```

이 묶는 방식은 모델마다 다를 수 있으며, 실제 모델과 다르게 묶으면 계산은 오류 없이 끝나지만 결과가 달라집니다. 제15장의 GQA 복제 순서와 같은 종류의 함정입니다. 그래서 이 장의 구현은 라이브러리 결과와 한 자리까지 대조합니다.

### 회전 공식을 한 번에

쌍마다 회전 행렬을 곱하는 대신, 다음 식으로 32쌍을 한꺼번에 회전시킵니다.

```text
회전된 x = x × cos(각도) + rotate_half(x) × sin(각도)
rotate_half([x₁, x₂]) = [-x₂, x₁]          (x₁: 앞 절반, x₂: 뒤 절반)
```

`rotate_half`는 모든 쌍을 90도 돌린 벡터를 만들고, 원래 벡터와 섞어 원하는 각도의 회전을 만듭니다. 위의 2차원 회전 행렬을 펼친 식과 같습니다.

## rope_theta와 구현

32쌍은 모두 같은 속도로 돌지 않습니다. 앞쪽 쌍은 빠르게, 뒤쪽 쌍은 느리게 돕니다.

```text
쌍 i의 회전 속도 = θ^(−2i / 64),   i = 0 … 31
위치 p에서 쌍 i의 회전각 = p × θ^(−2i / 64)
```

여기서 θ가 `config.json`의 `rope_theta`이며, Qwen2.5는 1,000,000입니다. 시계의 초침·분침·시침처럼, 빠른 쌍은 가까운 거리를 세밀하게 구별하고 느린 쌍은 먼 거리를 구별합니다.

| 쌍 | θ = 10,000(원조 방식) | θ = 1,000,000(Qwen2.5) |
|---|---|---|
| 0 | 약 6토큰마다 한 바퀴 | 약 6토큰마다 한 바퀴 |
| 16 | 약 628토큰 | 약 6,283토큰 |
| 31 | 약 47,000토큰 | 약 4,080,000토큰 |

θ가 클수록 느린 쌍이 훨씬 천천히 돌아, 아주 긴 문맥에서도 위치가 한 바퀴 돌아 겹치지 않습니다. Qwen2.5가 큰 θ를 쓰는 것은 긴 문맥(최대 32,768토큰)을 다루기 위해서입니다. 이 값을 잘못 쓰면 모델은 오류 없이 다른 결과를 냅니다. 실습 2에서 확인합니다.

## 핵심 실습

### 실습 1. RoPE 직접 구현과 성질 확인

파일명: `examples/ch16/rope.py`

```python
# 제16장 핵심 실습: RoPE(회전 위치 임베딩) 직접 구현
#
# 실행: python examples/ch16/rope.py
#
# head_dim 64를 앞 절반(0~31)과 뒤 절반(32~63)으로 나누고, i번째 칸과 (i+32)번째 칸을
# 한 쌍으로 묶어 위치 × 주파수만큼 회전시킨다(Qwen2·Llama 계열의 방식).

import math

import torch


def inv_freq(head_dim: int, theta: float) -> torch.Tensor:
    """쌍마다 회전 속도: θ^(-2i/d), i = 0 … d/2-1. 앞쪽 쌍은 빠르게, 뒤쪽 쌍은 느리게 돈다."""
    return 1.0 / theta ** (torch.arange(0, head_dim, 2).float() / head_dim)


def rope_cos_sin(seq: int, head_dim: int, theta: float) -> tuple:
    """위치 p, 쌍 i의 회전각 = p × inv_freq[i]. 앞·뒤 절반이 같은 각을 쓰도록 이어 붙인다."""
    angles = torch.outer(torch.arange(seq).float(), inv_freq(head_dim, theta))  # [seq, d/2]
    angles = torch.cat([angles, angles], dim=-1)                                # [seq, d]
    return angles.cos(), angles.sin()


def rotate_half(x: torch.Tensor) -> torch.Tensor:
    """[x₁, x₂] → [-x₂, x₁]: 쌍 (x₁[i], x₂[i])를 90도 돌린 벡터"""
    half = x.shape[-1] // 2
    return torch.cat([-x[..., half:], x[..., :half]], dim=-1)


def apply_rope(x: torch.Tensor, cos: torch.Tensor, sin: torch.Tensor) -> torch.Tensor:
    """2차원 회전 공식 x·cosθ + (x를 90도 돌린 것)·sinθ 를 모든 쌍에 한 번에 적용"""
    return x * cos + rotate_half(x) * sin


def rotate_2d(v: torch.Tensor, angle: float) -> torch.Tensor:
    """2차원 벡터 하나를 회전 행렬로 돌린다(비교용)."""
    r = torch.tensor([[math.cos(angle), -math.sin(angle)],
                      [math.sin(angle), math.cos(angle)]])
    return r @ v


def sinusoidal_pe(seq: int, dim: int) -> torch.Tensor:
    """원조 Transformer의 절대 위치 인코딩: 임베딩에 더하는 고정 벡터"""
    pe = torch.zeros(seq, dim)
    pos = torch.arange(seq).float()[:, None]
    freq = 1.0 / 10000 ** (torch.arange(0, dim, 2).float() / dim)
    pe[:, 0::2] = torch.sin(pos * freq)
    pe[:, 1::2] = torch.cos(pos * freq)
    return pe


def score_at(q: torch.Tensor, k: torch.Tensor, m: int, n: int, theta: float = 1e6) -> float:
    """Query를 위치 m, Key를 위치 n에 두었을 때의 RoPE 적용 내적"""
    d = q.shape[-1]
    cos, sin = rope_cos_sin(max(m, n) + 1, d, theta)
    return (apply_rope(q, cos[m], sin[m]) @ apply_rope(k, cos[n], sin[n])).item()


def main() -> None:
    torch.manual_seed(0)

    print("── 1. 위치 정보 없는 Attention은 순서를 모른다 ──")
    x = torch.randn(4, 8)
    perm = torch.tensor([2, 0, 3, 1])
    out = torch.softmax(x @ x.T, dim=-1) @ x
    out_perm = torch.softmax(x[perm] @ x[perm].T, dim=-1) @ x[perm]
    print(f"순서를 섞은 입력의 출력 = 원래 출력을 같은 순서로 섞은 것: {torch.allclose(out[perm], out_perm)}")

    print("\n── 2. 2차원 회전: 길이는 그대로, 방향만 바뀐다 ──")
    v = torch.tensor([3.0, 4.0])
    for deg in (0, 90, 180):
        r = rotate_2d(v, math.radians(deg))
        print(f"  {deg:>3}도 회전: {[round(a, 3) for a in r.tolist()]}  길이 {r.norm().item():.3f}")

    print("\n── 3. 상대 거리만 같으면 점수가 같다(head_dim 64) ──")
    q, k = torch.randn(64), torch.randn(64)
    for m, n in ((3, 1), (10, 8), (100, 98), (10, 1)):
        print(f"  Query 위치 {m:>3}, Key 위치 {n:>3} (거리 {m - n}): 점수 {score_at(q, k, m, n):+.4f}")

    print("\n── 4. 쌍마다 다른 회전 속도(한 바퀴 도는 데 필요한 토큰 수) ──")
    for theta in (1e4, 1e6):
        f = inv_freq(64, theta)
        waves = [2 * math.pi / f[i].item() for i in (0, 8, 16, 31)]
        print(f"  θ = {theta:>9,.0f}: 쌍 0 {waves[0]:.1f}, 쌍 8 {waves[1]:,.0f}, "
              f"쌍 16 {waves[2]:,.0f}, 쌍 31 {waves[3]:,.0f}")

    print("\n── 5. Sinusoidal 위치 인코딩(비교용) ──")
    pe = sinusoidal_pe(16, 8)
    print(f"  모양 {tuple(pe.shape)}: 위치마다 고정 벡터를 임베딩에 더한다. 위치 1의 값:",
          [round(a, 3) for a in pe[1].tolist()])


if __name__ == "__main__":
    main()
```

**핵심 코드 풀이**

- `inv_freq()`는 32쌍의 회전 속도, `rope_cos_sin()`은 위치마다 각도의 `cos`·`sin`을 만듭니다. `torch.cat([angles, angles])`로 앞·뒤 절반이 같은 각도를 쓰게 해, 쌍 `(i, i + 32)`가 함께 돌게 합니다.
- `apply_rope()`는 04절의 회전 공식 한 줄입니다. 묶음·헤드 축이 앞에 붙은 `[batch, heads, seq, 64]` 텐서에도 그대로 적용됩니다.
- 1번은 01절의 순열 등변성입니다. 위치 정보 없이 계산하면, 순서를 섞은 입력의 결과가 원래 결과를 섞은 것과 같습니다(`True`). 순서가 결과를 바꾸지 못한다는 뜻입니다.
- 2번은 회전이 길이를 보존함을 보여 줍니다. `[3, 4]`를 어느 각도로 돌려도 길이는 5입니다.
- 3번이 이 장의 핵심입니다. 위치가 (3, 1), (10, 8), (100, 98)로 달라져도 거리가 2로 같으면 점수가 `-1.1522`로 같고, 거리가 9이면 달라집니다. RoPE가 상대 거리만 점수에 반영한다는 증거입니다.
- 4번은 04절의 회전 속도표입니다. 쌍 0은 θ와 관계없이 약 6.3토큰마다(2π) 한 바퀴 돌고, 뒤쪽 쌍일수록 θ의 영향이 커집니다.
- 5번은 비교용 Sinusoidal 인코딩입니다. RoPE와 달리 위치마다 고정 벡터를 만들어 임베딩에 더하는 방식입니다.

### 실습 2. 직접 구현한 RoPE로 실제 모델 재현

제15장의 재현 코드에서 빌려 쓴 위치 회전 함수를 이 장의 `apply_rope`로 바꿉니다. 이제 Attention의 모든 부품이 이 교재에서 직접 만든 코드입니다.

파일명: `examples/ch16/qwen_rope.py`

```python
# 제16장 실습 2: 직접 구현한 RoPE로 바꿔 Qwen2.5 0번 계층 Attention을 다시 재현
#
# 실행: python examples/ch16/qwen_rope.py
#
# 제15장에서 빌려 쓴 apply_rotary_pos_emb 대신 이 장의 apply_rope를 쓴다.
# 이제 Attention의 모든 부품이 교재에서 직접 만든 코드다.

import sys
from pathlib import Path

ROOT = Path(__file__).resolve().parents[1]
for p in (ROOT, ROOT / "ch15", Path(__file__).resolve().parent):
    sys.path.insert(0, str(p))

import torch  # noqa: E402

from common.qwen import load_config, load_model, load_tokenizer  # noqa: E402
from mha_gqa import grouped_attention  # noqa: E402  (제15장)
from qwen_rebuild import TEXT, capture_layer0  # noqa: E402  (제15장)
from rope import apply_rope, rope_cos_sin  # noqa: E402


def rebuild_with_own_rope(model, x: torch.Tensor, theta: float) -> torch.Tensor:
    attn = model.model.layers[0].self_attn
    cos, sin = rope_cos_sin(x.shape[1], 64, theta)            # [seq, 64]

    def rope(q, k):
        return apply_rope(q, cos, sin), apply_rope(k, cos, sin)

    with torch.no_grad():
        q, k, v = attn.q_proj(x), attn.k_proj(x), attn.v_proj(x)
        return attn.o_proj(grouped_attention(q, k, v, 14, 2, rope=rope))


def main() -> None:
    config = load_config()
    theta = config.rope_parameters["rope_theta"]
    model, tok = load_model(), load_tokenizer()
    cap = capture_layer0(model, tok(TEXT, return_tensors="pt").input_ids)

    print(f"rope_theta = {theta:,.0f}, head_dim = {config.hidden_size // config.num_attention_heads}")
    mine = rebuild_with_own_rope(model, cap["x"], theta)
    print(f"직접 구현 RoPE로 재현한 Attention 출력과 실제 출력의 최대 오차: "
          f"{(mine - cap['attn']).abs().max().item():.1e}")

    wrong = rebuild_with_own_rope(model, cap["x"], 10_000.0)
    print(f"rope_theta를 10,000으로 잘못 쓰면 최대 오차: {(wrong - cap['attn']).abs().max().item():.2f}")


if __name__ == "__main__":
    main()
```

**결과 읽기**

- 직접 구현한 RoPE로 바꿔도 오차가 `3.0e-08`로, 라이브러리를 빌렸던 제15장과 같습니다. 테스트에서는 이 장의 `cos`·`sin`과 회전 결과가 Transformers의 값과 **정확히** 같은 것도 확인합니다.
- `rope_theta`를 10,000으로 잘못 쓰면 오차가 0.01로 커집니다. 작아 보이지만 허용 오차(1e-5)의 천 배이며, 첫 계층의 작은 차이는 24개 계층을 거치며 쌓입니다. 이 예제 문장은 16토큰으로 짧아 느린 쌍들이 거의 돌지 않았기 때문에 차이가 이 정도이고, 문맥이 길어질수록 차이는 커집니다.

import math
import sys
from pathlib import Path

import pytest
import torch

ROOT = Path(__file__).resolve().parents[1]
for p in (ROOT, ROOT / "ch15", Path(__file__).resolve().parent):
    sys.path.insert(0, str(p))

from rope import apply_rope, inv_freq, rope_cos_sin, rotate_2d, score_at  # noqa: E402


def test_rotation_preserves_length():
    v = torch.tensor([3.0, 4.0])
    assert rotate_2d(v, 1.234).norm().item() == pytest.approx(5.0, abs=1e-5)
    cos, sin = rope_cos_sin(50, 64, 1e6)
    x = torch.randn(50, 64)
    torch.testing.assert_close(apply_rope(x, cos, sin).norm(dim=-1), x.norm(dim=-1))


def test_rope_pair_matches_2d_rotation():
    # 쌍 (x[i], x[i+32])는 각도 p·inv_freq[i]로 회전한 2차원 벡터와 같다
    x = torch.randn(64)
    p, i = 7, 5
    cos, sin = rope_cos_sin(p + 1, 64, 1e6)
    y = apply_rope(x, cos[p], sin[p])
    angle = p * inv_freq(64, 1e6)[i].item()
    expected = rotate_2d(torch.stack([x[i], x[i + 32]]), angle)
    torch.testing.assert_close(torch.stack([y[i], y[i + 32]]), expected, atol=1e-5, rtol=1e-5)


def test_position_zero_is_identity():
    cos, sin = rope_cos_sin(1, 64, 1e6)
    x = torch.randn(64)
    torch.testing.assert_close(apply_rope(x, cos[0], sin[0]), x)


def test_relative_position_property():
    torch.manual_seed(0)
    q, k = torch.randn(64), torch.randn(64)
    assert score_at(q, k, 3, 1) == pytest.approx(score_at(q, k, 100, 98), abs=1e-3)
    assert score_at(q, k, 3, 1) != pytest.approx(score_at(q, k, 10, 1), abs=1e-3)


def test_matches_transformers():
    from transformers.models.qwen2.modeling_qwen2 import apply_rotary_pos_emb
    torch.manual_seed(1)
    cos, sin = rope_cos_sin(16, 64, 1e6)
    q, k = torch.randn(1, 14, 16, 64), torch.randn(1, 2, 16, 64)
    qh, kh = apply_rotary_pos_emb(q, k, cos[None], sin[None])
    torch.testing.assert_close(apply_rope(q, cos, sin), qh)
    torch.testing.assert_close(apply_rope(k, cos, sin), kh)


def test_first_pair_period():
    assert 2 * math.pi / inv_freq(64, 1e6)[0].item() == pytest.approx(2 * math.pi)


@pytest.fixture(scope="module")
def qwen():
    try:
        from common.qwen import load_config, load_model, load_tokenizer
        return load_config(True), load_model(True), load_tokenizer(True)
    except Exception:
        pytest.skip("Qwen 모델이 아직 내려받아지지 않음(qwen_rope.py를 먼저 실행)")


def test_rebuild_with_own_rope(qwen):
    from qwen_rebuild import TEXT, capture_layer0
    from qwen_rope import rebuild_with_own_rope
    config, model, tok = qwen
    cap = capture_layer0(model, tok(TEXT, return_tensors="pt").input_ids)
    theta = config.rope_parameters["rope_theta"]
    torch.testing.assert_close(rebuild_with_own_rope(model, cap["x"], theta), cap["attn"],
                               atol=1e-5, rtol=1e-5)

## 핵심 정리

- 위치 정보가 없는 Attention은 토큰의 순서를 모릅니다. 입력을 섞으면 출력도 똑같이 섞일 뿐입니다.
- RoPE는 위치 m의 Query와 위치 n의 Key를 각각 위치만큼 회전시켜, 두 벡터의 내적이 상대 거리 m − n에만 의존하게 만듭니다.
- 64차원을 32쌍으로 묶어 쌍마다 다른 속도로 회전시킵니다. Qwen2.5는 쌍 `(i, i + 32)`를 묶고, `rope_theta`는 1,000,000입니다.
- 회전은 `x·cos + rotate_half(x)·sin` 한 줄로 계산하며, 길이를 바꾸지 않습니다.
- 직접 구현한 RoPE로 실제 모델 Attention 출력을 오차 3×10⁻⁸로 재현했습니다. 이제 Attention의 모든 부품을 직접 만들었습니다.

**다음 장 연결:** Attention이 토큰 사이에서 정보를 모았다면, 그 정보를 토큰마다 가공하는 부품이 남았습니다. 제17장에서는 모델 파라미터의 대부분을 차지하는 FFN과, Qwen이 쓰는 SwiGLU를 직접 구현합니다.
