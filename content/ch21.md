## 장 개요

제2부에서 우리는 모델이 **어떻게 계산하는지**를 부품 하나하나까지 확인했습니다. 그런데 그 계산에 쓰인 4억 9천만 개의 숫자, 가중치는 어디서 왔을까요? 제3부는 이 질문, 모델이 **어떻게 배우는지**를 다룹니다.

이 장은 제3부의 출발점입니다. 오늘날 LLM이 만들어지는 두 단계, 사전학습과 파인튜닝의 관계를 정리하고, 같은 구조의 두 모델(Base와 Instruct)이 학습 단계에 따라 얼마나 다르게 행동하는지 직접 확인합니다. 그리고 앞으로 제3·4부의 모든 학습 실험에서 함께 쓸 **고정 데이터셋**을 준비합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 사전학습된 모델에 무엇을 더 가르치는 것이 파인튜닝이며, 언제 필요한가 |
| 실습 결과물 | Base·Instruct 모델의 응답 비교표(재현 확인), 고정 토큰 데이터와 기준 지문 |
| 실습 파일 | `examples/ch21/`의 `base_vs_instruct.py`, `fixed_dataset.py`, `test_ch21.py`, 공통 모듈 `examples/common/fixed_data.py` |
| 선수 장 | 제07장(다음 토큰 예측), 제20장(생성 설정과 Greedy) |

```text
[사전학습]  방대한 글 → 다음 토큰 예측 → Base 모델(일반 지식, 이어 쓰기)
   ↓ 가중치를 그대로 출발점으로
[파인튜닝]  대화 예시 → 같은 다음 토큰 예측 → Instruct 모델(질문에 답하기)
   ↓
[이 교재]   고정 데이터 → 손실·기울기·최적화(제22~25장) → LoRA(제26~30장)
```

## 사전학습과 전이학습

**사전학습**(Pretraining)은 모델이 처음 태어나는 단계입니다. 무작위 숫자로 채운 모델(제19장의 Qwen2-Tiny처럼)에 방대한 글을 보여 주며 제07장의 과제, "다음 토큰 맞히기"를 반복시킵니다. Qwen2.5는 약 18조 개의 토큰으로 사전학습했습니다. 0.5B 모델의 파라미터 하나당 3만 개가 넘는 토큰을 본 셈입니다.

다음 토큰을 잘 맞히려면 문법도, 사실도, 문장의 흐름도 알아야 합니다. 그래서 단순한 과제를 대규모로 반복하는 것만으로 모델 안에 언어와 세상에 대한 일반 지식이 쌓입니다. 이 단계에 드는 계산 자원은 개인이 감당할 수 있는 규모가 아닙니다.

**전이학습**(Transfer Learning)은 이렇게 얻은 가중치를 버리지 않고 새로운 과제의 출발점으로 다시 쓰는 생각입니다. 처음부터 배우는 대신, 이미 많이 아는 모델에 조금만 더 가르칩니다. 이 "조금 더 가르치는" 학습이 **파인튜닝**(Fine-tuning, 미세조정)입니다.

| 구분 | 사전학습 | 파인튜닝 |
|---|---|---|
| 출발점 | 무작위 가중치 | 사전학습된 가중치 |
| 데이터 | 방대한 일반 글(조 단위 토큰) | 목적에 맞는 적은 데이터 |
| 목표 | 일반적인 언어 능력 | 특정 형식·말투·과제 |
| 학습 원리 | 다음 토큰 예측 | 같다(다음 토큰 예측) |

마지막 줄이 중요합니다. 파인튜닝은 새로운 학습 방법이 아니라, **같은 학습을 다른 데이터로 이어서 하는 것**입니다. 그래서 제22~25장에서 익힐 손실·기울기·최적화는 사전학습과 파인튜닝 모두의 원리입니다.

## Base Model과 Instruct Model

Hugging Face에는 같은 이름에 `-Instruct`가 붙은 모델과 붙지 않은 모델이 나란히 있습니다.

| 모델 | 학습 단계 | 행동 |
|---|---|---|
| Qwen2.5-0.5B(Base) | 사전학습까지 | 주어진 글을 그럴듯하게 **이어 쓴다** |
| Qwen2.5-0.5B-Instruct | 사전학습 + 사후 학습 | 질문에 **답하고**, 답이 끝나면 멈춘다 |

두 모델은 구조, 계층 이름, 파라미터 수(494,032,768개)까지 완전히 같습니다. 다른 것은 가중치의 값뿐입니다. Instruct 모델은 Base 모델을 출발점으로 100만 개가 넘는 대화 예시로 지도 미세조정(SFT)을 하고, 사람이 선호하는 답에 가까워지도록 강화학습을 더한 모델입니다. 이 사후 학습이 바로 파인튜닝의 대표적인 예입니다.

Instruct 모델이 배운 것 중 하나는 **대화 형식**(Chat Template)입니다. 질문은 사용자 칸에, 답은 어시스턴트 칸에 쓰고, 답이 끝나면 `<|im_end|>`를 내놓는 약속입니다. 이 형식으로 넣어야 Instruct 모델이 제대로 답합니다. 형식의 자세한 구조는 제44장에서 다룹니다.

## 프롬프트, RAG, 파인튜닝

모델의 행동을 바꾸고 싶을 때 파인튜닝이 언제나 정답은 아닙니다. 바꾸고 싶은 것이 무엇인지에 따라 방법을 고릅니다.

| 방법 | 바꾸는 것 | 가중치 | 잘 맞는 경우 |
|---|---|---|---|
| 프롬프트 | 입력 문장 | 그대로 | 지시를 분명히 하거나 예시를 보여 주면 되는 일 |
| RAG | 입력에 붙이는 참고 자료 | 그대로 | 최신 정보, 사내 문서처럼 **지식**이 필요한 일 |
| 파인튜닝 | 가중치 | 바뀜 | 일정한 **형식·말투·행동**을 몸에 배게 하는 일 |

RAG(Retrieval-Augmented Generation, 검색 증강 생성)는 질문과 관련된 문서를 찾아 입력에 붙여 주는 방법입니다. 모델은 그 자료를 읽고 답하므로, 자료만 바꾸면 지식을 바로 갱신할 수 있습니다.

파인튜닝에 대한 흔한 오해는 "새 지식을 넣는 방법"이라는 것입니다. 적은 데이터로 몇 번 학습해서는 사실을 정확히 외우게 하기 어렵고, 잘못하면 원래 알던 것을 잊습니다. 이것을 파국적 망각이라 하며, 제25장에서 처음 측정하고 제50장에서 실전 데이터로 다시 측정합니다. 파인튜닝이 가장 잘하는 일은 **어떻게 답하는가**, 즉 형식과 행동을 바꾸는 것입니다. 핵심 실습의 결과에서도 이 구분이 드러납니다.

이 교재가 고르는 기준은 간단합니다. 먼저 프롬프트로 해 보고, 지식이 부족하면 RAG를 붙이고, 그래도 형식이나 행동이 원하는 대로 되지 않을 때 파인튜닝을 합니다. 세 방법은 함께 쓸 수도 있습니다.

## 실험용 고정 데이터셋

제3·4부에서는 같은 학습을 여러 방법으로 해 보고 결과를 비교합니다. Full Fine-tuning과 LoRA, FP32와 4비트 양자화, Rank 4와 Rank 16 같은 비교입니다. 공정하게 비교하려면 **바꾸는 조건 하나를 빼고 나머지는 모두 같아야** 합니다. 데이터가 그 첫 번째입니다.

그래서 이 장에서 실험용 데이터를 한 번 만들어 고정합니다.

```text
datasets/fixed/train.txt, eval.txt     이 교재를 위해 새로 쓴 일반 상식 문장
   │ Qwen2.5 토크나이저(제08~09장)
   │ 문장마다 끝에 <|endoftext|>(ID 151643)
   │ 하나로 이어 붙여 128토큰씩 자름(남는 꼬리는 버림)
   ▼
학습 블록 [25, 128], 평가 블록 [5, 128]   + 지문(16자리)
```

| 결정 | 이유 |
|---|---|
| 직접 쓴 문장 | 출처와 라이선스 문제가 없고(`datasets/LICENSES.md`), 누구나 같은 파일을 받는다 |
| 학습과 평가 분리 | 평가 문장은 같은 주제를 다르게 쓴 문장이다. 외운 것이 아니라 배운 것인지 확인한다 |
| 문장 끝 토큰 | 블록 안에서 문장이 어디서 끝나는지 모델이 알 수 있다 |
| 길이 128 | GT 1030에서 FP32로 학습할 수 있는 길이(제25장) |
| 지문 | 토큰이 하나라도 다르면 지문이 바뀐다. 실험 전에 같은 데이터인지 확인한다 |

데이터의 크기는 약 3,300토큰으로, Qwen2.5 사전학습의 약 55억분의 1입니다. 일부러 작게 만들었습니다. CPU에서 몇 분 안에 학습이 끝나야 원리를 여러 번 실험할 수 있기 때문입니다. 이 데이터는 원리 확인용이고, 실제 용도의 데이터는 제5부(제41장)에서 따로 설계합니다.

## 핵심 실습

### 실습 1. Base와 Instruct 비교

같은 질문 두 개를 Base와 Instruct 모델에 넣습니다. 입력은 평문 그대로와 대화 형식 두 가지로 넣고, 생성 설정은 Greedy로 고정합니다. 모든 조합을 두 번 실행해 결과가 같은지도 확인합니다.

파일명: `examples/ch21/base_vs_instruct.py`

```python
# 제21장 핵심 실습: 같은 구조의 Base 모델과 Instruct 모델에 같은 질문을 Greedy로 넣어 비교
#
# 실행: python examples/ch21/base_vs_instruct.py
#
# Base 모델(Qwen2.5-0.5B)은 처음 실행할 때 약 1GB를 내려받는다. 두 모델 모두 Apache 2.0 라이선스.

import hashlib
import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[1]))

import torch  # noqa: E402
from transformers import AutoModelForCausalLM  # noqa: E402
from transformers.utils import logging  # noqa: E402

from common.qwen import load_model, load_tokenizer  # noqa: E402

logging.disable_progress_bar()
logging.set_verbosity_error()

BASE_ID = "Qwen/Qwen2.5-0.5B"                                  # 대화 형식 학습 전
BASE_REVISION = "060db6499f32faf8b98477b0a26969ef7d8b9987"
QUESTIONS = ["대한민국의 수도는 어디인가요?", "물은 몇 도에서 끓나요?"]
NEW_TOKENS = 30


def load_base(local_only: bool = False):
    return AutoModelForCausalLM.from_pretrained(
        BASE_ID, revision=BASE_REVISION, dtype=torch.float32,
        local_files_only=local_only).eval()


def as_chat(tok, question: str) -> str:
    """Instruct 모델이 학습한 대화 형식(Chat Template)으로 감싼다. 자세한 구조는 제44장."""
    return tok.apply_chat_template([{"role": "user", "content": question}],
                                   tokenize=False, add_generation_prompt=True)


@torch.no_grad()
def greedy(model, tok, text: str, n: int = NEW_TOKENS) -> str:
    """생성 설정을 모두 명시해 고정한다. generation_config.json의 무작위 추출·반복 벌점을 끈다."""
    ids = tok(text, return_tensors="pt").input_ids
    out = model.generate(ids, max_new_tokens=n, do_sample=False, repetition_penalty=1.0,
                         temperature=None, top_p=None, top_k=None,
                         pad_token_id=tok.pad_token_id)
    return tok.decode(out[0, ids.shape[1]:], skip_special_tokens=True)


def run_all(models, tok) -> dict:
    results = {}
    for q in QUESTIONS:
        for form, text in (("평문", q), ("대화 형식", as_chat(tok, q))):
            for name, model in models.items():
                results[(q, form, name)] = greedy(model, tok, text)
    return results


def fingerprint(results: dict) -> str:
    joined = "\n".join(f"{k}|{v}" for k, v in sorted(results.items()))
    return hashlib.sha256(joined.encode()).hexdigest()[:16]


def main() -> None:
    tok = load_tokenizer()                       # 두 모델은 같은 토크나이저(어휘)를 쓴다
    models = {"Base": load_base(), "Instruct": load_model()}
    print(f"대화 형식 예: {as_chat(tok, QUESTIONS[0])!r}\n")

    first = run_all(models, tok)
    for (q, form, name), answer in first.items():
        if name == "Base":
            print(f"── 질문: {q} / 입력: {form} ──")
        print(f"  {name:<9}{answer.strip()[:60]!r}")
    second = run_all(models, tok)
    print(f"\n두 번 실행한 결과 동일: {first == second}  (지문 {fingerprint(first)})")


if __name__ == "__main__":
    main()
```

실행:

```bash
python examples/ch21/base_vs_instruct.py
```

**핵심 코드 풀이**

- `greedy()`는 생성 설정을 하나도 빠짐없이 적습니다. Instruct 모델의 `generation_config.json`에는 무작위 추출과 반복 벌점 1.1이 기본값으로 들어 있으므로(제20장), 설정을 비워 두면 두 모델이 서로 다른 조건으로 생성하게 됩니다. 비교 실험에서는 조건을 코드에 명시하는 것이 원칙입니다.
- `as_chat()`은 토크나이저에 들어 있는 대화 형식으로 질문을 감쌉니다. 출력 첫 줄에서 보듯 기본 시스템 문장, 사용자 칸, 어시스턴트 칸이 특수 토큰으로 구분됩니다.
- 두 모델은 어휘가 같으므로 같은 토크나이저로 입력을 만듭니다. 입력 토큰이 완전히 같아야 응답 차이를 모델의 차이로 설명할 수 있습니다.

**결과 읽기**

| 관찰 | 해석 |
|---|---|
| 평문을 받은 Base는 날짜·질문을 반복한다 | 질문을 **이어 쓸 글**로 본다. 웹 게시판의 질문 글처럼 이어 간다 |
| 대화 형식을 받은 Instruct만 답하고 멈춘다 | 대화 형식과 대화 종료 토큰으로 끝내는 법을 사후 학습으로 배웠다 |
| Base도 대화 형식에서는 "서울입니다"를 낸다 | 사실 지식은 사전학습에서 이미 생겼다. 다만 멈출 줄 몰라 엉뚱한 글이 이어진다 |
| 평문을 받은 Instruct는 질문에 따라 답하기도, 이어 쓰기도 한다 | 형식 밖의 입력에서는 사후 학습의 효과가 불안정하다 |
| Instruct도 물의 끓는점은 틀린다 | 0.5B 모델의 지식은 한계가 있다. 답하는 **형식**은 맞지만 **내용**은 틀릴 수 있다 |

마지막 두 줄이 03절의 구분을 그대로 보여 줍니다. 사후 학습(파인튜닝)은 모델에게 대화의 형식과 멈추는 법을 가르쳤지만, 모르는 사실을 알게 하지는 못했습니다. 끓는점 같은 지식이 필요하다면 RAG로 자료를 붙여 주는 편이 맞습니다.

두 번 실행한 결과가 같으므로(`True`), 이 표는 언제 실행해도 다시 얻을 수 있습니다. 결과 전체의 지문(`c2fda4d3…`)이 같으면 내 컴퓨터에서도 같은 결과를 얻은 것입니다. 다만 CPU 종류나 라이브러리 버전에 따라 계산 순서가 달라지면, 점수가 비슷한 두 토큰의 순위가 바뀌어 문장 끝부분이 달라질 수도 있습니다.

### 실습 2. 고정 데이터셋과 지문

문장 파일을 토큰 블록으로 바꾸는 공통 모듈을 만들고, 기준 지문을 기록합니다. 제22장부터는 이 모듈의 `load_blocks()` 한 줄로 같은 데이터를 불러옵니다.

파일명: `examples/common/fixed_data.py`

```python
# 제3·4부의 모든 학습 비교 실험이 함께 쓰는 고정 토큰 데이터
#
# 문장 파일(datasets/fixed/*.txt) → Qwen2.5 토크나이저 → 문장마다 끝에 <|endoftext|> →
# 하나로 이어 붙임 → 길이 SEQ_LEN의 블록으로 자름(남는 꼬리는 버림)
# 같은 파일·같은 토크나이저면 언제나 같은 토큰이 나오며, 지문(fingerprint)으로 확인한다.

import hashlib
from pathlib import Path

import torch

DATA_DIR = Path(__file__).resolve().parents[2] / "datasets" / "fixed"
SEQ_LEN = 128                                   # GT 1030 기준 학습 시퀀스 길이(제25장)


def read_lines(split: str) -> list:
    """split: "train" 또는 "eval". 빈 줄은 건너뛴다."""
    text = (DATA_DIR / f"{split}.txt").read_text(encoding="utf-8")
    return [line.strip() for line in text.splitlines() if line.strip()]


def token_stream(tok, split: str) -> list:
    ids = []
    for line in read_lines(split):
        ids += tok(line).input_ids + [tok.convert_tokens_to_ids("<|endoftext|>")]
    return ids


def make_blocks(ids: list, seq_len: int = SEQ_LEN) -> torch.Tensor:
    n = len(ids) // seq_len
    return torch.tensor(ids[: n * seq_len], dtype=torch.long).view(n, seq_len)


def load_blocks(tok, split: str, seq_len: int = SEQ_LEN) -> torch.Tensor:
    """[블록 수, seq_len] 정수 텐서"""
    return make_blocks(token_stream(tok, split), seq_len)


def fingerprint(blocks: torch.Tensor) -> str:
    """토큰 값과 모양이 하나라도 다르면 달라지는 16자리 지문"""
    data = str(tuple(blocks.shape)).encode() + blocks.numpy().astype("<i8").tobytes()
    return hashlib.sha256(data).hexdigest()[:16]
```

파일명: `examples/ch21/fixed_dataset.py`

```python
# 제21장 실습 2: 제3·4부 비교 실험의 기준이 되는 고정 토큰 데이터 만들기와 지문 확인
#
# 실행: python examples/ch21/fixed_dataset.py

import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[1]))

from common.fixed_data import SEQ_LEN, fingerprint, load_blocks, read_lines, token_stream  # noqa: E402
from common.qwen import load_tokenizer  # noqa: E402


def main() -> None:
    tok = load_tokenizer()
    print(f"── 1. 문장 파일 → 토큰 → 길이 {SEQ_LEN} 블록 ──")
    for split in ("train", "eval"):
        lines = read_lines(split)
        chars = sum(len(s) for s in lines)
        ids = token_stream(tok, split)
        blocks = load_blocks(tok, split)
        print(f"  {split:<6}문장 {len(lines):>3}개, 글자 {chars:>5,}, 토큰 {len(ids):>5,} "
              f"(글자당 {len(ids) / chars:.2f}) → 블록 {tuple(blocks.shape)}, "
              f"버린 꼬리 {len(ids) - blocks.numel()}")

    print("\n── 2. 첫 블록의 앞부분 ──")
    first = load_blocks(tok, "train")[0]
    print(f"  토큰 {first[:12].tolist()}")
    print(f"  복원 {tok.decode(first[:40])!r}")

    print("\n── 3. 지문(실험 비교의 기준값) ──")
    for split in ("train", "eval"):
        a, b = load_blocks(tok, split), load_blocks(tok, split)
        print(f"  {split:<6}{fingerprint(a)}  다시 만들어도 같음: {fingerprint(a) == fingerprint(b)}")


if __name__ == "__main__":
    main()
```

## 핵심 정리

- 사전학습은 무작위 가중치에서 방대한 글로 다음 토큰 예측을 배우는 단계이고, 파인튜닝은 그 가중치에서 출발해 적은 데이터로 같은 학습을 이어 가는 단계입니다.
- Base와 Instruct 모델은 구조가 같고 가중치만 다릅니다. Instruct 모델은 사후 학습으로 대화 형식에 답하고 멈추는 법을 배웠습니다.
- 프롬프트는 입력을, RAG는 참고 자료를, 파인튜닝은 가중치를 바꿉니다. 지식이 필요하면 RAG, 형식과 행동을 바꾸려면 파인튜닝이 맞습니다.
- 제3·4부의 비교 실험은 지문으로 고정된 같은 데이터(학습 블록 25개, 평가 블록 5개, 길이 128)를 씁니다.

**다음 장 연결:** 모델이 "다음 토큰을 얼마나 잘 맞히는가"를 숫자 하나로 재야 학습을 시작할 수 있습니다. 제22장에서는 그 숫자, Cross Entropy 손실과 Perplexity를 직접 계산하고, 고정 평가 데이터에서 Qwen2.5의 기준 Perplexity를 측정합니다.
