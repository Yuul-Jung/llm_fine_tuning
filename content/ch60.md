## 장 개요

마지막 장입니다. 제41장부터 만든 것들, 곧 데이터, 평가 기준, 학습, 오답 분석, 저장·병합, API를 **하나의 프로젝트**로 묶습니다. 한 번 실행해 결과가 나온 것만으로는 프로젝트가 끝나지 않습니다. 다른 사람이 같은 저장소를 받아 같은 절차를 따라 했을 때 같은 결과를 얻을 수 있어야 하고, 무엇이 확인되었고 무엇이 아직 확인되지 않았는지가 분명해야 합니다.

이 장은 프로젝트의 입력과 산출물에 지문(해시)을 붙이고, 판 번호·Seed·설정·결과를 한 장의 기록으로 남기며, 학습과 평가를 다시 실행해 기록과 같은 결과가 나오는지 확인합니다. 그리고 단계마다 완료·미검증·미작성을 정직하게 표시합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 데이터부터 API까지의 과정을 다른 사람이 재현할 수 있게 하려면 무엇을 남겨야 하는가 |
| 실습 결과물 | 입력·산출물 해시, 단계별 상태표, 학습·평가 재현 확인, API 연결 확인, 프로젝트 기록 파일 |
| 실습 파일 | `examples/ch60/`의 `project.py`, `test_ch60.py`, `project.json` |
| 선수 장 | 제41~53장, 제57·58장 |

```text
요구사항 → 데이터(fpga_qa) → 분할(split_v1) → 기준(eval_criteria v2) → 기준값(제47장)
   → 학습(LoRA, 15단계) → 오답 분석·test 1회(제50장) → Adapter(Revision 기록) → 병합 → API
   └ 기록: 해시 · 라이브러리 판 · Seed · 설정 · 결과 · 단계별 상태(완료 / 미검증 / 미작성)
```

## 요구사항과 데이터

프로젝트는 "무엇을 잘하는 모델을 만들 것인가"를 문장으로 정하는 데서 시작합니다. 이 교재의 프로젝트는 **FPGA·Verilog 질문에 짧은 존댓말로 정확히 답하는 로컬 모델**이었습니다. 이 요구사항이 데이터와 기준을 정했습니다.

| 요구사항 | 데이터·기준으로 바뀐 것 |
|---|---|
| FPGA·Verilog 질문 | 6개 분류 50문항, 분류마다 validation·test 1개(제41·43장) |
| 짧은 존댓말 | 답 1~4문장, 형식 준수율 기준 0.80(제43장) |
| 정확한 내용 | 문항별 핵심어, 적중률 기준 0.60(제43장) |
| 원래 능력 유지 | 일반 PPL 10% 이내 상승(제43장) |
| 로컬 실행 | 0.5B 모델, CPU·GT 1030 경로(제47~49장) |

데이터와 기준은 학습 전에 확정하고, 바꿀 때는 판 번호와 이유를 남겼습니다(기준 파일 version 2, 제43장). 다른 주제로 같은 프로젝트를 할 때도 순서는 같습니다. 요구사항을 문장으로, 그 문장을 데이터 설계와 측정 가능한 기준으로 바꾼 뒤에 학습합니다.

## 학습

설계상 기본 경로는 작은 Qwen2-Tiny의 도메인 SFT이고, GT 1030 경로는 Qwen2.5-0.5B QLoRA입니다. 이 교재의 실제 진행은 다음과 같았습니다.

| 경로 | 장 | 결과 |
|---|---|---|
| Qwen2-Tiny 전체 학습·LoRA 비교 | 제46·48장 | 루프와 범위 비교 확인. 한국어 사전학습이 없어 답 품질은 낮음 |
| 0.5B FP32 LoRA(CPU) | 제48·50장 | 확정 모델(원본-15) |
| 0.5B QLoRA(CPU 경로) | 제49장 | LoRA와 비교. GT 1030 실측은 미검증 |

어느 경로든 학습 설정(학습률, 단계, 묶음, 최대 길이, Loss 정책), Seed, 라이브러리 판을 기록해야 같은 결과를 다시 얻을 수 있습니다. 이 교재는 모든 난수에 Seed 0을 쓰고, 라이브러리 판을 `requirements/`에 고정했습니다.

## 병합·변환·배포

확정 모델은 Adapter로 저장하며 원본 Revision을 기록하고(제51장), 원본에 병합해 독립 모델로 만들었습니다(제52장). 설계상 다음 단계는 GGUF 변환과 양자화(제54·55장), Ollama 등록(제56장)이고, 그 위에 API(제57장)를 연결합니다.

이번 판에서는 GGUF 변환 도구의 설치가 허가되지 않아 **제54~56장을 아직 작성하지 못했습니다.** 그래서 이 장의 배포 경로는 병합 모델을 교재의 로컬 API 서버(Ollama와 같은 요청 형식)로 직접 제공하는 데까지입니다. 허가가 나면 변환·양자화·Ollama 단계를 채우고 이 장을 다시 판 올림합니다. 이렇게 빠진 단계를 감추지 않고 상태표에 적는 것도 프로젝트 기록의 일부입니다.

## 최종 평가와 재현성

최종 성능은 학습과 모델 선택에 쓰지 않은 test로 한 번 잰 값만 보고합니다(제50장). 이 프로젝트의 확정 모델은 형식(1.00)과 PPL 기준은 통과했지만 핵심어(0.08)는 통과하지 못해 **배포 후보로 채택하지 않았고**, 실습 절차는 끝까지 완료했습니다.

재현성은 세 겹으로 남깁니다.

| 남길 것 | 이 장의 방법 | 확인 |
|---|---|---|
| 입력이 같은가 | 데이터·분할·보강·기준 파일의 해시 | 테스트가 저장소의 현재 파일과 대조 |
| 과정이 같은가 | Seed, 설정, 라이브러리 판 | 같은 Seed로 두 번 학습해 손실 비교 |
| 결과가 같은가 | 산출물 해시, 기록된 지표 | 병합 모델의 PPL을 다시 계산해 기록과 비교 |

모델 가중치처럼 큰 산출물은 저장소에 넣지 않으므로(models/), 해시와 다시 만드는 절차를 남겨 받은 쪽이 같은 파일인지 확인할 수 있게 합니다.

# 제60장 핵심 실습: 데이터부터 API까지 전 과정의 산출물을 한 장의 기록으로 묶고, 재현성을 다시 확인한다

def sha(path: Path, n: int = 16) -> str:
    h = hashlib.sha256()
    with open(path, "rb") as f:
        for block in iter(lambda: f.read(1 << 20), b""):
            h.update(block)
    return h.hexdigest()[:n]


def versions() -> dict:
    import datasets
    import peft
    import transformers
    import trl
    return {"python": platform.python_version(), "torch": torch.__version__,
            "transformers": transformers.__version__, "peft": peft.__version__, "trl": trl.__version__,
            "datasets": datasets.__version__}


def repeat_training_check() -> tuple:
    """같은 Seed로 Qwen2-Tiny SFT를 두 번 5단계씩 학습해 손실이 똑같은지 본다(제46장 루프)"""
    from sft_loop import setup, train_sft
    runs = []
    for _ in range(2):
        _, model, tr, va = setup()
        runs.append([round(h["train_loss"], 6) for h in train_sft(model, tr, va, steps=5, log_every=1)])
    return runs[0], runs[0] == runs[1]


def main() -> None:

    from sft_loop import SFTDataset, split_rows, validate
    device, _ = select_device()
    final = json.loads((ROOT / "examples/ch50/final_test.json").read_text(encoding="utf-8"))

    hashes = {k: sha(ROOT / v) for k, v in {**FILES, **ARTIFACTS}.items()}
    for k, v in hashes.items():
        print(f"  {k:<12}{v}")
    manifest = json.loads((ROOT / "examples/ch51/manifest.json").read_text(encoding="utf-8"))
    same = manifest["adapter_sha256"].startswith(hashes["배포용 Adapter"])
    print(f"  배포용 Adapter 해시 = 제51장 대응 기록: {same}")

    print("\n── 2. 단계별 상태 ──")
    for stage, ch, state in STAGES:
        print(f"  {stage}({ch}): {state}")

    print("\n── 3. 재현 확인 ──")
    losses, same_loss = repeat_training_check()
    print(f"  Seed 0으로 두 번 학습(Tiny 5단계): 손실 {losses} → 두 번 같음 {same_loss}")
    tok = AutoTokenizer.from_pretrained(ROOT / "models" / "fpga_merged_v1")
    model = AutoModelForCausalLM.from_pretrained(ROOT / "models" / "fpga_merged_v1",
                                                 dtype=torch.float32).to(device).eval()
    ppl = validate(model, SFTDataset(tok, split_rows("validation")))["val_ppl"]
    print(f"  병합 모델의 도메인 PPL 다시 계산 {ppl:.4f} / 제52장 기록 {merged_rec['final']['ppl_after']:.4f}"
          f" → 같음 {math.isclose(ppl, merged_rec['final']['ppl_after'], rel_tol=1e-6)}")
    from local_api import Client, HFBackend, make_server
    from chat_template import SYSTEM
    backend = HFBackend.__new__(HFBackend)                        # 이미 불러온 모델을 그대로 쓴다
    backend.torch, backend.name, backend.n, backend.tok, backend.model = torch, "fpga-qwen", 40, tok, model
    srv = make_server(backend)
    ans = Client(f"http://127.0.0.1:{srv.server_address[1]}").generate("임계 경로란 무엇인가요?", system=SYSTEM)
    srv.shutdown()
    print(f"  API 연결 확인: {ans[:40]}…")

    print("\n── 4. 최종 결과(제50장, test 1회) ──")
    v = final["result"]
    hits = sum(v["keyword_hit"].values()) / len(v["keyword_hit"])

    print(f"  확정 모델 {final['chosen']}: 핵심어 {hits:.2f}, 형식 {fmts:.2f}, 도메인 PPL {v['domain_ppl']:.2f}, "
          f"일반 PPL {v['general_ppl']:.2f} → 배포 후보 불채택, 실습 완료")

    record = {

        "hashes": hashes, "versions": versions(), "seed": 0, "device": device,
        "training": {"method": "LoRA r 8, alpha 16, 모든 Linear", "lr": 2e-4, "steps": 15,
                     "batch": "4 × 누적 2", "max_length": 256, "loss": "Completion-only"},
        "final_test": {"chosen": final["chosen"], "keyword": hits, "format": fmts,
                       "domain_ppl": v["domain_ppl"], "general_ppl": v["general_ppl"], "adopted": False},
        "stages": [{"stage": s, "chapters": c, "state": t} for s, c, t in STAGES],
        "reproduced": {"training_loss_same": same_loss, "merged_ppl": ppl},

    print(f"\n  기록: {OUT.relative_to(ROOT)}, 라이브러리 {record['versions']}")

- **2번**의 상태표는 이 프로젝트가 어디까지 왔는지 보여 줍니다. 데이터부터 병합·API까지는 완료, GT 1030과 Raspberry Pi 실측, 실제 Ollama 접속은 미검증, GGUF·Ollama 장은 미작성입니다.
- **3번**에서 같은 Seed로 두 번 학습한 손실 다섯 개가 소수점 여섯째 자리까지 같고, 병합 모델의 도메인 PPL을 다시 계산한 값(12.0587)이 제52장 기록과 같습니다. API로 질문하면 답이 오지만, 임계 경로를 "신호의 최대 값과 최소 값 사이의 범위를 정하는 경로"라고 설명하는 등 내용은 틀립니다. 배포 후보로 채택하지 않은 판정과 일치합니다.
- **4번**은 제50장의 최종 test 결과를 그대로 옮긴 것입니다. 이 장에서는 test를 다시 재지 않습니다.

## 핵심 정리

- 프로젝트는 요구사항 문장에서 시작해, 그것을 데이터 설계와 측정 가능한 기준으로 바꾼 뒤에 학습합니다.
- 입력과 산출물에는 해시를, 과정에는 Seed·설정·라이브러리 판을 남기고, 다시 실행해 같은 결과가 나오는지 확인합니다.
- 최종 성능은 test 1회의 값만 보고하며, 기준 미달이면 배포 후보로 채택하지 않습니다. 실습 완료와 채택은 다른 판정입니다.
- 완료·미검증·미작성을 단계마다 정직하게 표시합니다. 빠진 단계를 감추지 않는 것이 재현 가능한 기록의 일부입니다.

**교재를 마치며:** 이 교재는 수 표현과 Transformer 구조에서 출발해, 직접 만든 데이터로 실제 모델을 학습하고, 실패를 기록하고, 저장·병합·API까지 이었습니다. 이번 판에서 남은 일은 GGUF 변환·양자화·Ollama 배포(제54~56장)와 GT 1030 실측입니다. 그 결과가 들어오면 해당 장과 이 장의 기록을 새 판으로 올립니다.
