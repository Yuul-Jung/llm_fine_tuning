## 장 개요

제31장의 고정소수점은 소수점 위치가 고정되어 있어, 간격을 촘촘히 하면 범위가 좁아지고 범위를 넓히면 간격이 거칠어졌습니다. 신경망에는 0.0001 같은 아주 작은 값과 수만 같은 큰 값이 함께 나옵니다. 이런 수를 다루려면 소수점이 값의 크기에 따라 **떠다니는** 표현, 부동소수점(Floating-point)이 필요합니다.

이 장은 IEEE 754 부동소수점의 구조를 비트 단위로 분해하고, 같은 16비트를 서로 다르게 나눈 FP16과 BF16의 차이를 확인합니다. 그리고 "16비트로 저장하고 32비트로 계산하는" 방식이 GT 1030의 기본 전략인 이유, 최신 GPU의 혼합 정밀도 학습이 GT 1030에 맞지 않는 이유를 정리합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 부동소수점은 비트를 어떻게 나누며, FP16과 BF16은 무엇을 맞바꿨는가 |
| 실습 결과물 | 세 자료형의 비트 분해와 재계산, 범위·정밀도 표, 저장 오차와 용량, Loss Scaling, 자료형별 행렬곱 속도 |
| 실습 파일 | `examples/ch32/`의 `float_bits.py`, `test_ch32.py` |
| 선수 장 | 제02장(자료형과 GT 1030), 제31장(비트와 범위) |

```text
FP32  부호 1 | 지수 8 | 가수 23     범위 넓음, 정밀함     4바이트
FP16  부호 1 | 지수 5 | 가수 10     범위 좁음, 정밀함     2바이트
BF16  부호 1 | 지수 8 | 가수 7      범위 넓음, 거칢       2바이트
```

## IEEE 754 구조

부동소수점은 수를 **과학적 표기법**처럼 저장합니다. 123.4를 1.234 × 10²로 쓰듯, 이진수로 `1.xxx × 2^지수` 꼴로 씁니다.

```text
값 = (−1)^부호 × 2^(지수 − bias) × (1 + 가수 ÷ 2^가수비트)

FP32의 −2.5:  1 | 10000000 | 01000000000000000000000
              부호 1(음수), 지수 128 − 127 = 1, 가수 0.25
              = −1 × 2¹ × 1.25 = −2.5
```

| 부분 | 결정하는 것 |
|---|---|
| 부호 1비트 | 양수인가 음수인가 |
| 지수 | **범위**: 표현할 수 있는 가장 큰 수와 가장 작은 수 |
| 가수 | **정밀도**: 1과 그다음 수 사이의 간격(가수가 m비트이면 2⁻ᵐ) |

지수는 그대로 저장하지 않고 **bias**(치우침)를 더해 저장합니다. 8비트 지수의 bias는 127이므로 지수 1은 128로 저장됩니다. 이렇게 하면 음수 지수도 부호 없이 저장할 수 있습니다. 가수 앞의 `1.`은 언제나 1이므로 저장하지 않습니다(숨은 비트). 그 덕분에 가수 비트 하나를 공짜로 얻습니다.

0.1은 이진수로 끝나지 않는 소수(0.000110011…)라 어느 자료형으로도 정확히 저장되지 않습니다. FP32는 0.1000000015, FP16은 0.0999755859, BF16은 0.1000976562가 됩니다. 가수가 짧을수록 오차가 큽니다.

## FP16과 BF16

FP16과 BF16은 둘 다 16비트이지만 비트를 다르게 나눴습니다.

| 성질 | FP16 | BF16 |
|---|---|---|
| 지수 / 가수 | 5 / 10 | 8 / 7 |
| 최댓값 | 약 65,504 | 약 3.4 × 10³⁸(FP32와 같음) |
| 1 다음 간격 | 2⁻¹⁰ ≈ 0.001 | 2⁻⁷ ≈ 0.008 |
| 선택한 것 | 정밀도 | 범위 |

FP16은 가수를 길게 두어 **정밀**하지만 범위가 좁습니다. 70,000은 무한대(`inf`)가 되고, 2 × 10⁻⁸처럼 아주 작은 값은 0이 됩니다. BF16(Brain Floating Point)은 FP32의 지수 8비트를 그대로 두고 가수를 7비트로 줄였습니다. FP32와 **범위가 같아** 넘침·사라짐 걱정이 거의 없지만, 간격이 FP16보다 8배 거칩니다. BF16은 FP32의 앞 16비트를 잘라 낸 것과 같은 구조라 FP32와 오가기도 쉽습니다.

신경망 학습에서는 범위가 정밀도보다 중요한 경우가 많습니다. Gradient나 활성값이 범위를 벗어나면 학습이 무너지지만, 끝자리가 조금 거친 것은 학습이 견딥니다. 그래서 최신 GPU(Ampere 이후)는 BF16 학습을 기본으로 씁니다. 제01장 `select_device()`가 세대별로 자료형을 고른 것이 이 때문입니다.

## 저장 자료형과 연산 자료형

자료형은 두 가지 역할을 따로 정할 수 있습니다. **어떻게 저장하느냐**(메모리)와 **어떻게 계산하느냐**(정확도·속도)입니다.

```text
저장: FP16 가중치(2바이트)  ──꺼낼 때 FP32로 변환──▶  계산: FP32 행렬곱  ──▶ FP32 결과
```

GT 1030(Pascal)은 FP16 연산 성능이 FP32의 1/64입니다(제02장). FP16으로 계산하면 오히려 느려지므로, GT 1030에서는 **FP16은 저장에만, 계산은 FP32로** 합니다. 저장을 16비트로 하면 메모리는 절반이 되고, 꺼낼 때 FP32로 바꾸는 비용은 행렬곱에 비해 작습니다. 이 "저장은 작게, 계산은 크게" 원칙은 제34·36장의 4비트 양자화에서도 그대로 쓰입니다. 4비트로 저장하고, 계산할 때 FP32(또는 BF16)로 복원합니다.

## Mixed Precision과 GradScaler

최신 GPU에서는 **혼합 정밀도**(Mixed Precision) 학습을 씁니다. 행렬곱은 16비트로 빠르게 계산하고, 가중치의 원본(Master Weight)과 갱신은 FP32로 유지합니다. PyTorch의 `torch.autocast`가 이 전환을 자동으로 합니다.

FP16으로 혼합 정밀도 학습을 하면 문제가 하나 생깁니다. Gradient는 아주 작은 값이 많은데, FP16은 약 6 × 10⁻⁸보다 작은 값을 표현하지 못해 0이 됩니다(언더플로). **Loss Scaling**은 손실에 큰 수(예: 2¹⁶ = 65,536)를 곱해 역전파 전체의 Gradient를 키운 뒤, FP32로 갱신하기 직전에 다시 나눕니다. PyTorch의 `GradScaler`가 이 배율을 자동으로 조정합니다. BF16은 범위가 FP32와 같으므로 Loss Scaling이 거의 필요 없습니다.

| GPU | 이 교재의 선택 | 이유 |
|---|---|---|
| Ampere 이후 | BF16 혼합 정밀도 | BF16 연산이 빠르고 범위가 넓다 |
| Volta·Turing | FP16 혼합 정밀도 + GradScaler | FP16 연산이 빠르지만 범위가 좁다 |
| Pascal(GT 1030) | FP32 연산, 16비트·4비트는 저장만 | FP16 연산이 1/64로 느리고 BF16 연산을 지원하지 않는다 |

## 핵심 실습

파일명: `examples/ch32/float_bits.py`

```python
# 제32장 핵심 실습: FP32·FP16·BF16을 비트로 분해하고, 같은 가중치를 세 자료형으로 저장해 비교한다
#
# 실행: python examples/ch32/float_bits.py

import sys
import time
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[1]))

import torch  # noqa: E402

from common.device import select_device  # noqa: E402

# (부호, 지수, 가수) 비트 수와 지수 치우침(bias)
LAYOUT = {torch.float32: (1, 8, 23, 127), torch.float16: (1, 5, 10, 15), torch.bfloat16: (1, 8, 7, 127)}
INT_VIEW = {torch.float32: torch.int32, torch.float16: torch.int16, torch.bfloat16: torch.int16}


def bits_of(x: float, dtype) -> str:
    _, e, m, _ = LAYOUT[dtype]
    raw = torch.tensor([x], dtype=dtype).view(INT_VIEW[dtype]).item()
    total = 1 + e + m
    return format(raw & ((1 << total) - 1), f"0{total}b")


def decode(pattern: str, dtype) -> float:
    """비트열 → (−1)^부호 × 2^(지수 − bias) × (1 + 가수 ÷ 2^가수비트). 정규수만 다룬다."""
    _, e, m, bias = LAYOUT[dtype]
    s, ex, man = int(pattern[0]), int(pattern[1:1 + e], 2), int(pattern[1 + e:], 2)
    return (-1) ** s * 2.0 ** (ex - bias) * (1 + man / 2 ** m)


def show(x: float, dtype) -> str:
    _, e, m, _ = LAYOUT[dtype]
    p = bits_of(x, dtype)
    return f"{p[0]} {p[1:1 + e]} {p[1 + e:]}  → {decode(p, dtype):.10g}"


def matmul_speed(device: str, dtype, n: int = 512, reps: int = 10) -> float:
    a = torch.randn(n, n, device=device).to(dtype)
    b = torch.randn(n, n, device=device).to(dtype)
    a @ b
    if device == "cuda":
        torch.cuda.synchronize()
    t0 = time.perf_counter()
    for _ in range(reps):
        a @ b
    if device == "cuda":
        torch.cuda.synchronize()
    return 2 * n ** 3 * reps / (time.perf_counter() - t0) / 1e9


def main() -> None:
    names = {torch.float32: "FP32", torch.float16: "FP16", torch.bfloat16: "BF16"}

    print("── 1. 비트 분해: 부호 | 지수 | 가수 → 다시 계산한 값 ──")
    for x in (0.1, -2.5):
        print(f"  {x}")
        for dt, nm in names.items():
            print(f"    {nm}  {show(x, dt)}")

    print("\n── 2. 범위와 정밀도(torch.finfo) ──")
    for dt, nm in names.items():
        f = torch.finfo(dt)
        print(f"  {nm}: 최댓값 {f.max:.3e}, 가장 작은 정규수 {f.tiny:.3e}, 1 다음 간격 {f.eps:.3e}")

    print("\n── 3. 범위 밖의 값 ──")
    for x in (70000.0, 1e-8):
        row = ", ".join(f"{nm} {torch.tensor(x, dtype=dt).float().item():.4g}" for dt, nm in names.items())
        print(f"  {x:g} → {row}")

    print("\n── 4. 같은 가중치를 세 자료형으로 저장(Qwen2-Tiny 크기 행렬, N(0, 0.02)) ──")
    torch.manual_seed(0)
    w = torch.randn(256, 768) * 0.02
    for dt, nm in names.items():
        back = w.to(dt).float()
        rel = ((back - w).norm() / w.norm()).item()
        print(f"  {nm}: {w.numel() * torch.finfo(dt).bits // 8 / 1024:.0f}KiB, 상대 오차 {rel:.2e}")

    print("\n── 5. 저장은 16비트, 계산은 FP32 ──")
    x = torch.randn(4, 768)
    exact = x @ w.T
    for dt, nm in ((torch.float16, "FP16"), (torch.bfloat16, "BF16")):
        stored = w.to(dt)
        mixed = x @ stored.float().T                    # 꺼낼 때 FP32로 올려 계산
        print(f"  {nm} 저장 → FP32 계산: 결과 상대 오차 {((mixed - exact).norm() / exact.norm()).item():.2e}")

    print("\n── 6. FP16 Gradient의 언더플로와 Loss Scaling ──")
    g = torch.tensor([2e-8, 1e-6, 1e-3])
    print(f"  FP16 그대로      {g.half().float().tolist()}")
    scaled = (g * 65536).half()                          # 손실에 2^16을 곱한 효과
    print(f"  ×65536 후 FP16  {(scaled.float() / 65536).tolist()}  (되돌릴 때 FP32에서 나눔)")

    device, _ = select_device()
    print(f"\n── 7. 행렬곱 속도(512×512, {device}, 환경마다 다름) ──")
    for dt, nm in names.items():
        try:
            print(f"  {nm}: {matmul_speed(device, dt):8.1f} GFLOPS")
        except RuntimeError as e:
            print(f"  {nm}: 실행 불가({str(e)[:40]})")


if __name__ == "__main__":
    main()
```

**결과 읽기**

- **1번**은 01절의 분해를 코드로 한 것입니다. −2.5는 세 자료형 모두 `1 | 1000…0 | 0100…`으로 정확히 저장되지만, 0.1은 가수 길이만큼만 정확합니다.
- **2번**에서 BF16의 최댓값과 가장 작은 정규수는 FP32와 거의 같고, 1 다음 간격(정밀도)은 FP16보다 8배 큽니다. 02절의 표 그대로입니다.
- **3번**에서 70,000은 FP16에서 `inf`, 10⁻⁸은 FP16에서 0이 됩니다. BF16은 두 값을 모두 담지만 7.014 × 10⁴처럼 끝자리가 거칩니다.
- **4번**에서 같은 가중치를 16비트로 저장하면 용량은 절반, 상대 오차는 FP16이 2 × 10⁻⁴, BF16이 1.7 × 10⁻³입니다. 가중치처럼 범위가 좁은 값(대부분 ±0.1 이내)은 FP16이 더 정확하게 담습니다.
- **5번**에서 16비트로 저장한 가중치를 FP32로 올려 계산한 결과의 오차는 저장 오차와 같은 수준입니다. 계산은 FP32로 했으므로 오차가 더 쌓이지 않았습니다.
- **6번**에서 2 × 10⁻⁸ 크기의 Gradient는 FP16에서 0이 되지만, 65,536배 키운 뒤 저장하고 FP32에서 되돌리면 살아남습니다. Loss Scaling의 원리입니다.
- **7번**은 행렬곱 속도입니다. 교재 검증 환경의 CPU는 16비트 행렬 연산 전용 명령(AVX-512 BF16·FP16, AMX)을 갖춰 16비트가 오히려 빠르게 나왔습니다. 이런 명령이 없는 일반 CPU에서는 16비트가 FP32보다 느린 경우가 많고, GT 1030에서는 FP16이 FP32보다 크게 느려야 합니다(제02장의 이론값 1/64). 속도는 하드웨어마다 크게 다르므로, 자신의 장비에서 실행한 값을 기록합니다.

## 검증과 완료 기준

파일명: `examples/ch32/test_ch32.py`

```python
# 제32장 검증 테스트
#
# 실행: python -m pytest examples/ch32 -q

import struct
import sys
from pathlib import Path

import pytest
import torch

sys.path.insert(0, str(Path(__file__).resolve().parent))

from float_bits import LAYOUT, bits_of, decode  # noqa: E402


def test_fp32_bits_match_struct():
    for x in (0.1, -2.5, 3.0e-5, 12345.678):
        expect = format(struct.unpack(">I", struct.pack(">f", x))[0], "032b")
        assert bits_of(x, torch.float32) == expect


@pytest.mark.parametrize("dt", list(LAYOUT))
def test_decode_matches_dtype_value(dt):
    for x in (0.1, -2.5, 0.0123, 300.0):
        assert decode(bits_of(x, dt), dt) == torch.tensor(x, dtype=dt).item()


def test_layouts_and_finfo():
    for dt, (s, e, m, bias) in LAYOUT.items():
        assert s + e + m == torch.finfo(dt).bits
        assert bias == 2 ** (e - 1) - 1
        assert torch.finfo(dt).eps == 2.0 ** -m


def test_range_vs_precision():
    assert torch.tensor(70000.0, dtype=torch.float16).isinf()
    assert torch.isfinite(torch.tensor(70000.0, dtype=torch.bfloat16))
    assert torch.tensor(2e-8, dtype=torch.float16).item() == 0.0
    w = torch.randn(1000) * 0.02
    err16 = (w.half().float() - w).abs().mean()
    errbf = (w.bfloat16().float() - w).abs().mean()
    assert err16 < errbf                                 # FP16이 더 정밀하다


def test_loss_scaling_recovers_small_gradient():
    g = torch.tensor(2e-8)
    assert g.half().item() == 0.0
    assert (g * 65536).half().float().item() / 65536 == pytest.approx(2e-8, rel=1e-3)
```

## 핵심 정리

- 부동소수점은 `(−1)^부호 × 2^(지수 − bias) × 1.가수`로 수를 저장합니다. 지수 비트가 범위를, 가수 비트가 정밀도를 정합니다.
- FP16(5/10)은 정밀하지만 범위가 좁고, BF16(8/7)은 FP32와 범위가 같지만 거칩니다. 학습에는 범위가 넓은 BF16이 유리합니다.
- 저장 자료형과 연산 자료형은 따로 정할 수 있습니다. GT 1030은 FP16·4비트를 저장에만 쓰고 FP32로 계산합니다.
- 혼합 정밀도는 16비트로 계산하고 FP32로 갱신합니다. FP16에서는 Gradient 언더플로를 막는 Loss Scaling(GradScaler)이 필요합니다.

**다음 장 연결:** 16비트로 줄이는 것은 자료형만 바꾸면 되었습니다. 8비트 이하는 정수로 바꿔야 하므로, 실수 범위를 정수 범위에 맞추는 **Scale**이 필요합니다. 제33장에서는 INT8 양자화를 직접 구현해 Qwen 가중치를 8비트로 저장해 봅니다.
