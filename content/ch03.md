## 장 개요

LLM 안에서 오가는 모든 데이터는 텐서(Tensor, 여러 차원으로 늘어선 숫자 묶음)입니다. 토큰 ID도, 임베딩 벡터도, Attention 점수도, 모델의 가중치도 모두 텐서입니다. 그래서 LLM 코드를 읽는 능력은 결국 **텐서의 모양을 읽는 능력**입니다.

이 장은 텐서의 모양을 읽고, 원하는 부분을 꺼내고, 모양을 바꾸는 기본 동작을 익힙니다. 그리고 그 동작을 조합해 Attention의 핵심 준비 단계인 **헤드 분할**을 직접 만들어 봅니다. 여기서 만든 두 함수는 제15장 Multi-Head Attention에서 그대로 다시 쓰입니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | LLM의 데이터는 어떤 모양이며, 모양을 바꿔도 내용이 보존되는가 |
| 실습 결과물 | 단계별 모양 추적 출력, 헤드 분할·결합 왕복 검증 |
| 실습 파일 | `examples/ch03/`의 `tensor_basics.py`, `head_split.py`, `test_ch03.py` |
| 선수 장 | 제01장(가상환경), 제02장(텐서 크기와 메모리) |

```text
[읽기] 차원 수(ndim) → 모양(shape) → 축(axis)
   ↓
[꺼내기] Indexing → Slicing → 메모리 공유(view)
   ↓
[바꾸기] Reshape → Squeeze·Unsqueeze → Transpose·Permute
   ↓
[핵심 실습] [2, 4, 8] → [2, 2, 4, 4] → [2, 4, 8] 왕복 후 원본과 일치
```

## 스칼라에서 텐서까지

차원이 하나 늘 때마다 텐서가 담을 수 있는 정보의 단위가 한 단계씩 커집니다. LLM의 데이터로 바꿔 보면 그 의미가 분명해집니다.

| 이름 | 차원 수 | 모양 예 | LLM에서의 의미 |
|---|---|---|---|
| 스칼라(Scalar) | 0 | `()` | 손실값 하나, 학습률 |
| 벡터(Vector) | 1 | `(8,)` | 토큰 하나의 표현(임베딩) |
| 행렬(Matrix) | 2 | `(4, 8)` | 문장 하나: 토큰 4개 × 표현 8차원 |
| 3차원 텐서 | 3 | `(2, 4, 8)` | 문장 묶음: 문장 2개 × 토큰 4개 × 표현 8차원 |
| 4차원 텐서 | 4 | `(2, 2, 4, 4)` | 헤드로 나눈 Attention 입력(이 장의 핵심 실습) |

이 교재에서 가장 자주 만나는 모양은 다음 세 축으로 이루어집니다.

```text
x.shape = [batch, seq, hidden]
           │      │    └─ hidden: 토큰 하나를 표현하는 숫자의 개수(Qwen2.5-0.5B: 896)
           │      └────── seq   : 문장 하나의 토큰 개수(시퀀스 길이)
           └───────────── batch : 한 번에 함께 처리하는 문장의 개수
```

제02장에서 Logits 메모리를 `[batch, seq, vocab]`로 계산한 것도 같은 읽기 방식입니다. 마지막 축만 hidden에서 어휘 크기(vocab)로 바뀌었을 뿐입니다.

## Shape·Dimension·Axis

세 용어는 같은 대상을 다른 각도에서 부릅니다.

| 용어 | 뜻 | PyTorch 표현 | `[2, 4, 8]` 텐서의 값 |
|---|---|---|---|
| Dimension(차원 수) | 축이 몇 개인가 | `x.ndim` | 3 |
| Shape(모양) | 축마다 길이가 얼마인가 | `x.shape` | `(2, 4, 8)` |
| Axis(축) | 몇 번째 축인가 | `dim=0`, `dim=1`, `dim=-1` | 0번 축 길이 2, 1번 축 길이 4, 2번 축 길이 8 |

축 번호는 0부터 셉니다. 음수 번호 `-1`은 "마지막 축"이라는 뜻이며, LLM 코드에서 hidden 축이나 vocab 축을 가리킬 때 즐겨 씁니다. 차원 수가 바뀌어도 마지막 축을 정확히 가리키기 때문입니다.

### 축을 따라 계산하기

합계·평균·최댓값 같은 연산에 `dim`을 주면, **그 축이 접혀서 사라집니다.**

| 연산 | 의미 | 결과 모양 |
|---|---|---|
| `x.sum(dim=0)` | 문장끼리 더한다 | `(4, 8)` |
| `x.sum(dim=1)` | 한 문장 안의 토큰끼리 더한다 | `(2, 8)` |
| `x.sum(dim=-1)` | 한 토큰 안의 표현값끼리 더한다 | `(2, 4)` |

"어느 축을 따라 계산하는가"를 정확히 읽는 것은 이후 모든 장의 기초입니다. 제06장 Softmax는 마지막 축을 따라 확률을 만들고, 제18장 RMSNorm은 마지막 축을 따라 크기를 맞춥니다.

## Indexing과 Slicing

텐서의 일부를 꺼내는 방법은 두 가지입니다. 한 칸을 고르면 그 축이 사라지고(Indexing), 범위를 고르면 그 축이 남습니다(Slicing).

| 코드 | 의미 | 결과 모양 | 쓰이는 곳 |
|---|---|---|---|
| `x[0]` | 첫 번째 문장 | `(4, 8)` | 묶음에서 한 문장 확인 |
| `x[:, -1, :]` | 모든 문장의 마지막 토큰 | `(2, 8)` | **다음 토큰 예측**에 쓰는 위치 |
| `x[:, :2, :]` | 모든 문장의 앞 두 토큰 | `(2, 2, 8)` | 문맥 일부 잘라내기 |

`x[:, -1, :]`는 특히 중요합니다. 제01장에서 배운 대로 LLM은 문맥의 **마지막 위치**에서 다음 토큰의 확률을 계산하므로, 생성 코드에는 거의 언제나 이 꺼내기가 등장합니다.

### 꺼낸 결과는 복사본이 아니다

Slicing으로 꺼낸 텐서는 원본의 복사본이 아니라 **같은 메모리를 다른 각도로 보는 창(view)**입니다. 꺼낸 쪽의 값을 바꾸면 원본도 함께 바뀝니다.

```text
first = x[0]          # 복사가 아니라 x의 일부를 가리킴
first[0, 0] = -1.0    # x[0, 0, 0]도 -1.0이 됨
```

메모리를 아끼는 똑똑한 설계이지만, 모르고 쓰면 원본 데이터를 망가뜨리는 함정이 됩니다. 원본을 지키며 따로 쓰려면 `.clone()`으로 명시적으로 복사합니다.

## Reshape, Squeeze, Unsqueeze

모양 바꾸기의 대원칙은 하나입니다. **원소의 개수와 순서는 그대로 두고, 축을 나누는 방식만 바꾼다.**

| 연산 | 하는 일 | 예 | 결과 모양 |
|---|---|---|---|
| `reshape(8, 8)` | 원소 64개를 새 모양으로 다시 나눈다 | `[2, 4, 8]` → | `(8, 8)` |
| `reshape(2, -1)` | `-1` 자리는 나머지로 자동 계산 | `[2, 4, 8]` → | `(2, 32)` |
| `squeeze(0)` | 길이 1인 축을 없앤다 | `[1, 4, 8]` → | `(4, 8)` |
| `unsqueeze(1)` | 길이 1인 축을 끼워 넣는다 | `[2, 4]` → | `(2, 1, 4)` |

`reshape`는 원소 개수가 맞아야만 성공합니다. `[2, 4, 8]`(64개)을 `(5, 13)`(65개)으로 바꾸려 하면 오류가 납니다. 모양을 바꾸기 전에 원소 개수를 곱해 보는 습관이 실수를 크게 줄여 줍니다.

### Unsqueeze가 필요한 순간

길이 1인 축을 일부러 끼워 넣는 이유는 다른 텐서와 **모양을 맞춰 함께 계산하기** 위해서입니다. 대표적인 예가 Attention 마스크입니다.

```text
마스크          [batch, seq]               = (2, 4)
unsqueeze 두 번 [batch, 1, 1, seq]         = (2, 1, 1, 4)
Attention 점수  [batch, heads, seq, seq]   = (2, 2, 4, 4)  ← 길이 1인 축이 자동으로 늘어나 맞춰짐
```

길이 1인 축이 상대 텐서의 길이에 맞춰 늘어나는 규칙을 Broadcasting(브로드캐스팅)이라 하며, 제04장에서 자세히 다룹니다.

## Transpose와 Permute

`reshape`가 축을 나누는 방식을 바꾼다면, `transpose`와 `permute`는 **축의 순서 자체를 바꿉니다.**

| 연산 | 하는 일 | `[2, 4, 8]`에 적용 | 결과 모양 |
|---|---|---|---|
| `transpose(1, 2)` | 두 축의 자리를 맞바꾼다 | 1번 축 ↔ 2번 축 | `(2, 8, 4)` |
| `permute(2, 0, 1)` | 모든 축의 순서를 새로 정한다 | (2번, 0번, 1번) 순서로 | `(8, 2, 4)` |

행렬의 전치(행과 열 바꾸기)를 여러 차원으로 넓힌 것이라 생각하면 됩니다. 제13장 Attention의 `QKᵀ`에서 Key를 전치할 때도 바로 이 연산을 씁니다.

### 연속 저장과 view·reshape의 차이

텐서의 원소는 메모리에 한 줄로 저장됩니다. `transpose`는 원소를 실제로 옮기지 않고 **읽는 순서만 바꾼** 창을 돌려주므로, 그 결과는 메모리상에서 연속적이지 않습니다(`is_contiguous() == False`).

| 방법 | 연속 저장이 아닌 텐서에서 | 특징 |
|---|---|---|
| `view()` | 오류 | 절대 복사하지 않음, 연속 저장일 때만 가능 |
| `reshape()` | 성공 | 필요하면 자동으로 복사해 새로 정렬 |
| `contiguous().view()` | 성공 | 명시적으로 복사·정렬한 뒤 `view` |

실제 LLM 코드에서 `transpose` 다음에 `reshape`나 `contiguous()`가 자주 따라오는 이유가 이것입니다. 다음 핵심 실습의 `merge_heads()`가 `view` 대신 `reshape`를 쓰는 것도 같은 이유입니다.

## 핵심 실습

지금까지 익힌 모양 바꾸기를 조합해 Attention의 준비 단계인 **헤드 분할**을 만듭니다. Multi-Head Attention은 hidden 축을 여러 조각(헤드)으로 나눠 각 조각이 따로 Attention을 계산하게 합니다(제15장). 이 실습은 그 "나누기"와 "다시 합치기"를 구현하고, 왕복한 결과가 원본과 **한 칸도 다르지 않은지** 확인합니다.

```text
[batch, seq, hidden]                 (2, 4, 8)
   │ view: hidden을 (heads, head_dim)으로 분할
[batch, seq, heads, head_dim]        (2, 4, 2, 4)
   │ transpose(1, 2): seq ↔ heads
[batch, heads, seq, head_dim]        (2, 2, 4, 4)   ← 헤드마다 독립된 [seq, head_dim] 행렬
   │ merge_heads: 역순으로 되돌리기
[batch, seq, hidden]                 (2, 4, 8)      ← 원본과 완전 일치해야 함
```

### 실습 1. 텐서 기본 동작 확인

먼저 이 장의 모든 기본 동작을 한 번에 실행해 모양을 확인합니다.

파일명: `examples/ch03/tensor_basics.py`

```python
# 제03장 실습 1: 텐서의 차원·모양·꺼내기·모양 바꾸기
#
# 실행: python examples/ch03/tensor_basics.py

import torch


def show(name: str, t: torch.Tensor) -> None:
    """텐서 이름, 차원 수, 모양을 한 줄로 출력한다."""
    print(f"{name:<28} ndim={t.ndim}  shape={tuple(t.shape)}")


def main() -> None:
    print("── 1. 스칼라에서 텐서까지 ──")
    show("스칼라(값 하나)", torch.tensor(3.0))
    show("벡터(토큰 하나의 표현)", torch.zeros(8))
    show("행렬(문장 하나)", torch.zeros(4, 8))
    show("3차원(문장 묶음)", torch.zeros(2, 4, 8))

    # LLM의 기본 모양: [batch, seq, hidden] = [문장 2개, 토큰 4개, 표현 8차원]
    x = torch.arange(2 * 4 * 8, dtype=torch.float32).reshape(2, 4, 8)

    print("\n── 2. Axis(축)별 연산 ──")
    show("x", x)
    show("x.sum(dim=0) 문장끼리 합", x.sum(dim=0))
    show("x.sum(dim=1) 토큰끼리 합", x.sum(dim=1))
    show("x.sum(dim=-1) 표현끼리 합", x.sum(dim=-1))

    print("\n── 3. Indexing과 Slicing ──")
    show("x[0] 첫 번째 문장", x[0])
    show("x[:, -1, :] 마지막 토큰", x[:, -1, :])
    show("x[:, :2, :] 앞 두 토큰", x[:, :2, :])

    # Slicing 결과는 복사본이 아니라 같은 메모리를 보는 창(view)이다.
    first = x[0]
    first[0, 0] = -1.0
    print(f"first[0, 0]을 바꾼 뒤 x[0, 0, 0] = {x[0, 0, 0].item()}  (원본도 바뀜)")
    x[0, 0, 0] = 0.0

    print("\n── 4. Reshape·Squeeze·Unsqueeze ──")
    show("x.reshape(8, 8)", x.reshape(8, 8))
    show("x.reshape(2, -1)", x.reshape(2, -1))
    mask = torch.ones(2, 4)
    show("mask [batch, seq]", mask)
    show("mask.unsqueeze(1).unsqueeze(2)", mask.unsqueeze(1).unsqueeze(2))
    show("torch.zeros(1, 4, 8).squeeze(0)", torch.zeros(1, 4, 8).squeeze(0))

    print("\n── 5. Transpose와 Permute ──")
    t = x.transpose(1, 2)
    show("x.transpose(1, 2)", t)
    show("x.permute(2, 0, 1)", x.permute(2, 0, 1))
    print(f"x 연속 저장 여부: {x.is_contiguous()},  transpose 결과: {t.is_contiguous()}")
    try:
        t.view(2, -1)
    except RuntimeError:
        print("t.view(2, -1) → 오류: 연속 저장이 아닌 텐서는 view로 모양을 바꿀 수 없음")
    show("t.reshape(2, -1) → 가능", t.reshape(2, -1))
    show("t.contiguous().view(2, -1)", t.contiguous().view(2, -1))


if __name__ == "__main__":
    main()
```


### 실습 2. 헤드 분할과 왕복 검증

파일명: `examples/ch03/head_split.py`

```python
# 제03장 핵심 실습: Attention 헤드 분할과 결합(모양 바꾸기의 왕복 검증)
#
# 실행: python examples/ch03/head_split.py
#
# [batch, seq, hidden] → [batch, heads, seq, head_dim] → [batch, seq, hidden]
# 제15장 Multi-Head Attention에서 이 두 함수를 그대로 다시 사용한다.

import torch


def split_heads(x: torch.Tensor, num_heads: int) -> torch.Tensor:
    """hidden 축을 num_heads개의 헤드로 나누고, 헤드 축을 seq 앞으로 옮긴다."""
    batch, seq, hidden = x.shape
    head_dim = hidden // num_heads
    x = x.view(batch, seq, num_heads, head_dim)     # 1) hidden → (heads, head_dim)
    return x.transpose(1, 2)                         # 2) seq ↔ heads 축 교환


def merge_heads(x: torch.Tensor) -> torch.Tensor:
    """split_heads의 역연산: 헤드 축을 되돌리고 (heads, head_dim)을 hidden으로 합친다."""
    batch, heads, seq, head_dim = x.shape
    x = x.transpose(1, 2)                            # 1) heads ↔ seq 축 되돌리기
    return x.reshape(batch, seq, heads * head_dim)   # 2) 연속 저장이 아니므로 reshape 사용


def main() -> None:
    batch, seq, hidden, heads = 2, 4, 8, 2
    x = torch.arange(batch * seq * hidden, dtype=torch.float32).reshape(batch, seq, hidden)

    print("단계별 모양 추적")
    print(f"  입력 x                 : {tuple(x.shape)}   예측 (2, 4, 8)")
    step1 = x.view(batch, seq, heads, hidden // heads)
    print(f"  1) view로 hidden 분할  : {tuple(step1.shape)} 예측 (2, 4, 2, 4)")
    y = split_heads(x, heads)
    print(f"  2) transpose(1, 2)     : {tuple(y.shape)} 예측 (2, 2, 4, 4)")
    z = merge_heads(y)
    print(f"  3) 되돌리기            : {tuple(z.shape)}   예측 (2, 4, 8)")

    print(f"\n왕복 후 원본과 완전 일치: {torch.equal(x, z)}")

    # 원소 하나의 이동 확인: x[b, s, h*head_dim + d] == y[b, h, s, d]
    b, s, h, d = 1, 2, 1, 3
    head_dim = hidden // heads
    print(f"x[{b}, {s}, {h * head_dim + d}] = {x[b, s, h * head_dim + d].item():.0f}  "
          f"→  y[{b}, {h}, {s}, {d}] = {y[b, h, s, d].item():.0f}")

    print("\n헤드 0이 보는 데이터(문장 0): 각 토큰의 hidden 앞쪽 4칸")
    print(y[0, 0])

    # 실제 Qwen2.5-0.5B 크기로 같은 함수 적용: hidden 896, Query 헤드 14
    q = torch.randn(1, 16, 896)
    print(f"\nQwen2.5-0.5B 크기: {tuple(q.shape)} → {tuple(split_heads(q, 14).shape)}")


if __name__ == "__main__":
    main()
```

**핵심 코드 풀이**

- `split_heads()`의 첫 줄 `view(batch, seq, num_heads, head_dim)`은 hidden 8칸을 "헤드 2개 × 4칸"으로 다시 묶습니다. 원소를 옮기지 않으므로 순서가 그대로이며, 연속 저장 상태라 `view`를 쓸 수 있습니다.
- 둘째 줄 `transpose(1, 2)`는 seq와 heads 축을 바꿉니다. 그 결과 `y[b, h]`가 "문장 b의 헤드 h가 보는 `[seq, head_dim]` 행렬"이 되어, 헤드마다 독립적으로 Attention을 계산할 수 있는 모양이 됩니다.
- `merge_heads()`는 역순으로 되돌립니다. `transpose` 결과는 연속 저장이 아니므로 마지막 단계에서 `view` 대신 `reshape`를 씁니다.
- `x[1, 2, 7] → y[1, 1, 2, 3]`은 원소 하나의 이동 경로입니다. hidden 7번 칸은 "헤드 1(4~7번 칸 담당)의 3번째 칸"이므로 `h = 1`, `d = 3`이 됩니다. 일반식은 `x[b, s, h × head_dim + d] = y[b, h, s, d]`입니다.
- "헤드 0이 보는 데이터"는 각 토큰 표현의 앞쪽 절반(0~3번 칸)만 모아 놓은 행렬입니다. 헤드 분할이란 결국 **표현 벡터를 칸 단위로 나눠 맡기는 것**임을 숫자로 보여 줍니다.
- 마지막 줄은 같은 함수를 실제 Qwen2.5-0.5B 크기(hidden 896, Query 헤드 14)에 적용한 결과입니다. 896 ÷ 14 = 64로, 제02장에서 계산에 사용한 head_dim 64와 일치합니다.

```python
    "shape, heads, expected",

    assert x.sum(dim=0).shape == (4, 8)
    assert x.sum(dim=1).shape == (2, 8)
    assert x.sum(dim=-1).shape == (2, 4)


def test_unsqueeze_mask_shape():
    # [batch, seq] 마스크를 Attention 점수 [batch, heads, seq, seq]에 맞추는 모양
    mask = torch.ones(2, 4)
    assert mask.unsqueeze(1).unsqueeze(2).shape == (2, 1, 1, 4)


# ── 2. 왕복 변환과 원소 위치 ─────────────────────────────────────────────

def test_round_trip_exact():
    x = sample()
    assert torch.equal(merge_heads(split_heads(x, 2)), x)


def test_round_trip_random_qwen_size():
    torch.manual_seed(0)
    x = torch.randn(2, 7, 896)
    assert torch.equal(merge_heads(split_heads(x, 14)), x)


def test_element_mapping():
    x = sample()
    y = split_heads(x, 2)
    head_dim = 4
    for b in range(2):
        for s in range(4):
            for h in range(2):
                for d in range(head_dim):
                    assert y[b, h, s, d] == x[b, s, h * head_dim + d]


# ── 3. 메모리 공유와 연속 저장 ───────────────────────────────────────────

def test_slice_shares_memory():
    x = sample()
    view = x[:, -1, :]
    view[0, 0] = -1.0
    assert x[0, -1, 0] == -1.0


def test_view_fails_after_transpose():
    t = sample().transpose(1, 2)
    assert not t.is_contiguous()
    with pytest.raises(RuntimeError):
        t.view(2, -1)
    assert t.reshape(2, -1).shape == (2, 32)
```

## 핵심 정리

- LLM 데이터의 기본 모양은 `[batch, seq, hidden]`이며, 텐서를 읽는 일은 각 축이 무엇을 뜻하는지 읽는 일입니다.
- `dim`을 준 연산은 그 축을 접어 없애고, Indexing은 축을 없애며, Slicing은 축을 남깁니다.
- Slicing 결과는 원본과 메모리를 공유하는 view입니다. 따로 쓰려면 `.clone()`으로 복사합니다.
- `reshape`는 축을 나누는 방식을, `transpose`·`permute`는 축의 순서를 바꿉니다. `transpose` 뒤에는 `view` 대신 `reshape`를 씁니다.
- 헤드 분할은 `view → transpose`, 결합은 `transpose → reshape`이며, 왕복해도 원소는 하나도 바뀌지 않습니다.
