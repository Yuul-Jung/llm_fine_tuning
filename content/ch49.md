## 장 개요

제48장의 LoRA 학습은 FP32 모델 전체(약 2GB)를 메모리에 올려야 해서 CPU에서만 할 수 있었습니다. GT 1030의 VRAM 2GB에서 같은 학습을 하려면 원본 가중치를 4비트로 줄여야 합니다. 제36~39장에서 원리를 익힌 **QLoRA**를 이제 실제 도메인 데이터에 적용합니다.

이 장은 Qwen2.5-0.5B를 NF4로 불러 제48장과 같은 LoRA를 붙이고, Gradient Checkpointing과 묶음 1 × 누적 8로 메모리를 줄여 학습합니다. 실제 데이터에서 메모리 예산을 다시 계산하고, 같은 데이터·평가 기준으로 제48장의 LoRA와 결과를 비교합니다. 비교에는 한 가지 질문이 더 붙습니다. QLoRA의 "학습 전"은 FP32 모델인가, 4비트 모델인가.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 2GB 예산 안에서 도메인 학습을 할 수 있는가, 4비트로 줄인 대가는 얼마인가 |
| 실습 결과물 | NF4 + LoRA 학습 기록(NaN·Inf 0건), 실제 데이터 메모리 예산, LoRA와 QLoRA 비교표, 답 비교 |
| 실습 파일 | `examples/ch49/`의 `qlora_sft.py`, `test_ch49.py`, `qlora.json` |
| 선수 장 | 제36~39장(NF4, 4비트 로딩, QLoRA 메모리, QLoRA 학습), 제48장(LoRA 실전) |

```text
Qwen2.5-0.5B ─NF4 + 이중 양자화(FP32 계산)─▶ prepare_model_for_kbit_training(Checkpointing)
   ─SFTTrainer(peft_config=모든 Linear r 8, 묶음 1 × 누적 8, 최대 256)─▶ Adapter(models/ch49_qlora)
   ─measure─▶ NF4 학습 전 · QLoRA 학습 후 · 제48장 LoRA와 비교
```

## 4비트 모델과 PEFT

QLoRA 학습의 준비는 세 단계이며 순서가 중요합니다.

| 순서 | 하는 일 | 빠뜨리면 |
|---|---|---|
| 1. NF4 로딩 | 원본 Linear를 4비트로, 계산은 FP32로 | 메모리가 2GB를 넘는다 |
| 2. 학습 준비 | 원본 고정, 입력 Gradient 켜기, Checkpointing | Checkpointing이 Gradient를 끊는다 |
| 3. LoRA 부착 | SFTTrainer가 peft_config로 붙인다 | 2번이 LoRA까지 고정한다(제39장) |

교재 검증 환경은 GPU가 없어 bitsandbytes의 CPU 경로로 실행합니다. 이 경로는 AVX512-BF16을 지원하는 CPU에서 평가 모드로 계산할 때 4비트 가중치를 추론 전용 배치로 바꾸고, 바뀐 뒤에는 학습이 실패합니다. 그래서 제39장의 방법으로 이 변환을 끕니다(Linear4bit 168개). GPU 경로와는 무관한 설정입니다.

LoRA 설정, 학습률, 단계 수, 분할, Label 정책은 제48장과 똑같습니다. 바뀐 것은 원본이 4비트라는 점과 메모리 설정뿐이어서, 두 결과의 차이를 4비트의 영향으로 읽을 수 있습니다.

## 메모리 설정

| 설정 | 값 | 줄이는 것 |
|---|---|---|
| 원본 가중치 | NF4 + 이중 양자화 | 가중치 약 2GB → 약 0.7GB |
| 묶음 크기와 누적 | 1 × 8 | 한 번에 계산하는 Activation(단계당 8샘플은 유지) |
| Gradient Checkpointing | 켬 | 역전파용으로 저장하는 Activation |
| 최대 길이 | 256 | 가장 긴 샘플의 Activation 상한 |

**Paged Optimizer**는 GPU 메모리가 순간적으로 모자랄 때 Optimizer 상태를 CPU 메모리로 내보내는 bitsandbytes의 기능으로, QLoRA 논문이 메모리 급증을 막으려고 함께 제안했습니다. CUDA 통합 메모리를 쓰므로 GPU 경로에서만 의미가 있습니다. 이 장의 LoRA Optimizer 상태는 67MiB 정도로 작아서, GT 1030 경로에서도 반드시 필요하지는 않습니다. 메모리가 빠듯하면 GT 1030 경로에서 Optimizer를 Paged 방식으로 바꿔 볼 수 있습니다(미검증).

## 실전 데이터 메모리 분석

제38장은 고정 데이터(256토큰 블록)로 메모리를 계산했습니다. 실제 SFT 데이터는 샘플마다 길이가 다르므로, **가장 긴 샘플**로 다시 계산합니다. 묶음이 1이면 한 번에 하나의 샘플만 계산하므로, 가장 긴 샘플이 Activation의 최댓값을 정합니다.

| 항목 | 계산 방법 |
|---|---|
| 가중치 | 4비트 번호 + absmax + Embedding·편향·RMSNorm(제37장) |
| LoRA 상태 | 학습 파라미터 × 4바이트 × 4(값, Gradient, AdamW 1·2차 모멘트) |
| Activation | 가장 긴 샘플 하나로 Checkpointing 켠 채 한 단계 실행해 측정(제38장) |

제45장에서 확인했듯 최대 길이 256에서 잘리는 샘플은 0개이고, 가장 긴 샘플은 199토큰입니다. 실제 데이터의 Activation은 고정 데이터의 256토큰보다 작습니다. 이 합계에는 CUDA 실행 환경 자체가 쓰는 메모리와 단편화 여유가 빠져 있으므로, GT 1030에서는 실제 최대 사용량을 따로 기록해야 합니다.

## LoRA와 QLoRA 결과 비교

QLoRA의 결과를 판정하려면 "학습 전"을 정해야 합니다. 두 가지 기준이 있고, 각각 다른 질문에 답합니다.

| 기준 | 답하는 질문 |
|---|---|
| NF4 기본 모델 | 이 학습이 4비트 모델을 얼마나 바꾸었는가 |
| FP32 기본 모델 | 4비트로 학습한 모델을 FP32 원본 대신 써도 되는가 |

제43장 기준 파일의 비율은 학습이 만든 변화를 재려는 것이므로, 판정은 NF4 기본 모델을 기준으로 합니다. 그러나 사용자가 실제로 받는 품질은 FP32 원본과 비교해야 알 수 있으므로 두 판정을 함께 적습니다.

## 핵심 실습

파일명: `examples/ch49/qlora_sft.py`

```python
# 제49장 핵심 실습: Qwen2.5-0.5B NF4 + LoRA를 SFTTrainer로 도메인 학습하고 제48장 LoRA와 비교한다
#
# 실행: python examples/ch49/qlora_sft.py   (교재 검증 환경 CPU 약 25분: 학습 + 평가)
#
# GT 1030 경로: 같은 스크립트가 GPU를 찾으면 cuda로 실행한다(미검증, 아래 예산표 참고).
# 만드는 파일: examples/ch49/qlora.json, models/ch49_qlora/(Adapter)

import json
import math
import sys
import time
from pathlib import Path

HERE = Path(__file__).resolve().parent
ROOT = HERE.parents[1]
for p in (HERE.parent, HERE.parent / "ch37", HERE.parent / "ch38", HERE.parent / "ch39",
          HERE.parent / "ch43", HERE.parent / "ch46", HERE.parent / "ch47", HERE.parent / "ch48"):
    sys.path.insert(0, str(p))

import torch  # noqa: E402
from transformers.utils import logging  # noqa: E402
from peft import prepare_model_for_kbit_training  # noqa: E402
from transformers import TrainerCallback  # noqa: E402

from baseline import measure  # noqa: E402                        (제47장)
from common.fixed_data import load_blocks  # noqa: E402
from common.qwen import load_tokenizer  # noqa: E402
from criteria import judge, load_criteria  # noqa: E402            (제43장)
from load_4bit import hardware, load_nf4, memory_parts  # noqa: E402   (제37장)
from lora_sft import SCOPES, lora_config  # noqa: E402             (제48장)
from qlora_memory import saved_bytes_of_step  # noqa: E402          (제38장)
from qlora_train import keep_training_layout  # noqa: E402         (제39장)
from sft_loop import SFTDataset, split_rows  # noqa: E402          (제46장)
from sft_trainer import SAME_AS_CH46, TMP, to_hf_dataset  # noqa: E402  (제47장)

logging.disable_progress_bar()
logging.set_verbosity_error()
ADAPTER = ROOT / "models" / "ch49_qlora"
MiB = 2 ** 20
# GT 1030 경로 설정: 묶음 1 × 누적 8 = 단계당 8샘플(제48장과 같음), Checkpointing, 최대 256
QLORA = {"per_device_train_batch_size": 1, "gradient_accumulation_steps": 8, "gradient_checkpointing": True,
         "gradient_checkpointing_kwargs": {"use_reentrant": False}, "learning_rate": 2e-4}


class FiniteCheck(TrainerCallback):
    """기록마다 손실·Gradient 노름이 유한한지 센다"""

    def __init__(self):
        self.bad = 0

    def on_log(self, args, state, control, logs=None, **kw):
        for k in ("loss", "grad_norm", "eval_loss"):
            if k in (logs or {}) and not math.isfinite(float(logs[k])):
                self.bad += 1


def build(device: str):
    torch.manual_seed(0)
    model = load_nf4(device)
    parts = memory_parts(model)                        # PEFT로 감싸기 전에 센다(제39장)
    model = prepare_model_for_kbit_training(model, use_gradient_checkpointing=True,
                                            gradient_checkpointing_kwargs={"use_reentrant": False})
    n_layout = keep_training_layout(model) if device == "cpu" else 0
    return model, parts, n_layout


def train_qlora(model, tok, tr, va, device: str, callbacks: list):
    """제48장과 같은 조립. 장치에 따라 use_cpu를 정하고, 점검 Callback을 붙인다."""
    from trl import SFTConfig, SFTTrainer
    torch.manual_seed(0)
    args = SFTConfig(output_dir=str(TMP / "ch49_run"), use_cpu=(device == "cpu"), disable_tqdm=True,
                     **{**SAME_AS_CH46, **QLORA})
    trainer = SFTTrainer(model=model, args=args, processing_class=tok,
                         peft_config=lora_config(SCOPES["모든 Linear"]), callbacks=callbacks,
                         train_dataset=to_hf_dataset(tr), eval_dataset=to_hf_dataset(va))
    trainer.train()
    m = trainer.model
    return m, sum(p.numel() for p in m.parameters() if p.requires_grad), trainer.state.log_history


def budget(model, tok, tr, parts: dict, n_lora: int) -> dict:
    """GT 1030(2GB) 예산: 가중치 + LoRA(FP32 값·Gradient·AdamW 2개) + 가장 긴 샘플의 Activation"""
    longest = max(tr.items, key=lambda e: len(e["input_ids"]))
    ids = torch.tensor([longest["input_ids"]])
    act, _, _ = saved_bytes_of_step(model, ids)
    fixed = load_blocks(tok, "train", seq_len=256)[:1]
    act_fixed, _, _ = saved_bytes_of_step(model, fixed)
    model.zero_grad(set_to_none=True)
    return {"weights": sum(parts.values()), "lora_states": n_lora * 4 * 4, "act_real": act,
            "act_fixed256": act_fixed, "longest": len(longest["input_ids"])}


def main() -> None:
    hw = hardware()
    device = hw["device"]
    tok = load_tokenizer()
    tr, va = SFTDataset(tok, split_rows("train")), SFTDataset(tok, split_rows("validation"))
    print(f"── 1. 4비트 모델과 PEFT(장치 {hw['name']}) ──")
    model, parts, n_layout = build(device)
    print(f"  원본 메모리 {sum(parts.values()) / MiB:.1f}MiB, CPU 추론용 재배치 끔 {n_layout}개")
    start = measure(tok, model)                       # QLoRA의 학습 전 = NF4 기본 모델
    model.train()
    print(f"  NF4 기본 모델: 도메인 PPL {start['domain_ppl']:.2f}, 일반 PPL {start['general_ppl']:.2f}"
          f"(FP32는 17.64, 21.45)")

    check = FiniteCheck()
    print("\n── 2·3. 학습(NF4, 모든 Linear r 8, 묶음 1 × 누적 8, Checkpointing, 30단계) ──")
    t0 = time.time()
    m, n, hist = train_qlora(model, tok, tr, va, device, [check])
    secs = round(time.time() - t0)
    train = {r["step"]: r["loss"] for r in hist if "loss" in r}
    curve = [(r["step"], r["eval_loss"]) for r in hist if "eval_loss" in r]
    print(f"  학습 파라미터 {n:,}개, 학습 {secs}초, NaN·Inf 기록 {check.bad}건")
    print("  단계   train   val(샘플 평균)")
    for s, v in curve:
        print(f"  {s:>4}  {train[s]:.3f}   {v:.3f}")

    b = budget(m, tok, tr, parts, n)
    total = b["weights"] + b["lora_states"] + b["act_real"]
    print("\n── 메모리 예산(GT 1030 2GB 기준, 계산값) ──")
    print(f"  4비트 가중치 등 {b['weights'] / MiB:7.1f}MiB")
    print(f"  LoRA 값·Gradient·AdamW 2개 {b['lora_states'] / MiB:7.1f}MiB")
    print(f"  Activation(실제 데이터 최장 {b['longest']}토큰) {b['act_real'] / MiB:7.1f}MiB"
          f"  / 고정 데이터 256토큰 {b['act_fixed256'] / MiB:.1f}MiB")
    print(f"  합계 {total / MiB:.1f}MiB(CUDA 실행 공간·단편화 여유 제외) < 2048MiB: {total < 2048 * MiB}")

    m.save_pretrained(ADAPTER)                       # 학습 결과부터 저장
    m.eval()
    after = measure(tok, m)
    base = json.loads((ROOT / "examples/ch47/baseline.json").read_text(encoding="utf-8"))
    lora = json.loads((ROOT / "examples/ch48/domain.json").read_text(encoding="utf-8"))
    hits, fmts = list(after["keyword_hit"].values()), list(after["format_ok"].values())
    verdict = judge(load_criteria(), domain_ratio=after["domain_ppl"] / start["domain_ppl"],
                    general_ratio=after["general_ppl"] / start["general_ppl"], hits=hits, fmts=fmts)
    vs_fp32 = judge(load_criteria(), domain_ratio=after["domain_ppl"] / base["domain_ppl"],
                    general_ratio=after["general_ppl"] / base["general_ppl"], hits=hits, fmts=fmts)

    def avg(d):
        return sum(d.values()) / len(d)
    print("\n── 4. LoRA(제48장, FP32)와 QLoRA(NF4) 비교 ──")
    print("  지표        FP32 전  LoRA 후  NF4 전  QLoRA 후  판정(NF4 전 기준 / FP32 전 기준)")
    for label, key, f in (("도메인 PPL", "domain_ppl", None), ("일반 PPL", "general_ppl", None),
                          ("핵심어", "keyword_hit", avg), ("형식", "format_ok", avg)):
        g = f or (lambda x: x)
        mark = {True: "합격", False: "불합격"}
        print(f"  {label:<9}{g(base[key]):>8.2f}{g(lora['after'][key]):>9.2f}{g(start[key]):>8.2f}"
              f"{g(after[key]):>10.2f}   {mark[verdict[key]]} / {mark[vs_fp32[key]]}")
    print("\n── 답 비교(앞부분) ──")
    for i in after["answers"]:
        print(f"  [{i}] LoRA:  {lora['after']['answers'][i][:40].replace(chr(10), ' ')}…")
        print(f"  {'':>10}QLoRA: {after['answers'][i][:40].replace(chr(10), ' ')}…")
    out = {"device": device, "trainable": n, "seconds": secs, "nonfinite": check.bad, "curve": curve,
           "train": train, "budget": b, "start": start, "after": after, "verdict": verdict, "verdict_vs_fp32": vs_fp32}
    (HERE / "qlora.json").write_text(json.dumps(out, ensure_ascii=False, indent=1) + "\n", encoding="utf-8")


if __name__ == "__main__":
    main()
```

**결과 읽기**

- **1번**에서 4비트 원본은 695.6MiB로, FP32의 약 3분의 1입니다. 4비트로 줄이는 것만으로 NF4 기본 모델의 도메인 PPL은 17.64에서 18.80, 일반 PPL은 21.45에서 27.90으로 나빠집니다(제37장의 27.78과 같은 경향). 학습하기 전부터 낸 대가입니다.
- **2·3번**에서 30단계 동안 NaN·Inf는 0건입니다. 학습 파라미터는 제48장과 정확히 같은 440만 개이고, 검증 손실은 15단계(2.570)에서 가장 낮았다가 조금 오릅니다. 제48장과 같은 과적합 모양입니다.
- **메모리 예산**은 가중치 695.6 + LoRA 상태 67.1 + Activation 132.3 = 895.1MiB로 2GB의 절반 이하입니다. 실제 데이터의 가장 긴 샘플(199토큰)은 고정 데이터 256토큰보다 Activation이 22% 작습니다. CUDA 실행 환경이 수백 MiB를 더 쓰더라도 GT 1030에 들어갈 것으로 예상하지만, 실제 최대 사용량은 측정하지 않았습니다(미검증).
- **4번**에서 NF4 기본 모델을 기준으로 하면 도메인 PPL(18.80 → 14.00, 26% 감소), 일반 PPL(27.90 → 27.80), 형식(0.33 → 1.00)이 합격이고 핵심어(0.00)는 제48장처럼 불합격입니다. FP32 기본 모델을 기준으로 하면 **일반 PPL도 불합격**입니다(21.45 대비 30% 높음). 학습이 나빠뜨린 것은 아니고, 4비트로 줄일 때 이미 잃은 것입니다.
- 같은 조건에서 LoRA의 도메인 PPL은 12.55, QLoRA는 14.00입니다. 4비트 원본 위에서 학습하면 같은 LoRA로도 덜 내려갑니다. 제40장 비교 B(17.71 / 14.34)와 같은 방향입니다. 형식은 QLoRA가 여섯 모두 지켜 LoRA(넷)보다 좋지만, 문항 6개에서 두 개 차이이므로 방식의 우열로 읽지 않습니다.
- 답을 읽으면 QLoRA도 제48장처럼 짧은 평서문으로 FPGA 단어를 쓰지만 내용은 틀립니다. DSP를 "드롭 슬롯"으로 풀고, 1Hz 질문에는 "1GHz 클럭에서 100MHz의 카운터를 만든다"고 답합니다. fpga-049(래치)는 "if 문에 값을 넣지 않았다"로 원인 근처까지 갔지만 래치라는 핵심어는 없습니다. 두 방식 모두 지식은 아직 배우지 못했습니다.
- 비교와 판정은 모두 validation 문항으로 했습니다(기준 파일 version 2). test는 제50장의 최종 평가에서 한 번만 씁니다.

## 검증과 완료 기준

파일명: `examples/ch49/test_ch49.py`

```python
# 제49장 검증 테스트
#
# 실행: python -m pytest examples/ch49 -q

import json
from pathlib import Path

HERE = Path(__file__).resolve().parent
MiB = 2 ** 20


def rec():
    return json.loads((HERE / "qlora.json").read_text(encoding="utf-8"))


def test_no_nonfinite_and_loss_decreases():
    r = rec()
    assert r["nonfinite"] == 0
    assert r["curve"][-1][1] < r["curve"][0][1]


def test_budget_within_2gb():
    b = rec()["budget"]
    total = b["weights"] + b["lora_states"] + b["act_real"]
    assert total < 2048 * MiB
    assert b["act_real"] < b["act_fixed256"] and b["longest"] < 256       # 실제 데이터는 256보다 짧다


def test_same_trainable_and_eval_as_lora():
    r = rec()
    lora = json.loads((HERE.parent / "ch48" / "domain.json").read_text(encoding="utf-8"))
    assert r["trainable"] == lora["trainable"]                             # 같은 LoRA 구성
    assert r["after"]["generation"] == lora["after"]["generation"]
    assert sorted(r["after"]["answers"]) == sorted(lora["after"]["answers"])
    assert set(r["verdict"]) == set(lora["verdict"])
```

## 핵심 정리

- QLoRA 준비는 NF4 로딩, 학습 준비(Checkpointing), LoRA 부착 순서입니다. bitsandbytes CPU 경로에서는 추론용 가중치 재배치를 끕니다.
- 묶음 1 × 누적 8, Checkpointing, 최대 256으로 계산한 예산은 895MiB로 2GB 안에 들어갑니다. 실제 데이터의 가장 긴 샘플로 다시 계산해야 하며, GPU 실측은 따로 필요합니다.
- QLoRA의 "학습 전"은 두 가지입니다. 학습의 효과는 NF4 기본 모델과, 사용할 수 있는 품질은 FP32 원본과 비교합니다.
- 같은 LoRA라도 4비트 원본 위에서는 도메인 PPL이 덜 내려가고, 일반 PPL은 4비트로 줄일 때 이미 나빠집니다.
- LoRA와 QLoRA 모두 말투는 배웠지만 지식은 배우지 못했습니다. 원인 분석과 데이터 보강은 다음 장에서 다룹니다.
