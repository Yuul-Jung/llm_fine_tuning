## 장 개요

병합한 모델은 하나의 Safetensors 파일 안에 텐서 290개로 들어 있습니다. 모델 전체를 다른 도구로 변환하는 일(제54장)도 있지만, 때로는 **특정 층의 가중치 하나**만 꺼내야 합니다. 가중치를 분석하거나 다른 프로그램과 결과를 맞춰 보거나, FPGA 같은 하드웨어의 메모리에 올려 직접 계산할 때입니다(제59장).

이 장은 이름으로 원하는 가중치를 찾고, Embedding과 LM Head가 같은 텐서인지 확인하며, 한 층의 가중치를 NumPy·CSV·Binary·HEX 네 형식으로 내보낸 뒤 다시 읽어 그 층의 계산을 재현합니다. 같은 숫자도 바이트를 놓는 순서에 따라 전혀 다르게 읽힌다는 것도 확인합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 원하는 가중치를 정확히 꺼내, 다른 도구와 하드웨어가 같은 값으로 읽게 하려면 무엇을 지켜야 하는가 |
| 실습 결과물 | 이름 검색, Weight Tying 확인, 네 형식 내보내기와 비트 단위 복원, HEX로 행렬곱 재현, Byte Order 비교 |
| 실습 파일 | `examples/ch53/`의 `export.py`, `test_ch53.py` |
| 선수 장 | 제19·20장(모델 구조와 이름), 제32장(부동소수점 비트), 제52장(병합 모델) |

```text
병합 모델 ─named_parameters·get_submodule─▶ 0층 k_proj(128 × 896, FP32) + bias(128)
   ─▶ .npy  .csv  .bin(little-endian)  .hex(한 줄에 32비트 단어)
   ─다시 읽기─▶ 비트 단위 비교 ─▶ y = x Wᵀ + b 재현, 계층 출력과 비교
```

## Named Parameters

모델의 모든 학습 가능한 텐서는 점으로 이어진 이름을 가집니다. 이름은 모듈의 포함 관계를 그대로 따릅니다. 예를 들어 0번째 Decoder 층의 Attention 안 Key 투영의 가중치 이름은 다음과 같습니다.

```text
model.layers.0.self_attn.k_proj.weight
```

| 방법 | 쓰임 |
|---|---|
| `named_parameters()` | 모든 파라미터를 이름과 함께 차례로 꺼낸다 |
| 이름 끝맺음으로 거르기 | 같은 종류의 층을 모두 고른다(층마다 하나씩) |
| `get_submodule(이름)` | 모듈 하나를 정확히 찾아 weight와 bias를 함께 꺼낸다 |

이름으로 찾으면 층 번호를 세다 틀리는 일이 없고, 제51장의 Adapter 텐서 이름처럼 다른 파일과 대응시키기도 쉽습니다. 이 장은 크기가 작은 0층 k_proj(128 × 896)를 예로 씁니다. Qwen2.5는 Key·Value 머리가 2개뿐이라(GQA) k_proj의 출력이 128로 작습니다.

## Weight Tying 확인

Qwen2.5-0.5B는 입력 Embedding과 출력 LM Head가 **같은 텐서**를 씁니다(Weight Tying, 제20장). 설정 값만으로는 실제로 묶여 있는지 확신할 수 없으므로, 두 텐서의 메모리 주소를 직접 비교합니다. 주소가 같으면 하나의 텐서를 두 곳에서 가리키는 것입니다.

묶인 텐서는 저장할 때도 한 번만 저장됩니다. 병합 모델 파일에는 Embedding만 있고 LM Head 이름은 없습니다. 가중치를 꺼내거나 변환할 때 이를 모르면 "LM Head가 없다"고 오해하거나, 반대로 같은 519MiB를 두 번 내보내게 됩니다.

## NumPy·CSV·Binary·HEX

| 형식 | 담는 방식 | 쓰임 |
|---|---|---|
| NumPy(.npy) | 머리말(자료형·모양) + 바이트 | 파이썬 분석. 자료형과 모양이 함께 저장된다 |
| CSV | 10진수 문자열, 줄마다 한 행 | 표 계산 프로그램, 사람이 읽기. 크고 느리다 |
| Binary(.bin) | 머리말 없는 원시 바이트 | C 프로그램, 임베디드. 자료형·모양·순서를 따로 약속해야 한다 |
| HEX | 한 줄에 32비트 값 하나(16진수 8자리) | Verilog 메모리 초기화($readmemh) |

NumPy 외의 형식은 **모양과 자료형을 담지 않습니다.** 행 우선 순서, FP32, 바이트 순서를 문서로 약속하고, 읽는 쪽이 같은 약속으로 해석해야 합니다. CSV는 10진수로 바꾸는 과정에서 값이 달라질 수 있는데, 이 장은 각 값을 원래 값으로 정확히 되돌아오는 가장 짧은 10진 표현으로 써서 손실을 막습니다. 저장한 뒤에는 다시 읽어 **비트 단위로** 같은지 확인합니다. 값이 "거의 같다"가 아니라 정확히 같아야 다른 도구의 결과와 대조할 수 있습니다.

## 자료형과 Byte Order

FP32 하나는 4바이트입니다. 이 4바이트를 메모리에 놓는 순서가 **Byte Order(Endianness)** 입니다. 가장 낮은 자리 바이트를 먼저 놓으면 little-endian, 가장 높은 자리를 먼저 놓으면 big-endian입니다. x86과 대부분의 ARM은 little-endian이고, 네트워크 프로토콜과 일부 하드웨어는 big-endian을 씁니다.

같은 바이트를 다른 순서로 읽으면 전혀 다른 숫자가 됩니다. 오류 없이 엉뚱한 값이 나오므로 알아차리기 어렵습니다. 그래서 Binary 파일은 바이트 순서를 명시해 쓰고 읽습니다(NumPy의 '<f4'는 little-endian FP32). HEX 파일은 32비트 단어를 숫자로 적으므로 바이트 순서와 무관하게, 사람이 읽는 순서(높은 자리부터)로 값이 보입니다.

## 핵심 실습

파일명: `examples/ch53/export.py`

```python
# 제53장 핵심 실습: 한 계층의 가중치를 이름으로 찾아 NumPy·CSV·Binary·HEX로 내보내고, 다시 읽어 행렬곱을 재현한다
#
# 실행: python examples/ch53/export.py   (제52장의 병합 모델 필요, CPU 약 30초)
#
# 만드는 파일: models/ch53/(내보낸 파일 네 가지, 저장소에는 넣지 않음)

import csv
import struct
import sys
from pathlib import Path

HERE = Path(__file__).resolve().parent
ROOT = HERE.parents[1]
sys.path.insert(0, str(HERE.parent))

import numpy as np  # noqa: E402
import torch  # noqa: E402

from common.device import select_device  # noqa: E402

MERGED = ROOT / "models" / "fpga_merged_v1"                      # 제52장
OUT = ROOT / "models" / "ch53"
NAME = "model.layers.0.self_attn.k_proj"                          # 896 → 128, 작은 계층


def save_all(w: np.ndarray, b: np.ndarray, out: Path) -> dict:
    """같은 가중치를 네 형식으로 저장한다. 모두 행 우선(row-major), FP32."""
    out.mkdir(parents=True, exist_ok=True)
    paths = {k: out / f"k_proj.{k}" for k in ("npy", "csv", "bin", "hex")}
    np.save(paths["npy"], w)
    with open(paths["csv"], "w", newline="") as f:
        csv.writer(f).writerows(w.tolist())                       # 파이썬 float → 최단 10진 표현(왕복 손실 없음)
    w.astype("<f4").tofile(paths["bin"])                          # little-endian 4바이트씩
    with open(paths["hex"], "w") as f:                            # 한 줄에 32비트 단어 하나($readmemh 형식)
        f.writelines(f"{x:08x}\n" for x in w.astype("<f4").view("<u4").ravel())
    np.save(out / "k_proj_bias.npy", b)
    return paths


def load_all(paths: dict, shape: tuple) -> dict:
    return {
        "npy": np.load(paths["npy"]),
        "csv": np.loadtxt(paths["csv"], delimiter=",", dtype=np.float32).reshape(shape),
        "bin": np.fromfile(paths["bin"], dtype="<f4").reshape(shape),
        "hex": np.array([int(x, 16) for x in paths["hex"].read_text().split()], dtype="<u4")
                 .view("<f4").reshape(shape),
    }


def main() -> None:
    from transformers import AutoModelForCausalLM
    device, _ = select_device()
    model = AutoModelForCausalLM.from_pretrained(MERGED, dtype=torch.float32).to(device).eval()

    print("── 1. Named Parameters: 이름으로 찾기 ──")
    params = dict(model.named_parameters())
    print(f"  파라미터 텐서 {len(params)}개. 앞의 셋:")
    for k in list(params)[:3]:
        print(f"    {k:<44}{tuple(params[k].shape)}")
    k_all = [k for k in params if k.endswith("self_attn.k_proj.weight")]
    print(f"  'self_attn.k_proj.weight'로 끝나는 이름 {len(k_all)}개(층마다 하나)")
    layer = model.get_submodule(NAME)
    print(f"  {NAME}: weight {tuple(layer.weight.shape)}, bias {tuple(layer.bias.shape)}")

    print("\n── 2. Weight Tying ──")
    emb, head = model.model.embed_tokens.weight, model.lm_head.weight
    print(f"  설정 tie_word_embeddings {model.config.tie_word_embeddings}")
    print(f"  Embedding과 LM Head의 메모리 주소가 같음: {emb.data_ptr() == head.data_ptr()}"
          f"(주소 값 자체는 실행마다 다르다)")
    print(f"  named_parameters에 LM Head가 따로 있음: {'lm_head.weight' in params}"
          f"(같은 텐서는 한 번만 나옴), 크기 {emb.numel() * 4 / 2**20:.0f}MiB")

    print("\n── 3. 네 형식으로 내보내고 다시 읽기 ──")
    w = layer.weight.detach().cpu().numpy()
    b = layer.bias.detach().cpu().numpy()
    paths = save_all(w, b, OUT)
    back = load_all(paths, w.shape)
    for k, arr in back.items():
        print(f"  {k:<4}{paths[k].stat().st_size / 1024:>8.0f}KiB  원본과 비트 단위로 같음 {np.array_equal(arr, w)}")
    print(f"  HEX 첫 줄 {paths['hex'].read_text().split()[0]} = {w[0, 0]!r}")

    print("\n── 4. 읽어 들인 HEX로 행렬곱 재현 ──")
    torch.manual_seed(0)
    x = torch.randn(4, w.shape[1])
    with torch.no_grad():
        y_layer = layer(x.to(device)).cpu()
    w_hex, b_t = torch.from_numpy(back["hex"]), torch.from_numpy(b)
    y_linear = torch.nn.functional.linear(x, w_hex, b_t)           # 계층과 같은 연산
    y_manual = x @ w_hex.T + b_t                                   # 곱한 뒤 따로 더함
    print(f"  같은 연산(linear)으로 재현: 최대 차이 {(y_layer - y_linear).abs().max().item():.2e}")
    print(f"  곱셈과 덧셈을 나눠 재현:    최대 차이 {(y_layer - y_manual).abs().max().item():.2e}(계산 순서 차이)")

    print("\n── 5. 자료형과 Byte Order ──")
    v = np.float32(1.0)
    little, big = struct.pack("<f", v), struct.pack(">f", v)
    print(f"  1.0의 바이트: little-endian {little.hex(' ')}, big-endian {big.hex(' ')}")
    wrong = np.fromfile(paths["bin"], dtype=">f4", count=4)
    print(f"  little로 쓴 파일을 big으로 읽으면 {wrong} (원래 {w.ravel()[:4]})")
    print(f"  이 컴퓨터의 기본 순서: {sys.byteorder}")


if __name__ == "__main__":
    main()
```

**결과 읽기**

- **1번**에서 병합 모델의 파라미터 텐서는 290개이고, Key 투영 가중치는 층마다 하나씩 24개입니다. 0층 k_proj는 128 × 896 가중치와 128개의 bias를 가집니다.
- **2번**에서 Embedding과 LM Head의 주소가 같아, 하나의 텐서임을 확인했습니다. 그래서 `named_parameters()`에는 LM Head가 따로 나오지 않습니다. 이 텐서 하나가 519MiB로 모델의 4분의 1이 넘습니다.
- **3번**에서 네 형식 모두 다시 읽은 값이 원본과 비트 단위로 같습니다. 크기는 Binary와 NumPy가 448KiB(114,688 × 4바이트)로 가장 작고, HEX는 줄마다 9바이트라 약 두 배, CSV는 10진 표현 때문에 다섯 배 넘게 큽니다. HEX 첫 줄 3cf778e3은 FP32 0.03020901의 비트입니다.
- **4번**에서 HEX에서 읽은 가중치로 계층과 같은 연산을 하면 출력이 **정확히 같습니다**(차이 0). 곱셈과 bias 덧셈을 나눠 계산하면 1.5e-5만큼 달라지는데, 이는 값이 아니라 계산 순서의 차이입니다. 하드웨어 구현과 결과를 맞춰 볼 때는 이런 순서 차이를 허용 오차로 정해 두어야 합니다.
- **5번**에서 1.0은 little-endian으로 00 00 80 3f, big-endian으로 3f 80 00 00입니다. little-endian으로 쓴 파일을 big-endian으로 읽으면 -4.6 × 10²¹ 같은 엉뚱한 값이 오류 없이 나옵니다.

# 제53장 검증 테스트

import sys
from pathlib import Path

HERE = Path(__file__).resolve().parent
sys.path.insert(0, str(HERE))

import numpy as np  # noqa: E402
import pytest  # noqa: E402
import torch  # noqa: E402

from export import MERGED, load_all, save_all  # noqa: E402


def test_four_formats_roundtrip_bit_exact(tmp_path):
    rng = np.random.default_rng(0)
    w = (rng.standard_normal((5, 7)) * 1e-3).astype(np.float32)
    w[0, 0], w[0, 1] = np.float32(1.0), np.float32(-0.0)
    paths = save_all(w, np.zeros(5, np.float32), tmp_path)
    for arr in load_all(paths, w.shape).values():
        assert arr.dtype == np.float32 and arr.view(np.uint32).tolist() == w.view(np.uint32).tolist()
    lines = paths["hex"].read_text().split()
    assert len(lines) == 35 and all(len(x) == 8 for x in lines) and lines[0] == "3f800000"
    assert paths["bin"].stat().st_size == 35 * 4


def test_byte_order():
    b = np.array([1.0], dtype="<f4").tobytes()
    assert b == bytes([0, 0, 0x80, 0x3F]) and np.frombuffer(b, dtype=">f4")[0] != 1.0


def test_linear_reproduction_exact():
    torch.manual_seed(0)
    layer = torch.nn.Linear(16, 4)
    w = np.frombuffer(layer.weight.detach().numpy().astype("<f4").tobytes(), dtype="<f4").reshape(4, 16)
    x = torch.randn(3, 16)
    y = torch.nn.functional.linear(x, torch.from_numpy(w.copy()), layer.bias.detach())
    assert torch.equal(y, layer(x).detach())


@pytest.mark.skipif(not MERGED.exists(), reason="제52장의 병합 모델 필요")
def test_merged_file_stores_tied_weight_once():
    from safetensors import safe_open
    with safe_open(MERGED / "model.safetensors", "pt") as f:
        keys = list(f.keys())
    assert "model.embed_tokens.weight" in keys and "lm_head.weight" not in keys

| 행렬곱 재현 | 내보낸 가중치로 같은 연산을 하면 계층 출력과 같음 | 통과(차이 0) |
| Weight Tying | 병합 모델 파일에 묶인 텐서가 한 번만 저장됨 | 통과 |

이 장의 실습은 `select_device()`로 장치를 고르며, 내보내기는 CPU로 옮긴 뒤에 합니다. 병합 모델 전체(FP32 1.9GB)를 GPU에 올리는 단계는 GT 1030의 2GB에서 여유가 거의 없으므로, GT 1030 경로에서는 CPU에서 실행하는 것이 안전합니다(미검증).

**완료 기준:** 같은 층의 가중치를 INT8로 양자화한 HEX(한 줄에 8비트)로 내보내고, 다시 읽어 역양자화한 값으로 계층 출력을 재현해 오차를 적으며(제33장), 테스트 4개를 모두 통과하면 이 장을 마친 것입니다.

## 핵심 정리

- 가중치는 모듈 포함 관계를 따른 이름으로 찾습니다. 이름 끝맺음으로 같은 종류를 모으고, `get_submodule()`로 하나를 정확히 꺼냅니다.
- Weight Tying은 메모리 주소로 확인하며, 묶인 텐서는 파일에 한 번만 저장됩니다.
- NumPy는 자료형과 모양을 함께 담고, CSV·Binary·HEX는 담지 않으므로 순서·자료형·바이트 순서를 약속해야 합니다. 내보낸 뒤에는 비트 단위로 확인합니다.
- 같은 가중치라도 연산 순서가 다르면 결과의 마지막 자리가 달라집니다. 같은 연산이면 정확히 같습니다.
- 같은 바이트도 Byte Order에 따라 전혀 다른 숫자가 되며, 오류 없이 틀린 값이 나옵니다.
