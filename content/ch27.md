## 장 개요

제26장에서 PEFT의 발상, "원본은 그대로 두고 작은 추가 파라미터만 학습한다"를 정리했습니다. LoRA는 그 추가 파라미터로 **작은 행렬 두 개의 곱**을 씁니다. 896 × 896 크기의 가중치 변화를 896 × 8과 8 × 896 두 행렬로 나타내면 파라미터가 56분의 1로 줄어듭니다. 이런 일이 왜 가능한지, 그리고 어디까지 가능한지를 알려면 **Rank**라는 개념이 필요합니다.

이 장은 행렬의 Rank가 무엇인지, SVD(특잇값 분해)로 행렬을 가장 잘 근사하는 작은 행렬 두 개를 어떻게 찾는지 다룹니다. 그리고 실제 Qwen 가중치와, Base에서 Instruct로 바뀌며 생긴 **가중치 변화량**을 Rank별로 근사해 봅니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 큰 행렬을 작은 행렬 두 개의 곱으로 나타낼 수 있는 조건은 무엇이며, 실제 가중치는 어떠한가 |
| 실습 결과물 | Rank와 SVD 예제, 실제 가중치·무작위 행렬·변화량의 Rank별 복원 오차표 |
| 실습 파일 | `examples/ch27/`의 `rank_basics.py`, `qwen_svd.py`, `test_ch27.py` |
| 선수 장 | 제04장(행렬곱), 제05장(가중치 `[out, in]`), 제21장(Base와 Instruct) |

```text
W [out, in]  ≈  B [out, r]  ×  A [r, in]          r ≪ out, in
숫자 out × in    →    r × (out + in)
896 × 896 = 802,816  →  8 × 1,792 = 14,336   (1.8%)
```

## 행렬의 Rank

행렬 `[1, 2, 3]ᵀ × [1, 0, −1, 2]`를 계산하면 3 × 4 행렬이 나옵니다. 그런데 이 행렬의 모든 행은 `[1, 0, −1, 2]`의 1배, 2배, 3배입니다. 원소는 12개지만, 실제로 담긴 정보는 "방향 하나 `[1, 0, −1, 2]`와 배율 세 개 `[1, 2, 3]`", 즉 숫자 7개면 충분합니다.

**Rank**는 행렬이 실제로 담고 있는 **독립된 방향의 수**입니다. 위 행렬의 Rank는 1입니다. 다른 방향을 하나 더하면 Rank는 2가 됩니다.

| Rank | 의미 |
|---|---|
| 1 | 열 벡터 하나 × 행 벡터 하나(바깥곱)로 정확히 표현된다 |
| r | 바깥곱 r개의 합, 즉 `[out, r] × [r, in]`으로 정확히 표현된다 |
| min(out, in) | 최대 Rank(Full Rank). 줄일 수 있는 중복이 없다 |

Rank가 r인 행렬은 `[out, r] × [r, in]` 두 행렬의 곱으로 **정확히** 나타낼 수 있습니다. r이 작다면 숫자를 크게 아낄 수 있습니다. 문제는 실제 행렬의 Rank가 대개 작지 않다는 것입니다. 그래서 정확한 표현 대신 **근사**를 생각합니다.

## SVD와 저랭크 근사

**SVD**(Singular Value Decomposition, 특잇값 분해)는 어떤 행렬이든 "중요한 방향부터 차례로" 나눠 줍니다.

```text
W = U × diag(s₁, s₂, …) × Vᵀ        s₁ ≥ s₂ ≥ … ≥ 0   (특잇값)
  = s₁ u₁v₁ᵀ + s₂ u₂v₂ᵀ + …          Rank 1 조각들의 합, 큰 조각부터
```

특잇값 sᵢ는 i번째 조각이 얼마나 중요한지(크기)를 나타냅니다. 앞의 r개 조각만 남기면 Rank r의 근사가 됩니다. 이렇게 자른 근사는 **같은 Rank의 모든 행렬 가운데 원래 행렬과 가장 가깝습니다**(Eckart–Young 정리). 그리고 근사의 오차는 버린 특잇값들로 정확히 계산됩니다.

```text
상대 오차 = √( 버린 sᵢ²의 합 ÷ 전체 sᵢ²의 합 )
```

그러므로 특잇값이 앞쪽에 몰려 있는 행렬은 작은 r로도 잘 근사되고, 특잇값이 고르게 퍼진 행렬은 r을 크게 해야 합니다. 특잇값 제곱의 몇 %가 앞쪽에 모여 있는지(에너지 집중도)가 저랭크 근사의 가능성을 알려 줍니다.

## 파라미터 수 절약

`[out, in]` 행렬을 `[out, r] × [r, in]`으로 바꾸면 숫자의 개수는 다음과 같습니다.

```text
원래:   out × in
분해:   r × (out + in)
비율:   r × (out + in) ÷ (out × in)
```

| 행렬(Qwen2.5-0.5B) | 원래 → r = 8 | 비율 |
|---|---|---|
| q_proj 896 × 896 | 802,816 → 14,336 | 1.8% |
| k_proj 128 × 896 | 114,688 → 8,192 | 7.1% |
| down_proj 896 × 4864 | 4,358,144 → 46,080 | 1.1% |

행렬이 클수록, 특히 정사각형에 가까울수록 절약이 큽니다. 반대로 r이 `out × in ÷ (out + in)`보다 크면 오히려 숫자가 늘어납니다. 896 × 896에서는 r = 448이 손익분기점입니다.

## LoRA와 SVD의 차이

여기까지 보면 "가중치를 SVD로 잘라 쓰자"는 생각이 들 수 있습니다. 그러나 LoRA가 하는 일은 그것이 아닙니다.

| 구분 | SVD 저랭크 근사 | LoRA |
|---|---|---|
| 대상 | 원본 가중치 W 자체 | 학습으로 생길 **변화량** ΔW |
| 원본 | 근사로 바꾼다(정보 손실) | 그대로 둔다(Full Rank 유지) |
| 작은 행렬을 얻는 법 | 이미 있는 행렬을 분해 | Gradient로 처음부터 학습 |
| 결과 | W ≈ BA | W' = W + BA |

LoRA는 원본 W를 조금도 줄이지 않습니다. 원본은 모든 정보를 가진 채 동결되고, 그 옆에 **변화량만** Rank r로 학습합니다. 핵심 가정은 "새 과제에 맞추는 데 필요한 변화는 적은 수의 방향으로 충분하다"는 것입니다. 이 가정이 실제로 어떤지 실습 2에서 살펴봅니다.

## 핵심 실습

### 실습 1. Rank, SVD, 저랭크 근사

파일명: `examples/ch27/rank_basics.py`

```python
# 제27장 실습 1: 작은 행렬로 보는 Rank, SVD, 저랭크 근사
#
# 실행: python examples/ch27/rank_basics.py

import torch


def low_rank(w: torch.Tensor, r: int) -> tuple:
    """SVD로 W ≈ B @ A (B: [out, r], A: [r, in])를 만든다. 특잇값은 B 쪽에 곱해 둔다."""
    u, s, vh = torch.linalg.svd(w, full_matrices=False)
    return u[:, :r] * s[:r], vh[:r]


def rel_error(w: torch.Tensor, approx: torch.Tensor) -> float:
    """상대 오차 ‖W − 근사‖ / ‖W‖ (Frobenius 노름)"""
    return ((w - approx).norm() / w.norm()).item()


def main() -> None:
    print("── 1. Rank: 독립된 방향의 수 ──")
    col = torch.tensor([[1.0], [2.0], [3.0]])
    row = torch.tensor([[1.0, 0.0, -1.0, 2.0]])
    r1 = col @ row                                         # 모든 행이 [1, 0, −1, 2]의 배수
    print(f"  열 [1, 2, 3] × 행 [1, 0, −1, 2] =\n{r1}")
    print(f"  원소 {r1.numel()}개, Rank {torch.linalg.matrix_rank(r1).item()}, "
          f"필요한 숫자는 3 + 4 = 7개")
    r2 = r1 + torch.tensor([[0.0], [1.0], [0.0]]) @ torch.tensor([[0.0, 1.0, 0.0, 0.0]])
    print(f"  다른 방향 하나를 더하면 Rank {torch.linalg.matrix_rank(r2).item()}")

    print("\n── 2. SVD: 중요한 방향부터 차례로 ──")
    torch.manual_seed(0)
    w = torch.randn(6, 2) @ torch.randn(2, 5) + 0.05 * torch.randn(6, 5)   # 거의 Rank 2
    s = torch.linalg.svdvals(w)
    print(f"  특잇값 {[round(v, 3) for v in s.tolist()]}")
    for r in (1, 2, 3, 5):
        b, a = low_rank(w, r)
        print(f"  Rank {r}: B {tuple(b.shape)} × A {tuple(a.shape)}, 숫자 {b.numel() + a.numel():>2}개, "
              f"상대 오차 {rel_error(w, b @ a):.4f}")


if __name__ == "__main__":
    main()
```

```bash

```

- 1번은 01절의 예제입니다. 원소 12개짜리 행렬의 Rank가 1이고, 방향 하나를 더하면 2가 됩니다.

- `low_rank()`는 특잇값을 B 쪽에 곱해 두 행렬 `B [out, r]`, `A [r, in]`으로 돌려줍니다. LoRA의 두 행렬과 같은 모양입니다.

### 실습 2. 실제 Qwen 가중치의 Rank별 근사

Qwen2.5-0.5B-Instruct의 0번 계층 `q_proj`를 Rank별로 근사합니다. 비교 대상은 같은 크기의 무작위 행렬, 그리고 Base 모델에서 Instruct 모델로 사후 학습하며 생긴 변화량 `ΔW = W_instruct − W_base`입니다. 두 모델을 함께 올리므로 약 4GB의 RAM이 필요합니다.

파일명: `examples/ch27/qwen_svd.py`

```python
# 제27장 핵심 실습: 실제 Qwen 가중치를 Rank별로 근사해 복원 오차와 파라미터 수를 비교한다
#
# 실행: python examples/ch27/qwen_svd.py
#
# 대상: 0번 계층 q_proj [896, 896]. 비교: 같은 크기의 무작위 행렬,
#       그리고 Base → Instruct 사후 학습에서 생긴 변화량 ΔW = W_instruct − W_base(제21장)

import sys
from pathlib import Path

HERE = Path(__file__).resolve().parent
for p in (HERE, HERE.parent, HERE.parent / "ch21"):
    sys.path.insert(0, str(p))

import torch  # noqa: E402

from base_vs_instruct import load_base  # noqa: E402   (제21장)
from common.qwen import load_model  # noqa: E402
from rank_basics import low_rank, rel_error  # noqa: E402

NAME = "model.layers.0.self_attn.q_proj.weight"
RANKS = (1, 4, 16, 64, 128, 256, 512, 896)


def error_curve(w: torch.Tensor) -> list:
    return [rel_error(w, b @ a) for b, a in (low_rank(w, r) for r in RANKS)]


def main() -> None:
    inst, base = dict(load_model().named_parameters()), dict(load_base().named_parameters())
    w_inst, w_base = inst[NAME].detach(), base[NAME].detach()
    delta = w_inst - w_base
    torch.manual_seed(0)
    rand = torch.randn_like(w_inst) * w_inst.std()
    out_dim, in_dim = w_inst.shape

    print(f"── 1. {NAME} {tuple(w_inst.shape)}, 원소 {w_inst.numel():,}개 ──")
    print(f"  Rank(수치) {torch.linalg.matrix_rank(w_inst).item()}, "
          f"‖ΔW‖ / ‖W_base‖ = {(delta.norm() / w_base.norm()).item():.3f}")

    print("\n── 2. Rank r 근사: 파라미터 수와 상대 오차 ──")
    curves = {"Instruct W": error_curve(w_inst), "무작위": error_curve(rand), "ΔW": error_curve(delta)}
    print(f"  {'r':>4}{'파라미터 r(out+in)':>19}{'비율':>8}" + "".join(f"{k:>12}" for k in curves))
    for i, r in enumerate(RANKS):
        n = r * (out_dim + in_dim)
        print(f"  {r:>4}{n:>19,}{n / w_inst.numel():>8.1%}" + "".join(f"{c[i]:>12.3f}" for c in curves.values()))

    print("\n── 3. 특잇값 에너지가 상위 10%(90개)에 모인 비율 ──")
    for label, m in (("Instruct W", w_inst), ("무작위", rand), ("ΔW", delta)):
        s2 = torch.linalg.svdvals(m) ** 2
        print(f"  {label:<11}{(s2[:90].sum() / s2.sum()).item():.1%}")

    print("\n── 4. 다른 행렬의 ΔW: Rank 64 근사의 상대 오차 ──")
    for name in ("model.layers.0.self_attn.v_proj.weight", "model.layers.12.self_attn.q_proj.weight",
                 "model.layers.0.mlp.down_proj.weight"):
        d = (inst[name] - base[name]).detach()
        b, a = low_rank(d, 64)
        print(f"  {name:<42}{tuple(d.shape)!s:<13}{rel_error(d, b @ a):.3f}")


if __name__ == "__main__":
    main()
```

**결과 읽기**

- 1번에서 실제 가중치의 Rank는 879로, 최대 896에 가깝습니다. 학습된 가중치는 엄밀한 의미의 저랭크 행렬이 아닙니다. 사후 학습에 따른 변화량 ΔW는 원본 크기의 7.2%입니다.
- 2번에서 실제 가중치는 무작위 행렬보다 훨씬 빨리 근사됩니다. Rank 64(파라미터 14%)에서 오차가 0.29인 반면 무작위 행렬은 0.87입니다. 3번의 에너지 집중도(94% 대 32%)가 같은 사실을 보여 줍니다. 학습된 가중치에는 중요한 방향과 덜 중요한 방향이 뚜렷이 나뉩니다.
- 그래도 원본을 Rank 16 정도로 잘라 쓰면 오차가 0.50으로 너무 큽니다. 원본을 근사하는 방식으로는 모델을 크게 망가뜨린다는 뜻이며, LoRA가 원본을 건드리지 않는 이유입니다.
- 이 행렬의 **변화량** ΔW도 에너지의 88%가 상위 10% 방향에 모여 있어, 무작위 행렬과 달리 적은 방향으로 상당 부분 설명됩니다. LoRA의 가정과 맞는 결과입니다.
- 그러나 4번처럼 행렬마다 다릅니다. 12번 계층 `q_proj`나 FFN `down_proj`의 변화량은 Rank 64로 근사해도 오차가 0.83, 0.92로 거의 줄지 않습니다. Instruct 모델은 모든 가중치를 학습하는 방식으로 만들어졌으므로, 그 변화량이 저랭크일 이유는 없습니다.

정리하면, 저랭크 가정은 "Full Fine-tuning의 변화량은 언제나 저랭크다"가 아니라 "**목표한 과제에 필요한 변화는** 저랭크로도 충분히 얻을 수 있다"는 주장입니다. 이 주장이 우리 과제에서 맞는지는 근사 오차가 아니라 **학습 결과**로 판정해야 합니다. 제29장에서 Qwen2-Tiny에 LoRA를 붙여, 제26장의 Full FT·부분 학습과 같은 조건으로 비교합니다.

import torch

HERE = Path(__file__).resolve().parent

from rank_basics import low_rank, rel_error  # noqa: E402


def test_outer_product_is_rank_one():
    m = torch.tensor([[1.0], [2.0], [3.0]]) @ torch.tensor([[1.0, 0.0, -1.0, 2.0]])
    assert torch.linalg.matrix_rank(m).item() == 1


def test_full_rank_reconstructs_exactly():
    torch.manual_seed(0)
    w = torch.randn(7, 5)
    b, a = low_rank(w, 5)
    assert b.shape == (7, 5) and a.shape == (5, 5)
    torch.testing.assert_close(b @ a, w, atol=1e-5, rtol=1e-5)


def test_error_equals_dropped_singular_values():
    # Eckart–Young: 잘린 특잇값의 에너지가 곧 오차
    torch.manual_seed(1)
    w = torch.randn(20, 12)
    s = torch.linalg.svdvals(w)
    for r in (1, 4, 8):
        b, a = low_rank(w, r)
        expect = (s[r:].pow(2).sum() / s.pow(2).sum()).sqrt().item()
        assert rel_error(w, b @ a) == pytest.approx(expect, rel=1e-4)


def test_parameter_saving():
    out_dim, in_dim, r = 896, 896, 8
    assert r * (out_dim + in_dim) == 14_336
    assert r * (out_dim + in_dim) / (out_dim * in_dim) == pytest.approx(0.01786, abs=1e-5)


def test_qwen_error_decreases_with_rank():
    try:
        from common.qwen import load_model
        model = load_model(True)
    except Exception:
        pytest.skip("Qwen 모델이 아직 내려받아지지 않음")
    from qwen_svd import NAME, RANKS, error_curve
    curve = error_curve(dict(model.named_parameters())[NAME].detach())
    assert all(a > b for a, b in zip(curve, curve[1:]))
    assert curve[-1] < 1e-4

## 핵심 정리

- Rank는 행렬이 담은 독립된 방향의 수입니다. Rank r인 행렬은 `[out, r] × [r, in]`으로 정확히 표현됩니다.
- SVD는 행렬을 중요한 방향부터 나눠 주고, 앞의 r개만 남긴 근사가 Rank r의 최선입니다. 오차는 버린 특잇값의 에너지입니다.
- 분해하면 숫자가 `out × in`에서 `r × (out + in)`으로 줄어듭니다. 896 × 896에서 r = 8이면 1.8%입니다.
- 실제 가중치는 Full Rank에 가깝지만 무작위 행렬보다 중요한 방향이 뚜렷합니다. 원본을 잘라 쓰면 오차가 큽니다.
- LoRA는 원본을 근사하지 않고 그대로 둔 채 **변화량**만 저랭크로 학습합니다. 이 가정이 맞는지는 학습 결과로 판정합니다.
