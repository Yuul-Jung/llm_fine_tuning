## 장 개요

제36~38장에서 QLoRA의 재료를 모두 확인했습니다. NF4 4비트 원본(제36·37장), 그 위의 LoRA와 학습 메모리 계산(제38장)입니다. 이 장에서는 마침내 Qwen2.5-0.5B-Instruct를 **QLoRA로 학습**합니다. 제3부의 고정 학습 데이터로 30단계를 학습하고, 학습 전후의 PPL, 4비트 원본이 정말 그대로인지, 저장되는 것이 Adapter뿐인지를 확인합니다.

이 교재의 기준 장치는 GT 1030입니다. 교재 검증 환경에는 GPU가 없어, bitsandbytes의 CPU 경로로 **같은 QLoRA를 실제로** 실행했습니다. 형식과 절차는 GPU 경로와 같고, 장치와 속도만 다릅니다. GPU 경로의 최대 VRAM은 학습자 장비에서 측정해 기록할 항목으로 남깁니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 4비트 0.5B 모델을 LoRA로 학습하면 실제로 배우는가, 원본은 정말 그대로인가 |
| 실습 결과물 | QLoRA 준비 과정, 학습 기록과 PPL 변화, 4비트 원본 동결 확인, Adapter 파일 |
| 실습 파일 | `examples/ch39/`의 `qlora_train.py`, `test_ch39.py` |
| 선수 장 | 제25장(학습 루프), 제30장(PEFT), 제37장(4비트 로딩), 제38장(QLoRA 메모리) |

```text
4비트 로딩(NF4, 이중 양자화, FP32 계산)
  → prepare_model_for_kbit_training(Checkpointing 준비)
  → LoRA(q·v_proj, r 8, α 16)
  → 제25장 train()(Batch 1 × Accumulation 4, 시퀀스 256)
  → 동결 확인 → Adapter 저장(약 2MB)
```

## 학습 준비

준비 순서에는 이유가 있습니다.

| 순서 | 하는 일 | 순서가 바뀌면 |
|---|---|---|
| ① 4비트 로딩 | Linear 168개를 NF4로, Embedding·RMSNorm은 FP32로 불러온다(제37장) | — |
| ② kbit 학습 준비 | 입력 Gradient를 켜고 Checkpointing을 준비한다(제38장) | 이 함수는 모든 파라미터를 동결하므로, LoRA를 먼저 붙이면 A·B까지 얼어 아무것도 학습되지 않는다 |
| ③ LoRA 부착 | 원본 전체를 동결하고 q·v_proj에 A·B를 붙인다(제30장) | — |

이 세 단계는 제38장의 `build_qlora()`에 이미 들어 있으므로 그대로 씁니다. 학습 파라미터는 540,672개(전체의 0.11%), 원본 메모리는 약 696MiB입니다.

## GT 1030 메모리 설정

제38장의 메모리 분해를 바탕으로 GT 1030의 학습 설정을 정합니다.

| 설정 | 값 | 이유 |
|---|---|---|
| 시퀀스 길이 | 256 | Logits(256 × 151,936 × 4 = 148MiB)와 Activation이 시퀀스에 비례한다 |
| Batch | 1 | 묶음이 2배면 Activation과 Logits도 2배 |
| Accumulation | 4 | 메모리는 묶음 1개분으로, 효과는 묶음 4개처럼(제24·25장) |
| Gradient Checkpointing | 켬 | Activation을 602MiB에서 170MiB로(제38장) |
| 계산 자료형 | FP32 | GT 1030은 FP16·BF16 연산이 느리거나 없다(제32장) |

고정 학습 데이터(3,289토큰)를 256토큰으로 자르면 블록 12개가 됩니다. 30단계 × 유효 묶음 4 = 120블록이므로 약 10 Epoch를 학습합니다. 평가는 제22장과 같은 조건(128토큰 블록 5개, 지문 `1d8635627d660631`)으로 해, 기준값과 비교할 수 있게 합니다.

## 최소 학습 루프

학습은 제25장의 `train()`을 그대로 씁니다. `train()`은 `requires_grad=True`인 파라미터, 즉 LoRA의 A·B만 AdamW에 넘기고, Accumulation·Clipping·Warmup + Cosine을 적용합니다. 4비트 원본이든 Qwen2-Tiny든 같은 함수로 학습할 수 있는 것은, 학습 루프가 모델의 내부 형식을 몰라도 되도록 만들었기 때문입니다.

학습률은 5e-4로 정했습니다. 제29장에서 본 것처럼 학습 파라미터가 적은 LoRA는 Full FT보다 큰 학습률이 필요합니다.

## 동결 검증과 Adapter 저장

학습 후 확인할 것은 두 가지입니다.

첫째, **4비트 원본이 그대로인가**입니다. 학습 전에 168개 Linear의 4비트 번호(uint8)와 absmax를 복사해 두고, 학습 후 하나하나 비트까지 비교합니다. 제26·29장에서 FP32 가중치로 한 확인을 4비트 형식에서 다시 하는 것입니다.

둘째, **저장되는 것이 Adapter뿐인가**입니다. PEFT 모델의 `save_pretrained`는 `adapter_config.json`과 `adapter_model.safetensors`만 저장합니다(제30장). 0.5B 모델의 q·v LoRA는 540,672개 × 4바이트 ≈ 2.1MB입니다. 원본 4비트 모델은 공개 저장소에서 언제든 다시 받을 수 있으므로, 학습 결과로 보관할 것은 이 2MB뿐입니다.

## CPU 경로

GPU가 없을 때 QLoRA를 어떻게 할지는 bitsandbytes의 CPU 지원 여부에 달려 있습니다. 이 교재가 쓰는 bitsandbytes 0.50.2는 CPU에서 4비트 로딩·계산·역전파를 지원하므로, 교재 검증 환경은 **실제 QLoRA**를 CPU로 실행했습니다. CPU 지원이 없는 버전이나 환경이라면, 제35·36장의 가짜 양자화로 4비트 원본을 흉내 내고 제29장의 LoRA를 붙여 원리를 따라가는 방식(원리 모사)으로 대신합니다.

CPU 경로에는 함정이 하나 있었습니다. bitsandbytes 0.50.2는 AVX512-BF16을 지원하는 CPU에서 **평가 모드**로 계산할 때, 4비트 가중치를 추론에 빠른 배치로 바꿔 저장합니다. 이 변환이 일어난 뒤에는 학습 모드의 역전파가 오류로 멈춥니다. 학습 전 PPL을 재는 순간(평가 모드) 변환이 일어나므로, 학습할 모델에서는 이 변환을 꺼 두었습니다(`keep_training_layout()`). GPU 경로와는 관계없는 CPU 경로만의 동작입니다. 이 변환 여부에 따라 계산 순서가 달라져, 학습 전 PPL은 제37장의 27.78과 조금 다른 27.90으로 나옵니다.

## 핵심 실습

파일명: `examples/ch39/qlora_train.py`

```python
# 제39장 핵심 실습: Qwen2.5-0.5B-Instruct QLoRA 최소 학습 — 학습 전후 PPL, 동결 확인, Adapter 저장
#
# 실행: python examples/ch39/qlora_train.py
#
# 설정(이 교재의 GT 1030 기준): NF4 + FP32 계산, 시퀀스 256, Batch 1, Accumulation 4, Checkpointing
# GPU가 없으면 bitsandbytes CPU 경로로 같은 QLoRA를 실행한다(교재 검증 환경).

import math
import sys
import time
from pathlib import Path

HERE = Path(__file__).resolve().parent
for p in (HERE.parent, HERE.parent / "ch22", HERE.parent / "ch24", HERE.parent / "ch25",
          HERE.parent / "ch37", HERE.parent / "ch38"):
    sys.path.insert(0, str(p))

import torch  # noqa: E402

from common.fixed_data import fingerprint, load_blocks  # noqa: E402
from common.qwen import load_tokenizer  # noqa: E402
from load_4bit import hardware  # noqa: E402             (제37장)
from qlora_memory import build_qlora  # noqa: E402       (제38장)
from trainer import eval_loss, train  # noqa: E402       (제25장)

ADAPTER = HERE.parents[1] / "models" / "qwen2.5-0.5b-qlora-fixed"
SEQ, STEPS, LR = 256, 30, 5e-4


def keep_training_layout(model) -> int:
    """bitsandbytes 0.50 CPU 경로는 AVX512-BF16 CPU에서 평가 모드로 계산할 때 4비트 가중치를 추론 전용
    배치로 바꾼다. 바뀐 뒤에는 학습이 실패하므로, 학습할 모델에서는 이 변환을 끈다(GPU 경로와는 무관)."""
    n = 0
    for m in model.modules():
        if hasattr(m, "support_avx512bf16_for_cpu"):
            m.support_avx512bf16_for_cpu = False
            n += 1
    return n


def frozen_4bit(model) -> dict:
    """4비트 가중치(번호, uint8)와 absmax를 복사해 둔다."""
    out = {}
    for name, p in model.named_parameters():
        if p.dtype == torch.uint8:
            out[name] = p.detach().clone()
            out[name + ".absmax"] = p.quant_state.absmax.detach().clone()
    return out


def main() -> None:
    hw = hardware()
    device = hw["device"]
    tok = load_tokenizer()
    train_blocks = load_blocks(tok, "train", seq_len=SEQ)
    eval_blocks = load_blocks(tok, "eval")                    # 평가는 제22장 기준(128토큰 블록)
    print(f"장치 {hw['name']}, 학습 블록 {tuple(train_blocks.shape)}, 평가 블록 {tuple(eval_blocks.shape)} "
          f"(지문 {fingerprint(eval_blocks)})\n")

    print("── 1. 학습 준비: 4비트 로딩 → prepare_model_for_kbit_training → LoRA ──")
    torch.manual_seed(0)
    model, parts = build_qlora(device, checkpointing=True)
    if device == "cpu":
        print(f"  CPU 추론용 가중치 재배치 끔: Linear4bit {keep_training_layout(model)}개")
    trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)
    print(f"  학습 파라미터 {trainable:,}개, 원본 메모리 {sum(parts.values()) / 2**20:.1f}MiB")
    before = frozen_4bit(model)
    ppl0 = math.exp(eval_loss(model, eval_blocks, device))
    print(f"  학습 전 PPL {ppl0:.2f}")

    print(f"\n── 2. 학습: Batch 1 × Accumulation 4, {STEPS}단계, lr {LR:.0e}, Warmup 3 ──")
    if device == "cuda":
        torch.cuda.reset_peak_memory_stats()
    t0 = time.perf_counter()
    hist = train(model, train_blocks, {"평가": eval_blocks}, steps=STEPS, batch=1, accum=4, lr=LR,
                 warmup=3, device=device, log_every=10)
    for r in hist:
        print(f"  단계 {r['step']:>3}  학습 {r['train']:.3f}  Grad노름 {r['grad_norm']:.2f}  "
              f"평가 {r['평가']:.3f}(PPL {math.exp(r['평가']):.2f})")
    print(f"  걸린 시간 {time.perf_counter() - t0:.0f}초(환경마다 다름)")
    if device == "cuda":
        print(f"  GPU 최대 할당 {torch.cuda.max_memory_allocated() / 2**20:.0f}MiB")

    print("\n── 3. 동결 검증과 Adapter 저장 ──")
    after = frozen_4bit(model)
    same = all(torch.equal(before[k], after[k]) for k in before)
    print(f"  4비트 원본(번호 {sum(1 for k in before if not k.endswith('absmax'))}개 텐서 + absmax) 그대로: {same}")
    model.save_pretrained(ADAPTER)
    files = {f.name: f.stat().st_size for f in sorted(ADAPTER.iterdir()) if f.suffix in (".json", ".safetensors")}
    print(f"  저장 {files}")
    print(f"  PPL {ppl0:.2f} → {math.exp(hist[-1]['평가']):.2f}")


if __name__ == "__main__":
    main()
```

**결과 읽기**

- **1번**에서 학습 파라미터는 540,672개, 원본 메모리는 695.6MiB로 제38장과 같습니다. CPU 경로이므로 추론용 재배치를 168개 Linear 모두에서 껐습니다.
- **2번**에서 평가 PPL이 27.90에서 10단계 만에 19.74, 30단계에서 17.73으로 내려갔습니다. Grad노름은 1.6 안팎으로 안정적이고, 손실은 단계마다 꾸준히 줄었습니다. 4비트로 얼린 0.5B 모델이 LoRA 54만 개만으로 고정 데이터의 문장을 배웠습니다.
- 17.73은 제22장의 FP32 Instruct(21.45)는 물론 Base(18.13)보다도 낮습니다. 그러나 이것을 "모델이 전반적으로 좋아졌다"로 읽으면 안 됩니다. 평가 문장은 학습 문장과 같은 주제를 다르게 쓴 것이라(제21장), 학습 데이터의 내용과 문체를 배우면 평가 PPL도 내려갑니다. 일반 능력을 잃지 않았는지는 다른 데이터로 따로 재야 하며, 제50장에서 다룹니다.
- **3번**에서 168개 4비트 텐서와 absmax가 학습 전과 비트까지 같습니다. 저장된 Adapter는 약 2.1MB입니다.
- GT 1030 경로에서는 2번에 GPU 최대 할당량이 출력됩니다. 이 값이 설계 예산(약 1.5GB 내외) 안에 들어오는지가 GT 1030 QLoRA의 판정 기준입니다.

# 0.5B QLoRA 학습(수 분)은 qlora_train.py로 실행하고, 테스트는 사전학습한 Qwen2-Tiny(제25장)를

@pytest.fixture()

        pytest.skip("제25장 pretrain_tiny.py를 먼저 실행")
    from load_4bit import nf4_config

                                        gradient_checkpointing_kwargs={"use_reentrant": False})
    torch.manual_seed(0)
    m = get_peft_model(m, LoraConfig(r=8, lora_alpha=16, target_modules=["q_proj", "v_proj"],

    keep_training_layout(m)
    return m


def test_qlora_steps_keep_4bit_frozen(tiny_qlora, tmp_path):

    ids = torch.randint(0, 5000, (4, 32))
    before = frozen_4bit(tiny_qlora)
    assert len(before) == 2 * 4 * 7                       # 4계층 × Linear 7종 × (번호, absmax)
    l0 = eval_loss(tiny_qlora, ids, "cpu")                 # 평가 모드를 거쳐도 학습이 가능해야 한다

    after = frozen_4bit(tiny_qlora)
    assert all(torch.equal(before[k], after[k]) for k in before)
    assert math.isfinite(eval_loss(tiny_qlora, ids, "cpu")) and math.isfinite(l0)
    tiny_qlora.save_pretrained(tmp_path)
    names = {f.name for f in tmp_path.iterdir()}
    assert "adapter_model.safetensors" in names and "model.safetensors" not in names
    assert (tmp_path / "adapter_model.safetensors").stat().st_size < 200_000   # LoRA 26,624개 × 4바이트 + 헤더

| 동결 | 학습 후 4비트 번호·absmax가 모두 학습 전과 같음 | 통과 |
| 평가 후 학습 | 평가 모드를 거친 뒤에도 학습이 진행됨(CPU 경로) | 통과 |
| Adapter 저장 | Adapter 파일만 저장되고 원본 가중치 파일은 없음 | 통과 |
| PPL 감소 | 0.5B QLoRA에서 학습 후 평가 PPL 감소(실습 2번) | 통과(27.90 → 17.73) |
| GT 1030 최대 VRAM | 설계 예산 약 1.5GB 내외 | 미검증 |

**완료 기준:** `target_modules`를 7종 전부로 바꿔 학습하고 학습 파라미터·PPL·Adapter 크기를 q·v 결과와 표로 비교하며, GPU가 있다면 2번의 GPU 최대 할당량을 기록하고, 테스트 2개를 모두 통과하면 이 장을 마친 것입니다.

## 핵심 정리

- QLoRA는 4비트 로딩 → kbit 학습 준비 → LoRA 부착 순서로 준비하고, 제25장의 학습 루프로 그대로 학습합니다.
- GT 1030 기준 설정은 시퀀스 256, Batch 1, Accumulation 4, Gradient Checkpointing, FP32 계산입니다.
- 교재 검증 환경(CPU 경로)에서 30단계 학습으로 평가 PPL이 27.90에서 17.73으로 내려갔고, 4비트 원본은 비트까지 그대로였습니다. 저장한 것은 약 2.1MB의 Adapter뿐입니다.
- 평가 PPL의 감소는 학습 데이터와 같은 주제·문체를 배운 결과이며, 일반 능력의 유지는 별도로 확인해야 합니다.
- bitsandbytes CPU 경로에서는 평가 모드의 추론용 가중치 재배치를 꺼야 학습할 수 있습니다. GT 1030 경로의 실제 실행과 VRAM은 미검증입니다.

**다음 장 연결:** 제25장(Full FT), 제29장(LoRA), 이 장(QLoRA)에서 세 가지 학습 방식을 모두 해 보았습니다. 제40장에서는 세 방식을 같은 체크포인트·데이터·평가 조건으로 맞춰 메모리와 품질을 한 표로 비교하고, 장비에 따라 어떤 방식을 고를지 정리하며 제4부를 마무리합니다.
