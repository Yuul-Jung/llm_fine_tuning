## 장 개요

제35장에서 균일한 간격의 INT4는 0.5B 모델의 PPL을 21.45에서 35.43(Group 64)으로 크게 떨어뜨렸습니다. 그런데 간격이 꼭 균일해야 할까요? 가중치는 0 근처에 몰려 있고 큰 값은 드뭅니다. 값이 많은 곳에 단계를 촘촘히, 드문 곳에 성기게 두면 같은 16단계로도 오차를 줄일 수 있습니다.

이 장은 QLoRA(제39장)가 쓰는 4비트 형식 **NF4**(NormalFloat 4)를 직접 구현합니다. 정규분포의 분위수로 16개 값을 만드는 방법, 균일 간격 대신 미리 정한 값 중에서 고르는 Codebook 양자화, 64개 블록마다 Scale을 두고 그 Scale까지 다시 양자화하는 이중 양자화를 차례로 만들고, bitsandbytes 라이브러리와 같은 결과를 내는지 확인합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 같은 4비트에서 값의 배치를 바꾸면 오차가 얼마나 줄며, 메타데이터까지 포함한 실제 비트는 얼마인가 |
| 실습 결과물 | NF4 Codebook과 bitsandbytes 비교, INT4·NF4 가중치 오차, 평균 비트 계산, 모델 PPL |
| 실습 파일 | `examples/ch36/`의 `nf4.py`, `test_ch36.py` |
| 선수 장 | 제33장(Scale), 제34장(INT4, Group), 제35장(가짜 양자화와 PPL 비교) |

```text
균일 INT4:  −1 ─┬──┬──┬──┬──┬──┬──┬── 0 ──┬──┬──┬──┬──┬──┬──┬─ 1     간격이 모두 같다
NF4:        −1 ──┬────┬───┬──┬─┬─┬┬── 0 ─┬┬─┬─┬──┬───┬────┬── 1     0 근처가 촘촘하다
```

## 가중치 분포와 NF4

학습된 신경망의 가중치는 대체로 **0을 중심으로 한 정규분포**에 가깝습니다. 블록 64개를 블록의 절댓값 최대로 나눠 [−1, 1]에 맞추면, 대부분의 값이 −0.5 ~ 0.5에 들어갑니다. 실습에서 확인하면 84%입니다. 그런데 균일 INT4는 이 구간에 16단계 중 7단계만 둡니다. 값의 84%가 단계의 절반도 안 되는 곳에 몰리는 셈입니다.

NF4는 반대로 생각합니다. 표준정규분포를 넓이가 같은 조각으로 나누고, 그 경계(분위수)에 단계를 둡니다. 값이 많이 나오는 0 근처는 조각이 좁아 단계가 촘촘하고, 드문 양 끝은 조각이 넓어 단계가 성깁니다. 이렇게 하면 16개 단계가 **고르게 쓰입니다**. 정규분포를 따르는 값이라면 어느 단계에 떨어질 확률이 거의 같아집니다.

NF4의 16개 값에는 몇 가지 약속이 더 있습니다.

| 약속 | 이유 |
|---|---|
| 0을 정확히 포함 | Padding이나 0 가중치를 정확히 표현한다(제33장) |
| 양수 8개, 음수 7개 | 0을 넣으면 16개를 대칭으로 나눌 수 없어 한쪽에 하나를 더 둔다 |
| 양 끝은 정확히 ±1 | 블록의 절댓값 최대가 오차 없이 표현된다 |
| 분위수 범위의 끝을 0.9677에서 자름 | 무한대인 분위수 0과 1을 피하면서 양 끝 값을 정한다 |

이 장의 `nf4_codebook()`은 이 규칙대로 PyTorch의 정규분포 역함수(`icdf`)로 16개 값을 계산합니다. bitsandbytes가 쓰는 표와 1e-7 이내로 같습니다.

## Codebook 양자화

NF4의 값은 균일하지 않으므로 `round(w ÷ Scale)`로는 코드를 구할 수 없습니다. 대신 **가장 가까운 값을 찾습니다**.

```text
양자화:    x = w ÷ absmax            블록을 [−1, 1]로 맞춘다
           번호 = argmin |x − Codebook[i]|,  i = 0 ~ 15     → 4비트로 저장
역양자화:  ŵ = Codebook[번호] × absmax
```

16개 값의 목록을 Codebook이라 부르고, 저장하는 것은 값이 아니라 목록의 **번호**입니다. 번호는 0 ~ 15이므로 제34장의 Bit Packing으로 바이트 하나에 두 개씩 담습니다. NF4는 부동소수점처럼 부호·지수·가수로 나뉜 형식이 아니라, 순전히 표에서 찾아 쓰는 형식입니다.

## Block-wise와 Double Quantization

NF4는 64개 가중치마다 블록을 나눠 블록마다 absmax를 하나씩 둡니다(제34장의 Group 양자화와 같은 생각). absmax를 FP32로 저장하면 가중치 하나당 32 ÷ 64 = 0.5비트가 더 듭니다. 4비트의 8분의 1이나 되는 적지 않은 비용입니다.

**이중 양자화**(Double Quantization)는 이 absmax들을 **다시 양자화**합니다. absmax는 모두 양수이고 비슷한 크기이므로, 평균을 빼고 256개씩 묶어 8비트로 담아도 오차가 작습니다.

```text
1단계: 가중치 64개 → NF4 번호 64개 + absmax 1개(FP32)
2단계: absmax 256개 → INT8 256개 + Scale 1개(FP32)  (평균 하나는 행렬 전체에 하나)
```

QLoRA 논문은 2단계를 8비트 부동소수점(FP8)으로 합니다. 이 장은 원리를 보이기 위해 제33장의 INT8 대칭 양자화로 단순화했습니다. 비트 계산은 같습니다.

## 저장 비용

양자화의 실제 비용은 가중치 비트에 메타데이터 비트를 더한 **평균 비트**로 따집니다.

```text
INT4 Group 64(FP32 Scale)     4 + 32 ÷ 64                     = 4.500비트
NF4 블록 64(FP32 absmax)      4 + 32 ÷ 64                     = 4.500비트
NF4 블록 64 + 이중 양자화      4 + 8 ÷ 64 + 32 ÷ (64 × 256)    ≈ 4.127비트
```

이중 양자화로 가중치 하나당 0.37비트를 아낍니다. 0.5B 모델의 양자화 대상 약 3.6억 개 가중치(Linear 168개)로 계산하면 약 16MiB입니다. 작아 보이지만 2GB VRAM에서는 의미 있는 크기이고, 모델이 커질수록 절약도 비례해서 커집니다.

## 핵심 실습

파일명: `examples/ch36/nf4.py`

```python
# 제36장 핵심 실습: NF4(NormalFloat 4비트)와 블록 단위·이중 양자화를 직접 구현해 INT4와 비교한다
#
# 실행: python examples/ch36/nf4.py
#
# NF4: 정규분포의 분위수로 만든 16개 값(Codebook) 중 가장 가까운 것을 고른다.
#      블록(64개)마다 절댓값 최대(absmax)로 [−1, 1]에 맞춘 뒤 Codebook에서 고르고, 번호(4비트)를 저장한다.

import math
import sys
from pathlib import Path

HERE = Path(__file__).resolve().parent
for p in (HERE.parent, HERE.parent / "ch22", HERE.parent / "ch33", HERE.parent / "ch34", HERE.parent / "ch35"):
    sys.path.insert(0, str(p))

import torch  # noqa: E402

from common.fixed_data import load_blocks  # noqa: E402
from common.qwen import load_model, load_tokenizer  # noqa: E402
from int4_pack import dequant_int4, quant_int4  # noqa: E402            (제34장)
from int8_quant import NAME  # noqa: E402                               (제33장)
from qwen_ppl import evaluate  # noqa: E402                             (제22장)
from quant_error import fake_quantize_model  # noqa: E402               (제35장)

BLOCK, BLOCK2 = 64, 256


def nf4_codebook(offset: float = 0.9677083) -> torch.Tensor:
    """정규분포 분위수로 16개 값을 만든다: 양수 8개 + 음수 7개 + 0, 최댓값으로 나눠 [−1, 1]"""
    normal = torch.distributions.Normal(0.0, 1.0)
    pos = normal.icdf(torch.linspace(offset, 0.5, 9, dtype=torch.float64)[:-1])     # 양수 8개
    neg = -normal.icdf(torch.linspace(offset, 0.5, 8, dtype=torch.float64)[:-1])    # 음수 7개
    values = torch.cat([pos, neg, torch.zeros(1, dtype=torch.float64)]).sort().values
    return (values / values.max()).float()


CODE = nf4_codebook()


def nf4_quant(w: torch.Tensor, block: int = BLOCK) -> tuple:
    """(4비트 번호 0~15, 블록별 absmax) 반환"""
    blocks = w.reshape(-1, block)
    absmax = blocks.abs().amax(dim=1, keepdim=True).clamp(min=1e-12)
    idx = (blocks / absmax).unsqueeze(-1).sub(CODE).abs().argmin(dim=-1)   # 가장 가까운 Codebook 값
    return idx.to(torch.uint8), absmax


def nf4_dequant(idx: torch.Tensor, absmax: torch.Tensor, shape) -> torch.Tensor:
    return (CODE[idx.long()] * absmax).reshape(shape)


def double_quant(absmax: torch.Tensor, block2: int = BLOCK2) -> tuple:
    """absmax(FP32)를 평균을 뺀 뒤 256개씩 INT8 대칭 양자화한다(QLoRA의 이중 양자화를 단순화)."""
    a = absmax.flatten()
    mean = a.mean()
    c = (a - mean).reshape(-1, block2)
    s2 = c.abs().amax(dim=1, keepdim=True) / 127
    return torch.round(c / s2).clamp(-127, 127).to(torch.int8), s2, mean


def double_dequant(q2, s2, mean, shape) -> torch.Tensor:
    return (q2.float() * s2).flatten().add(mean).reshape(shape)


def nf4_fake(w: torch.Tensor, dq: bool = False) -> torch.Tensor:
    idx, absmax = nf4_quant(w)
    if dq:
        absmax = double_dequant(*double_quant(absmax), absmax.shape)
    return nf4_dequant(idx, absmax, w.shape)


def avg_bits(block: int = BLOCK, dq: bool = False, block2: int = BLOCK2) -> float:
    """가중치 하나당 평균 비트 = 4 + Scale 비용"""
    return 4 + (8 / block + 32 / (block * block2) if dq else 32 / block)


def main() -> None:
    print("── 1. NF4 Codebook(정규분포 분위수로 만든 16개 값) ──")
    print("  " + ", ".join(f"{v:+.4f}" for v in CODE.tolist()))
    print("  균일 INT4(÷7):  " + ", ".join(f"{v / 7:+.3f}" for v in range(-7, 8)))
    try:
        import bitsandbytes.functional as bF
        ref = bF.get_4bit_type("nf4", device="cpu")
        print(f"  bitsandbytes NF4 표와 최대 차이: {(ref - CODE).abs().max().item():.1e}")
    except Exception as e:                                         # 설치되지 않은 환경
        print(f"  bitsandbytes 비교 생략({type(e).__name__})")

    w = dict(load_model().named_parameters())[NAME].detach()
    print(f"\n── 2. {NAME}: 블록 64, 같은 4비트 비교 ──")
    blocks = (w.reshape(-1, BLOCK) / w.reshape(-1, BLOCK).abs().amax(dim=1, keepdim=True)).flatten()
    within = (blocks.abs() < 0.5).float().mean().item()
    n_int4 = sum(abs(v / 7) < 0.5 for v in range(-7, 8))
    n_nf4 = int((CODE.abs() < 0.5).sum())
    print(f"  블록 최댓값으로 나눈 값의 {within:.0%}가 −0.5 ~ 0.5에 있다"
          f"(이 구간의 단계: 균일 INT4 {n_int4}개, NF4 {n_nf4}개)")
    rows = {"INT4 Group 64": dequant_int4(*quant_int4(w, 64), 64),
            "NF4 블록 64": nf4_fake(w), "NF4 블록 64 + 이중 양자화": nf4_fake(w, dq=True)}
    for label, back in rows.items():
        print(f"  {label:<26}상대 오차 {((back - w).norm() / w.norm()).item():.4f}")
    try:
        import bitsandbytes.functional as bF
        q, st = bF.quantize_4bit(w.contiguous(), blocksize=BLOCK, quant_type="nf4", compress_statistics=False)
        theirs = bF.dequantize_4bit(q, st)
        print(f"  bitsandbytes NF4(CPU)와 직접 구현의 최대 차이 {(theirs - rows['NF4 블록 64']).abs().max().item():.1e}")
    except Exception as e:
        print(f"  bitsandbytes 비교 생략({type(e).__name__})")

    print("\n── 3. 가중치 하나당 평균 비트 ──")
    for label, b in (("INT4 Group 64(FP32 Scale)", avg_bits()), ("NF4 블록 64(FP32 absmax)", avg_bits()),
                     ("NF4 블록 64 + 이중 양자화", avg_bits(dq=True))):
        print(f"  {label:<28}{b:.3f}비트")

    print("\n── 4. 모델 전체 PPL(제35장과 같은 조건) ──")
    tok = load_tokenizer()
    eval_blocks = load_blocks(tok, "eval")
    for label, f in (("INT4 Group 64", lambda x: dequant_int4(*quant_int4(x, 64), 64)),
                     ("NF4 블록 64", nf4_fake), ("NF4 + 이중 양자화", lambda x: nf4_fake(x, dq=True))):
        m = load_model()
        fake_quantize_model(m, f)
        print(f"  {label:<18}PPL {math.exp(evaluate(m, eval_blocks)['loss']):.2f}")
        del m


if __name__ == "__main__":
    main()
```

def test_codebook_shape():
    assert CODE.numel() == 16 and CODE[0] == -1 and CODE[-1] == 1
    assert (CODE == 0).sum() == 1 and (CODE > 0).sum() == 8 and (CODE < 0).sum() == 7
    assert torch.all(CODE[1:] > CODE[:-1])


def test_matches_bitsandbytes_table():
    bF = pytest.importorskip("bitsandbytes.functional")
    torch.testing.assert_close(bF.get_4bit_type("nf4", device="cpu"), CODE, atol=1e-6, rtol=0)


def test_nearest_codebook_choice():
    idx, absmax = nf4_quant(torch.tensor([0.0, 0.5, -1.0, 0.08] + [0.0] * 60))
    assert absmax.item() == 1.0
    assert CODE[idx[0, :4].long()].tolist() == pytest.approx([0.0, 0.4407, -1.0, 0.0796], abs=1e-4)   # 0.5는 0.4407이 더 가깝다


def test_nf4_beats_int4_on_normal_weights():
    torch.manual_seed(0)
    w = torch.randn(256, 256) * 0.02
    e_int4 = (dequant_int4(*quant_int4(w, 64), 64) - w).norm()
    e_nf4 = (nf4_fake(w) - w).norm()
    assert e_nf4 < 0.9 * e_int4


def test_double_quant_small_error_and_bits():
    torch.manual_seed(1)
    absmax = torch.rand(1024, 1) * 0.1 + 0.02
    back = double_dequant(*double_quant(absmax), absmax.shape)
    assert ((back - absmax).abs() / absmax).max() < 0.01
    assert avg_bits() == 4.5 and avg_bits(dq=True) == pytest.approx(4.127, abs=1e-3)


def test_roundtrip_shape():
    w = torch.randn(8, 128)
    idx, absmax = nf4_quant(w)
    assert idx.dtype == torch.uint8 and idx.max() <= 15
    assert nf4_dequant(idx, absmax, w.shape).shape == w.shape

## 핵심 정리

- 가중치는 0 중심의 정규분포에 가깝습니다. NF4는 정규분포의 분위수에 16단계를 두어, 값이 몰린 0 근처를 촘촘하게 표현합니다.
- NF4는 Codebook 양자화입니다. 블록을 absmax로 [−1, 1]에 맞춘 뒤 16개 값 중 가장 가까운 것의 번호(4비트)를 저장합니다.
- 블록 64개마다 absmax를 두고, 이중 양자화로 absmax까지 8비트로 줄이면 평균 4.127비트입니다.
- 같은 4비트에서 NF4는 균일 INT4보다 가중치 오차(12.4% → 9.7%)와 모델 PPL(35.43 → 27.86)이 모두 좋습니다.
- 직접 구현한 NF4는 bitsandbytes의 표·복원값과 일치합니다.

**다음 장 연결:** 이 장은 CPU에서 NF4를 계산했습니다. QLoRA는 bitsandbytes의 GPU 커널로 4비트 가중치를 GPU 메모리에 올리고 계산합니다. 제37장에서는 bitsandbytes를 GT 1030 같은 오래된 GPU에서 쓸 때의 호환성(Compute Capability, CUDA 버전)과 CPU 대체 경로를 정리합니다.
