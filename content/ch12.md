## 장 개요

제11장의 지도에서 Self-Attention은 "다른 토큰의 정보를 가져오는" 부품이었습니다. 그런데 어떤 토큰이 어떤 토큰의 정보를, 얼마나 가져와야 할까요? Attention은 이 질문을 **검색**처럼 풉니다. 각 토큰이 질문(Query)을 던지고, 모든 토큰이 내건 색인(Key)과 비교해, 잘 맞는 토큰의 내용(Value)을 가져옵니다.

이 장은 그 세 가지 벡터, Query·Key·Value를 만드는 단계를 다룹니다. 계산 자체는 제05장의 Linear 세 번이 전부지만, 같은 입력이 세 개의 서로 다른 역할로 갈라지는 지점이라 의미가 큽니다. 실제 Qwen2.5-0.5B의 0번 계층에서 Q·K·V를 직접 계산하고, 모델 내부에 Hook을 걸어 꺼낸 값과 비교해 정확히 같음을 확인합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | Query·Key·Value는 각각 무엇이며, 어떻게 만들어지는가 |
| 실습 결과물 | 검색 비유 계산, 0번 계층 Q·K·V의 직접 계산과 모델 내부 출력 비교, Bias 크기 |
| 실습 파일 | `examples/ch12/`의 `qkv_projection.py`, `test_ch12.py` |
| 선수 장 | 제03장(헤드 분할), 제05장(Linear), 제11장(구조 지도) |

```text
입력 x [batch, seq, 896]   (RMSNorm을 거친 토큰 벡터)
   ├── q_proj ──▶ Query  [batch, seq, 896]  → 헤드 14개 × 64
   ├── k_proj ──▶ Key    [batch, seq, 128]  → 헤드  2개 × 64
   └── v_proj ──▶ Value  [batch, seq, 128]  → 헤드  2개 × 64
```

## Query·Key·Value의 역할

도서관에서 자료를 찾는 장면을 떠올려 봅시다. 찾고 싶은 것을 **질문**으로 적고, 책마다 붙은 **색인**과 비교해, 잘 맞는 책의 **내용**을 가져옵니다. Attention은 이 과정을 벡터로 합니다.

| 벡터 | 비유 | 하는 일 |
|---|---|---|
| Query(쿼리, 질의 벡터) | 질문 | "나는 어떤 정보가 필요한가" |
| Key(키, 비교 대상 벡터) | 색인 | "나는 어떤 정보를 가지고 있다고 내세우는가" |
| Value(밸류, 전달할 정보 벡터) | 내용 | "선택되면 실제로 건네줄 정보" |

도서관과 다른 점이 두 가지 있습니다. 첫째, 책 한 권만 고르지 않고 **모든 책을 닮은 정도에 비례해 조금씩** 가져옵니다. 닮은 정도는 제04장의 내적으로 재고, 비율은 제06장의 Softmax로 만듭니다. 둘째, 모든 토큰이 질문자이자 동시에 책입니다. 각 토큰이 자기 Query로 다른 모든 토큰의 Key를 훑어, Value를 섞어 가져옵니다.

```text
Query와 가장 닮은 Key를 찾는다
   점수 = Query · Key          (제04장 내적)
   비율 = Softmax(점수)        (제06장)
   결과 = Σ 비율 × Value       (가중 평균)
```

핵심 실습 1에서 Key 3개와 Value 3개로 이 과정을 계산합니다. 점수 계산과 Softmax의 세부, 그리고 `√dₖ`로 나누는 이유는 제13장에서 본격적으로 다룹니다. 이 장의 관심은 Q·K·V가 **어디서 오는가**입니다.

## WQ·WK·WV와 차원

Q·K·V는 같은 입력 `x`에서 나옵니다. 같은 토큰 벡터에 서로 다른 가중치 행렬 세 개를 곱해, 세 가지 역할의 벡터를 만듭니다. 제05장의 규약으로 쓰면 다음과 같습니다.

```text
Q = x W_Qᵀ + b_Q      W_Q: [896, 896]   →  Q: [batch, seq, 896]
K = x W_Kᵀ + b_K      W_K: [128, 896]   →  K: [batch, seq, 128]
V = x W_Vᵀ + b_V      W_V: [128, 896]   →  V: [batch, seq, 128]
```

세 행렬은 학습으로 정해집니다. 같은 토큰이라도 "무엇을 찾을지(Q)", "무엇으로 찾아질지(K)", "무엇을 건넬지(V)"가 다르므로, 각각 다른 행렬로 다른 측면을 뽑아냅니다.

### Q는 896, K·V는 128인 이유

Query의 출력은 896인데 Key와 Value는 128밖에 되지 않습니다. 헤드로 나눠 보면 이유가 보입니다.

| 벡터 | 출력 크기 | 헤드 수 × head_dim |
|---|---|---|
| Query | 896 | 14 × 64 |
| Key | 128 | 2 × 64 |
| Value | 128 | 2 × 64 |

Query 헤드는 14개인데 Key·Value 헤드는 2개뿐입니다. Query 헤드 7개가 Key·Value 헤드 하나를 함께 쓰는 GQA(Grouped Query Attention) 구조이기 때문입니다. Key와 Value는 생성 중에 계속 저장해 둬야 하는 값이라(KV Cache, 제20장), 개수를 줄이면 메모리를 크게 아낄 수 있습니다. GQA의 동작은 제15장에서 직접 구현합니다. 헤드로 나누는 연산은 제03장에서 만든 `split_heads()`를 그대로 씁니다.

### Q·K·V의 입력은 RMSNorm의 출력

제11장의 구조도대로, Q·K·V를 만드는 입력은 토큰 벡터 그 자체가 아니라 `input_layernorm`(RMSNorm)을 거친 값입니다. 이 장의 실습은 RMSNorm의 출력을 모델 내부에서 꺼내 그대로 입력으로 씁니다. RMSNorm을 직접 구현하는 일은 제18장에서 합니다.

## QKV Bias

제05장에서 확인했듯 Qwen2.5는 Q·K·V Projection에만 편향(Bias)이 있고, `o_proj`와 FFN에는 없습니다. 이것은 모델마다 다른 설계 선택입니다.

| 모델 계열 | Q·K·V Bias |
|---|---|
| Qwen2·Qwen2.5 | 있음 |
| Llama 계열 | 없음 |

Bias 유무는 모델을 직접 구현하거나 파라미터 수를 계산할 때, 그리고 제19장에서 Qwen2와 호환되는 작은 모델을 만들 때 반드시 맞춰야 하는 세부입니다. 문서나 일반론에 의존하지 말고 실제 가중치에서 확인하는 습관이 필요합니다.

실제 값을 들여다보면 흥미로운 점이 하나 더 있습니다. 핵심 실습 5번에서 보듯 0번 계층의 Q·K Bias는 입력에 따라 달라지는 부분보다 훨씬 큽니다. Q·K 벡터의 상당 부분이 입력과 관계없이 고정된 방향이라는 뜻입니다. Bias를 무시해도 되는 작은 보정값으로 여기면 안 되는 이유입니다.

## QKV Projection 직접 구현

직접 구현은 제05장의 `linear_forward()`를 세 번 부르는 것으로 충분합니다. 핵심은 계산보다 **검증 방법**입니다. 모델 내부에서 실제로 계산된 Q·K·V를 꺼내, 같은 입력으로 직접 계산한 값과 비교해야 합니다.

### Forward Hook: 모델 내부 들여다보기

PyTorch의 Forward Hook은 특정 계층이 계산을 마칠 때마다 자동으로 불리는 함수입니다. 모델 코드를 고치지 않고도 중간 결과를 꺼낼 수 있어, 이 교재의 검증에서 계속 쓰입니다.

```text
handle = 계층.register_forward_hook(함수)      ← Hook 걸기
model(입력)                                    ← 순전파 중에 함수(계층, 입력, 출력)가 불림
handle.remove()                               ← 다 쓰면 반드시 제거
```

Hook을 제거하지 않으면 이후 모든 순전파에서 계속 불려 메모리를 차지하고 결과를 엉키게 합니다. 실습 코드는 Hook을 건 순전파가 끝나자마자 모두 제거합니다.

## 핵심 실습

0번 계층에 Hook 네 개를 걸어 RMSNorm 출력과 q·k·v_proj 출력을 꺼내고, RMSNorm 출력을 입력 삼아 Q·K·V를 직접 계산해 비교합니다. 제03장의 `split_heads()`와 제05장의 `linear_forward()`를 다시 씁니다.

파일명: `examples/ch12/qkv_projection.py`

```python
# 제12장 핵심 실습: Qwen2.5-0.5B 0번 계층의 Q·K·V Projection을 직접 계산해 모델 내부 출력과 비교
#
# 실행: python examples/ch12/qkv_projection.py

import sys
from pathlib import Path

ROOT = Path(__file__).resolve().parents[1]
sys.path.insert(0, str(ROOT))
sys.path.insert(0, str(ROOT / "ch03"))
sys.path.insert(0, str(ROOT / "ch05"))

import torch  # noqa: E402

from common.qwen import load_model, load_tokenizer  # noqa: E402
from head_split import split_heads  # noqa: E402  (제03장)
from linear_scratch import linear_forward  # noqa: E402  (제05장)

TEXT = "언어 모델은 다음 토큰을 예측한다."


def toy_retrieval() -> None:
    """검색 비유: Query와 가장 닮은 Key의 Value를 가져온다(가중 평균)."""
    keys = torch.tensor([[1.0, 0.0], [0.0, 1.0], [0.7, 0.7]])     # 색인 3개
    values = torch.tensor([[10.0], [20.0], [30.0]])                 # 각 색인의 내용
    query = torch.tensor([0.0, 5.0])                                # 두 번째 색인과 닮은 질문
    weights = torch.softmax(keys @ query, dim=0)                    # 닮은 정도 → 비율
    print(f"Query·Key 점수: {(keys @ query).tolist()}")
    print(f"가져올 비율:    {[round(w, 3) for w in weights.tolist()]}")
    print(f"가져온 내용:    {(weights @ values).item():.2f}  (Value 20에 가까움)")


def capture_projections(model, ids: torch.Tensor) -> dict:
    """Forward Hook으로 0번 계층의 RMSNorm 출력과 q/k/v_proj 출력을 붙잡는다."""
    layer = model.model.layers[0]
    captured, handles = {}, []
    targets = {"norm": layer.input_layernorm, "q": layer.self_attn.q_proj,
               "k": layer.self_attn.k_proj, "v": layer.self_attn.v_proj}
    for name, module in targets.items():
        def hook(mod, inputs, output, name=name):
            captured[name] = output.detach()
        handles.append(module.register_forward_hook(hook))
    with torch.no_grad():
        model(ids)
    for h in handles:
        h.remove()                                                   # Hook은 쓰고 나면 반드시 제거
    return captured


def main() -> None:
    print("── 1. 검색 비유로 보는 Q·K·V ──")
    toy_retrieval()

    model, tok = load_model(), load_tokenizer()
    attn = model.model.layers[0].self_attn

    print("\n── 2. 0번 계층 Q·K·V Projection 가중치 ──")
    for name in ("q_proj", "k_proj", "v_proj", "o_proj"):
        lin = getattr(attn, name)
        bias = tuple(lin.bias.shape) if lin.bias is not None else "없음"
        print(f"  {name}: weight {tuple(lin.weight.shape)}, bias {bias}")

    ids = tok(TEXT, return_tensors="pt").input_ids
    cap = capture_projections(model, ids)
    x = cap["norm"]                                                  # q/k/v_proj에 들어간 입력
    print(f"\n── 3. 같은 입력 {tuple(x.shape)}으로 직접 계산 ──")
    for name in ("q", "k", "v"):
        lin = getattr(attn, f"{name}_proj")
        mine = linear_forward(x, lin.weight.detach(), lin.bias.detach())
        error = (mine - cap[name]).abs().max().item()
        print(f"  {name.upper()}: 직접 {tuple(mine.shape)}, 모델 내부 {tuple(cap[name].shape)}, 최대 오차 {error:.1e}")

    print("\n── 4. 헤드로 나누기(제03장 split_heads) ──")
    q_heads = split_heads(cap["q"], 14)
    k_heads = split_heads(cap["k"], 2)
    print(f"  Q {tuple(cap['q'].shape)} → {tuple(q_heads.shape)}  (Query 헤드 14개)")
    print(f"  K {tuple(cap['k'].shape)} → {tuple(k_heads.shape)}  (KV 헤드 2개)")

    print("\n── 5. Bias의 크기 ──")
    for name in ("q", "k", "v"):
        lin = getattr(attn, f"{name}_proj")
        no_bias = (x @ lin.weight.detach().T).norm(dim=-1).mean().item()
        print(f"  {name}_proj: bias 크기 {lin.bias.norm().item():7.2f},  "
              f"bias 없는 출력의 평균 크기 {no_bias:7.2f}")


if __name__ == "__main__":
    main()
```

**핵심 코드 풀이**

- `toy_retrieval()`은 01절의 검색 비유를 숫자로 보여 줍니다. Query `[0, 5]`는 두 번째 Key `[0, 1]`과 가장 닮았으므로(점수 5.0) 비율 0.813을 받고, 결과 21.76은 두 번째 Value 20에 가깝습니다. 세 번째 Key도 어느 정도 닮아(점수 3.5) Value 30을 조금 섞었습니다. 한 권만 고르지 않고 닮은 만큼 섞는다는 점을 확인하세요.
- `capture_projections()`는 `register_forward_hook`으로 Hook 네 개를 걸고, 순전파를 한 번 한 뒤 모두 제거합니다. Hook 함수의 `name=name`은 반복문 안에서 만든 함수가 각자 자기 이름을 기억하게 하는 Python 관용구입니다.
- 3번에서 직접 계산과 모델 내부 출력의 차이는 `1e-5` 수준 이하입니다. K의 오차가 Q보다 조금 큰 것은 5번에서 보듯 K의 Bias가 커서 값 자체가 크기 때문이며, 상대 오차로는 매우 작습니다. 우리가 계산한 Q·K·V가 실제 모델의 것과 같다는 뜻입니다.
- 4번에서 Q는 헤드 14개, K는 헤드 2개로 나뉩니다. 두 텐서의 헤드 수가 다른 상태로 어떻게 Attention을 계산하는지가 제15장 GQA의 주제입니다.
- 5번은 03절에서 말한 Bias의 크기입니다. `q_proj`와 `k_proj`의 Bias 크기(235.10, 367.12)는 입력에서 나온 부분의 평균 크기(19.78, 6.48)보다 열 배 이상 큽니다. 반면 `v_proj`의 Bias는 0.17로 작습니다. 같은 Bias라도 역할에 따라 크기가 전혀 다르게 학습되었습니다.

    assert all(getattr(attn, n).bias is not None for n in ("q_proj", "k_proj", "v_proj"))
    assert attn.o_proj.bias is None


@pytest.mark.parametrize("name, out_dim", [("q", 896), ("k", 128), ("v", 128)])
def test_direct_equals_hook(captured, name, out_dim):
    model, cap, seq = captured

    mine = linear_forward(cap["norm"], lin.weight.detach(), lin.bias.detach())
    assert mine.shape == (1, seq, out_dim)
    torch.testing.assert_close(mine, cap[name], atol=1e-4, rtol=1e-5)

## 핵심 정리

- Query는 질문, Key는 색인, Value는 내용입니다. 각 토큰은 Query로 모든 토큰의 Key와 닮은 정도를 재고, 그 비율대로 Value를 섞어 가져옵니다.
- Q·K·V는 RMSNorm을 거친 같은 입력에 서로 다른 Linear 세 개를 적용해 만듭니다.
- Qwen2.5-0.5B는 Query 896(14 × 64), Key·Value 128(2 × 64)입니다. Key·Value 헤드가 적은 GQA 구조입니다.
- Qwen2.5는 Q·K·V Projection에만 Bias가 있으며, 0번 계층의 Q·K Bias는 입력에서 나온 부분보다 훨씬 큽니다.
- Forward Hook으로 모델 내부 출력을 꺼내 직접 계산과 비교하는 것이 제2부의 기본 검증 방법입니다.

**다음 장 연결:** Q·K·V가 준비되었습니다. 제13장에서는 이 셋으로 실제 Attention을 계산합니다. Query와 Key의 내적으로 점수를 만들고, `√dₖ`로 나누고, Softmax로 비율을 정해, Value를 섞는 전 과정을 4×4 행렬로 손계산하며 따라갑니다.
