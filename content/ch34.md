## 장 개요

제33장의 INT8은 FP32의 4분의 1로 가중치를 담았습니다. 4비트로 가면 다시 절반, FP32의 8분의 1이 됩니다. 0.5B 모델의 2GB가 약 250MB가 되어 GT 1030의 VRAM 안에 넉넉히 들어갑니다. 대가는 정밀도입니다. 표현할 수 있는 값이 256가지에서 **16가지**로 줄어듭니다.

또 하나의 문제는 저장입니다. 컴퓨터 메모리의 최소 단위는 바이트(8비트)이고, PyTorch에는 4비트 정수 자료형이 없습니다. 4비트 값 두 개를 바이트 하나에 직접 담고(Bit Packing), 꺼낼 때 음수를 올바르게 되돌려야(부호 확장) 합니다. 이 장은 그 시프트·마스킹 연산을 직접 구현하고, 패킹한 가중치 파일이 FPGA 메모리에 어떻게 놓이는지까지 연결합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 4비트로 가중치를 담으면 오차가 얼마나 커지며, 4비트 값을 어떻게 바이트에 담고 꺼내는가 |
| 실습 결과물 | 패킹 손계산, INT8·INT4(채널·묶음별) 오차 비교, 패킹 왕복 확인, INT4·INT8 파일 크기, FPGA용 hex 파일 |
| 실습 파일 | `examples/ch34/`의 `int4_pack.py`, `test_ch34.py` |
| 선수 장 | 제31장(2의 보수, 비트 연산), 제33장(대칭 양자화, Per-Channel) |

```text
INT4 코드:   w0 = 3 (0011)   w1 = −2 (1110)
패킹:        바이트 = (w1 & 0xF) << 4  |  (w0 & 0xF)  =  1110 0011  = 0xE3
언패킹:      하위 = 0xE3 & 0xF = 3        상위 = (0xE3 >> 4) & 0xF = 14 → 부호 확장 → −2
```

## 4비트 표현 범위

부호 있는 4비트는 −8 ~ 7, 16가지 값입니다(제31장). 대칭 양자화에서는 양쪽을 똑같이 쓰기 위해 −7 ~ 7의 15가지를 씁니다.

```text
INT8 대칭:  Scale = 절댓값 최대 ÷ 127      간격이 범위의 1/254
INT4 대칭:  Scale = 절댓값 최대 ÷ 7        간격이 범위의 1/14   → 같은 범위에서 약 18배 거칠다
```

간격이 18배 넓어지면 오차도 그만큼 커집니다. Per-Channel만으로는 부족하므로, 4비트에서는 행 하나를 다시 **작은 묶음**(Group)으로 나눠 묶음마다 Scale을 둡니다. 묶음이 작을수록 이상값의 영향이 그 묶음 안에만 머물러 오차가 줄지만, Scale을 저장할 공간이 늘어납니다.

| 묶음 크기 | Scale 저장 비용(FP32 Scale 기준) |
|---|---|
| 행 전체(896개) | 가중치당 +0.04비트 |
| 128개 | 가중치당 +0.25비트 |
| 64개 | 가중치당 +0.5비트 |
| 32개 | 가중치당 +1비트 |

실무의 4비트 양자화(GPTQ, AWQ, 제36장의 NF4 등)는 대개 64~128개 묶음을 씁니다. NF4는 Scale 자체를 다시 양자화해(Double Quantization) 이 비용을 더 줄입니다.

## Bit Packing

4비트 값 두 개를 바이트 하나에 담는 데는 두 가지 비트 연산이면 충분합니다.

```text
v & 0xF     하위 4비트만 남긴다(마스킹)    음수 −2의 2의 보수 비트열에서 하위 4비트 1110만 꺼낸다
v << 4      왼쪽으로 4칸 민다(시프트)      상위 4비트 자리로 옮긴다
a | b       비트별 OR                      두 4비트를 한 바이트로 합친다
```

```text
패킹:    byte = (w_홀수 & 0xF) << 4  |  (w_짝수 & 0xF)
언패킹:  w_짝수 = byte & 0xF,   w_홀수 = (byte >> 4) & 0xF     (그다음 부호 확장)
```

`& 0xF`가 음수에도 통하는 것은 2의 보수 덕분입니다. −2는 8비트로 `11111110`이고, 하위 4비트 `1110`은 그 자체로 4비트 2의 보수의 −2입니다. 패킹 순서(짝수 번째를 하위, 홀수 번째를 상위)는 약속이므로, 패킹하는 쪽과 꺼내는 쪽이 같은 약속을 써야 합니다.

## 부호 있는 4비트 복원

언패킹으로 꺼낸 4비트는 0 ~ 15의 부호 없는 수입니다. 이것을 −8 ~ 7로 되돌리는 것이 **부호 확장**(Sign Extension)입니다.

```text
4비트 v의 맨 위 비트(자리값 8)가 1이면 음수:  v − 16
  1110 = 14  →  14 − 16 = −2
  0011 = 3   →  3
```

제31장의 2의 보수 정의, "맨 앞 비트의 자리값을 −2ⁿ⁻¹로 읽는다"를 그대로 적용한 것입니다. 14 = 8 + 4 + 2를 −8 + 4 + 2 = −2로 읽으면 14 − 16과 같습니다. 부호 확장을 빠뜨리면 음수 가중치가 모두 8 ~ 15의 큰 양수가 되어, 모델은 오류 없이 엉뚱한 값을 계산합니다. 테스트에서 16가지 값 전부를 확인하는 이유입니다.

## 파일 생성과 FPGA 연계

패킹한 가중치는 그대로 바이트 열로 저장할 수 있습니다. INT8 파일이 가중치 하나에 1바이트라면, INT4 파일은 2개에 1바이트이므로 정확히 절반입니다.

FPGA에서 가중치를 쓰려면 이 바이트를 블록 메모리(BRAM)에 실어야 합니다. Verilog의 `$readmemh`가 읽는 hex 파일은 한 줄에 메모리 한 워드를 16진수로 적습니다. 이 장은 32비트 워드 하나에 INT4 가중치 8개를 담고, 워드의 하위 4비트부터 차례로 가중치 0, 1, 2, …가 놓이도록 만듭니다.

```text
워드 01f122f0  →  니블(4비트) 하위부터:  0  f  2  2  1  f  1  0
                 부호 확장:              0 −1  2  2  1 −1  1  0     = 가중치 w0 ~ w7

// Verilog에서 i번째 가중치 꺼내기
wire signed [3:0] w_i = word[4*i +: 4];
```

Verilog의 `signed` 선언이 부호 확장을 대신해 줍니다. 하드웨어에서는 언패킹이 배선을 나누는 것뿐이라 추가 비용이 거의 없습니다. 용량도 계산해 봅시다. q_proj 하나의 INT4 가중치는 401,408바이트, 약 3.1Mb입니다. Artix-7 XC7A35T(예: Basys3 보드)의 BRAM은 모두 1.8Mb이므로 계층 하나의 q_proj도 다 담지 못합니다. 대형 모델을 FPGA에서 돌릴 때 외부 DRAM에서 가중치를 흘려 넣는 구조가 필요한 이유입니다.

## 핵심 실습

파일명: `examples/ch34/int4_pack.py`

```python
# 제34장 핵심 실습: INT4 양자화와 Bit Packing — 4비트 두 개를 한 바이트에 담아 파일로 저장한다
#
# 실행: python examples/ch34/int4_pack.py
#
# 바이트 하나 = [상위 4비트: 홀수 번째 값][하위 4비트: 짝수 번째 값]

import sys
import tempfile
from pathlib import Path

HERE = Path(__file__).resolve().parent
sys.path.insert(0, str(HERE.parent))
sys.path.insert(0, str(HERE.parent / "ch33"))

import torch  # noqa: E402

from common.qwen import load_model  # noqa: E402
from int8_quant import NAME, dequant_symmetric, quant_symmetric  # noqa: E402  (제33장)


def quant_int4(w: torch.Tensor, group: int | None = None) -> tuple:
    """INT4 대칭 양자화(−7 ~ 7). group이 없으면 행마다, 있으면 행 안의 group개씩 Scale 하나."""
    rows = w.reshape(-1, group) if group else w
    scale = (rows.abs().amax(dim=1, keepdim=True) / 7).clamp(min=1e-12)
    q = torch.round(rows / scale).clamp(-7, 7).to(torch.int8)       # 담는 그릇은 int8, 값은 4비트
    return q.reshape(w.shape), scale


def dequant_int4(q: torch.Tensor, scale: torch.Tensor, group: int | None = None) -> torch.Tensor:
    rows = q.reshape(-1, group) if group else q
    return (rows.float() * scale).reshape(q.shape)


def pack(q: torch.Tensor) -> torch.Tensor:
    """−8 ~ 7 정수 두 개를 바이트 하나로: 하위 4비트 = 짝수 번째, 상위 4비트 = 홀수 번째"""
    flat = q.flatten().to(torch.int16)
    assert flat.numel() % 2 == 0 and flat.min() >= -8 and flat.max() <= 7
    low, high = flat[0::2] & 0xF, flat[1::2] & 0xF          # & 0xF: 2의 보수 하위 4비트만 남김
    return (low | (high << 4)).to(torch.uint8)


def sign_extend4(v: torch.Tensor) -> torch.Tensor:
    """4비트 2의 보수(0 ~ 15)를 −8 ~ 7로: 맨 위 비트(8)가 켜져 있으면 16을 뺀다"""
    return torch.where(v >= 8, v - 16, v)


def unpack(packed: torch.Tensor, shape) -> torch.Tensor:
    b = packed.to(torch.int16)
    low, high = sign_extend4(b & 0xF), sign_extend4((b >> 4) & 0xF)
    return torch.stack([low, high], dim=1).flatten().to(torch.int8).reshape(shape)


def rel_err(a, b) -> float:
    return ((a - b).norm() / b.norm()).item()


def main() -> None:
    print("── 1. 손계산: [3, −2] → 한 바이트 ──")
    p = pack(torch.tensor([3, -2]))
    print(f"  3 = 0011, −2 = 1110(2의 보수) → 상위 1110 | 하위 0011 = {int(p):08b} = 0x{int(p):02X} = {int(p)}")
    print(f"  되돌리기: 하위 {int(p) & 0xF} → {int(sign_extend4(torch.tensor(int(p) & 0xF)))}, "
          f"상위 {int(p) >> 4} → {int(sign_extend4(torch.tensor(int(p) >> 4)))}")
    every = torch.arange(-8, 8)
    print(f"  −8 ~ 7 전체 왕복 일치: {torch.equal(unpack(pack(every), every.shape), every.to(torch.int8))}")

    w = dict(load_model().named_parameters())[NAME].detach()
    print(f"\n── 2. {NAME} {tuple(w.shape)}: INT8 vs INT4 상대 오차 ──")
    q8, s8 = quant_symmetric(w, per_channel=True)
    print(f"  INT8 Per-Channel        {rel_err(dequant_symmetric(q8, s8), w):.3f}  (값 255가지)")
    for label, g in (("INT4 Per-Channel", None), ("INT4 Group 128", 128), ("INT4 Group 64", 64), ("INT4 Group 32", 32)):
        q4, s4 = quant_int4(w, g)
        extra = s4.numel() * 4 / w.numel() * 8                   # Scale(FP32)이 가중치 하나당 더하는 비트
        print(f"  {label:<24}{rel_err(dequant_int4(q4, s4, g), w):.3f}  (Scale {s4.numel():>6,}개, "
              f"가중치당 +{extra:.2f}비트)")

    print("\n── 3. 패킹과 파일 크기 ──")
    q4, s4 = quant_int4(w, 64)
    packed = pack(q4)
    same = torch.equal(unpack(packed, q4.shape), q4)
    with tempfile.TemporaryDirectory() as d:
        (Path(d) / "w_int8.bin").write_bytes(q8.numpy().tobytes())
        (Path(d) / "w_int4.bin").write_bytes(packed.numpy().tobytes())
        (Path(d) / "w_int4.hex").write_text(
            "\n".join(packed[i:i + 4].flip(0).numpy().tobytes().hex() for i in range(0, packed.numel(), 4)) + "\n")
        sizes = {f.name: f.stat().st_size for f in sorted(Path(d).iterdir())}
        head = (Path(d) / "w_int4.hex").read_text().splitlines()[:2]
    print(f"  패킹 → 언패킹 왕복 완전 일치: {same}")
    print(f"  파일 크기 {sizes}")
    print(f"  INT4 / INT8 = {sizes['w_int4.bin'] / sizes['w_int8.bin']:.3f}")
    print(f"  w_int4.hex 앞 두 줄(32비트 워드, 가중치 8개씩): {head}")
    print(f"  워드 하나의 가중치 8개: {q4.flatten()[:8].tolist()}")


if __name__ == "__main__":
    main()
```

# 제34장 검증 테스트
#
# 실행: python -m pytest examples/ch34 -q

import sys
from pathlib import Path

import pytest
import torch

HERE = Path(__file__).resolve().parent
for p in (HERE, HERE.parent, HERE.parent / "ch33"):
    sys.path.insert(0, str(p))

from int4_pack import dequant_int4, pack, quant_int4, sign_extend4, unpack  # noqa: E402


def test_hand_byte():
    assert int(pack(torch.tensor([3, -2]))) == 0xE3


def test_sign_extension_all_nibbles():
    v = torch.arange(16)
    assert sign_extend4(v).tolist() == list(range(8)) + list(range(-8, 0))


def test_roundtrip_random():
    torch.manual_seed(0)
    q = torch.randint(-8, 8, (64, 32), dtype=torch.int8)
    p = pack(q)
    assert p.dtype == torch.uint8 and p.numel() == q.numel() // 2
    assert torch.equal(unpack(p, q.shape), q)


def test_int4_error_bound_and_groups():
    torch.manual_seed(1)
    w = torch.randn(16, 128) * 0.05
    for g in (None, 64, 32):
        q, s = quant_int4(w, g)
        assert q.abs().max() <= 7
        err = (dequant_int4(q, s, g) - w).reshape(-1, g or 128).abs()
        assert (err <= s / 2 + 1e-7).all()
    e = [((dequant_int4(*quant_int4(w, g), g) - w).norm()).item() for g in (None, 64, 32)]
    assert e[0] > e[1] > e[2]                        # 묶음이 작을수록 오차 감소


def test_odd_length_rejected():
    with pytest.raises(AssertionError):
        pack(torch.tensor([1, 2, 3]))

이 장의 실습은 CPU에서 실행하며, CPU와 GT 1030 경로 모두 위 결과가 기준입니다. hex 파일을 실제 FPGA에 올려 읽는 것은 이 교재의 범위 밖이며 검증하지 않았습니다.

**완료 기준:** 가중치 [−7, 5]를 손으로 패킹해 16진수 바이트를 구한 뒤 `pack()`으로 확인하고, 3번의 두 번째 워드 `0e013ff2`를 손으로 언패킹해 가중치 8개를 적으며, 테스트 5개를 모두 통과하면 이 장을 마친 것입니다.

## 핵심 정리

- INT4 대칭 양자화는 −7 ~ 7의 15가지 값을 써서 INT8보다 간격이 약 18배 넓습니다. 그래서 행을 다시 작은 묶음으로 나눠 Scale을 둡니다(Group 양자화).
- 묶음이 작을수록 오차는 줄고 Scale 저장 비용은 늘어납니다. 실무에서는 64~128개 묶음을 주로 씁니다.
- Bit Packing은 `& 0xF`(마스킹), `<< 4`(시프트), `|`(OR)로 4비트 두 개를 한 바이트에 담습니다. 꺼낼 때는 맨 위 비트가 1이면 16을 빼는 부호 확장이 필요합니다.
- 패킹한 INT4 파일은 INT8의 정확히 절반이며, 32비트 워드 hex 파일로 만들어 FPGA BRAM에 실을 수 있습니다.

**다음 장 연결:** 가중치 하나하나의 오차는 재었지만, 정말 중요한 것은 양자화한 모델의 **출력**이 얼마나 달라지는가입니다. 제35장에서는 역양자화한 가중치로 실제 모델을 계산해, 계층별·모델 전체의 오차와 Perplexity 변화를 분석합니다.
