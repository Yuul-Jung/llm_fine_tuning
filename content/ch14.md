## 장 개요

제13장의 Attention에서는 모든 토큰이 모든 토큰을 봤습니다. 문장을 이해만 하는 모델이라면 문제가 없습니다. 하지만 LLM은 **다음 토큰을 맞히도록** 학습합니다. 정답이 바로 옆 칸에 있는데 그 칸을 볼 수 있다면, 모델은 예측하는 법이 아니라 베끼는 법을 배웁니다.

이 장은 미래를 가리는 Causal Mask(인과 마스크)를 다룹니다. 그리고 묶음 학습에서 함께 쓰는 Padding Mask와의 차이, 두 마스크를 결합하는 방법을 정리합니다. 핵심 실습에서는 직접 구현한 Attention과 실제 Qwen2.5-0.5B 모두에서 "마지막 토큰을 바꿔도 앞 위치의 결과는 한 자리도 바뀌지 않는다"는 것을 증명합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 생성 모델은 어떻게 미래를 보지 않으며, 길이 맞춤용 PAD는 어떻게 무시하는가 |
| 실습 결과물 | 마스크 행렬과 가중치, 미래 변경 실험, Padding 결합, 실제 모델 확인 |
| 실습 파일 | `examples/ch14/`의 `causal_attention.py`, `qwen_causal_check.py`, `test_ch14.py` |
| 선수 장 | 제03장(Unsqueeze), 제06장(Softmax), 제13장(Attention) |

```text
점수 [seq, seq]
   │ 미래 위치(상삼각) = -∞          ← Causal Mask
   │ PAD 위치(열)     = -∞          ← Padding Mask
   ▼
Softmax → 가린 칸의 가중치 = 0
   ▼
가중치 × V → 과거와 실제 토큰의 정보만 섞인 출력
```

## 미래 정보 차단

제07장에서 언어 모델의 학습은 "문맥이 주어졌을 때 다음 토큰 맞히기"라고 했습니다. Decoder-only 모델은 한 문장의 **모든 위치에서 동시에** 이 문제를 풉니다.

```text
입력:   언어  모델은  다음  토큰을
정답:   모델은 다음   토큰을 예측한다
        └ 위치 0은 '언어'만 보고 '모델은'을 맞혀야 한다
                └ 위치 1은 '언어 모델은'만 보고 '다음'을 맞혀야 한다
```

그런데 Attention은 행렬곱 한 번으로 모든 토큰 쌍을 계산합니다(제13장). 아무 장치 없이 계산하면 위치 0이 위치 1, 즉 자기가 맞혀야 할 정답을 볼 수 있습니다. 그러면 학습 손실은 쉽게 줄지만, 실제 생성에서는 미래가 없으므로 아무것도 맞히지 못하는 모델이 됩니다.

해법은 점수 행렬에서 **자기보다 뒤의 칸을 −∞로 바꾸는 것**입니다. Softmax에 −∞를 넣으면 `e^(-∞) = 0`이 되어, 그 칸의 가중치가 정확히 0이 됩니다. 미래 토큰의 Value는 결과에 조금도 섞이지 않습니다. 이 방법 덕분에 모든 위치의 학습을 병렬로 하면서도 각 위치는 과거만 보게 됩니다.

## 하삼각 마스크

토큰 4개의 Causal Mask는 다음과 같습니다. `1`(True)이 가리는 칸입니다.

```text
           Key 0  Key 1  Key 2  Key 3
Query 0  [   0      1      1      1  ]    토큰 0은 자기 자신만
Query 1  [   0      0      1      1  ]    토큰 1은 0~1
Query 2  [   0      0      0      1  ]    토큰 2는 0~2
Query 3  [   0      0      0      0  ]    토큰 3은 전부
```

가리는 칸은 대각선 위의 삼각형(상삼각)이고, 볼 수 있는 칸은 대각선을 포함한 아래 삼각형(하삼각)입니다. PyTorch의 `torch.triu(…, diagonal=1)`이 이 상삼각을 만듭니다. `diagonal=1`은 대각선은 남기고 그 위부터 고르라는 뜻으로, 모든 토큰이 자기 자신은 볼 수 있게 합니다.

마스크를 적용한 가중치는 핵심 실습의 2번처럼 하삼각만 값을 갖습니다. 첫 행은 볼 수 있는 칸이 자기 자신뿐이라 가중치가 `[1, 0, 0, 0]`입니다. 각 행의 합은 여전히 1이며, 볼 수 있는 칸끼리만 나눠 갖습니다.

## Causal Mask와 Padding Mask

길이가 다른 문장을 묶음(Batch)으로 계산하려면 짧은 문장 뒤를 PAD 토큰으로 채워 길이를 맞춰야 합니다(제08장). PAD는 의미 없는 채움이므로, 다른 토큰이 PAD의 정보를 가져가면 안 됩니다. 이것을 막는 것이 Padding Mask입니다.

| 구분 | Causal Mask | Padding Mask |
|---|---|---|
| 가리는 것 | 미래 위치 | PAD 위치 |
| 모양 | `[seq, seq]` 상삼각 | 문장마다 `[seq]`, PAD 자리의 **열** |
| 문장마다 다른가 | 같다 | 다르다(PAD 개수에 따라) |
| 만드는 곳 | 모델 내부 | 토크나이저가 `attention_mask`로 만들어 줌 |

Hugging Face에서 모델에 넘기는 `attention_mask`는 **Padding Mask**입니다. 실제 토큰은 1, PAD는 0으로 표시하며, Causal Mask는 Decoder-only 모델이 내부에서 알아서 더합니다. 이름 때문에 헷갈리기 쉬우니 구분해 두세요.

### 두 마스크의 결합

두 마스크는 "어느 쪽이든 가리면 가린다"(논리합)로 합칩니다. 모양이 다르므로 제03장의 Unsqueeze와 제04장의 Broadcasting을 씁니다.

```text
Causal      [seq, seq]                    =    (4, 4)
Padding     [batch, seq] → [batch, 1, 1, seq] = (2, 1, 1, 4)
합친 마스크  Causal | Padding              =    (2, 1, 4, 4)   ← 점수 [batch, heads, seq, seq]에 적용
```

Padding Mask는 **열**을 가립니다. 모든 토큰이 PAD 위치의 정보를 가져가지 못하게 하는 것입니다. PAD 위치 자신의 행(Query)은 계산되지만, 그 출력은 의미가 없으므로 이후 손실 계산에서 제외합니다(제22·45장).

### 오른쪽 Padding

Qwen2.5 토크나이저는 기본적으로 문장 **뒤쪽**(오른쪽)에 PAD를 붙입니다(`padding_side = "right"`). 오른쪽 Padding에서는 실제 토큰이 모두 앞쪽에 모여 있어, Causal Mask만으로도 실제 토큰은 뒤의 PAD를 볼 수 없습니다. 핵심 실습에서 짧은 문장을 묶음으로 계산한 결과와 혼자 계산한 결과가 같다는 것을 확인합니다.

## Causal Self-Attention 구현

제13장의 Attention 함수에 마스크 세 줄을 더하면 생성 모델용 Self-Attention이 됩니다.

```text
scores  = Q Kᵀ / √dₖ
blocked = causal_mask(seq) | padding                ← 가릴 칸 표시
scores  = scores.masked_fill(blocked, -∞)          ← 가린 칸을 -∞로
weights = softmax(scores)                           ← 가린 칸의 가중치 = 0
output  = weights × V
```

`masked_fill(조건, 값)`은 조건이 True인 칸을 지정한 값으로 바꿉니다. PyTorch의 `F.scaled_dot_product_attention`에 `is_causal=True`를 주면 같은 계산을 하며, 실습에서 결과가 일치하는지 확인합니다.

## 핵심 실습

### 실습 1. 직접 구현한 Causal Self-Attention

파일명: `examples/ch14/causal_attention.py`

```python
# 제14장 실습 1: Causal Mask와 Padding Mask를 포함한 Self-Attention 직접 구현
#
# 실행: python examples/ch14/causal_attention.py

import math

import torch
import torch.nn.functional as F


def causal_mask(seq: int) -> torch.Tensor:
    """True = 가림. 자기보다 뒤(미래) 위치를 가리는 상삼각 행렬."""
    return torch.triu(torch.ones(seq, seq, dtype=torch.bool), diagonal=1)


def causal_attention(q, k, v, padding_mask=None):
    """q, k, v: [batch, heads, seq, d],  padding_mask: [batch, seq] (1 = 실제 토큰, 0 = PAD)"""
    seq = q.shape[-2]
    scores = q @ k.transpose(-2, -1) / math.sqrt(q.shape[-1])      # [batch, heads, seq, seq]
    blocked = causal_mask(seq)                                     # [seq, seq]
    if padding_mask is not None:
        pad = padding_mask[:, None, None, :] == 0                  # [batch, 1, 1, seq] (제03장)
        blocked = blocked | pad                                    # 두 마스크 결합(Broadcasting)
    scores = scores.masked_fill(blocked, float("-inf"))            # 가린 칸 = -∞
    weights = torch.softmax(scores, dim=-1)                        # e^(-∞) = 0
    return weights @ v, weights


def main() -> None:
    torch.manual_seed(0)
    q, k, v = (torch.randn(1, 1, 4, 8) for _ in range(3))

    print("── 1. Causal Mask(True = 가림) ──")
    print(causal_mask(4).int())

    print("\n── 2. 마스크를 적용한 가중치 ──")
    out, w = causal_attention(q, k, v)
    print(w[0, 0].round(decimals=3))
    print("행 합:", [round(x, 4) for x in w[0, 0].sum(dim=-1).tolist()])
    ref = F.scaled_dot_product_attention(q, k, v, is_causal=True)
    print(f"PyTorch(is_causal=True)와 최대 차이: {(out - ref).abs().max().item():.1e}")

    print("\n── 3. 마지막 토큰을 바꾸면? ──")
    q2, k2, v2 = q.clone(), k.clone(), v.clone()
    for t in (q2, k2, v2):
        t[0, 0, -1] = torch.randn(8)
    out2, _ = causal_attention(q2, k2, v2)
    print(f"앞 3개 위치 출력 완전 일치: {torch.equal(out[0, 0, :3], out2[0, 0, :3])}")
    print(f"마지막 위치 출력 차이: {(out[0, 0, 3] - out2[0, 0, 3]).abs().max().item():.3f}")

    print("\n── 4. Padding Mask 결합(두 번째 문장은 실제 토큰 2개 + PAD 2개) ──")
    qb, kb, vb = (torch.randn(2, 1, 4, 8) for _ in range(3))
    padding = torch.tensor([[1, 1, 1, 1], [1, 1, 0, 0]])
    _, wb = causal_attention(qb, kb, vb, padding_mask=padding)
    print(wb[1, 0].round(decimals=3))
    print(f"PAD 위치(열 2·3)로 가는 가중치 합: {wb[1, 0, :, 2:].sum().item():.1f}")


if __name__ == "__main__":
    main()
```

**핵심 코드 풀이**

- `causal_mask()`는 `torch.triu(…, diagonal=1)`로 상삼각만 True인 행렬을 만듭니다. 1번 출력이 02절의 그림과 같습니다.
- 2번 가중치에서 대각선 위는 모두 0이고 각 행의 합은 1입니다. 첫 행이 `[1, 0, 0, 0]`인 것은 토큰 0이 볼 수 있는 것이 자기 자신뿐이기 때문입니다. PyTorch의 `is_causal=True`와도 반올림 수준(`2.4e-07`)으로 일치합니다.
- 3번은 이 장의 결론입니다. 마지막 토큰의 Q·K·V를 무작위로 바꿨는데도 앞 3개 위치의 출력이 **완전히** 같습니다(`torch.equal`). 가린 칸의 가중치가 근사적인 0이 아니라 정확한 0이기 때문입니다. 마지막 위치의 출력만 달라집니다.
- 4번에서 두 번째 문장은 실제 토큰 2개와 PAD 2개입니다. 합친 마스크 덕분에 열 2·3(PAD)으로 가는 가중치가 모두 0입니다. 행 2·3은 PAD 자신의 Query라 실제 토큰 쪽을 보고 있지만, 앞 절에서 말했듯 이 출력은 이후 손실 계산에서 버립니다.
- `padding_mask[:, None, None, :]`는 `unsqueeze`를 두 번 한 것과 같습니다. `[batch, seq]`를 `[batch, 1, 1, seq]`로 만들어 점수 `[batch, heads, seq, seq]`의 열 방향으로 Broadcasting합니다.

### 실습 2. 실제 Qwen2.5-0.5B에서 확인

직접 구현에서 확인한 성질이 실제 모델에서도 성립하는지 봅니다. 문장의 마지막 토큰만 다른 토큰으로 바꿔 넣고 전체 Logits를 비교합니다. 그리고 길이가 다른 두 문장을 묶음으로 넣었을 때 짧은 문장의 결과가 혼자 넣었을 때와 같은지 확인합니다.

파일명: `examples/ch14/qwen_causal_check.py`

```python
# 제14장 핵심 실습: 실제 Qwen2.5-0.5B에서 미래 차단과 Padding Mask 확인
#
# 실행: python examples/ch14/qwen_causal_check.py

import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[1]))

import torch  # noqa: E402

from common.qwen import load_model, load_tokenizer  # noqa: E402

TEXT = "언어 모델은 다음 토큰을 예측한다"


def future_change_test(model, tok) -> tuple:
    """마지막 토큰만 바꿔 넣고, 앞 위치들과 마지막 위치의 Logits 차이를 잰다."""
    a = tok(TEXT, return_tensors="pt").input_ids
    b = a.clone()
    b[0, -1] = tok.encode(" 바나나")[0]
    with torch.no_grad():
        la, lb = model(a).logits, model(b).logits
    past = (la[0, :-1] - lb[0, :-1]).abs().max().item()
    last = (la[0, -1] - lb[0, -1]).abs().max().item()
    return past, last


def padding_test(model, tok) -> tuple:
    """긴 문장과 짧은 문장을 묶음으로 계산한 결과와, 짧은 문장을 단독으로 계산한 결과 비교."""
    short = "행렬곱"
    batch = tok([TEXT, short], return_tensors="pt", padding=True)
    with torch.no_grad():
        batched = model(**batch).logits
        alone = model(tok(short, return_tensors="pt").input_ids).logits
    n = alone.shape[1]
    return batch, (batched[1, :n] - alone[0]).abs().max().item()


def main() -> None:
    model, tok = load_model(), load_tokenizer()

    print("── 1. 마지막 토큰을 바꾸면 앞 위치의 예측이 변하는가 ──")
    past, last = future_change_test(model, tok)
    print(f"앞 위치 Logits 최대 차이: {past}")
    print(f"마지막 위치 Logits 최대 차이: {last:.2f}")

    print("\n── 2. Padding과 attention_mask ──")
    print(f"토크나이저 padding_side: {tok.padding_side},  PAD ID: {tok.pad_token_id}")
    batch, diff = padding_test(model, tok)
    print("짧은 문장의 input_ids:     ", batch.input_ids[1].tolist())
    print("짧은 문장의 attention_mask:", batch.attention_mask[1].tolist())
    print(f"묶음 계산과 단독 계산의 최대 차이(실제 토큰 위치): {diff:.1e}")


if __name__ == "__main__":
    main()
```

- 이 성질은 생성 속도에도 중요합니다. 앞 위치의 계산 결과가 뒤 토큰에 영향을 받지 않으므로, 생성할 때 이미 계산한 앞 위치의 Key·Value를 저장해 두고 재사용할 수 있습니다. 이것이 제20장의 KV Cache입니다.
- 2번에서 짧은 문장 "행렬곱"(토큰 3개)은 뒤에 PAD(ID 151643) 12개가 붙고 `attention_mask`는 `[1, 1, 1, 0, …]`이 됩니다. 묶음 결과와 단독 결과의 차이 `5.9e-05`는 묶음 크기에 따라 행렬곱의 계산 순서가 달라져 생기는 FP32 반올림 차이로, 허용 오차 안에 있습니다. PAD가 실제 토큰의 결과에 영향을 주지 않았다는 뜻입니다.

## 핵심 정리

- 다음 토큰을 예측하는 모델은 미래 위치를 보면 안 됩니다. 점수 행렬의 상삼각을 −∞로 바꾸면 Softmax 뒤 가중치가 정확히 0이 됩니다.
- Causal Mask는 모든 문장에 같은 상삼각 `[seq, seq]`, Padding Mask는 문장마다 PAD 자리의 열을 가립니다. 둘은 논리합으로 결합합니다.
- Hugging Face의 `attention_mask`는 Padding Mask입니다. Causal Mask는 Decoder-only 모델이 내부에서 더합니다.
- 실제 Qwen2.5-0.5B에서도 마지막 토큰을 바꾸면 앞 위치의 Logits는 한 자리도 변하지 않습니다. 이 성질이 KV Cache를 가능하게 합니다.
