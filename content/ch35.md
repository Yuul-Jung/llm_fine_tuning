## 장 개요

제33·34장에서 가중치 하나하나의 오차를 쟀습니다. INT8은 1%, INT4는 묶음 크기에 따라 11~19%였습니다. 그런데 이 숫자만으로는 모델이 얼마나 나빠지는지 알 수 없습니다. 가중치 오차는 행렬곱을 거치며 줄어들 수도, 커질 수도 있고, 24개 계층을 지나며 쌓이기 때문입니다.

이 장은 양자화한 가중치를 계산 직전에 실수로 되돌리는 **역양자화**에서 출발해, 오차를 재는 두 기준(평균과 최악), 이상치 하나가 일으키는 피해, 그리고 실제 입력을 넣은 계층 출력과 모델 전체의 Perplexity에서 오차가 어떻게 나타나는지를 차례로 측정합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 가중치의 양자화 오차는 실제 계층 출력과 모델 성능에서 얼마만큼의 차이로 나타나는가 |
| 실습 결과물 | MSE·최대 오차 비교, 이상치 실험, 계층 출력 오차표, 양자화 방식별 모델 PPL, 오차 분포 |
| 실습 파일 | `examples/ch35/`의 `quant_error.py`, `test_ch35.py` |
| 선수 장 | 제20장(Hook), 제22장(PPL 기준값), 제33장(INT8), 제34장(INT4) |

```text
저장:   INT8/INT4 코드 + Scale
계산:   ŵ = 코드 × Scale (역양자화, 계산 직전) ──▶  y = ŵ x  ──▶ 다음 계층 ──▶ … ──▶ Logits ──▶ PPL
측정:   가중치 오차 │ 계층 출력 오차 │ 모델 PPL       ← 이 장은 세 단계 모두 잰다
```

## 역양자화

양자화된 모델은 가중치를 정수 코드와 Scale로 **저장**하고, 행렬곱을 하기 직전에 `ŵ = 코드 × Scale`로 **복원**해 계산합니다. 제32장의 "저장은 작게, 계산은 크게" 원칙 그대로입니다. 복원한 값은 FP32(또는 BF16)이므로 행렬곱 자체는 원래 정밀도로 합니다.

그래서 양자화가 모델에 주는 영향은 "가중치가 ŵ로 바뀐 모델"의 영향과 같습니다. 이 장은 이 성질을 이용해 **가짜 양자화**(Fake Quantization)로 측정합니다. 양자화한 뒤 즉시 역양자화해 FP32 가중치에 덮어쓰고, 평소처럼 계산합니다. 메모리 절약은 없지만, 실제 양자화 모델과 같은 값으로 계산하므로 오차를 정확히 잴 수 있습니다.

## MSE와 최대 절대오차

오차를 하나의 숫자로 줄이는 방법은 여럿이고, 각각 다른 것을 봅니다.

| 지표 | 계산 | 보는 것 |
|---|---|---|
| MSE(평균 제곱 오차) | 오차 제곱의 평균 | 전체적으로 얼마나 틀렸는가 |
| 최대 절대오차 | 오차 절댓값의 최댓값 | 가장 크게 틀린 하나는 얼마인가 |
| 상대 오차 | 오차의 노름 ÷ 원래 값의 노름 | 값의 크기에 견준 비율 |

평균만 보면 대부분 정확하고 소수만 크게 틀린 경우를 놓치고, 최악만 보면 전체 품질을 알 수 없습니다. 예를 들어 Per-Channel과 Group 64는 최대 절대오차가 같을 수 있습니다. 가장 큰 오차는 Scale이 가장 큰 행(또는 묶음), 즉 이상치가 있는 곳에서 나오고, 묶음을 나눠도 그 묶음의 Scale은 그대로이기 때문입니다. 그러나 나머지 묶음들은 Scale이 작아져 MSE는 크게 줄어듭니다. 두 지표를 함께 봐야 하는 이유입니다.

## 이상치의 영향

제33장에서 본 것처럼, Scale은 범위 안의 **가장 큰 절댓값**이 정합니다. 값 하나가 크면 Scale이 커지고, 간격이 넓어져 나머지 모든 값의 정밀도가 떨어집니다. 작은 값들은 간격의 절반보다 작아져 코드 0으로 뭉개지기도 합니다.

```text
원래 행:    최댓값 0.06 → Scale 0.0005 → 작은 값들도 여러 칸에 나뉘어 담긴다
이상치 1개: 최댓값 0.6  → Scale 0.005  → 작은 값들이 0, ±1 칸에 몰린다
```

LLM에는 이런 이상치가 실제로 있습니다. 제18장에서 잔차 스트림의 어떤 원소가 1,500을 넘는 것을 보았고, 가중치에도 다른 값보다 열 배 넘게 큰 원소들이 있습니다(제33장). 그래서 실무의 양자화 방법들은 이상치를 따로 처리하거나(LLM.int8), 이상치의 영향을 묶음 안에 가두거나(Group·Block 양자화, 제34·36장), 이상치에 맞춰 값을 미리 조정합니다.

## 행렬곱 출력 오차

가중치 오차가 계층 출력에서 어떻게 나타나는지는 **실제 입력**으로 재야 합니다. 이 장은 Hook(제20장)으로 0번 계층 `q_proj`와 `down_proj`에 들어가는 실제 입력을 꺼내, 원래 가중치와 역양자화한 가중치로 각각 계산해 비교합니다.

여기에는 함정이 하나 있습니다. q_proj에는 크기가 아주 큰 편향이 있습니다(제12장). 출력 `W x + b`에서 b가 대부분을 차지하면, `W x`가 꽤 틀려도 전체 출력의 상대 오차는 작게 보입니다. 양자화하는 것은 W이므로, **W x 부분만** 따로 비교해야 양자화의 영향을 제대로 볼 수 있습니다. 측정 대상이 무엇에 지배되는지 먼저 확인하는 것이 공정한 측정의 출발점입니다.

마지막으로 모델 전체를 봅니다. 24개 계층의 Linear 일곱 종, 행렬 168개를 모두 가짜 양자화하고 제22장의 고정 평가 데이터로 PPL을 잽니다. Embedding(= LM Head)은 양자화하지 않고 FP32로 둡니다. 제22장의 기준값(Instruct 21.45)과 비교하면 양자화의 비용이 모델 수준에서 보입니다.

## 핵심 실습

파일명: `examples/ch35/quant_error.py`

```python
# 제35장 핵심 실습: 역양자화한 가중치로 실제 계층과 모델 전체를 계산해 양자화 오차를 분석한다
#
# 실행: python examples/ch35/quant_error.py
#
# "가짜 양자화"(Fake Quantization): 양자화 → 즉시 역양자화한 FP32 가중치로 계산한다.
# 저장 형식만 다를 뿐, 실제 양자화 모델이 계산 직전에 복원하는 값과 같다.

import math
import sys
from pathlib import Path

HERE = Path(__file__).resolve().parent
for p in (HERE.parent, HERE.parent / "ch22", HERE.parent / "ch33", HERE.parent / "ch34"):
    sys.path.insert(0, str(p))

import torch  # noqa: E402

from common.fixed_data import load_blocks  # noqa: E402
from common.qwen import load_model, load_tokenizer  # noqa: E402
from int4_pack import dequant_int4, quant_int4  # noqa: E402        (제34장)
from int8_quant import dequant_symmetric, quant_symmetric  # noqa: E402  (제33장)
from qwen_ppl import evaluate  # noqa: E402                         (제22장)

METHODS = {
    "INT8 Per-Channel": lambda w: dequant_symmetric(*quant_symmetric(w, per_channel=True)),
    "INT4 Per-Channel": lambda w: dequant_int4(*quant_int4(w)),
    "INT4 Group 64": lambda w: dequant_int4(*quant_int4(w, 64), 64),
}
LINEARS = ("q_proj", "k_proj", "v_proj", "o_proj", "gate_proj", "up_proj", "down_proj")


def capture_input(model, ids, module):
    """module(nn.Linear)에 들어가는 입력을 Hook으로 꺼낸다(제20장)."""
    box = {}

    def hook(m, args, out):                        # 아무것도 돌려주지 않아야 출력이 바뀌지 않는다
        box["x"] = args[0].detach()

    h = module.register_forward_hook(hook)
    try:
        with torch.no_grad():
            model(ids)
    finally:
        h.remove()
    return box["x"]


@torch.no_grad()
def fake_quantize_model(model, method) -> int:
    """모든 Decoder Layer의 Linear 가중치 7종을 양자화 → 역양자화로 바꾼다. 바꾼 행렬 수를 돌려준다."""
    n = 0
    for name, mod in model.named_modules():
        if name.split(".")[-1] in LINEARS:
            mod.weight.copy_(method(mod.weight))
            n += 1
    return n


def main() -> None:
    tok = load_tokenizer()
    model = load_model()
    ids = load_blocks(tok, "eval")[:1]
    lin = model.model.layers[0].self_attn.q_proj
    w = lin.weight.detach()

    print("── 1. 가중치 오차: 평균(MSE)과 최악(최대 절대오차) ──")
    for name, f in METHODS.items():
        e = f(w) - w
        print(f"  {name:<18}MSE {e.pow(2).mean():.2e}, 최대 절대오차 {e.abs().max():.4f}, "
              f"상대 오차 {(e.norm() / w.norm()):.3f}")

    print("\n── 2. 이상치 하나의 영향(Per-Tensor INT8, 0번 행) ──")
    row = w[0:1].clone()
    base = (dequant_symmetric(*quant_symmetric(row)) - row).abs().mean().item()
    spiked = row.clone()
    spiked[0, 0] = row.abs().max() * 10                           # 값 하나만 10배로
    q, s = quant_symmetric(spiked)
    rest = (dequant_symmetric(q, s) - spiked)[0, 1:].abs().mean().item()
    zeros = (q[0, 1:] == 0).float().mean().item()
    print(f"  원래 행: 평균 절대오차 {base:.2e}")
    print(f"  값 하나를 10배: 나머지 895개의 평균 절대오차 {rest:.2e}({rest / base:.1f}배), "
          f"코드 0이 된 비율 {zeros:.0%}")

    print("\n── 3. 계층 출력 오차(0번 계층, 실제 입력, 토큰마다 상대 오차의 평균) ──")
    down = model.model.layers[0].mlp.down_proj
    xq, xd = capture_input(model, ids, lin), capture_input(model, ids, down)
    print(f"  {'':<18}{'q_proj(편향 포함)':>16}{'q_proj(W x만)':>15}{'down_proj':>11}{'가중치 오차':>11}")
    with torch.no_grad():
        F = torch.nn.functional
        for name, f in METHODS.items():
            def rel(a, b):
                return ((a - b).norm(dim=-1) / b.norm(dim=-1)).mean().item()
            with_bias = rel(F.linear(xq, f(w), lin.bias), F.linear(xq, w, lin.bias))
            no_bias = rel(F.linear(xq, f(w)), F.linear(xq, w))
            wd = down.weight.detach()
            d = rel(F.linear(xd, f(wd)), F.linear(xd, wd))
            print(f"  {name:<18}{with_bias:>16.4f}{no_bias:>15.4f}{d:>11.4f}"
                  f"{((f(w) - w).norm() / w.norm()):>11.3f}")

    print("\n── 4. 모델 전체(24계층 × Linear 7종)를 양자화한 PPL(고정 평가 데이터) ──")
    blocks = load_blocks(tok, "eval")
    print(f"  {'FP32(기준)':<18}PPL {math.exp(evaluate(model, blocks)['loss']):.2f}")
    for name, f in METHODS.items():
        m = load_model()
        n = fake_quantize_model(m, f)
        print(f"  {name:<18}PPL {math.exp(evaluate(m, blocks)['loss']):.2f}  (행렬 {n}개)")
        del m

    print("\n── 5. INT4 Group 64 가중치 오차의 분포(÷ Scale) ──")
    q4, s4 = quant_int4(w, 64)
    r = ((dequant_int4(q4, s4, 64) - w).reshape(-1, 64) / s4).flatten()
    hist = torch.histc(r, bins=10, min=-0.5, max=0.5)
    for i, c in enumerate(hist.tolist()):
        lo = -0.5 + i * 0.1
        print(f"  [{lo:+.1f}, {lo + 0.1:+.1f})  {'█' * round(40 * c / hist.max().item())}")


if __name__ == "__main__":
    main()
```

**결과 읽기**

- **1번**에서 INT4 Per-Channel과 Group 64의 최대 절대오차는 0.0876으로 같지만, MSE는 Group 64가 절반 이하입니다. 02절의 설명대로 최악의 오차는 이상치가 있는 묶음에서 나오고, 묶음을 나누면 나머지가 좋아집니다.
- **2번**에서 행 하나의 값 하나만 10배로 키웠는데 나머지 895개의 평균 오차가 9.6배가 되었고, 11%의 값이 코드 0으로 뭉개졌습니다. 이상치 하나의 피해가 행 전체로 번집니다.
- **3번**에서 q_proj를 편향까지 포함해 비교하면 INT4 Per-Channel도 출력 오차가 0.5%로 작아 보입니다. 그러나 W x만 비교하면 6.6%입니다. 편향 b가 출력을 지배해 오차를 가린 것입니다. 편향이 없는 down_proj는 INT4 Per-Channel에서 15%로, 가중치 오차(18.7%)에 가까운 출력 오차를 냅니다.
- **4번**이 가장 중요한 결과입니다. INT8 Per-Channel은 PPL 21.45 → 21.77로 거의 차이가 없습니다. INT4 Per-Channel은 68.13으로 세 배가 넘게 나빠지고, Group 64는 35.43으로 피해를 절반 넘게 줄입니다. 가중치 오차 12% 정도의 차이가 모델 전체에서는 PPL 두 배라는 큰 차이로 쌓였습니다.
- **5번**에서 오차를 Scale로 나눈 값은 −0.5 ~ 0.5에 고르게 퍼져 있습니다. 반올림 오차는 간격 안의 어디에나 똑같이 나오기 때문입니다. 0 근처가 조금 높은 것은 묶음마다 절댓값이 가장 큰 값이 정확히 ±7로 표현되어 오차가 0이기 때문입니다.

균일한 간격의 INT4는 0.5B 모델에서 품질을 크게 잃습니다. 하지만 4비트여야 GT 1030에 0.5B 모델과 학습 공간이 함께 들어갑니다. 제36장의 NF4는 **간격을 고르게 두지 않는** 방법으로 같은 4비트에서 오차를 더 줄입니다.

import sys
from pathlib import Path

import pytest
import torch

HERE = Path(__file__).resolve().parent
for p in (HERE, HERE.parent, HERE.parent / "ch19", HERE.parent / "ch22", HERE.parent / "ch33",
          HERE.parent / "ch34"):
    sys.path.insert(0, str(p))

from int8_quant import dequant_symmetric, quant_symmetric  # noqa: E402
from quant_error import METHODS, capture_input, fake_quantize_model  # noqa: E402


@pytest.fixture()
def tiny():
    from hf_compat import to_hf
    from tiny_model import Qwen2Tiny, init_weights
    return to_hf(init_weights(Qwen2Tiny(), seed=0)).eval()


def test_error_grows_as_bits_shrink():
    torch.manual_seed(0)
    w, x = torch.randn(128, 256) * 0.05, torch.randn(16, 256)
    errs = [((x @ METHODS[k](w).T - x @ w.T).norm() / (x @ w.T).norm()).item()
            for k in ("INT8 Per-Channel", "INT4 Group 64", "INT4 Per-Channel")]
    assert errs[0] < errs[1] < errs[2]


def test_outlier_inflates_error_of_others():
    torch.manual_seed(1)
    row = torch.randn(1, 512) * 0.05
    base = (dequant_symmetric(*quant_symmetric(row)) - row).abs().mean()
    spiked = row.clone()
    spiked[0, 0] = row.abs().max() * 10
    rest = (dequant_symmetric(*quant_symmetric(spiked)) - spiked)[0, 1:].abs().mean()
    assert rest > 5 * base


def test_capture_input_does_not_change_output(tiny):
    ids = torch.tensor([[1, 2, 3, 4, 5]])
    with torch.no_grad():
        before = tiny(ids).logits
    x = capture_input(tiny, ids, tiny.model.layers[0].mlp.down_proj)
    with torch.no_grad():
        assert torch.equal(tiny(ids).logits, before)
    assert x.shape == (1, 5, 768)


def test_fake_quantize_touches_all_linears(tiny):
    emb = tiny.model.embed_tokens.weight.detach().clone()
    q_before = tiny.model.layers[2].self_attn.q_proj.weight.detach().clone()
    assert fake_quantize_model(tiny, METHODS["INT8 Per-Channel"]) == 4 * 7
    assert torch.equal(tiny.model.embed_tokens.weight, emb)           # Embedding은 그대로
    q_after = tiny.model.layers[2].self_attn.q_proj.weight
    assert not torch.equal(q_after, q_before)
    assert q_after.abs().amax(dim=1).sub(q_before.abs().amax(dim=1)).abs().max() < 1e-6  # 행 최댓값 보존

이 장의 실습은 CPU에서 실행하며, CPU와 GT 1030 경로 모두 위 결과가 기준입니다.

작성 중에 발견한 함정 하나를 기록해 둡니다. Hook 함수가 값을 돌려주면(`return`), PyTorch는 그 값으로 모듈의 **출력을 바꿔치기**합니다. 처음 만든 `capture_input()`은 람다(`lambda`)로 입력을 저장하면서 그 값을 돌려주는 바람에, 모델 계산이 오류 없이 엉뚱하게 진행되거나 모양이 맞지 않는 곳에서 멈췄습니다. 값을 꺼내기만 하는 Hook은 아무것도 돌려주지 않게 작성하고, 테스트로 출력이 바뀌지 않는 것을 확인합니다.

**완료 기준:** 4번에 "INT4 Group 128"을 추가해 PPL을 Group 64·Per-Channel 사이에 놓고, 3번에 `v_proj`(편향은 있지만 크기가 작음)를 추가해 편향 포함·제외의 차이가 q_proj보다 작은지 확인하며, 테스트 4개를 모두 통과하면 이 장을 마친 것입니다.

## 핵심 정리

- 양자화 모델은 정수 코드와 Scale로 저장하고, 계산 직전에 역양자화한 실수로 계산합니다. 가짜 양자화로 그 영향을 정확히 잴 수 있습니다.
- 평균(MSE)과 최악(최대 절대오차)을 함께 봅니다. 최악의 오차는 이상치가 있는 곳에서 나오고, 묶음을 나누면 나머지의 오차가 줄어듭니다.
- 값 하나의 이상치가 Scale을 키워 같은 행(묶음) 전체의 정밀도를 떨어뜨립니다.
- 계층 출력 오차는 실제 입력으로, 양자화되는 부분(W x)만 떼어 잽니다. 큰 편향은 오차를 가립니다.
- 모델 전체에서 INT8은 PPL이 거의 같고(21.45 → 21.77), 균일 INT4는 크게 나빠집니다(Per-Channel 68.13, Group 64 35.43).

**다음 장 연결:** 제36장에서는 가중치가 0 근처에 몰려 있다는 사실을 이용해, 값이 많은 곳에 단계를 촘촘히 두는 NF4 양자화를 구현합니다. 같은 4비트로 균일 INT4보다 오차와 PPL이 얼마나 좋아지는지 이 장의 표에 이어서 비교합니다.
