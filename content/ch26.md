## 장 개요

제25장의 Full Fine-tuning은 새 분야를 잘 배웠지만 두 가지 대가를 치렀습니다. 모든 가중치에 Gradient와 Optimizer 상태가 붙어 메모리를 많이 썼고(0.5B 모델은 GT 1030에서 불가능), 원래 알던 것을 일부 잊었습니다.

이 장은 그 해법의 첫걸음입니다. 가중치 대부분을 **얼리고**(동결) 일부만 학습하면 무엇이 달라지는지, 같은 데이터와 같은 설정으로 학습 범위만 바꿔 비교합니다. 그리고 이 생각을 발전시킨 **PEFT**(Parameter-Efficient Fine-Tuning, 매개변수 효율적 미세조정)의 공통 발상을 정리해, 제27~30장의 LoRA로 이어 갑니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 일부 가중치만 학습하면 메모리, 학습 효과, 망각이 각각 어떻게 달라지는가 |
| 실습 결과물 | 동결 동작 확인, 세 가지 학습 범위의 파라미터 수·메모리·PPL 비교표 |
| 실습 파일 | `examples/ch26/`의 `freeze_demo.py`, `partial_ft.py`, `test_ch26.py` |
| 선수 장 | 제23장(Gradient), 제24장(Optimizer 상태), 제25장(학습 루프, 사전학습 모델) |

```text
Full FT:      [Emb][B0][B1][B2][B3][Norm]   모두 학습      메모리 ↑  망각 ↑
부분 학습:    [Emb][B0][B1][B2][B3][Norm]   B3만 학습      메모리 ↓  망각 ↓
               ───── 동결 ─────
PEFT(LoRA):   원본 전체 동결 + 작은 추가 행렬만 학습(제28장)
```

## 가중치 동결

PyTorch에서 가중치를 얼리는 방법은 한 줄입니다.

```python
param.requires_grad_(False)
```

`requires_grad=False`인 가중치에는 세 가지 일이 일어나지 않습니다.

| 일어나지 않는 일 | 결과 |
|---|---|
| Gradient 계산 | `.grad`가 `None`으로 남는다. Gradient 메모리가 없다 |
| Optimizer 상태 생성 | Gradient가 없으면 AdamW는 그 가중치를 건너뛴다. 상태 메모리가 없다 |
| 가중치 갱신 | 값이 학습 전과 비트 하나까지 같다 |

여기에 한 가지 이득이 더 있습니다. 역전파는 손실에서 출발해 **학습할 가중치가 있는 곳까지만** 거슬러 올라가면 됩니다. 마지막 Block만 학습한다면, 그 앞 계층의 역전파 계산과 중간값 저장 일부를 건너뛸 수 있습니다.

다만 Optimizer에는 학습할 가중치만 넘기는 것이 원칙입니다. 얼린 가중치를 넘겨도 Gradient가 없어 건너뛰지만, 의도를 코드에 분명히 남기고 실수를 막기 위해서입니다. 제25장의 `train()`도 `requires_grad=True`인 것만 골라 Optimizer에 넘깁니다.

## 부분 학습

어느 부분을 학습할지에 따라 결과가 달라집니다. 이 장에서는 사전학습한 Qwen2-Tiny(제25장)를 세 가지 범위로, 자전거 정비 데이터에 같은 설정(60단계, 학습률 3e-4)으로 학습합니다.

| 범위 | 학습 파라미터 | 생각 |
|---|---|---|
| 전체(Full FT) | 41,914,112개 | 제25장과 같다. 비교 기준 |
| 마지막 Block | 754,560개(1.8%) | 출력에 가까운 층이 과제에 맞춘 표현을 만든다 |
| RMSNorm만 | 2,304개(0.01%) | 크기 조절 값만 바꾸면 어디까지 가능한가 |

Qwen2-Tiny는 Embedding과 LM Head가 같은 텐서(제19장)이고 전체의 93%를 차지합니다. "마지막 Block"과 "RMSNorm만"은 이 큰 표를 얼리므로, 어휘 표는 사전학습 상태 그대로 둔 채 계산 부분만 바꿉니다.

비교할 때는 세 가지를 함께 봅니다. 학습 효과(도메인 PPL), 망각(일반 PPL), 비용(학습 파라미터와 추가 메모리)입니다. 셋 중 하나만 보면 판단을 그르칩니다.

## PEFT의 발상

부분 학습은 "원본의 일부를 고친다"는 방식입니다. PEFT는 한 걸음 더 나아가 **원본은 전혀 고치지 않고, 작은 파라미터를 새로 붙여 그것만 학습**합니다.

| 방법 | 새로 붙이는 것 | 학습하는 것 |
|---|---|---|
| 부분 학습 | 없음 | 원본의 일부 계층 |
| Adapter | 계층 사이에 작은 신경망 | 추가한 신경망 |
| Prompt Tuning, Prefix Tuning | 입력 앞에 학습되는 벡터 | 추가한 벡터 |
| LoRA | 가중치 옆에 작은 행렬 두 개(곱이 변화량) | 추가한 행렬 |

공통점은 세 가지입니다.

- **원본 보존:** 원본 가중치는 동결되어 그대로 남습니다. 추가 부분만 떼어 내면 언제든 원래 모델로 돌아갑니다.
- **작은 저장 단위:** 학습 결과물이 추가 파라미터뿐이라 수 MB에 그칩니다. 원본 하나에 여러 과제용 추가 파라미터를 바꿔 끼울 수 있습니다.
- **메모리 절약:** Gradient와 Optimizer 상태가 추가 파라미터에만 생깁니다. 원본은 4비트로 압축해 둘 수도 있습니다(QLoRA, 제4부).

이 중 LoRA는 학습이 끝난 뒤 추가 행렬을 원본 가중치에 **더해서 합칠** 수 있어, 추론 속도가 원래 모델과 같다는 장점이 있습니다. 그래서 오늘날 가장 널리 쓰입니다. LoRA가 왜 "작은 행렬 두 개의 곱"으로 충분한지는 제27장의 Rank에서 출발합니다.

## 핵심 실습

### 실습 1. 동결의 동작

작은 두 층 신경망의 첫 층을 얼리고, 학습 한 단계 후 Gradient·Optimizer 상태·가중치를 확인합니다.

파일명: `examples/ch26/freeze_demo.py`

```python
# 제26장 실습 1: requires_grad=False인 가중치는 Gradient도 Optimizer 상태도 만들지 않는다
#
# 실행: python examples/ch26/freeze_demo.py

import torch


def build():
    torch.manual_seed(0)
    return torch.nn.Sequential(torch.nn.Linear(8, 16), torch.nn.ReLU(), torch.nn.Linear(16, 4))


def one_step(model, params) -> torch.optim.Optimizer:
    opt = torch.optim.AdamW(params, lr=0.1)
    x, y = torch.randn(5, 8), torch.randint(0, 4, (5,))
    torch.nn.functional.cross_entropy(model(x), y).backward()
    opt.step()
    return opt


def main() -> None:
    model = build()
    first, last = model[0], model[2]
    first.weight.requires_grad_(False)                 # 첫 Linear 가중치를 얼린다
    first.bias.requires_grad_(False)
    w0 = first.weight.detach().clone()

    print("── 1. 얼린 가중치에는 Gradient가 생기지 않는다 ──")
    opt = one_step(model, model.parameters())          # 일부러 전체 파라미터를 넘겨도
    print(f"  첫 Linear .grad: {first.weight.grad}, 마지막 Linear .grad 모양: {tuple(last.weight.grad.shape)}")
    print(f"  첫 Linear 가중치 그대로: {torch.equal(first.weight, w0)}")

    print("\n── 2. Optimizer 상태도 학습하는 가중치에만 생긴다 ──")
    with_state = [p for p in model.parameters() if p in opt.state]
    n_state = sum(p.numel() for p in with_state)
    print(f"  상태가 있는 텐서 {len(with_state)}개, 원소 {n_state}개 "
          f"(마지막 Linear 16×4 + 4 = {16 * 4 + 4})")

    print("\n── 3. 학습할 것만 Optimizer에 넘기는 것이 원칙 ──")
    model = build()
    for p in model[0].parameters():
        p.requires_grad_(False)
    trainable = [p for p in model.parameters() if p.requires_grad]
    print(f"  학습 파라미터 {sum(p.numel() for p in trainable)} / 전체 {sum(p.numel() for p in model.parameters())}")


if __name__ == "__main__":
    main()
```

실행:

```bash
python examples/ch26/freeze_demo.py
```

```text

  첫 Linear .grad: None, 마지막 Linear .grad 모양: (4, 16)
  첫 Linear 가중치 그대로: True

── 2. Optimizer 상태도 학습하는 가중치에만 생긴다 ──
  상태가 있는 텐서 2개, 원소 68개 (마지막 Linear 16×4 + 4 = 68)
```

### 실습 2. 학습 범위 비교

제25장에서 저장한 사전학습 모델(`models/qwen2-tiny-pretrained`)을 범위마다 새로 불러 학습합니다. 학습 전후의 모든 가중치를 비교해, 바뀐 텐서가 전부 학습 대상인지 확인합니다.

파일명: `examples/ch26/partial_ft.py`

```python
# 제26장 핵심 실습: 사전학습한 Qwen2-Tiny를 세 가지 범위로 도메인 학습하고 비교한다
#
# 실행: python examples/ch26/partial_ft.py   (먼저 제25장 pretrain_tiny.py로 사전학습 모델을 만든다)
#
# 범위: 전체(Full FT) / 마지막 Block만 / RMSNorm만. 학습 설정은 제25장 Full FT와 같다.

import math
import sys
from pathlib import Path

HERE = Path(__file__).resolve().parent
for p in (HERE.parent, HERE.parent / "ch24", HERE.parent / "ch25"):
    sys.path.insert(0, str(p))

import torch  # noqa: E402
from transformers import Qwen2ForCausalLM  # noqa: E402
from transformers.utils import logging  # noqa: E402

from common.device import select_device  # noqa: E402
from common.fixed_data import load_blocks  # noqa: E402
from common.qwen import load_tokenizer  # noqa: E402
from trainer import eval_loss, train  # noqa: E402     (제25장)

logging.disable_progress_bar()
PRETRAINED = HERE.parents[1] / "models" / "qwen2-tiny-pretrained"

SCOPES = {
    "전체(Full FT)": lambda name: True,
    "마지막 Block": lambda name: name.startswith("model.layers.3."),
    "RMSNorm만": lambda name: "norm" in name,
}


def freeze_except(model, keep) -> tuple:
    """keep(name)이 참인 파라미터만 학습하고 나머지는 얼린다. (학습 수, 전체 수)를 돌려준다."""
    for name, p in model.named_parameters():
        p.requires_grad_(keep(name))
    trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)
    return trainable, sum(p.numel() for p in model.parameters())


def snapshot(model) -> dict:
    return {n: p.detach().clone() for n, p in model.named_parameters()}


def main() -> None:
    device, _ = select_device()
    tok = load_tokenizer()
    data = {s: load_blocks(tok, s) for s in ("eval", "domain_train", "domain_eval")}
    base = Qwen2ForCausalLM.from_pretrained(PRETRAINED, dtype=torch.float32)
    ppl0 = {k: math.exp(eval_loss(base, data[k], device)) for k in ("domain_eval", "eval")}
    print(f"사전학습 모델: 도메인 PPL {ppl0['domain_eval']:.1f}, 일반 PPL {ppl0['eval']:.1f}\n")

    print(f"── 범위별 학습(60단계, lr 3e-4, 제25장 Full FT와 같은 설정) ──")
    rows = []
    for label, keep in SCOPES.items():
        model = Qwen2ForCausalLM.from_pretrained(PRETRAINED, dtype=torch.float32)
        trainable, total = freeze_except(model, keep)
        before = snapshot(model)
        train(model, data["domain_train"], {}, steps=60, lr=3e-4, warmup=5, device=device, log_every=60)
        after = snapshot(model)
        changed = [n for n in before if not torch.equal(before[n], after[n].cpu())]
        frozen_ok = all(keep(n) for n in changed)                  # 바뀐 것은 모두 학습 대상인가
        ppl = {k: math.exp(eval_loss(model, data[k], device)) for k in ("domain_eval", "eval")}
        extra = trainable * 12                                       # Gradient 4 + AdamW 8바이트
        rows.append((label, trainable, total, len(changed), frozen_ok, extra, ppl))

    for label, trainable, total, n_changed, ok, extra, ppl in rows:
        print(f"\n  [{label}]")
        print(f"    학습 파라미터 {trainable:,} / {total:,} ({trainable / total:.2%}), 바뀐 텐서 {n_changed}개")
        print(f"    동결 가중치 전부 그대로: {ok}")
        print(f"    Gradient + AdamW 상태 {extra / 2**20:,.2f}MiB")
        print(f"    도메인 PPL {ppl0['domain_eval']:.1f} → {ppl['domain_eval']:.1f}, "
              f"일반 PPL {ppl0['eval']:.1f} → {ppl['eval']:.1f}")


if __name__ == "__main__":
    main()
```

```text
    도메인 PPL 884.9 → 157.0, 일반 PPL 342.8 → 399.2

  [마지막 Block]
    학습 파라미터 754,560 / 41,914,112 (1.80%), 바뀐 텐서 12개
    동결 가중치 전부 그대로: True
    Gradient + AdamW 상태 8.64MiB
    도메인 PPL 884.9 → 477.0, 일반 PPL 342.8 → 349.9

  [RMSNorm만]
    학습 파라미터 2,304 / 41,914,112 (0.01%), 바뀐 텐서 9개
    동결 가중치 전부 그대로: True
```

**결과 읽기**

| 범위 | 도메인 PPL / 일반 PPL | 추가 메모리 |
|---|---|---|
| 전체 | 885 → 157 / 343 → 399(망각) | 479.67MiB |
| 마지막 Block | 885 → 477 / 343 → 350(거의 유지) | 8.64MiB |
| RMSNorm만 | 885 → 883 / 343 → 341(변화 없음) | 0.03MiB |

- **전체** 결과는 제25장의 Full FT와 똑같습니다. 같은 모델, 같은 데이터, 같은 설정이면 결과가 재현됩니다.
- **마지막 Block**은 파라미터의 1.8%만 학습해, 추가 메모리가 전체의 2%도 되지 않습니다. 도메인 PPL은 전체 학습만큼 내려가지는 않았지만 절반 가까이 줄었고, 일반 PPL은 거의 그대로입니다. 학습 효과와 망각 사이에서 균형을 잡은 결과입니다.
- **RMSNorm만**은 같은 학습률에서 거의 아무것도 배우지 못했습니다. 2,304개의 크기 조절 값만으로는 표현할 수 있는 변화가 작고, 학습률 3e-4로는 움직이는 폭도 작습니다. 학습 파라미터가 적을수록 더 큰 학습률이 필요할 수 있다는 점은 LoRA에서 다시 만납니다(제29장).
- 세 경우 모두 "동결 가중치 전부 그대로: True"입니다. 바뀐 텐서는 모두 학습 대상이었습니다. 전체 50개 텐서 중 마지막 Block은 12개, RMSNorm은 9개(계층마다 2개 + Final Norm)가 바뀌었습니다.

이 비교에서 두 가지를 얻습니다. 첫째, 일부만 학습해도 꽤 많이 배울 수 있고 망각은 크게 줄어듭니다. 둘째, **어떤** 파라미터를 학습하느냐가 개수만큼 중요합니다. LoRA는 "원본 가중치 행렬마다 작은 변화량을 붙인다"는 방식으로, 적은 파라미터로 모든 계층에 손을 대는 방법입니다.

## 핵심 정리

- `requires_grad=False`인 가중치는 Gradient도 Optimizer 상태도 만들지 않고, 값이 그대로 유지됩니다.
- 같은 조건에서 학습 범위만 바꾸면, 범위가 좁을수록 메모리와 망각은 줄지만 학습 효과도 줄어듭니다. 마지막 Block만 학습해도 1.8%의 파라미터로 도메인 PPL을 절반 가까이 낮췄습니다.
- 학습 효과(도메인 PPL), 망각(일반 PPL), 비용(파라미터·메모리)을 함께 보고 판단합니다.
- PEFT는 원본을 동결한 채 작은 추가 파라미터만 학습합니다. 원본 보존, 작은 저장 단위, 메모리 절약이 공통점이며, LoRA는 학습 후 원본에 합칠 수 있습니다.
