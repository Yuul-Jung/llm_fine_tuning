## 장 개요

제36장에서 NF4를 직접 구현해 bitsandbytes와 같은 결과를 냈습니다. 이제 실제 모델을 bitsandbytes로 **4비트로 불러올** 차례입니다. Hugging Face Transformers는 설정 객체 하나(`BitsAndBytesConfig`)만 넘기면, 모델을 불러오면서 모든 Linear를 4비트로 바꿔 줍니다.

다만 양자화는 하드웨어와 라이브러리 버전에 민감한 영역입니다. 어떤 기능은 GPU 세대에 따라 쓸 수 없고, 계산 자료형을 잘못 고르면 GT 1030에서 크게 느려집니다. 이 장은 설정 항목을 제36장의 개념과 하나씩 연결하고, 하드웨어 조건과 자료형 선택을 정리한 뒤, Qwen2.5-0.5B를 4비트로 불러와 계층별 자료형·메모리·PPL을 잽니다. 그리고 지금까지 검증한 라이브러리 버전을 고정합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 4비트 로딩 설정은 무엇을 정하며, GT 1030에서 무엇이 가능하고 무엇이 불가능한가 |
| 실습 결과물 | 하드웨어 조건 판정, 설정 대응표, 4비트 모델의 계층·자료형, 메모리 분해, 실제 4비트 모델의 PPL |
| 실습 파일 | `examples/ch37/`의 `load_4bit.py`, `test_ch37.py`, `requirements/cpu.txt`, `requirements/gt1030.txt` |
| 선수 장 | 제02장(GT 1030 특성), 제32장(저장·연산 자료형), 제36장(NF4, 이중 양자화) |

```text
from_pretrained(…, quantization_config=BitsAndBytesConfig(…), dtype=torch.float32)
   ├── Linear 168개 → Linear4bit: NF4 번호(uint8) + absmax(이중 양자화)   계산 시 FP32로 복원
   └── 나머지(Embedding, RMSNorm, 편향) → dtype(FP32) 그대로
```

## BitsAndBytesConfig

4비트 로딩 설정은 제36장에서 직접 만든 것과 하나씩 대응합니다.

```text
설정                          값               제36장의 대응
load_in_4bit                  True             Linear 가중치를 4비트로 저장
bnb_4bit_quant_type           "nf4"            Codebook을 NF4로(다른 선택: "fp4")
bnb_4bit_use_double_quant     True             absmax 이중 양자화(평균 4.127비트)
bnb_4bit_compute_dtype        torch.float32    역양자화한 뒤 계산하는 자료형
(블록 크기)                   64(기본값)       BLOCK = 64
```

`bnb_4bit_quant_type`에는 `"fp4"`도 있습니다. FP4는 부호·지수·가수를 가진 4비트 부동소수점으로, 정규분포를 따르는 가중치에는 NF4가 더 정확하다는 것이 QLoRA 논문의 결과입니다. 이 교재는 NF4만 씁니다.

## 하드웨어 조건

bitsandbytes는 기능마다 필요한 GPU 세대(Compute Capability, CC)가 다릅니다. bitsandbytes 공식 설치 문서(0.50 기준)의 조건은 다음과 같습니다.

| 기능 | 필요한 CC | GT 1030(CC 6.1) |
|---|---|---|
| NF4·FP4 4비트 양자화 | 6.0 이상 | 가능 |
| 8비트 Optimizer | 6.0 이상 | 가능 |
| LLM.int8(8비트 행렬곱) | 7.5 이상 | 불가 |

GT 1030은 QLoRA에 필요한 4비트 양자화와 8비트 Optimizer는 쓸 수 있지만, 8비트로 모델을 불러오는 LLM.int8은 쓸 수 없습니다. 그래서 이 교재는 GPU 경로의 양자화 학습을 4비트(NF4) 하나로 정하고, 8비트는 제33장에서 원리로만 다룹니다.

GPU가 없는 경우도 있습니다. 이 교재가 쓰는 bitsandbytes 0.50은 CPU 경로(AVX2 이상)도 지원해, 이 교재의 검증 환경처럼 GPU가 없어도 4비트 모델을 불러와 계산할 수 있습니다. 속도는 GPU보다 느리지만 같은 형식, 같은 결과를 확인하기에는 충분합니다.

## Compute Dtype과 torch_dtype

4비트 모델에는 자료형이 세 가지 있습니다. 헷갈리기 쉬우므로 역할을 나눠 둡니다.

```text
자료형                          정하는 곳                    이 교재(GT 1030 기준)
저장 자료형                     load_in_4bit                 NF4 번호(uint8에 두 개씩)
계산 자료형                     bnb_4bit_compute_dtype       FP32
양자화하지 않는 계층의 자료형   from_pretrained의 dtype      FP32
```

**계산 자료형**은 4비트 가중치를 복원해 행렬곱을 할 때의 자료형입니다. 최신 GPU에서는 BF16이 빠르지만, GT 1030은 BF16 연산이 없고 FP16 연산은 1/64 속도이므로(제02·32장) FP32로 정합니다.

**양자화하지 않는 계층**은 Embedding, RMSNorm, 편향입니다. bitsandbytes는 Linear만 4비트로 바꾸고, Embedding은 그대로 둡니다. Qwen2.5-0.5B의 Embedding은 151,936 × 896개, FP32로 약 519MiB입니다. 4비트 Linear 168개를 모두 합친 것(약 171MiB)보다 세 배나 큽니다. 4비트 모델의 메모리는 Embedding이 지배합니다. `dtype=torch.float16`으로 Embedding을 절반(약 260MiB)으로 줄일 수도 있지만, 그러면 Embedding 출력과 RMSNorm 계산이 FP16이 되어 GT 1030에서 느려지므로 이 교재는 FP32를 씁니다.

## 버전 조합 확정

양자화 라이브러리는 PyTorch·CUDA 빌드와 맞물려 있어, 한 가지만 바꿔도 동작하지 않을 수 있습니다. 그래서 이 장에서 지금까지 실제로 검증한 버전을 `requirements`에 고정합니다.

```text
requirements/cpu.txt      torch 2.15.0+cpu, transformers 5.24.0, peft 0.22.0, bitsandbytes 0.50.2 …
                          → 교재 검증 환경에서 제1~37장 전체 테스트 통과
requirements/gt1030.txt   torch 2.14.0+cu126 + 같은 라이브러리 버전
                          → 후보 조합. GT 1030 실제 실행은 미검증
```

GT 1030 경로의 조건은 세 가지입니다. PyTorch는 Pascal을 지원하는 마지막 CUDA 12.6 빌드인 2.14 계열(제01장), NVIDIA 드라이버는 570 이상, bitsandbytes는 CC 6.0 이상을 지원하는 공식 배포판입니다. 학습자 장비에서 이 장의 실습을 GPU로 실행해 통과하면, 그 결과를 `gt1030.txt`의 주석에 기록합니다.

## 핵심 실습

파일명: `examples/ch37/load_4bit.py`

```python
# 제37장 핵심 실습: bitsandbytes로 Qwen2.5-0.5B-Instruct를 NF4 4비트로 불러와 자료형·메모리·PPL을 확인한다
#
# 실행: python examples/ch37/load_4bit.py
#
# GPU(CC 6.0 이상)가 있으면 GPU에, 없으면 bitsandbytes CPU 경로로 불러온다.

import math
import sys
from collections import Counter
from pathlib import Path

HERE = Path(__file__).resolve().parent
for p in (HERE.parent, HERE.parent / "ch22"):
    sys.path.insert(0, str(p))

import torch  # noqa: E402
from transformers import AutoModelForCausalLM, BitsAndBytesConfig  # noqa: E402
from transformers.utils import logging  # noqa: E402

from common.fixed_data import load_blocks  # noqa: E402
from common.models import QWEN_ID, QWEN_REVISION  # noqa: E402
from common.qwen import load_tokenizer  # noqa: E402
from qwen_ppl import evaluate  # noqa: E402            (제22장)

logging.disable_progress_bar()
MiB = 2 ** 20


def hardware() -> dict:
    """bitsandbytes 기능별 하드웨어 조건(공식 문서: NF4 CC 6.0+, LLM.int8 CC 7.5+)"""
    if not torch.cuda.is_available():
        return {"device": "cpu", "name": "CPU", "cc": None, "nf4": True, "int8": True}
    major, minor = torch.cuda.get_device_capability(0)
    cc = major + minor / 10
    return {"device": "cuda", "name": torch.cuda.get_device_name(0), "cc": cc,
            "nf4": cc >= 6.0, "int8": cc >= 7.5}


def nf4_config() -> BitsAndBytesConfig:
    """제36장과 같은 NF4 + 이중 양자화, 계산은 FP32(GT 1030 기준)"""
    return BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4",
                              bnb_4bit_use_double_quant=True, bnb_4bit_compute_dtype=torch.float32)


def load_nf4(device: str):
    return AutoModelForCausalLM.from_pretrained(
        QWEN_ID, revision=QWEN_REVISION, quantization_config=nf4_config(),
        dtype=torch.float32, device_map=device).eval()       # dtype: 양자화하지 않는 계층의 자료형


def memory_parts(model) -> dict:
    """파라미터·버퍼 바이트를 '4비트 가중치'와 '그 밖'으로 나눈다(4비트 메타데이터는 따로)."""
    parts = Counter()
    for name, p in model.named_parameters():
        key = "4비트 가중치(번호)" if p.dtype == torch.uint8 else (
            "Embedding(= LM Head)" if "embed_tokens" in name else "편향·RMSNorm")
        parts[key] += p.numel() * p.element_size()
    meta = 0
    for mod in model.modules():
        qs = getattr(getattr(mod, "weight", None), "quant_state", None)
        if qs is not None:
            meta += qs.absmax.numel() * qs.absmax.element_size()
            if qs.state2 is not None:
                meta += qs.state2.absmax.numel() * qs.state2.absmax.element_size()
    parts["4비트 메타데이터(absmax)"] = meta
    return dict(parts)


def main() -> None:
    hw = hardware()
    print("── 1. 하드웨어 조건 ──")
    print(f"  장치 {hw['name']}, Compute Capability {hw['cc'] or '해당 없음'}")
    print(f"  NF4 4비트: {'가능' if hw['nf4'] else '불가'}, LLM.int8: {'가능' if hw['int8'] else '불가'}"
          f"{' (CPU 경로)' if hw['device'] == 'cpu' else ''}")

    print("\n── 2. BitsAndBytesConfig(제36장과의 대응) ──")
    c = nf4_config()
    for k, meaning in (("bnb_4bit_quant_type", "Codebook(제36장 NF4)"),
                       ("bnb_4bit_use_double_quant", "absmax 이중 양자화"),
                       ("bnb_4bit_compute_dtype", "역양자화 후 계산 자료형")):
        print(f"  {k:<27}{str(getattr(c, k)):<16}{meaning}")

    print("\n── 3. 4비트 로딩: 계층 종류와 자료형 ──")
    tok = load_tokenizer()
    model = load_nf4(hw["device"])
    kinds = Counter(type(m).__name__ for m in model.modules() if not list(m.children()))
    print(f"  말단 계층 {dict(kinds)}")
    q = model.model.layers[0].self_attn.q_proj
    print(f"  q_proj: {type(q).__name__}, 저장 {q.weight.dtype} {tuple(q.weight.shape)} "
          f"(896 × 896 ÷ 2 = {896 * 896 // 2:,}바이트), 계산 {q.compute_dtype}")
    qs = q.weight.quant_state
    print(f"  블록 크기 {qs.blocksize}, 이중 양자화 블록 {qs.state2.blocksize}, Codebook 값 {qs.code.numel()}개")
    print(f"  Embedding {model.model.embed_tokens.weight.dtype}, LM Head 공유 "
          f"{model.lm_head.weight is model.model.embed_tokens.weight}")

    print("\n── 4. 메모리(파라미터 기준) ──")
    parts = memory_parts(model)
    for k, v in parts.items():
        print(f"  {k:<26}{v / MiB:8.1f}MiB")
    total = sum(parts.values())
    print(f"  {'합계':<26}{total / MiB:8.1f}MiB  (FP32 전체 {494_032_768 * 4 / MiB:,.0f}MiB의 "
          f"{total / (494_032_768 * 4):.0%})")
    print(f"  get_memory_footprint() {model.get_memory_footprint() / MiB:.1f}MiB")
    if hw["device"] == "cuda":
        print(f"  GPU 최대 할당 {torch.cuda.max_memory_allocated() / MiB:.0f}MiB")

    print("\n── 5. 고정 평가 데이터 PPL ──")
    r = evaluate(model, load_blocks(tok, "eval"), hw["device"])
    print(f"  bitsandbytes NF4 + 이중 양자화  PPL {math.exp(r['loss']):.2f}")
    print("  (참고: FP32 21.45, 제36장 직접 구현 NF4 + 이중 양자화 27.87)")


if __name__ == "__main__":
    main()
```


**결과 읽기**

- **1번**은 GPU가 없어 CPU 경로로 판정했습니다. GT 1030에서는 CC 6.1로 NF4 가능, LLM.int8 불가로 표시되어야 합니다.
- **3번**에서 Linear 168개(24계층 × 7종)가 모두 `Linear4bit`로 바뀌었고, LM Head(`Linear` 1개)와 Embedding은 그대로입니다. q_proj의 가중치는 `uint8` 401,408개로, 896 × 896개의 4비트 번호를 바이트 하나에 두 개씩 담은 크기입니다(제34장). 블록 64, 이중 양자화 블록 256, Codebook 16개는 제36장의 설정과 같습니다.
- **4번**에서 4비트 모델의 파라미터 메모리는 약 696MiB로 FP32(1,885MiB)의 37%입니다. 그중 519MiB가 Embedding입니다. 4비트 가중치와 메타데이터는 합쳐서 176MiB에 불과합니다.
- **5번**에서 실제 bitsandbytes 4비트 모델의 PPL은 27.78로, 제36장의 직접 구현(27.87)과 거의 같습니다. 작은 차이는 이중 양자화 방식의 차이입니다. 제36장은 absmax를 INT8로 단순화했고, bitsandbytes는 블록 단위 8비트 부동소수점 형식을 씁니다. 직접 구현으로 예측한 품질이 실제 라이브러리에서 재현되었습니다.

GT 1030 경로에서는 4번에 GPU 최대 할당량이 함께 출력됩니다. 파라미터 696MiB에 CUDA 실행 환경이 차지하는 메모리(수백 MiB)가 더해지며, 설계서의 예산(QLoRA 학습 전체 약 1.5GB 내외) 안에서 학습 공간이 남는지가 제38장의 주제입니다.

## 검증과 완료 기준

파일명: `examples/ch37/test_ch37.py`

```python
# 제37장 검증 테스트
#
# 실행: python -m pytest examples/ch37 -q

import sys
from pathlib import Path

import pytest
import torch

HERE = Path(__file__).resolve().parent
for p in (HERE, HERE.parent, HERE.parent / "ch22", HERE.parent / "ch36"):
    sys.path.insert(0, str(p))

pytest.importorskip("bitsandbytes")

from load_4bit import hardware, memory_parts, nf4_config  # noqa: E402


def test_hardware_rules():
    hw = hardware()
    if hw["device"] == "cuda":
        assert hw["nf4"] == (hw["cc"] >= 6.0) and hw["int8"] == (hw["cc"] >= 7.5)
    else:
        assert hw["nf4"]


def test_config_matches_ch36():
    c = nf4_config()
    assert c.load_in_4bit and c.bnb_4bit_quant_type == "nf4" and c.bnb_4bit_use_double_quant
    assert c.bnb_4bit_compute_dtype == torch.float32


def test_linear4bit_matches_own_nf4():
    import bitsandbytes as bnb
    from nf4 import nf4_fake
    torch.manual_seed(0)
    lin = torch.nn.Linear(128, 64, bias=False)
    q = bnb.nn.Linear4bit(128, 64, bias=False, compute_dtype=torch.float32, quant_type="nf4")
    q.weight = bnb.nn.Params4bit(lin.weight.data.clone(), requires_grad=False, quant_type="nf4",
                                compress_statistics=False)                # 이중 양자화 없이 비교
    q = q.to("cpu") if not torch.cuda.is_available() else q.cuda()
    x = torch.randn(3, 128, device=q.weight.device)
    expect = x.cpu() @ nf4_fake(lin.weight.data).T                  # 제36장 직접 구현(이중 양자화 없음)
    torch.testing.assert_close(q(x).cpu(), expect, atol=1e-4, rtol=1e-4)


def test_qwen_4bit_memory():
    try:
        from load_4bit import load_nf4
        model = load_nf4(hardware()["device"])
    except Exception:
        pytest.skip("Qwen 모델이 아직 내려받아지지 않음")
    parts = memory_parts(model)
    assert parts["Embedding(= LM Head)"] == 151_936 * 896 * 4          # 양자화하지 않음(약 519MiB)
    assert parts["4비트 가중치(번호)"] == 24 * (896 * 896 * 2 + 128 * 896 * 2 + 4864 * 896 * 3) // 2
    assert sum(parts.values()) < 0.4 * 494_032_768 * 4
```

## 핵심 정리

- `BitsAndBytesConfig`의 항목은 제36장의 NF4, 이중 양자화, 블록 크기, 계산 자료형에 하나씩 대응합니다.
- bitsandbytes의 NF4·8비트 Optimizer는 CC 6.0 이상(GT 1030 가능), LLM.int8은 CC 7.5 이상(GT 1030 불가)이 필요합니다. GPU가 없으면 CPU 경로로 같은 형식을 쓸 수 있습니다.
- 저장(NF4), 계산(`bnb_4bit_compute_dtype`), 양자화하지 않는 계층(`dtype`)의 자료형은 따로 정합니다. GT 1030은 계산과 나머지 계층 모두 FP32입니다.
- 4비트 Qwen2.5-0.5B의 파라미터 메모리는 약 696MiB이며, 그중 519MiB가 양자화하지 않는 Embedding입니다. PPL은 27.78로 직접 구현과 일치합니다.
- 검증한 라이브러리 버전을 `requirements`에 고정했습니다. GT 1030 경로의 실제 실행은 미검증입니다.

**다음 장 연결:** 4비트 모델을 불러왔으니 그 위에 LoRA를 붙여 학습하면 QLoRA입니다. 제38장에서는 QLoRA 학습에 필요한 메모리를 가중치·Activation·Gradient·Optimizer·Logits로 분해해 계산하고, Gradient Checkpointing으로 메모리를 줄이는 원리를 측정합니다.
