## 장 개요

제44장에서 대화를 템플릿 문자열로 바꾸었습니다. 이 문자열을 토큰화하면 학습 샘플이 되지만, 그대로 학습하면 모델은 System 문구와 질문까지 **따라 쓰도록** 배웁니다. 우리가 원하는 것은 질문을 보고 **답을 쓰는** 능력이므로, 채점은 답 부분에서만 해야 합니다.

이 장은 학습 샘플을 이루는 세 배열(input_ids, attention_mask, labels)을 실제 값으로 확인하고, 질문 부분의 Label을 -100으로 가리는 **Label Masking**을 구현합니다. 그리고 이 과정에서 생기기 쉬운 세 가지 오류를 실험으로 재현합니다. 생성 구간 표시가 없는 템플릿에서 Assistant-only Loss를 쓰는 오류, PAD와 끝 표시를 같게 두어 끝 표시가 가려지는 오류, 최대 길이에서 답이 잘리는 오류입니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 어떤 토큰을 학습 대상으로 삼아야 하며, 그 경계가 어긋나면 무엇이 잘못되는가 |
| 실습 결과물 | 학습 대상을 표시한 토큰표, PAD 묶음의 두 마스크, 질문·답 부분 Loss, 끝 표시·잘림 점검 |
| 실습 파일 | `examples/ch45/`의 `label_mask.py`, `test_ch45.py` |
| 선수 장 | 제22장(Loss와 IGNORE), 제44장(Chat Template) |

```text
학습 문자열: [system][user][assistant 시작] │ 정답 … 끝 표시 │ 줄바꿈
labels:       -100  -100  -100           │ 정답 토큰 그대로 │ -100
                     질문 부분(가림)        │ 학습 대상        │
```

## 학습 샘플의 세 배열

학습 샘플 하나는 같은 길이의 배열 세 개입니다.

| 배열 | 값 | 역할 |
|---|---|---|
| input_ids | 토큰 id | 모델이 읽는 입력 |
| attention_mask | 1 또는 0 | 1인 자리만 Attention이 본다 |
| labels | 토큰 id 또는 -100 | 각 자리에서 맞혀야 할 토큰. -100은 채점하지 않음 |

labels는 input_ids와 같은 위치에 정답 토큰을 둡니다. 다음 토큰을 맞히도록 한 칸 미는 일(Shift)은 모델 안에서 합니다(제22장). 그래서 labels를 만들 때는 "이 자리의 토큰을 학습할 것인가"만 정하면 됩니다. 학습하지 않을 자리에 -100을 넣으면 Cross Entropy가 그 자리를 평균에서 뺍니다.

## Attention Mask와 Loss Mask

길이가 다른 샘플을 하나의 묶음(Batch)으로 만들려면 짧은 샘플 뒤에 **PAD 토큰**을 채워 길이를 맞춥니다. PAD 자리에는 두 가지를 해야 합니다.

| 마스크 | PAD 자리 | 질문 부분 |
|---|---|---|
| Attention Mask(볼 것인가) | 0, 보지 않음 | 1, 봄 |
| Loss Mask(채점할 것인가) | -100, 채점 안 함 | -100, 채점 안 함 |

질문 부분은 **보지만 채점하지 않습니다.** 모델이 답을 쓰려면 질문을 읽어야 하므로 Attention은 질문을 보아야 하고, 질문을 맞히는 능력은 학습 목표가 아니므로 Loss에는 넣지 않습니다. 두 마스크는 다른 질문에 답하는 다른 장치이며, 하나로 다른 하나를 대신할 수 없습니다. PAD 자리는 둘 다 막습니다.

## Completion-only Loss

질문 부분을 가리고 답 부분만 학습하는 방식을 **Completion-only Loss**라고 하며, 이 교재의 기본 경로입니다. 경계는 제44장에서 확인한 성질로 구합니다. 추론용 문자열(질문까지와 응답 시작 표시)을 토큰화한 길이가 곧 답이 시작하는 위치이며, 그 앞은 모두 -100입니다.

| 부분 | 학습 대상 | 이유 |
|---|---|---|
| System, User, 응답 시작 표시 | 아니요 | 질문을 따라 쓰는 능력은 목표가 아니다 |
| 정답 토큰 | 예 | 학습 목표 |
| 끝 표시 | 예 | 답을 마치고 멈추는 법을 배운다 |
| 끝 표시 뒤의 줄바꿈 | 아니요 | 생성은 끝 표시에서 멈추므로 그 뒤는 쓰이지 않는다 |

질문 부분까지 학습하면 50개 샘플에 똑같이 들어 있는 System 문구를 매번 외우는 데 학습량이 쓰이고, 질문이 긴 샘플일수록 답의 비중이 작아집니다.

## Assistant-only Loss의 조건

여러 차례 주고받는 대화에서는 assistant가 말한 부분만 골라 학습하는 **Assistant-only Loss**가 필요할 수 있습니다. Transformers는 `return_assistant_tokens_mask=True` 옵션으로 이 마스크를 만들어 주고, TRL의 SFTTrainer도 같은 기능을 설정 하나로 켭니다.

이 기능에는 조건이 있습니다. 템플릿이 assistant의 말을 생성 구간 표시(Jinja의 generation 블록)로 감싸고 있어야 합니다. **Qwen2.5의 기본 템플릿에는 이 표시가 없습니다.** 그래서 이 옵션을 켜도 마스크가 모두 0이 되어, 학습 대상이 하나도 없는 샘플이 만들어집니다. 오류 메시지 없이 학습이 진행되므로 알아차리기 어렵습니다. 이 교재는 한 차례 질문과 답만 다루므로, 템플릿을 고치는 대신 위의 Completion-only 방식으로 경계를 직접 구합니다.

## 종료 토큰과 PAD

PAD를 따로 기록하지 않고 "input_ids가 PAD id인 자리를 모두 -100으로" 가리는 코드가 흔합니다. PAD id가 끝 표시와 다르면 문제가 없지만, **PAD를 끝 표시(EOS)와 같게 설정**하면 답 끝의 끝 표시까지 함께 가려집니다. 그러면 모델은 답을 마치고 멈추는 법을 배우지 못해, 학습 후 답이 끝나지 않고 이어집니다.

Qwen2.5-Instruct의 토크나이저는 PAD에 끝 표시와 다른 토큰을 씁니다. 그러나 PAD가 없는 모델에서 흔히 "PAD = EOS"로 직접 지정하므로, 모델을 바꿀 때 이 오류가 생깁니다. 이 교재는 PAD 자리를 attention_mask로 기록하고 labels는 샘플을 만들 때 -100으로 채우므로, PAD id가 무엇이든 끝 표시가 가려지지 않습니다.

## 길이 제한과 잘림

메모리에 맞추려면 샘플의 최대 길이를 정해야 합니다. 이 교재는 GT 1030 경로의 최대 시퀀스를 256으로 둡니다. 템플릿을 적용한 샘플이 이보다 길면 뒤를 자르는데, 학습 문자열에서 뒤는 **답 부분**입니다. 잘린 샘플은 답의 끝과 끝 표시를 배우지 못하므로, 학습한 모델이 답을 중간에 끊지 않고 이어 가는 원인이 됩니다.

그래서 최대 길이를 정하기 전에 전체 샘플의 길이 분포와 잘리는 비율을 먼저 셉니다. 잘리는 샘플이 많으면 최대 길이를 늘리거나, 답을 짧게 고치거나, 그 샘플을 빼는 것 중에서 고릅니다.

## 핵심 실습

파일명: `examples/ch45/label_mask.py`

```python
# 제45장 핵심 실습: 샘플 하나의 input_ids와 labels를 나란히 출력해 학습 대상 토큰을 표시한다
#
# 실행: python examples/ch45/label_mask.py

import sys
from pathlib import Path

HERE = Path(__file__).resolve().parent
for p in (HERE.parent, HERE.parent / "ch41", HERE.parent / "ch44"):
    sys.path.insert(0, str(p))

import torch  # noqa: E402

from chat_template import SYSTEM, render  # noqa: E402           (제44장)
from check_dataset import load, to_structures  # noqa: E402      (제41장)
from common.qwen import load_model, load_tokenizer  # noqa: E402

IGNORE = -100
MAX_LEN = 256                               # GT 1030 기준 최대 시퀀스


def chat(r: dict) -> list:
    return [{"role": "system", "content": SYSTEM}] + to_structures(r)["messages"]["messages"]


def build_example(tok, r: dict, max_len: int = MAX_LEN) -> dict:
    """질문 부분은 -100, 답과 끝 표시만 학습 대상. 끝 표시 뒤의 줄바꿈은 가린다."""
    msgs = chat(r)
    prompt = tok(render(tok, msgs[:2], gen=True), add_special_tokens=False).input_ids
    full = tok(render(tok, msgs, gen=False), add_special_tokens=False).input_ids
    assert full[:len(prompt)] == prompt, "추론 문자열이 학습 문자열의 앞부분이어야 한다"
    end = full.index(tok.convert_tokens_to_ids("<|im_end|>"), len(prompt))
    labels = [IGNORE] * len(prompt) + full[len(prompt):end + 1] + [IGNORE] * (len(full) - end - 1)
    ids, labels = full[:max_len], labels[:max_len]
    return {"input_ids": ids, "attention_mask": [1] * len(ids), "labels": labels,
            "answer_tokens": end + 1 - len(prompt), "full_len": len(full)}


def pad_batch(examples: list, pad_id: int) -> dict:
    """오른쪽 PAD: 보지 않을 자리(attention 0)이자 채점하지 않을 자리(label -100)"""
    n = max(len(e["input_ids"]) for e in examples)
    out = {"input_ids": [], "attention_mask": [], "labels": []}
    for e in examples:
        k = n - len(e["input_ids"])
        out["input_ids"].append(e["input_ids"] + [pad_id] * k)
        out["attention_mask"].append(e["attention_mask"] + [0] * k)
        out["labels"].append(e["labels"] + [IGNORE] * k)
    return {key: torch.tensor(v) for key, v in out.items()}


def mask_by_pad_id(batch: dict, pad_id: int) -> torch.Tensor:
    """흔한 방식: PAD 위치를 따로 기록하지 않고, PAD id와 같은 토큰을 모두 -100으로 만든다"""
    labels = batch["labels"].clone()
    labels[batch["input_ids"] == pad_id] = IGNORE
    return labels


def show(tok, e: dict, around: int = 4) -> None:
    ids, labels = e["input_ids"], e["labels"]
    start = labels.index(next(x for x in labels if x != IGNORE))
    keep = set(range(start - around, start + around)) | set(range(len(ids) - around, len(ids)))
    print("  위치  학습  input_id  토큰")
    for i in sorted(keep):
        mark = "●" if labels[i] != IGNORE else "·"
        print(f"  {i:>4}   {mark}   {ids[i]:>7}  {tok.decode([ids[i]])!r}")
        if i == start + around - 1:
            print("   …")


def main() -> None:
    tok = load_tokenizer()
    rows = load()
    r = rows[2]                                             # fpga-003
    e = build_example(tok, r)

    print("── 1. input_ids · attention_mask · labels(fpga-003) ──")
    n_train = sum(x != IGNORE for x in e["labels"])
    print(f"  길이 {len(e['input_ids'])}, attention 1인 자리 {sum(e['attention_mask'])}, 학습 대상 {n_train}"
          f"(답 {n_train - 1} + 끝 표시 1)")
    show(tok, e)

    print("\n── 2. Attention Mask와 Loss Mask(두 샘플을 오른쪽 PAD로 묶음) ──")
    b = pad_batch([e, build_example(tok, rows[9])], tok.pad_token_id)
    for j in range(2):
        a, lab = b["attention_mask"][j], b["labels"][j]
        print(f"  샘플 {j}: 길이 {len(a)}, 보는 자리 {int(a.sum())}, 채점 자리 {int((lab != IGNORE).sum())}, "
              f"PAD {int((a == 0).sum())}")
    print(f"  PAD 토큰 {tok.pad_token!r}(id {tok.pad_token_id}), 끝 표시 {tok.eos_token!r}(id {tok.eos_token_id})")

    print("\n── 3. Completion-only Loss: 질문 부분과 답 부분의 Loss(Qwen2.5 그대로) ──")
    model = load_model()
    ids = torch.tensor([e["input_ids"]])
    with torch.no_grad():
        logits = model(ids).logits[0, :-1]
    tok_loss = torch.nn.functional.cross_entropy(logits, ids[0, 1:], reduction="none")
    target = torch.tensor(e["labels"][1:]) != IGNORE
    print(f"  가린 부분 평균 Loss {tok_loss[~target].mean():.3f}({int((~target).sum())}토큰, 질문과 끝 줄바꿈)")
    print(f"  답 부분 평균 Loss  {tok_loss[target].mean():.3f}({int(target.sum())}토큰)  ← 학습이 줄일 값")
    lab = torch.tensor([e["labels"]])
    print(f"  labels로 계산한 Loss {model(ids, labels=lab).loss.item():.3f}(답 부분 평균과 같아야 함)")

    print("\n── 4. Assistant-only Loss의 조건 ──")
    has = "{% generation %}" in tok.chat_template
    out = tok.apply_chat_template(chat(r), tokenize=True, return_dict=True, return_assistant_tokens_mask=True)
    print(f"  템플릿에 생성 구간 표시 있음: {has}, assistant 마스크의 1 개수: {sum(out['assistant_masks'])}")

    print("\n── 5. 끝 표시와 PAD ──")
    print("  PAD id로 가리는 방식을 썼을 때 학습 대상으로 남는 끝 표시(샘플 2개, 정답은 2개):")
    for name, pad in (("PAD = endoftext(Qwen2.5 Instruct 기본)", tok.pad_token_id),
                      ("PAD = 끝 표시(PAD를 EOS로 지정)", tok.eos_token_id)):
        bb = pad_batch([e, build_example(tok, rows[9])], pad)
        left = int((mask_by_pad_id(bb, pad) == tok.eos_token_id).sum())
        print(f"    {name}: {left}개 → {'정상' if left == 2 else '모델이 멈추는 법을 배우지 못함'}")

    print("\n── 6. 길이 제한과 잘림(50개, 질문 앞부분은 같고 답이 잘림) ──")
    for max_len in (256, 128):
        ex = [build_example(tok, x, max_len) for x in rows]
        cut = [x for x in ex if x["full_len"] > max_len]
        lost = sum(x["answer_tokens"] - sum(t != IGNORE for t in x["labels"]) for x in ex)
        total = sum(x["answer_tokens"] for x in ex)
        no_end = sum(1 for x in ex if tok.eos_token_id not in [t for t in x["labels"] if t != IGNORE])
        print(f"  최대 {max_len}: 잘린 샘플 {len(cut)}개, 잃은 학습 대상 토큰 {lost}(답·끝 표시 토큰의 {lost / total:.1%}), "
              f"끝 표시를 못 배우는 샘플 {no_end}개")
    lens = sorted(build_example(tok, x)["full_len"] for x in rows)
    print(f"  전체 길이: 최소 {lens[0]}, 중앙 {lens[25]}, 최대 {lens[-1]}")


if __name__ == "__main__":
    main()
```

- **2번**에서 짧은 샘플 뒤에 PAD 8개가 붙었습니다. PAD 자리는 보는 자리에서도, 채점 자리에서도 빠집니다. 질문 부분은 보는 자리에는 들어가고 채점 자리에서는 빠집니다.
- **3번**에서 Qwen2.5는 가린 부분의 Loss가 4.20으로 답 부분(2.66)보다 높습니다. 한국어 System 문구가 모델에게 낯설기 때문입니다. 가리지 않으면 학습은 이 문구를 외우는 데 먼저 힘을 씁니다. labels로 계산한 Loss는 답 부분 평균과 정확히 같아, -100 자리가 평균에서 빠졌음을 확인합니다.
- **4번**에서 Qwen2.5 템플릿에는 생성 구간 표시가 없고, assistant 마스크를 요청하면 1이 하나도 없습니다. 이 마스크로 학습하면 아무것도 배우지 않습니다.
- **5번**에서 PAD id로 가리는 방식은 기본 설정에서는 끝 표시 2개를 남기지만, PAD를 끝 표시로 지정하면 모두 지웁니다. 같은 코드가 토크나이저 설정 하나로 조용히 틀린 데이터를 만든다는 뜻입니다.
- **6번**에서 최대 256이면 50개 모두 잘리지 않습니다(가장 긴 샘플 199). 최대 128로 줄이면 44개가 잘리고 학습 대상의 25.7%를 잃으며, 43개는 끝 표시를 배우지 못합니다. 나머지 하나는 끝 표시 뒤의 줄바꿈만 잘렸습니다.

파일명: `examples/ch45/test_ch45.py`

```python
# 제45장 검증 테스트

# 실행: python -m pytest examples/ch45 -q

import sys
from pathlib import Path

HERE = Path(__file__).resolve().parent
for p in (HERE, HERE.parent, HERE.parent / "ch41", HERE.parent / "ch44"):
    sys.path.insert(0, str(p))

import pytest  # noqa: E402

from check_dataset import load  # noqa: E402
from label_mask import IGNORE, build_example, mask_by_pad_id, pad_batch  # noqa: E402


@pytest.fixture(scope="module")
def tok():
    from common.qwen import load_tokenizer
    return load_tokenizer()


def test_only_answer_and_end_are_targets(tok):
    end = tok.convert_tokens_to_ids("<|im_end|>")
    for r in load():
        e = build_example(tok, r)
        target = [t for t in e["labels"] if t != IGNORE]
        assert target[-1] == end and target.count(end) == 1          # 끝 표시는 하나, 맨 끝
        assert tok.decode(target[:-1]) == r["output"]                 # 나머지는 정확히 정답
        assert len(e["input_ids"]) == len(e["labels"]) == len(e["attention_mask"])


def test_padding_is_excluded(tok):
    rows = load()
    b = pad_batch([build_example(tok, rows[2]), build_example(tok, rows[9])], tok.pad_token_id)
    pad = b["attention_mask"] == 0
    assert pad.any() and (b["labels"][pad] == IGNORE).all() and (b["input_ids"][pad] == tok.pad_token_id).all()


def test_pad_equal_eos_loses_end_token(tok):
    rows = load()
    b = pad_batch([build_example(tok, rows[2]), build_example(tok, rows[9])], tok.eos_token_id)
    assert int((mask_by_pad_id(b, tok.eos_token_id) == tok.eos_token_id).sum()) == 0
    b = pad_batch([build_example(tok, rows[2]), build_example(tok, rows[9])], tok.pad_token_id)
    assert int((mask_by_pad_id(b, tok.pad_token_id) == tok.eos_token_id).sum()) == 2


def test_truncation_counts(tok):
    rows = load()
    assert all(build_example(tok, r)["full_len"] <= 256 for r in rows)
    short = [build_example(tok, r, 128) for r in rows]
    assert all(len(e["input_ids"]) <= 128 for e in short)
    assert sum(1 for e in short if e["full_len"] > 128) == 44
```

## 핵심 정리

- 학습 샘플은 input_ids(입력), attention_mask(볼 자리), labels(채점할 정답, -100은 제외) 세 배열입니다.
- 질문 부분은 보지만 채점하지 않고, PAD는 보지도 채점하지도 않습니다. Attention Mask와 Loss Mask는 다른 장치입니다.
- Completion-only Loss는 추론 문자열의 길이로 답의 시작을 구해 그 앞을 -100으로 가립니다. 정답과 끝 표시는 학습하고, 끝 표시 뒤 줄바꿈은 가립니다.
- Assistant-only Loss는 템플릿의 생성 구간 표시가 필요하며, Qwen2.5 기본 템플릿에서는 학습 대상이 0개가 됩니다.
- PAD를 끝 표시와 같게 두고 PAD id로 가리면 끝 표시가 사라져 모델이 멈추지 못합니다. 최대 길이는 잘림 비율을 센 뒤 정합니다.
