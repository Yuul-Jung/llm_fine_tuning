## 장 개요

제32장에서 FP32를 16비트로 줄이는 것은 자료형만 바꾸면 되었습니다. 8비트부터는 다릅니다. INT8은 정수 256개밖에 표현하지 못하므로, 가중치의 실수 범위를 정수 범위에 **맞춰 넣는 규칙**이 필요합니다. 그 규칙이 양자화(Quantization)입니다.

이 장은 양자화의 두 숫자, Scale과 Zero Point에서 출발합니다. 0을 중심으로 대칭으로 맞출지, 최솟값과 최댓값에 맞출지, Scale을 텐서 전체에 하나만 둘지 출력 채널마다 둘지, 범위 밖의 값을 어떻게 자르고 끝자리를 어떻게 반올림할지를 하나씩 직접 구현하고, 실제 Qwen 가중치를 INT8로 저장해 오차와 용량을 잽니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | 실수 가중치를 8비트 정수로 바꾸는 규칙은 무엇이며, 그 선택에 따라 오차가 얼마나 달라지는가 |
| 실습 결과물 | 손계산 예제, Qwen 가중치 분포, Per-Tensor·Per-Channel·비대칭 오차 비교, Clipping·Rounding 효과, 저장 용량 실측 |
| 실습 파일 | `examples/ch33/`의 `int8_quant.py`, `test_ch33.py` |
| 선수 장 | 제05장(가중치 `[out, in]`), 제31장(INT8 범위, Saturation, 반올림) |

```text
실수 w ──÷ Scale──▶ 반올림 ──Clamp [−127, 127]──▶ INT8 코드 q   (저장: 1바이트)
                                                       │
복원 ŵ = q × Scale  ◀───────────────────────────────────┘       오차 |ŵ − w| ≤ Scale ÷ 2
```

## Scale과 Zero Point

양자화는 실수 구간을 정수 구간에 **직선으로** 대응시키는 일입니다. 직선을 정하는 데는 두 숫자면 충분합니다.

```text
q = round(w ÷ Scale) + Zero Point          양자화(실수 → 정수 코드)
ŵ = (q − Zero Point) × Scale               역양자화(정수 코드 → 실수)
```

**Scale**은 정수 1칸이 실수로 얼마인지, 즉 양자화의 **간격**입니다. **Zero Point**는 실수 0이 어느 정수 코드에 놓이는지입니다. 복원값 ŵ는 원래 값 w를 Scale 간격의 격자에 반올림한 것이므로, 범위 안의 값이라면 오차는 언제나 **Scale의 절반 이하**입니다. 그러니 Scale을 작게 할수록 정확해지지만, Scale × 127이 표현할 수 있는 범위이므로 범위는 좁아집니다. 제31장의 Q Format에서 본 범위와 정밀도의 맞바꿈이 여기서는 Scale 하나로 나타납니다.

## 대칭, 비대칭 양자화

| 방식 | Scale | Zero Point | 정수 범위 |
|---|---|---|---|
| 대칭 | 절댓값의 최댓값 ÷ 127 | 0 | −127 ~ 127(INT8) |
| 비대칭 | (max − min) ÷ 255 | round(−min ÷ Scale) | 0 ~ 255(UINT8) |

**대칭** 양자화는 0을 중심으로 양쪽 끝을 ±max|w|에 맞춥니다. Zero Point가 0이므로 계산이 단순하고, 실수 0은 언제나 정확히 코드 0이 됩니다. 신경망 가중치는 대체로 0을 중심으로 대칭으로 퍼져 있으므로, 가중치 양자화에는 대칭 방식을 주로 씁니다. 정수 범위를 −128이 아니라 −127에서 시작하는 것은 양쪽을 똑같이 127칸씩 써서 대칭을 지키기 위해서입니다.

**비대칭** 양자화는 실제 최솟값과 최댓값에 맞춥니다. ReLU를 지난 활성값처럼 한쪽으로 치우친 값을 담을 때 256칸을 낭비 없이 씁니다. Zero Point를 정수로 반올림해 두므로, 비대칭에서도 실수 0이 정확히 표현됩니다. 0이 정확해야 하는 이유는 Padding이나 0으로 채운 값이 양자화 뒤에 0이 아닌 값으로 바뀌면 계산 전체에 작은 오차가 끼어들기 때문입니다.

## Per-Tensor와 Per-Channel

Scale을 몇 개 둘지도 선택입니다.

| 방식 | Scale 개수(`[out, in]` 가중치) | 성질 |
|---|---|---|
| Per-Tensor | 1개 | 가장 단순하다. 가장 큰 값 하나가 모든 행의 간격을 정한다 |
| Per-Channel | 출력 채널(행)마다 1개, out개 | 행마다 자기 크기에 맞는 간격을 쓴다 |
| Per-Group | 행 안을 일정 개수(예: 64개)씩 묶어 묶음마다 1개 | 제36장의 4비트 양자화에서 사용 |

Per-Tensor 방식의 약점은 **이상값**(Outlier)입니다. 텐서 안에 값 하나만 커도 Scale이 커지고, 작은 값이 대부분인 다른 행들은 몇 칸 안 되는 정수에 뭉쳐 정밀도를 잃습니다. Per-Channel은 행마다 Scale을 따로 두어 이 문제를 줄입니다. 추가 비용은 Scale 몇백 개(FP32)뿐입니다. 출력 채널 단위로 나누는 이유는, `y = W x`에서 행 하나가 출력 하나를 만들므로 복원할 때 출력마다 Scale 하나를 곱하면 되기 때문입니다.

## Clipping과 Rounding

**Clipping**은 Scale을 max|w|보다 작게 잡아, 범위를 일부러 좁히는 것입니다. 범위 밖으로 나간 소수의 큰 값은 ±127로 포화되어(제31장) 큰 오차를 갖지만, 나머지 대부분의 값은 간격이 좁아져 정확해집니다. 얼마나 자를지는 둘의 균형이며, 너무 많이 자르면 포화 오차가 전체를 망칩니다.

**Rounding**은 제31장의 규칙 그대로입니다. 반올림 대신 내림(버림)을 쓰면 오차가 언제나 한쪽(음수)으로 쌓여, 복원한 가중치 전체가 조금씩 작아집니다. 오차의 크기만이 아니라 **치우침**도 봐야 하는 이유입니다.

## 핵심 실습

파일명: `examples/ch33/int8_quant.py`

```python
# 제33장 핵심 실습: INT8 양자화를 직접 구현해 Qwen 가중치를 8비트로 저장·복원하고 오차를 비교한다
#
# 실행: python examples/ch33/int8_quant.py
#
# 대칭:   q = round(w ÷ s),             s = max|w| ÷ 127,          복원 ŵ = q × s
# 비대칭: q = round(w ÷ s) + z,         s = (max − min) ÷ 255,     복원 ŵ = (q − z) × s

import sys
import tempfile
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[1]))

import torch  # noqa: E402
from safetensors.torch import save_file  # noqa: E402

from common.qwen import load_model  # noqa: E402

NAME = "model.layers.0.self_attn.q_proj.weight"


def quant_symmetric(w: torch.Tensor, per_channel: bool = False, clip: float | None = None,
                    rounding=torch.round) -> tuple:
    """INT8 대칭 양자화. per_channel이면 출력 행마다 Scale을 따로 둔다. (코드 int8, Scale) 반환."""
    amax = w.abs().amax(dim=1, keepdim=True) if per_channel else w.abs().max()
    if clip is not None:                                       # 범위를 일부러 좁힌다(큰 값은 포화)
        amax = torch.quantile(w.abs().float().flatten(), clip) if not per_channel else amax
    scale = (amax / 127).clamp(min=1e-12)
    q = rounding(w / scale).clamp(-127, 127).to(torch.int8)
    return q, scale


def dequant_symmetric(q: torch.Tensor, scale: torch.Tensor) -> torch.Tensor:
    return q.float() * scale


def quant_asymmetric(w: torch.Tensor) -> tuple:
    """UINT8 비대칭 양자화(Per-Tensor). (코드 uint8, Scale, Zero Point) 반환."""
    lo, hi = w.min(), w.max()
    scale = (hi - lo) / 255
    zero = torch.round(-lo / scale).clamp(0, 255)
    q = (torch.round(w / scale) + zero).clamp(0, 255).to(torch.uint8)
    return q, scale, zero


def dequant_asymmetric(q, scale, zero) -> torch.Tensor:
    return (q.float() - zero) * scale


def rel_err(a, b) -> float:
    return ((a - b).norm() / b.norm()).item()


def main() -> None:
    print("── 1. 손계산: w = [−0.5, 0.0, 0.25, 1.0] ──")
    w = torch.tensor([-0.5, 0.0, 0.25, 1.0])
    q, s = quant_symmetric(w)
    print(f"  대칭  s = 1.0 ÷ 127 = {s.item():.6f}, q = {q.tolist()}, 복원 {[round(v, 4) for v in dequant_symmetric(q, s).tolist()]}")
    qa, sa, za = quant_asymmetric(w)
    print(f"  비대칭 s = 1.5 ÷ 255 = {sa.item():.6f}, z = {int(za)}, q = {qa.tolist()}, "
          f"복원 {[round(v, 4) for v in dequant_asymmetric(qa, sa, za).tolist()]}")

    w = dict(load_model().named_parameters())[NAME].detach()
    print(f"\n── 2. {NAME} {tuple(w.shape)}의 값 분포 ──")
    a = w.abs().flatten()
    print(f"  |w| 평균 {a.mean():.4f}, 99% 지점 {torch.quantile(a, 0.99):.4f}, 99.99% 지점 "
          f"{torch.quantile(a, 0.9999):.4f}, 최댓값 {a.max():.4f}")
    row_max = w.abs().amax(dim=1)
    print(f"  행(출력 채널)별 최댓값: 최소 {row_max.min():.4f}, 중앙 {row_max.median():.4f}, 최대 {row_max.max():.4f}")

    print("\n── 3. Per-Tensor vs Per-Channel(대칭 INT8) ──")
    for label, pc in (("Per-Tensor", False), ("Per-Channel", True)):
        q, s = quant_symmetric(w, per_channel=pc)
        back = dequant_symmetric(q, s)
        worst = ((back - w).abs() / s.expand_as(w) if pc else (back - w).abs() / s).max().item()
        print(f"  {label:<12}Scale {s.numel():>3}개, 상대 오차 {rel_err(back, w):.2e}, "
              f"최대 오차 ÷ Scale = {worst:.3f}(≤ 0.5)")
    qa, sa, za = quant_asymmetric(w)
    print(f"  비대칭(Per-Tensor) 상대 오차 {rel_err(dequant_asymmetric(qa, sa, za), w):.2e}")

    print("\n── 4. Clipping과 Rounding(Per-Tensor) ──")
    for label, clip in (("최댓값 기준", None), ("99.99% 지점에서 자름", 0.9999), ("99% 지점에서 자름", 0.99)):
        q, s = quant_symmetric(w, clip=clip)
        print(f"  {label:<18}Scale {s.item():.2e}, 상대 오차 {rel_err(dequant_symmetric(q, s), w):.2e}")
    q, s = quant_symmetric(w, rounding=torch.floor)
    print(f"  반올림 대신 내림       상대 오차 {rel_err(dequant_symmetric(q, s), w):.2e}, "
          f"평균 치우침 {(dequant_symmetric(q, s) - w).mean():+.2e}")

    print("\n── 5. 저장 용량 실측(safetensors) ──")
    q, s = quant_symmetric(w, per_channel=True)
    with tempfile.TemporaryDirectory() as d:
        save_file({"w": w.contiguous()}, f"{d}/fp32.safetensors")
        save_file({"q": q.contiguous(), "scale": s.contiguous()}, f"{d}/int8.safetensors")
        a32, a8 = (Path(d) / "fp32.safetensors").stat().st_size, (Path(d) / "int8.safetensors").stat().st_size
    print(f"  FP32 {a32:,}바이트 → INT8 + Scale {a8:,}바이트 ({a8 / a32:.1%})")


if __name__ == "__main__":
    main()
```

- **1번**에서 대칭 방식은 1.0을 127로, −0.5를 −64로 바꿉니다. −0.5 ÷ 0.007874 = −63.5가 짝수 쪽으로 반올림되어 −64가 되었고, 복원값 −0.5039의 오차 0.0039는 Scale의 절반(0.0039)과 같습니다. 비대칭 방식은 −0.5를 0, 1.0을 255에 맞추고 실수 0을 코드 85에 정확히 놓습니다.
- **2번**에서 실제 가중치의 99%는 0.24 이하인데 최댓값은 1.23으로 다섯 배가 넘습니다. 행별 최댓값도 0.02에서 1.23까지 60배 차이가 납니다. 이상값과 행마다 다른 크기, Per-Tensor 방식이 불리한 조건이 모두 있습니다.
- **3번**에서 Per-Channel의 상대 오차(1.0%)는 Per-Tensor(4.2%)의 약 4분의 1입니다. 두 방식 모두 최대 오차는 정확히 Scale의 절반(0.500)으로, 01절의 보장이 지켜집니다. 비대칭 방식은 가중치가 0 중심 대칭이라 대칭 방식과 거의 차이가 없습니다.
- **4번**에서 99.99% 지점에서 자르면(값 80여 개만 포화) 오차가 4.2%에서 3.5%로 줄지만, 99% 지점에서 자르면(값 8천여 개 포화) 27%로 크게 나빠집니다. 내림을 쓰면 오차가 두 배가 되고, 복원값이 평균적으로 Scale의 절반 정도(−0.0048)만큼 작아지는 치우침이 생깁니다.
- **5번**에서 INT8 코드와 Scale 896개를 함께 저장해도 FP32의 25.1%입니다. 0.5B 모델 전체에 적용하면 약 2GB가 약 500MB가 됩니다.

```python
# 제33장 검증 테스트
#
# 실행: python -m pytest examples/ch33 -q

import sys
from pathlib import Path

import pytest
import torch

HERE = Path(__file__).resolve().parent
sys.path.insert(0, str(HERE))
sys.path.insert(0, str(HERE.parent))

from int8_quant import dequant_asymmetric, dequant_symmetric, quant_asymmetric, quant_symmetric  # noqa: E402


def test_hand_example():
    q, s = quant_symmetric(torch.tensor([-0.5, 0.0, 0.25, 1.0]))
    assert q.tolist() == [-64, 0, 32, 127] and q.dtype == torch.int8
    qa, sa, za = quant_asymmetric(torch.tensor([-0.5, 0.0, 0.25, 1.0]))
    assert qa.tolist() == [0, 85, 127, 255] and int(za) == 85
    assert dequant_asymmetric(qa, sa, za)[1].item() == 0.0      # 0이 정확히 표현된다


@pytest.mark.parametrize("pc", [False, True])
def test_error_within_half_scale(pc):
    torch.manual_seed(0)
    w = torch.randn(64, 48) * torch.linspace(0.01, 1.0, 64)[:, None]
    q, s = quant_symmetric(w, per_channel=pc)
    err = (dequant_symmetric(q, s) - w).abs()
    assert (err <= s.expand_as(w) / 2 + 1e-7).all() if pc else (err <= s / 2 + 1e-7).all()


def test_per_channel_beats_per_tensor_when_rows_differ():
    torch.manual_seed(1)
    w = torch.randn(32, 32) * torch.logspace(-3, 0, 32)[:, None]   # 행마다 크기가 크게 다름
    e_t = (dequant_symmetric(*quant_symmetric(w)) - w).norm()
    e_c = (dequant_symmetric(*quant_symmetric(w, per_channel=True)) - w).norm()
    assert e_c < e_t / 2


def test_floor_is_biased_round_is_not():
    torch.manual_seed(2)
    w = torch.randn(10000) * 0.1
    up = dequant_symmetric(*quant_symmetric(w)) - w
    down = dequant_symmetric(*quant_symmetric(w, rounding=torch.floor)) - w
    assert abs(up.mean()) < 1e-4 and down.mean() < -1e-4


def test_qwen_storage_is_quarter():
    try:
        from common.qwen import load_model
        model = load_model(True)
    except Exception:
        pytest.skip("Qwen 모델이 아직 내려받아지지 않음")
    from int8_quant import NAME
    w = dict(model.named_parameters())[NAME].detach()
    q, s = quant_symmetric(w, per_channel=True)
    assert q.numel() * q.element_size() + s.numel() * 4 == w.numel() + 896 * 4
    assert ((dequant_symmetric(q, s) - w).norm() / w.norm()).item() < 0.02
```

## 핵심 정리

- 양자화는 실수 구간을 정수 구간에 직선으로 대응시키는 일이며, Scale(간격)과 Zero Point(0의 위치) 두 숫자로 정해집니다. 범위 안의 복원 오차는 Scale의 절반 이하입니다.
- 대칭 방식은 Zero Point가 0이라 단순하고 가중치에 알맞습니다. 비대칭 방식은 한쪽으로 치우친 값에 알맞으며, 두 방식 모두 0을 정확히 표현합니다.
- 이상값이 있으면 Per-Tensor의 Scale이 커져 오차가 커집니다. Per-Channel은 적은 추가 비용으로 오차를 크게 줄입니다.
- 조금 자르는(Clipping) 것은 도움이 될 수 있지만 많이 자르면 포화 오차가 커집니다. 반올림은 치우침이 없고 내림은 한쪽으로 치우칩니다.
- INT8 + Per-Channel Scale은 FP32의 약 25%로 저장됩니다.

**다음 장 연결:** 8비트에서 4비트로 가면 용량은 다시 절반이 되지만, 표현할 수 있는 값은 256가지에서 16가지로 줄어듭니다. 그리고 PyTorch에는 4비트 정수 자료형이 없어, 4비트 두 개를 한 바이트에 직접 담아야 합니다. 제34장에서는 INT4와 Bit Packing을 구현합니다.
