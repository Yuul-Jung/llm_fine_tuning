## 장 개요

제52장의 병합 모델은 Hugging Face 형식입니다. 설정은 config.json, 토크나이저는 tokenizer.json, 템플릿은 chat_template.jinja, 가중치는 Safetensors로 여러 파일에 나뉘어 있고, 읽으려면 파이썬과 Transformers가 필요합니다. llama.cpp와 Ollama 같은 로컬 실행 도구는 이것들을 **GGUF 한 파일**에 담아 씁니다. 파이썬 없이 C/C++ 프로그램이 바로 읽을 수 있고, 양자화한 가중치(제55장)도 같은 파일 형식에 담습니다.

이 장은 GGUF의 구조를 확인하고, Qwen2 모델을 GGUF로 바꾸는 변환기를 직접 만들어 Qwen2-Tiny와 0.5B 병합 모델을 변환합니다. 변환한 파일을 다시 읽어 원본과 같은 Token ID에서 Logits와 Greedy 출력이 같은지 확인합니다. 이 과정에서 가중치가 같아도 **생성 설정**을 옮기지 않으면 출력이 달라진다는 것도 발견합니다.

| 구분 | 내용 |
|---|---|
| 핵심 질문 | GGUF 한 파일에는 무엇이 들어가며, 변환한 모델이 원본과 같은지 어떻게 확인하는가 |
| 실습 결과물 | Qwen2용 GGUF 변환기, Tiny·0.5B GGUF(F32·F16), 파일 구조 요약, 토큰화·Logits·Greedy 비교 |
| 실습 파일 | `examples/ch54/`의 `to_gguf.py`, `gguf_convert.py`, `test_ch54.py`, `compare.json` |
| 선수 장 | 제32장(FP16), 제44장(Chat Template), 제51·52장(Safetensors, 병합 모델) |

```text
config.json + tokenizer.json + chat_template + model.safetensors(Hugging Face, 여러 파일)
   ─to_gguf.py(이름 대응, 메타데이터, 어휘, 텐서)─▶ fpga-f32.gguf / fpga-f16.gguf(한 파일)
   ─다시 읽기(Transformers의 GGUF 읽기)─▶ 같은 Token ID → Logits 비교, Greedy 비교
```

## GGUF 구조

GGUF는 llama.cpp 프로젝트가 정한 파일 형식입니다. 제51장의 Safetensors가 텐서만 담는다면, GGUF는 모델을 실행하는 데 필요한 것을 모두 담습니다.

| 부분 | 내용 |
|---|---|
| 머리말 | 형식 표시(GGUF), 판 번호, 텐서 수, 메타데이터 수 |
| 메타데이터 | 열쇠-값 쌍. 구조(층 수, 머리 수, 문맥 길이, RoPE), 어휘와 병합 규칙, 특수 토큰, Chat Template |
| 텐서 정보 | 텐서마다 이름, 차원, 자료형(F32·F16·Q8_0 …), 본문 안의 위치 |
| 본문 | 정렬된 텐서 바이트 |

메타데이터의 열쇠에는 구조 이름이 붙습니다(qwen2.block_count처럼). 텐서 이름도 Hugging Face와 다른 GGUF만의 규칙을 씁니다. 예를 들어 0층 Query 가중치는 blk.0.attn_q.weight이고, Embedding은 token_embd.weight입니다. 실행 도구는 구조 이름과 텐서 이름으로 모델을 조립하므로, 변환기의 핵심은 이 **이름 대응표**입니다.

## llama.cpp 도구

| 도구 | 하는 일 |
|---|---|
| 변환 스크립트(convert_hf_to_gguf) | Hugging Face 폴더를 GGUF로 바꾼다 |
| llama-quantize | GGUF를 Q8_0·Q4_0 등으로 양자화한다(제55장) |
| llama-cli, llama-server | GGUF를 불러 대화하거나 API로 제공한다 |
| llama-perplexity | GGUF 모델의 PPL을 잰다 |

이 교재 검증 환경에서는 llama.cpp를 설치하지 않았습니다. 대신 llama.cpp 프로젝트가 배포하는 파이썬 라이브러리(gguf)의 쓰기 기능과 Qwen2 형식 정의로 변환기를 직접 만들고, Transformers의 GGUF 읽기 기능으로 결과를 검증합니다. 공식 변환 스크립트와 같은 이름·열쇠 규칙을 따르지만, **llama.cpp가 이 파일을 실제로 실행하는지는 확인하지 못했습니다(미검증).** 학습자 환경에서 llama.cpp가 있다면 공식 변환 스크립트로 같은 파일을 만들어 비교해 볼 수 있습니다.

## 원본 자료형 유지 변환

변환의 첫 기준 파일은 **원본과 같은 정밀도**로 만듭니다. Qwen2.5는 BF16으로 배포되지만, 이 교재의 병합 모델은 FP32로 병합했으므로(제52장) 기준 GGUF는 F32입니다. 기준 파일이 원본과 같아야, 이후 양자화한 파일의 차이를 "양자화 때문"이라고 말할 수 있습니다.

| 파일 | 행렬 | 1차원 텐서(편향, RMSNorm) |
|---|---|---|
| F32 | FP32 | FP32 |
| F16 | FP16 | FP32(작고 정밀도에 민감해 그대로 둔다) |

F16은 크기가 절반이지만 FP16의 유효 자리(제32장) 때문에 값이 조금 달라집니다. Qwen2.5의 Embedding과 LM Head는 하나의 텐서이므로(제53장) GGUF에도 한 번만 들어가고, 실행 도구가 출력층에 같은 텐서를 씁니다.

## Logits 비교 검증

변환 검증은 세 단계로 합니다.

| 단계 | 같아야 하는 것 | 허용 기준 |
|---|---|---|
| 토큰화 | 같은 문장의 Token ID | 완전히 같음 |
| Logits | 같은 Token ID를 넣었을 때 출력 | F32는 0, F16은 작은 차이 |
| Greedy | 같은 생성 설정으로 만든 토큰열 | 완전히 같음 |

토큰화가 다르면 그 뒤는 비교할 수 없으므로 먼저 확인합니다. Logits는 같은 Token ID를 넣어 비교하고, 마지막으로 실제 사용처럼 여러 토큰을 생성해 봅니다. 생성은 모델 가중치뿐 아니라 **생성 설정**(반복 억제, 종료 토큰 등)에도 달려 있습니다. Hugging Face 폴더의 generation_config.json에 들어 있던 설정은 GGUF에 들어가지 않으므로, 실행 도구에서 따로 맞춰야 합니다.

## 핵심 실습

파일명: `examples/ch54/to_gguf.py`

```python
# 제54장: Hugging Face(Safetensors) Qwen2 모델을 GGUF 한 파일로 바꾸는 변환기
#
# GGUF 쓰기·읽기는 llama.cpp 프로젝트의 파이썬 라이브러리(gguf)를 쓴다.
# 텐서 이름과 메타데이터 열쇠는 그 라이브러리가 정의한 Qwen2 형식을 따른다.

import json
from pathlib import Path

import numpy as np
import torch
from gguf import GGMLQuantizationType, GGUFWriter, LlamaFileType, TokenType, quants
from safetensors.torch import load_file

NAME_MAP = {                                                 # Hugging Face 이름 → GGUF 이름
    "model.embed_tokens.weight": "token_embd.weight",
    "model.norm.weight": "output_norm.weight",
    "lm_head.weight": "output.weight",
}
LAYER_MAP = {
    "input_layernorm.weight": "attn_norm.weight",
    "self_attn.q_proj.weight": "attn_q.weight", "self_attn.q_proj.bias": "attn_q.bias",
    "self_attn.k_proj.weight": "attn_k.weight", "self_attn.k_proj.bias": "attn_k.bias",
    "self_attn.v_proj.weight": "attn_v.weight", "self_attn.v_proj.bias": "attn_v.bias",
    "self_attn.o_proj.weight": "attn_output.weight",
    "post_attention_layernorm.weight": "ffn_norm.weight",
    "mlp.gate_proj.weight": "ffn_gate.weight", "mlp.up_proj.weight": "ffn_up.weight",
    "mlp.down_proj.weight": "ffn_down.weight",
}
FILE_TYPES = {"F32": (LlamaFileType.ALL_F32, np.float32), "F16": (LlamaFileType.MOSTLY_F16, np.float16),
              "Q8_0": (LlamaFileType.MOSTLY_Q8_0, None), "Q4_0": (LlamaFileType.MOSTLY_Q4_0, None)}   # 제55장


def gguf_name(hf: str) -> str:
    if hf in NAME_MAP:
        return NAME_MAP[hf]
    _, _, layer, rest = hf.split(".", 3)                     # model.layers.{i}.{나머지}
    return f"blk.{layer}.{LAYER_MAP[rest]}"


def vocab(model_dir: Path, vocab_size: int) -> tuple:
    """토큰 문자열·종류·병합 규칙. 모델의 어휘 크기까지 빈 칸은 PAD로 채운다(llama.cpp 변환기와 같은 방식)."""
    tj = json.loads((model_dir / "tokenizer.json").read_text(encoding="utf-8"))
    tokens = {i: t for t, i in tj["model"]["vocab"].items()}
    types = {i: TokenType.NORMAL for i in tokens}
    for a in tj["added_tokens"]:
        tokens[a["id"]] = a["content"]
        types[a["id"]] = TokenType.CONTROL if a["special"] else TokenType.USER_DEFINED
    names = [tokens.get(i, f"[PAD{i}]") for i in range(vocab_size)]
    kinds = [int(types.get(i, TokenType.UNUSED)) for i in range(vocab_size)]
    merges = [m if isinstance(m, str) else " ".join(m) for m in tj["model"]["merges"]]
    return names, kinds, merges


def convert(model_dir: Path, out: Path, ftype: str = "F32") -> dict:
    cfg = json.loads((model_dir / "config.json").read_text())
    tok_cfg = json.loads((model_dir / "tokenizer_config.json").read_text(encoding="utf-8"))
    file_type, np_dtype = FILE_TYPES[ftype]
    w = GGUFWriter(str(out), "qwen2")
    w.add_name(model_dir.name)
    w.add_context_length(cfg["max_position_embeddings"])
    w.add_embedding_length(cfg["hidden_size"])
    w.add_block_count(cfg["num_hidden_layers"])
    w.add_feed_forward_length(cfg["intermediate_size"])
    w.add_head_count(cfg["num_attention_heads"])
    w.add_head_count_kv(cfg["num_key_value_heads"])
    w.add_rope_freq_base(float(cfg.get("rope_theta") or cfg.get("rope_parameters", {}).get("rope_theta", 1e6)))
    w.add_layer_norm_rms_eps(cfg["rms_norm_eps"])
    w.add_file_type(int(file_type))
    names, kinds, merges = vocab(model_dir, cfg["vocab_size"])
    w.add_tokenizer_model("gpt2")                            # 바이트 단위 BPE
    w.add_tokenizer_pre("qwen2")
    w.add_token_list(names)
    w.add_token_types(kinds)
    w.add_token_merges(merges)
    w.add_eos_token_id(cfg["eos_token_id"] if isinstance(cfg["eos_token_id"], int) else cfg["eos_token_id"][0])
    w.add_bos_token_id(cfg.get("bos_token_id") or 151643)  # 설정에 없으면 endoftext(Qwen2.5와 같음)
    w.add_pad_token_id(151643)                               # endoftext(제45장)
    w.add_add_bos_token(False)
    template = model_dir / "chat_template.jinja"
    w.add_chat_template(template.read_text() if template.exists() else tok_cfg["chat_template"])

    state = {}
    for f in sorted(model_dir.glob("*.safetensors")):
        state.update(load_file(f))
    counts = {"F32": 0, ftype: 0}
    for hf, t in state.items():
        a = t.to(torch.float32).numpy()
        if a.ndim == 2 and ftype.startswith("Q"):            # 제55장: 32개 블록 양자화(gguf 라이브러리 구현)
            q = GGMLQuantizationType[ftype]
            w.add_tensor(gguf_name(hf), quants.quantize(a, q), raw_dtype=q)
            counts[ftype] += 1
            continue
        if a.ndim == 2 and ftype != "F32":                   # 행렬만 낮은 정밀도, 1차원(편향·정규화)은 F32
            a = a.astype(np_dtype)
            counts[ftype] += 1
        else:
            counts["F32"] += 1
        w.add_tensor(gguf_name(hf), a)
    w.write_header_to_file()
    w.write_kv_data_to_file()
    w.write_tensors_to_file()
    w.close()
    return {"tensors": len(state), "tied": "lm_head.weight" not in state, "types": counts}


def read_summary(path: Path) -> dict:
    from gguf import GGUFReader
    r = GGUFReader(str(path))
    kv = {}
    for k in ("general.architecture", "qwen2.block_count", "qwen2.attention.head_count_kv",
              "tokenizer.ggml.model", "tokenizer.ggml.eos_token_id"):
        field = r.fields[k]
        v = field.parts[field.data[0]]
        kv[k] = bytes(v).decode() if v.dtype == np.uint8 else v.tolist()[0]
    t0 = r.tensors[0]
    return {"kv": kv, "n_tensors": len(r.tensors), "n_fields": len(r.fields),
            "first": (t0.name, [int(x) for x in t0.shape], GGMLQuantizationType(t0.tensor_type).name),
            "has_template": "tokenizer.chat_template" in r.fields}
```

파일명: `examples/ch54/gguf_convert.py`

```python
# 제54장 핵심 실습: Qwen2-Tiny와 0.5B 병합 모델을 GGUF로 바꾸고, 다시 읽어 Logits·Greedy 출력을 비교한다
#
# 실행: python examples/ch54/gguf_convert.py   (CPU 약 3분, 메모리 8GB에서 실행)
#
# 만드는 파일: models/gguf/(tiny-f32, fpga-f32, fpga-f16 .gguf), examples/ch54/compare.json
# 변환한 GGUF를 llama.cpp로 실행해 보는 일은 교재 검증 환경에서 하지 않았다(미검증).
# 여기서는 Transformers의 GGUF 읽기 기능으로 파일을 다시 불러와 원본과 비교한다.

import gc
import json
import sys
from pathlib import Path

HERE = Path(__file__).resolve().parent
ROOT = HERE.parents[1]
for p in (HERE, HERE.parent, HERE.parent / "ch41", HERE.parent / "ch44"):
    sys.path.insert(0, str(p))

import torch  # noqa: E402
from transformers import AutoModelForCausalLM, AutoTokenizer  # noqa: E402
from transformers.utils import logging  # noqa: E402

from chat_template import SYSTEM, render  # noqa: E402            (제44장)
from check_dataset import load  # noqa: E402                     (제41장)
from common.device import select_device  # noqa: E402
from to_gguf import convert, read_summary  # noqa: E402

logging.disable_progress_bar()
logging.set_verbosity_error()
OUT_DIR = ROOT / "models" / "gguf"
JOBS = [("tiny-f32", ROOT / "models" / "qwen2-tiny-pretrained", "F32"),
        ("fpga-f32", ROOT / "models" / "fpga_merged_v1", "F32"),
        ("fpga-f16", ROOT / "models" / "fpga_merged_v1", "F16")]
MiB = 2 ** 20


def gen_config(src: Path):
    """원본 폴더의 생성 설정(반복 억제 1.1 등)을 그대로 쓰되 Greedy로. GGUF에는 이 파일이 들어가지 않는다."""
    from transformers import GenerationConfig
    try:
        g = GenerationConfig.from_pretrained(src)
    except OSError:
        g = GenerationConfig()
    g.do_sample, g.max_new_tokens, g.pad_token_id = False, 24, 151643
    g.temperature = g.top_p = g.top_k = None
    return g


def greedy(model, ids, gen):
    with torch.no_grad():
        return model.generate(ids, generation_config=gen)[0, ids.shape[1]:]


def main() -> None:
    device, _ = select_device()
    OUT_DIR.mkdir(parents=True, exist_ok=True)
    print("── 1. 변환 ──")
    for name, src, ftype in JOBS:
        info = convert(src, OUT_DIR / f"{name}.gguf", ftype)
        src_mib = sum(f.stat().st_size for f in src.glob("*.safetensors")) / MiB
        print(f"  {name}: 텐서 {info['tensors']}개(LM Head 묶임 {info['tied']}), 자료형 {info['types']}, "
              f"Safetensors {src_mib:.0f}MiB → GGUF {(OUT_DIR / f'{name}.gguf').stat().st_size / MiB:.0f}MiB")

    print("\n── 2. GGUF 구조(fpga-f16) ──")
    s = read_summary(OUT_DIR / "fpga-f16.gguf")
    print(f"  메타데이터 {s['n_fields']}개, 텐서 {s['n_tensors']}개, Chat Template 포함 {s['has_template']}")
    for k, v in s["kv"].items():
        print(f"    {k} = {v}")
    print(f"  첫 텐서 {s['first'][0]}: 모양 {s['first'][1]}(GGUF는 차원 순서를 거꾸로 적는다), {s['first'][2]}")

    print("\n── 3. 같은 Token ID로 Logits 비교(원본 Safetensors ↔ GGUF를 다시 읽은 모델) ──")
    rows = load()
    results = {}
    for name, src, _ in JOBS:
        tok = AutoTokenizer.from_pretrained(src)
        tok_g = AutoTokenizer.from_pretrained(OUT_DIR, gguf_file=f"{name}.gguf")
        texts = [render(tok, [{"role": "system", "content": SYSTEM},
                              {"role": "user", "content": r["instruction"]}], gen=True) for r in rows[:10]]
        same_ids = all(tok(t).input_ids == tok_g(t).input_ids for t in texts)
        ids = torch.tensor([tok(texts[2]).input_ids], device=device)
        a = AutoModelForCausalLM.from_pretrained(src, dtype=torch.float32).to(device).eval()
        with torch.no_grad():
            la = a(ids).logits.float().cpu()
        gen = gen_config(src)
        ga = greedy(a, ids, gen)
        del a
        gc.collect()
        b = AutoModelForCausalLM.from_pretrained(OUT_DIR, gguf_file=f"{name}.gguf", dtype=torch.float32).to(device).eval()
        with torch.no_grad():
            lb = b(ids).logits.float().cpu()
        gb = greedy(b, ids, gen)
        plain = gen_config(ROOT / "없는 폴더")                               # 생성 설정 파일이 없을 때(반복 억제 없음)
        gb_default = greedy(b, ids, plain) if name == "fpga-f32" else gb
        del b
        gc.collect()
        d = (la - lb).abs().max().item()
        same_greedy = torch.equal(ga, gb)
        results[name] = {"token_ids_same": same_ids, "logits_max_diff": d, "greedy_same": same_greedy,
                         "repetition_penalty": gen.repetition_penalty}
        print(f"  {name}: 토큰화 10문장 같음 {same_ids}, Logits 최대 차이 {d:.2e}, Greedy 24토큰 같음 {same_greedy}")
        if name == "fpga-f32":
            results[name]["greedy_same_without_config"] = torch.equal(ga, gb_default)
            print(f"    생성 설정(반복 억제 {gen.repetition_penalty})을 옮기지 않으면 Greedy 같음 "
                  f"{torch.equal(ga, gb_default)}")
    (HERE / "compare.json").write_text(json.dumps(results, indent=1) + "\n", encoding="utf-8")


if __name__ == "__main__":
    main()
```

```text
  fpga-f16: 텐서 290개(LM Head 묶임 True), 자료형 {'F32': 121, 'F16': 169}, Safetensors 1885MiB → GGUF 948MiB

── 2. GGUF 구조(fpga-f16) ──
  메타데이터 24개, 텐서 290개, Chat Template 포함 True
    general.architecture = qwen2
    qwen2.block_count = 24
    qwen2.attention.head_count_kv = 2
    tokenizer.ggml.model = gpt2
    tokenizer.ggml.eos_token_id = 151645
  첫 텐서 token_embd.weight: 모양 [896, 151936](GGUF는 차원 순서를 거꾸로 적는다), F16

── 3. 같은 Token ID로 Logits 비교(원본 Safetensors ↔ GGUF를 다시 읽은 모델) ──
  tiny-f32: 토큰화 10문장 같음 True, Logits 최대 차이 0.00e+00, Greedy 24토큰 같음 True
  fpga-f32: 토큰화 10문장 같음 True, Logits 최대 차이 0.00e+00, Greedy 24토큰 같음 True
    생성 설정(반복 억제 1.1)을 옮기지 않으면 Greedy 같음 False
  fpga-f16: 토큰화 10문장 같음 True, Logits 최대 차이 3.89e-02, Greedy 24토큰 같음 True
```

**결과 읽기**

- **1번**에서 Tiny와 0.5B 모두 텐서 이름이 빠짐없이 대응되었습니다. LM Head는 Embedding과 묶여 있어 따로 저장되지 않습니다. F32 GGUF는 Safetensors보다 약 5MiB 큰데, 늘어난 몫은 어휘·병합 규칙·템플릿 같은 메타데이터입니다. F16은 행렬 169개만 FP16으로 바꿔 948MiB로 절반이 되었습니다.
- **2번**에서 파일 하나에 메타데이터 24개(구조, 어휘, 특수 토큰, Chat Template)와 텐서 290개가 들어 있습니다. Embedding의 모양이 [896, 151936]으로 거꾸로 적힌 것은 GGUF가 가장 빨리 변하는 차원을 먼저 적기 때문이며, 실제 배치는 같습니다.
- **3번**에서 F32 파일은 Tiny와 0.5B 모두 Logits 차이가 0이고 Greedy 24토큰도 같습니다. 변환이 가중치를 정확히 옮겼습니다. F16은 Logits가 최대 0.039 다르지만 Greedy 출력은 같습니다.
- 생성 설정을 옮기지 않으면 F32에서도 Greedy가 달라집니다. 원본 폴더의 생성 설정에는 반복 억제 1.1이 들어 있어, Greedy라도 이미 나온 토큰의 점수를 낮춥니다. 제47~50장의 Greedy 평가에도 이 설정이 함께 적용되었습니다. 제56장에서 Ollama로 옮길 때 이 값을 Modelfile에 그대로 적어야 학습 평가와 같은 답이 나옵니다.
- GGUF의 어휘는 151,936개로, 원본 토크나이저(151,665개)보다 많습니다. 모델의 어휘 크기에 맞춰 빈 칸을 PAD 토큰으로 채웠기 때문이며, 실제로 쓰는 토큰의 번호는 같습니다(토큰화 일치).

```python
need_tiny = pytest.mark.skipif(not TINY.exists(), reason="제25장의 Qwen2-Tiny 필요")


@need_tiny
def test_every_tensor_has_unique_gguf_name():
    with safe_open(TINY / "model.safetensors", "pt") as f:
        names = [gguf_name(k) for k in f.keys()]
    assert len(names) == len(set(names)) and "token_embd.weight" in names and "blk.3.ffn_down.weight" in names


@need_tiny
def test_vocab_padded_to_model_size():
    names, kinds, merges = vocab(TINY, 151936)
    assert len(names) == len(kinds) == 151936 and merges
    assert names[151645] == "<|im_end|>" and kinds[151645] == TokenType.CONTROL
    assert names[-1].startswith("[PAD") and kinds[-1] == TokenType.UNUSED


@need_tiny
def test_convert_and_read_back(tmp_path):
    info = convert(TINY, tmp_path / "t.gguf")
    s = read_summary(tmp_path / "t.gguf")
    assert info["tied"] and s["kv"]["general.architecture"] == "qwen2" and s["kv"]["qwen2.block_count"] == 4
    assert s["n_tensors"] == info["tensors"] and s["has_template"]


def test_recorded_comparison():
    r = json.loads((HERE / "compare.json").read_text())
    assert r["tiny-f32"]["logits_max_diff"] == 0 and r["fpga-f32"]["logits_max_diff"] == 0

    assert r["fpga-f16"]["logits_max_diff"] < 0.1
    assert r["fpga-f32"]["greedy_same_without_config"] is False                # 생성 설정도 옮겨야 같다
```

## 핵심 정리

- GGUF는 구조·어휘·특수 토큰·Chat Template·텐서를 한 파일에 담는 로컬 실행용 형식입니다.
- 변환의 핵심은 텐서 이름 대응과 메타데이터입니다. 기준 파일은 원본과 같은 정밀도(이 교재는 F32)로 만듭니다.
- 검증은 토큰화 → 같은 Token ID의 Logits → 같은 생성 설정의 Greedy 순서로 합니다. F32는 Logits 차이 0, F16은 작은 차이였습니다.
- 생성 설정(반복 억제 등)은 GGUF에 들어가지 않습니다. 실행 도구에서 따로 맞춰야 같은 답이 나옵니다.
