## 3. 발견 사항과 조치

| 번호 | 위치 | 문제 | 조치 |

| 1 | 제18장 실습 2 풀이, 핵심 정리 | "모든 계층 상대 오차 1e-6 이하"라고 썼으나 실제 0번 계층은 2.0e-6 | "2e-6 이하"로 정정 |
| 2 | 제18장 실습 2 풀이 | 절대오차가 큰 이유를 "값이 수백 단위"라고 설명했으나 0번 계층 출력은 최대 3.9로 작음. 근거와 설명 불일치 | FP32 계산 순서 차이로 설명하고, 상대 오차를 쓰는 근거를 실측값(12번 계층 입력 최댓값 약 1,559)으로 교체 |
| 3 | 제20장 03절 | "제14·15장에서는 `output_hidden_states`로만 볼 수 있었다"고 썼으나 Hook은 제12장에서 도입, 제15·17장에서도 사용 | 제12장 도입을 밝히고 이 장의 `capture()`를 범용 도구로 정리하는 서술로 수정 |
| 4 | 제11장 01절 | 미래 토큰을 가리는 이유를 "생성할 때"로 설명. 실제 이유는 모든 위치를 동시에 학습할 때 정답이 보이는 문제(제14장 설명과 불일치) | "다음 토큰을 맞히도록 학습하는 모델은 정답인 미래 토큰을 미리 보면 안 되므로"로 정정 |

| 6 | 제19·20장 | 실행 결과 표기가 "교재 실행 결과:"로 다른 장("실제 실행 결과(교재 검증 환경):")과 달라 재현성 검사 도구가 대조하지 못함 | 표기 통일 |

## 5. 남은 확인 사항

- 제12장에 2×2 수준의 Q·K·V Projection 손계산 예제를 추가하면 첫 번째 완료 기준을 완전히 충족(다음 개정 후보)
- Qwen2-Tiny → GGUF 변환(llama.cpp): 제6부 작성 시 확인 필요. 작업 환경에서 llama.cpp 내려받기·실행이 차단되어 있어, 사용자 환경 확인 또는 실행 허가가 필요
- GT 1030 경로의 실제 실행 결과: 제1부와 같이 학습자 장비에서 측정 후 반영
