**LLM Fine-tuning · Hugging Face · LoRA · QLoRA · SFTTrainer · On-device AI**

# 1. 교육과정 개요

- 전체 구성: **6부 60장** (제59장은 선택 장)
- 개발환경: Ubuntu, VS Code, Python, PyTorch
- 표준 실습 하드웨어: NVIDIA GeForce GT 1030 2GB(Pascal, Compute Capability 6.1) 또는 CPU
- 기본 실습 모델: Qwen2.5-0.5B-Instruct (Apache 2.0, 모델 Revision 고정)
- 원리 학습 모델: Qwen2 구조 호환 초소형 Transformer(Qwen2-Tiny, 직접 구현 후 Hugging Face 형식으로 저장)
- 핵심 기술: Transformer, PEFT, LoRA, QLoRA, Hugging Face, SFTTrainer
- 배포환경: Ollama, llama.cpp, PC, Raspberry Pi
- 확장 분야(선택): 온디바이스 AI 하드웨어, FPGA, NPU 연산 가속기

라이브러리 사용법에만 의존하지 않고 수학적 원리, 내부 연산 구조, 가중치 학습, 모델 구현, 성능 검증 및 배포를 단계적으로 학습한다.

## 1.1 기본 모델 고정 사유

- 교재의 구조도, 행렬 차원, 소스코드는 Qwen2.5-0.5B-Instruct의 실제 구성에 맞춘다.
- 후속 세대 모델(Qwen3 계열 등)은 QKV Bias 제거, QK-Norm 추가, 추론 모드 템플릿 등 구조가 달라 제2부 분석이 그대로 적용되지 않는다.
- 모델 교체 시 제2부 구조 분석, 제44장 Chat Template, 제53장 가중치 추출을 함께 개정한다.

## 1.2 표준 실습 하드웨어(GT 1030 2GB) 운용 기준

### 하드웨어 특성과 교재 적용 규칙

| 특성 | GT 1030 값 | 교재 적용 규칙 |
|---|---|---|
| Compute Capability | 6.1 (Pascal) | 지원 라이브러리 버전 고정 |
| FP32 연산 | 약 1.1 TFLOPS | 모든 GPU 연산의 기본 자료형 |
| FP16 연산 | FP32의 1/64 | FP16은 저장용으로만 사용하고 연산·학습에는 사용하지 않음 |
| BF16 | 미지원 | 사용하지 않음 |
| VRAM | 2GB | 메모리 예산표(아래) 준수 |
| 8비트 행렬곱(LLM.int8) | 미지원(CC 7.5 이상 필요) | 개념만 학습 |
| NF4 4비트 양자화·8비트 Optimizer | 지원(CC 6.0 이상) | QLoRA 실습에 사용 |

- GT 1030은 GDDR5와 DDR4 두 가지 메모리 사양이 있으며 DDR4 사양은 메모리 대역폭이 크게 낮다. 제02장 환경 보고서에 메모리 사양을 기록한다.
- 화면 출력은 내장 그래픽이나 원격 접속(SSH)으로 처리하여 VRAM 2GB를 학습 전용으로 확보한다.
- GT 1030의 FP32 연산 성능은 최신 다중 코어 CPU와 큰 차이가 없다. GPU 경로의 목적은 속도 향상보다 CUDA·bitsandbytes·QLoRA 실행 경험과 VRAM 제약 관리에 둔다.

### 소프트웨어 버전 고정 원칙

- PyTorch는 Pascal을 지원하는 CUDA 12.6(cu126) 빌드를 사용한다. PyTorch 2.15부터 CUDA 12.6 빌드가 배포되지 않으므로 2.14 계열을 마지막 지원 버전으로 고정한다.
- Ollama는 Compute Capability 5.0~6.2 GPU에 NVIDIA 드라이버 570 이상을 요구한다. 드라이버는 Pascal을 지원하는 570 이상 버전으로 고정한다.
- bitsandbytes, Transformers, PEFT, TRL은 고정한 PyTorch 버전과 호환되는 버전을 실제 설치·실행으로 확인한 뒤 `requirements/gt1030.txt`에 고정한다.

### VRAM 2GB 메모리 예산(기본값)

| 실습 | 모델 | 설정 | 예상 사용량 |
|---|---|---|---|
| Full Fine-tuning·LoRA·SFT | Qwen2-Tiny(약 4,190만 파라미터) | FP32, AdamW, 시퀀스 128, Batch 2 | 약 1.5GB 이하 |
| QLoRA | Qwen2.5-0.5B-Instruct | NF4 + FP32 연산, 시퀀스 256, Batch 1, Gradient Checkpointing, Gradient Accumulation | 약 1.5GB 내외 |
| 추론(Ollama) | Qwen2.5-0.5B Q4_K_M·Q8_0, Qwen2.5-1.5B Q4_K_M | 문맥 2,048 이하 | 2GB 이내 |
| 실행 불가 | Qwen2.5-0.5B의 LoRA(비양자화)·Full Fine-tuning | FP32 가중치만 약 2GB | CPU 경로로 대체 |

- 예상 사용량은 CUDA 컨텍스트, Embedding 가중치, Logits(시퀀스 × 어휘 151,936 × 4바이트)를 포함한 기본 추정값이다. 실제 값은 제37·39장에서 측정하여 갱신한다.
- 어휘 크기 151,936의 Logits는 시퀀스 길이에 비례하여 메모리를 크게 차지한다. VRAM이 부족하면 Batch보다 시퀀스 길이를 먼저 줄인다.

### Qwen2-Tiny 기본 구성

| 항목 | 값 | 비고 |
|---|---|---|
| hidden_size | 256 | |
| num_hidden_layers | 4 | |
| num_attention_heads | 4 | head_dim 64 (Qwen2.5-0.5B와 동일) |
| num_key_value_heads | 1 | GQA 4:1 |
| intermediate_size | 768 | SwiGLU |
| vocab_size | 151,936 | Qwen2.5 토크나이저 재사용 |
| QKV Bias | 사용 | Qwen2와 동일 |
| tie_word_embeddings | true | Qwen2.5-0.5B와 동일 |
| 전체 파라미터 | 약 4,190만 | Embedding이 약 93% 차지 |

- 계층 이름과 가중치 Shape를 Hugging Face `Qwen2ForCausalLM`과 동일하게 구현한다. 직접 학습한 체크포인트를 `Qwen2ForCausalLM`으로 불러와 PEFT·TRL·GGUF·Ollama 전 과정을 같은 모델로 진행한다.
- Qwen2.5 토크나이저를 재사용하므로 llama.cpp의 토크나이저 인식과 Chat Template을 그대로 사용할 수 있다. 제09장 BPE 토크나이저는 원리 학습용으로만 사용한다.
- 초소형 차원 모델의 llama.cpp 변환과 Ollama 실행 가능 여부는 교재 집필 전에 실제 실행으로 확인한다.

## 제40장. Full Fine-tuning·LoRA·QLoRA 비교

- 실습 경로별 비교 기준 정의
- 비교 A(CPU·GT 1030 공통): Qwen2-Tiny의 Full Fine-tuning, LoRA, QLoRA(GT 1030은 bitsandbytes, CPU는 직접 구현 양자화 + LoRA 원리 모사로 명명) 비교
- 비교 B(GT 1030): Qwen2.5-0.5B-Instruct의 QLoRA(GT 1030)와 LoRA(CPU, FP32)의 메모리·품질 비교, 장치가 다르므로 학습 시간은 비교하지 않음

- 학습 토큰 수·유효 배치·학습률 등 비교 조건을 기록하고 차이가 있는 경우 해석에 반영

- 학습 가능 파라미터 비교
- 가중치 저장 용량 비교
- 최대 메모리 사용량 비교
- 학습 시간 및 처리량
- 학습 손실과 검증 손실
- 학습 방식별 장단점
- 하드웨어 제약에 따른 최적 방식 선정

### 제4부 완료 기준

- INT8·INT4 양자화 및 역양자화를 직접 구현하고 저장 용량을 실측한다.
- 동일 가중치에 대한 INT4와 NF4의 복원 오차(MSE, 최대 절대오차)를 비교한 표를 제출한다.
- 가중치 저장 용량과 실제 학습 메모리를 구분한 메모리 분석표를 제출한다.
- 실습 경로의 비교 기준에 따라 학습 방식별 비교표를 작성한다.
- QLoRA 학습은 GT 1030 등 지원 GPU에서 수행하고 최대 VRAM 사용량을 1.2절 예산표와 비교한다. CPU 단독 경로는 원리 모사 결과를 제출하고 실제 QLoRA 실행 여부는 환경 보고서에 '미검증' 또는 '실행 불가'와 사유를 기록한다.

| SFT | SFTTrainer + Qwen2-Tiny | SFTTrainer + Qwen2-Tiny, QLoRA SFT + Qwen2.5-0.5B |
| 병합·GGUF 변환 | CPU | CPU |
| 배포 | Ollama CPU 추론 + Python API | Ollama GPU 추론 + Python API |

- 두 경로 모두 직접 학습한 Qwen2-Tiny를 GGUF·Ollama까지 배포하므로 학습부터 배포까지 같은 모델로 완결된다.
- GT 1030의 VRAM을 초과하는 작업(대형 모델 병합, GGUF 변환, 비양자화 0.5B LoRA)은 CPU에서 수행한다. 시스템 RAM은 16GB 이상을 권장한다.
- PyTorch·CUDA·드라이버·bitsandbytes 버전 조합은 1.2절 원칙에 따라 `requirements/gt1030.txt`와 `requirements/cpu.txt`에 고정한다.
- CPU 단독 경로의 원리 모사 결과는 실제 GPU 결과로 간주하지 않는다.
- 제58장 Raspberry Pi 실측은 장치 보유 시 수행하고 미보유 시 PC 측정과 장치 요구 자원 분석으로 대체한다.
- 기본 완료는 Qwen2-Tiny의 학습·저장·병합·GGUF 변환·Ollama 배포·API 구현으로 판정한다. Qwen2.5-0.5B QLoRA(GT 1030) 및 제59장 하드웨어 검증은 별도 기록한다.
- 실제 패키지 버전, 모델 Revision, 장치별 실행 결과는 실습환경 구축 후 검증하여 확정한다.

# 6. 학습안내서 제작 원칙

- 부·장·절의 계층 관계를 명확히 구성한다.

- 원리 학습과 실제 모델 적용을 분리한다.
- 불필요한 실습 중복을 방지하며, 여러 장에 걸친 주제는 장별 역할을 아래와 같이 구분한다.

## 6.3 구조화

- 코드의 함수명, 변수명, 모듈명과 구조도를 일치시킨다.
- 데이터의 입력·처리·출력 관계를 명확히 표현한다.
- 행렬의 차원 및 자료형을 표시한다.
- 행렬 표기는 제05장(`y = xWᵀ + b`, 가중치 `[out, in]`)과 제28장(LoRA A `[r, in]`, B `[out, r]`) 규약을 교재 전체에 동일하게 적용한다.
- 학습 모델과 배포 모델의 관계를 구조적으로 표현한다.

## 6.4 시각화

- 행렬곱 및 내적 연산을 시각화한다.
- Tensor의 차원 변화를 그림으로 표현한다.
- Transformer 내부 블록을 단계별로 분리한다.
- Gradient와 가중치 학습 경로를 표시한다.
- LoRA 학습 대상과 동결 영역을 구분한다.
- 양자화 전후 가중치 분포와 오차를 시각화한다.
- SVG 기반 구조도와 실제 실행 결과를 활용한다.

## 6.5 완료 기준 작성 원칙

- 완료 기준은 제출 가능한 결과물(표, 그래프, 출력 로그, 파일)이나 수치 판정으로 작성한다.
- '이해한다', '설명할 수 있다'처럼 판정할 수 없는 표현은 사용하지 않는다.

## 7.1 허용 오차 기준

아래 값은 기본값이며, 장별 특성에 따라 근거를 밝히고 조정할 수 있다.

| 비교 대상 | 판정 지표 | 기본 허용 기준 |
|---|---|---|
| 직접 구현과 PyTorch 연산(FP32 소규모) | 절대·상대오차 | atol=1e-6, rtol=1e-5 (초기 교육용 기준) |
| 수치 미분과 자동 미분 | FP64 수치 미분 및 gradcheck | gradcheck 통과, 0 근처는 절대오차 포함 |
| 동결 가중치 학습 전후 | 동일 자료형 원소·필요 시 비트 비교 | 완전 일치 |
| 저장·재로딩 가중치 | 동일 자료형 원소 비교 | 완전 일치(자료형 변환 없는 경우) |
| 저장·재로딩 전후 출력 | Logits 절대·상대오차 | 동일 환경·평가 모드에서 장별 기준 적용 |
| LoRA 병합 전후(FP32) | Logits 절대·상대오차 | 동일 비양자화 Base 비교, 초기 atol=1e-4, rtol=1e-5 |
| LoRA 병합 전후(BF16·FP16) | 자료형별 절대·상대오차 및 품질 | 장별 사전 기준 적용, Greedy 토큰 차이는 별도 기록 |
| Safetensors → GGUF(원본 자료형 유지: BF16 또는 F32) | 동일 Token ID 입력의 Logits 절대·상대오차, Greedy 출력 | 장별 사전 기준, Greedy 출력 토큰 일치 |
| GGUF 양자화(Q8_0), llama.cpp 내부 비교 | 기준 GGUF 대비 Perplexity 변화율 | 2% 이하 |
| GGUF 양자화(4비트 계열), llama.cpp 내부 비교 | Perplexity 변화율, 도메인 정답률 | `configs/eval_criteria.yaml` 사전 기준 |
| VRAM 예산(GT 1030) | 최대 할당 메모리(`torch.cuda.max_memory_allocated`)와 `nvidia-smi` 사용량 | 1.2절 예산 이내 |
| RTL 시뮬레이션과 Python 정수 기준값 | 동일 비트 폭·부호·반올림 규칙의 비트 비교 | 완전 일치 |

- 부동소수점 비교는 `torch.testing.assert_close`의 `|actual - expected| ≤ atol + rtol × |expected|` 조건을 사용한다. 행렬 크기·값의 범위·자료형·연산 장치에 따라 기준을 사전에 설정하고 근거를 기록한다.
- 평가 모드(`model.eval()`), 입력 토큰, 자료형, 장치, 커널·TF32 설정 및 생성 조건을 기록한다. NaN·Inf는 별도로 검출한다.
- GGUF의 수치 기준은 교육용 초기 목표이며 보편적인 보장값이 아니다. 동일 토큰화·문맥·평가 토큰 정책을 확인할 수 없는 경우 PPL을 직접 비교하지 않는다.
- 양자화 표현 변경, 순수 가중치 병합, 배포 엔진 변경에 따른 차이를 구분한다.
- '장별 사전 기준'과 도메인 품질·일반 능력 허용 기준은 실험 전에 `configs/eval_criteria.yaml`에 기록하고, 완료 판정은 이 파일의 값으로만 수행한다.
