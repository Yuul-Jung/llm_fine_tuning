# 제1부. LLM 기초 및 수치 연산

> 문자열이 숫자가 되고, 숫자가 행렬 연산을 거쳐 다시 다음 글자의 확률이 되는 흐름을 손으로 계산할 수 있게 만든다.

## 제01장. LLM 개요와 로컬 개발환경 — `개발환경`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | AI·머신러닝·딥러닝·생성형 AI | ▸ 포함 관계로 정리하고, LLM은 '텍스트를 생성하는 딥러닝 모델'의 한 종류임을 위치 짓는다. |
| 02 | LLM이 하는 일: 다음 토큰 예측 | ▸ LLM의 모든 능력은 '앞 문맥으로 다음 토큰의 확률을 고르는 일'의 반복이라는 한 문장으로 출발한다. |
| 03 | 사전학습·파인튜닝·추론 | ▸ 같은 모델의 일생을 세 단계로 나누고, 이 교재가 다루는 범위(파인튜닝·추론)를 표시한다. |
| 04 | 로컬 AI의 의미와 하드웨어 경로 | ▸ CPU 경로와 GT 1030 경로의 차이, 왜 FP32를 쓰는지, VRAM 2GB가 무엇을 제한하는지 미리 본다. |
| 05 | Ubuntu·VS Code 작업 환경 | ▸ 저장소 루트를 작업 폴더로 열고, 공통 설정·확장 프로그램으로 모든 장을 같은 환경에서 실행한다. |
| 06 | Python 가상환경과 PyTorch 설치 | ▸ 프로젝트별 가상환경과 버전 고정(requirements)이 재현성의 출발점임을 실행으로 확인한다. |
| 07 | 장치 자동 선택 | ▸ GPU 유무·PyTorch 지원 여부·연산 자료형을 판단하는 `select_device()`를 만들고 전 과정에서 재사용한다. |
| 08 | Ollama로 첫 로컬 LLM 실행 | ▸ 설치 → 모델 받기 → 대화 → API 호출 순서로 로컬 LLM이 실제로 동작함을 확인한다. |

- **핵심 실습:** 환경 점검 스크립트로 OS·Python·PyTorch·장치·자료형을 보고서로 출력하고, Ollama API로 질의해 생성 토큰 수와 초당 토큰 수를 측정한다.
- **검증:** 환경 보고서 파일 생성, 장치 선택 단위 테스트 통과, Ollama 응답 수신 및 속도 기록.

## 제02장. CPU·GPU 연산과 메모리 구조 — `CPU·GPU`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | CPU와 GPU의 설계 철학 | ▸ 소수의 강한 코어(CPU)와 다수의 단순 코어(GPU)가 행렬 연산에서 어떻게 다르게 일하는지 비교한다. |
| 02 | RAM과 VRAM | ▸ 모델 가중치·중간 결과·Optimizer 상태가 어느 메모리에 놓이는지, 왜 VRAM이 먼저 부족해지는지 설명한다. |
| 03 | CUDA와 Compute Capability | ▸ GT 1030은 CC 6.1이며, 설치된 PyTorch 빌드가 이 세대를 지원해야만 GPU를 쓸 수 있다. |
| 04 | 자료형별 연산 속도 | ▸ GT 1030은 FP16이 FP32의 1/64 속도이고 BF16을 지원하지 않으므로 FP32가 기본이다. |
| 05 | 가용 VRAM 측정 | ▸ CUDA 컨텍스트·화면 출력이 차지하는 VRAM을 빼고 실제로 쓸 수 있는 양을 측정한다. |

- **핵심 실습:** 크기를 키워 가며 행렬곱을 CPU·GPU에서 실행해 시간·메모리를 측정하고 그래프로 비교한다.
- **검증:** 두 장치의 결과 행렬이 허용 오차 이내로 일치, 측정표와 환경 보고서(메모리 사양 포함) 제출.

## 제03장. Tensor 구조와 차원 — `Tensor`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | 스칼라에서 텐서까지 | ▸ 차원이 하나씩 늘 때마다 표현할 수 있는 데이터(값·벡터·표·묶음)가 어떻게 넓어지는지 본다. |
| 02 | Shape·Dimension·Axis | ▸ LLM 텐서의 기본 모양 `[batch, seq, hidden]`을 처음부터 읽을 수 있게 한다. |
| 03 | Indexing과 Slicing | ▸ 특정 토큰·특정 차원의 값을 꺼내는 방법이 이후 모든 분석의 도구가 된다. |
| 04 | Reshape, Squeeze, Unsqueeze | ▸ 원소 개수는 그대로 두고 모양만 바꾸는 연산과 그 조건을 정리한다. |
| 05 | Transpose와 Permute | ▸ 축의 순서를 바꾸는 연산으로, Attention의 헤드 분할에서 다시 쓰인다. |

- **핵심 실습:** `[2, 4, 8]` 텐서를 헤드 분할 모양 `[2, 2, 4, 4]`로 바꾸고 되돌려 원본과 같은지 확인한다.
- **검증:** 단계별 Shape 출력과 손으로 예측한 Shape 일치, 왕복 변환 후 원소 완전 일치.

## 제04장. 행렬 연산과 내적 — `행렬 연산`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | 벡터의 내적 | ▸ 내적은 두 벡터가 얼마나 같은 방향인지를 하나의 숫자로 요약한다(Attention 점수의 정체). |
| 02 | 평균과 분산 | ▸ 내적 결과의 분산이 차원 수에 비례해 커진다는 사실을 가정과 함께 확인한다(√dₖ의 근거). |
| 03 | 원소별 곱과 행렬곱 | ▸ Hadamard 곱과 행렬곱을 구분하지 못하면 FFN·Attention 코드를 잘못 읽게 된다. |
| 04 | 행렬곱의 차원 규칙 | ▸ `[m, k] × [k, n] = [m, n]` 규칙 하나로 모든 계층의 입출력 차원을 예측한다. |
| 05 | Broadcasting과 Batch 행렬곱 | ▸ 차원 자동 확장과 묶음 단위 행렬곱이 실제 모델 코드에서 어떻게 쓰이는지 본다. |
| 06 | 반복문 행렬곱 직접 구현 | ▸ 세 겹 반복문으로 행렬곱을 만들어 라이브러리 연산이 하는 일을 눈으로 확인한다. |

- **핵심 실습:** 반복문 행렬곱과 `torch.matmul` 결과를 비교하고, 차원별 내적 분산을 실험으로 측정한다.
- **검증:** 두 결과의 허용 오차(7.1절) 이내 일치, 측정 분산이 이론값 d와 근사.

## 제05장. 가중치와 Linear Layer — `Linear Layer`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | 가중치와 편향 | ▸ 학습이란 결국 가중치 행렬과 편향 벡터의 숫자를 바꾸는 일이다. |
| 02 | 교재 공통 표기 규약 | ▸ `y = xWᵀ + b`, 가중치 저장 모양 `[out, in]`을 교재 전체에 고정한다. |
| 03 | nn.Linear 구조 | ▸ PyTorch가 가중치를 어떤 모양으로 저장하고 어떻게 곱하는지 실제 속성으로 확인한다. |
| 04 | Linear Layer 직접 구현 | ▸ 같은 가중치로 직접 구현과 라이브러리 결과가 일치함을 보인다. |

- **핵심 실습:** `nn.Linear(4, 3)`의 가중치를 꺼내 직접 구현에 넣고 출력을 비교한다.
- **검증:** 출력 일치, 가중치 Shape `[3, 4]` 확인, 파라미터 수 손계산(15개) 일치.

## 제06장. 활성화 함수와 Softmax — `활성화·Softmax`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | 비선형이 필요한 이유 | ▸ 선형 계층만 쌓으면 하나의 선형 계층과 같아진다는 사실을 수식으로 보인다. |
| 02 | Sigmoid·ReLU·GELU·SiLU | ▸ 모양과 미분 특성을 비교하고, Qwen이 쓰는 SiLU를 특히 기억한다. |
| 03 | Softmax와 확률분포 | ▸ 임의의 실수 벡터를 합이 1인 확률로 바꾸는 원리를 숫자로 따라간다. |
| 04 | 수치적으로 안정적인 Softmax | ▸ 최댓값을 빼는 이유를 Overflow 실험으로 확인한다. |

- **핵심 실습:** 큰 Logits(예: 1000)에서 단순 Softmax가 실패하고 안정화 Softmax가 성공함을 재현한다.
- **검증:** 안정화 구현과 `torch.softmax` 결과 일치, 확률 합 1.

## 제07장. 자기회귀 언어 모델의 원리 — `자기회귀 모델`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | 언어 모델과 조건부 확률 | ▸ 문장의 확률을 '앞 문맥이 주어졌을 때 다음 글자의 확률'의 곱으로 분해한다. |
| 02 | Logits에서 다음 토큰까지 | ▸ Logits → Softmax → 선택의 세 단계가 생성 한 번의 전부다. |
| 03 | Greedy Decoding | ▸ 가장 확률 높은 토큰을 고르는 가장 단순한 생성 방식과 그 한계를 본다. |
| 04 | Bigram 언어 모델 구현 | ▸ 문자 단위 빈도표만으로 동작하는 가장 작은 언어 모델을 직접 만든다. |

- **핵심 실습:** 짧은 한글 문서로 Bigram 모델을 만들고 한 글자씩 생성한다.
- **검증:** 확률표의 행 합 1, 같은 시작 글자에서 Greedy 생성 결과 재현.

## 제08장. Tokenizer와 Vocabulary — `Tokenizer`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | 토큰과 어휘 집합 | ▸ 모델은 글자가 아니라 정수 ID를 본다. 어휘 크기는 모델 크기와 메모리에 직결된다. |
| 02 | 문자·단어·서브워드 토큰화 | ▸ 세 방식의 장단점과 서브워드가 표준이 된 이유를 비교한다. |
| 03 | 특수 토큰 | ▸ BOS·EOS·PAD의 일반적 역할과 Qwen2.5의 실제 설정(BOS 미사용, EOS·PAD 구성)을 구분한다. |
| 04 | AutoTokenizer와 한글·영문 비교 | ▸ 같은 의미의 문장이 언어에 따라 토큰 수가 달라짐을 측정한다. |

- **핵심 실습:** Qwen2.5 토크나이저로 한글·영문 문장을 인코딩·디코딩하고 토큰 수를 비교한다.
- **검증:** 디코딩 결과가 원문과 일치, 특수 토큰 ID와 설정값 기록.

## 제09장. BPE 토크나이저 직접 구현 — `BPE`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | BPE의 아이디어 | ▸ 가장 자주 붙어 나오는 쌍을 하나로 합치는 일을 반복하면 어휘가 만들어진다. |
| 02 | 쌍 빈도 계산과 병합 | ▸ 병합 한 번이 어휘와 말뭉치를 어떻게 바꾸는지 표로 추적한다. |
| 03 | 병합 규칙과 인코딩 | ▸ 학습한 병합 규칙을 순서대로 적용해 새 문장을 토큰화한다. |
| 04 | Byte-level BPE | ▸ 어떤 문자도 미지 토큰이 되지 않는 이유와 실제 Qwen 토크나이저와의 관계를 정리한다. |

- **핵심 실습:** 교육용 BPE를 구현해 병합 과정을 단계별로 출력한다(원리용, 이후 모델은 Qwen2.5 토크나이저 재사용).
- **검증:** 병합 규칙 재적용 시 같은 토큰열, 인코딩→디코딩 왕복 일치.

## 제10장. Embedding과 벡터 표현 — `Embedding`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | One-hot에서 Embedding으로 | ▸ Embedding은 One-hot 벡터와 가중치 행렬의 곱을 '행 꺼내기'로 바꾼 것이다. |
| 02 | Embedding Table과 Lookup | ▸ Token ID가 행 번호가 되어 `[vocab, hidden]` 표에서 벡터를 꺼낸다. |
| 03 | 코사인 유사도 | ▸ 벡터 사이의 각도로 의미의 가까움을 측정하는 방법을 익힌다. |
| 04 | 실제 모델의 Embedding | ▸ Qwen2.5-0.5B의 Embedding이 전체 파라미터의 약 27.6%를 차지함을 계산한다(공유 텐서는 한 번만). |
| 05 | 어휘 크기와 Logits 메모리 | ▸ 시퀀스 × 어휘 151,936 × 4바이트가 VRAM 2GB에서 왜 가장 큰 부담인지 미리 계산한다. |

- **핵심 실습:** 문장 → Token ID → Embedding Vector 변환을 Shape와 함께 출력하고, 단어 간 코사인 유사도를 비교한다.
- **검증:** One-hot 곱과 Lookup 결과 일치, Embedding 비율 손계산과 코드 결과 일치.

# 제2부. Transformer 구조 및 LLM 내부 분석

> Transformer Block의 모든 연산을 직접 구현하고, Qwen2 구조와 계층 이름까지 같은 초소형 모델 Qwen2-Tiny를 완성한다.

## 제11장. Transformer 전체 구조 — `Transformer 구조`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | RNN에서 Transformer로 | ▸ 순차 처리의 한계를 병렬 Attention이 어떻게 풀었는지 비교한다. |
| 02 | Encoder·Decoder·Decoder-only | ▸ 세 구조의 차이와 LLM이 Decoder-only를 택한 이유를 정리한다. |
| 03 | Transformer Block 구성 | ▸ Norm → Attention → 잔차 → Norm → FFN → 잔차의 반복 단위를 한 장의 구조도로 고정한다. |
| 04 | Qwen2 계열의 데이터 흐름 | ▸ 토큰 ID에서 Logits까지의 전체 경로와 이후 장의 대응 관계를 지도처럼 보여 준다. |

- **핵심 실습:** Qwen2.5-0.5B의 `config.json`과 계층 목록을 출력해 구조도의 각 블록과 연결한다.
- **검증:** 구조도의 블록 이름과 실제 계층 이름 일치표 작성.

## 제12장. Query·Key·Value 생성 — `QKV`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | Query·Key·Value의 역할 | ▸ 질문(Q)과 색인(K)을 비교해 내용(V)을 가져오는 검색에 비유해 이해한다. |
| 02 | WQ·WK·WV와 차원 | ▸ 같은 입력이 세 개의 Linear를 거쳐 세 역할로 갈라지는 과정을 Shape로 추적한다. |
| 03 | QKV Bias | ▸ Qwen2는 Q·K·V Projection에 Bias가 있다. 모델마다 다르므로 실제 가중치로 확인한다. |
| 04 | QKV Projection 직접 구현 | ▸ 직접 구현 결과를 `nn.Linear`와 비교해 표기 규약을 다시 확인한다. |

- **핵심 실습:** Qwen2.5-0.5B 0번 계층의 q/k/v 가중치·Bias Shape를 출력하고 같은 입력으로 Projection을 재현한다.
- **검증:** 직접 계산과 모델 내부 출력(Hook) 일치.

## 제13장. Scaled Dot-Product Attention — `Attention`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | Attention Score | ▸ QKᵀ의 한 칸은 '이 토큰이 저 토큰을 얼마나 참고할지'의 점수다. |
| 02 | √dₖ Scaling | ▸ 제04장 분산 실험을 근거로 나누는 이유를 설명하고, 나누지 않을 때의 Softmax 쏠림을 보인다. |
| 03 | Softmax와 가중합 | ▸ 점수를 확률로 바꾼 뒤 V의 가중 평균을 구하는 두 단계로 정리한다. |
| 04 | 4×4 손계산 | ▸ 작은 숫자 행렬로 전 과정을 손으로 계산해 코드 결과와 맞춘다. |

- **핵심 실습:** 4×4 예제를 손계산·직접 구현·`F.scaled_dot_product_attention` 세 가지로 계산한다.
- **검증:** 세 결과의 허용 오차 이내 일치, Attention 가중치 행 합 1.

## 제14장. Causal Mask와 Self-Attention — `Causal Mask`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | 미래 정보 차단 | ▸ 학습 중 정답을 미리 보면 안 되므로 미래 위치의 점수를 −∞로 만든다. |
| 02 | 하삼각 마스크 | ▸ 마스크 행렬의 모양과 Softmax 뒤 0이 되는 원리를 숫자로 본다. |
| 03 | Causal Mask와 Padding Mask | ▸ Hugging Face의 `attention_mask`는 Padding Mask이며, 두 마스크는 결합해 쓴다. |
| 04 | Causal Self-Attention 구현 | ▸ 마스크를 포함한 Attention 함수를 완성한다. |

- **핵심 실습:** 마지막 토큰을 바꿔도 앞 위치들의 출력이 변하지 않음을 실험으로 증명한다.
- **검증:** 변경 전후 앞 위치 출력 완전 일치, Padding 위치 가중치 0.

## 제15장. Multi-Head Attention과 GQA — `MHA·GQA`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | 여러 헤드가 필요한 이유 | ▸ 서로 다른 관계를 동시에 보도록 hidden을 헤드로 나누어 병렬 계산한다. |
| 02 | 헤드 분할과 결합 | ▸ reshape·transpose로 `[b, s, h]` ↔ `[b, heads, s, d]`를 오가는 과정을 정확히 추적한다. |
| 03 | MQA와 GQA | ▸ K·V 헤드를 공유해 KV Cache를 줄이는 방법이며, Qwen2.5-0.5B는 Query 14 : KV 2(7:1)이다. |
| 04 | MHA·GQA 구현 | ▸ KV 헤드를 반복해 Query 헤드 수에 맞추는 연산을 구현한다. |

- **핵심 실습:** 같은 입력으로 MHA와 GQA를 구현해 파라미터 수와 KV 크기를 비교한다.
- **검증:** KV 헤드 수 = Query 헤드 수일 때 GQA 결과가 MHA와 일치.

## 제16장. 위치 정보와 RoPE — `RoPE`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | 위치 정보가 필요한 이유 | ▸ Attention은 순서를 모르므로 위치를 따로 알려 줘야 한다. |
| 02 | 절대·상대 위치와 Sinusoidal | ▸ 고전적 방식과 그 한계를 짧게 정리한다. |
| 03 | 회전 행렬과 RoPE | ▸ Q·K를 위치만큼 회전시키면 내적이 '상대 거리'만의 함수가 된다. |
| 04 | rope_theta와 구현 | ▸ Qwen2.5의 rope_theta 1,000,000의 의미와 회전 각도 계산을 구현한다. |

- **핵심 실습:** 두 토큰을 같은 거리만큼 함께 이동시켜도 Attention 점수가 유지됨을 확인한다.
- **검증:** 직접 구현 RoPE와 Transformers 구현 결과 일치.

## 제17장. FFN과 SwiGLU — `FFN·SwiGLU`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | FFN의 역할 | ▸ Attention이 정보를 모으면 FFN은 토큰별로 특징을 변환한다. |
| 02 | Gate·Up·Down Projection | ▸ 세 Linear와 intermediate_size(0.5B: 4,864)의 관계를 Shape로 정리한다. |
| 03 | SiLU와 SwiGLU | ▸ `down(silu(gate(x)) ⊙ up(x))` — 원소별 곱과 행렬곱을 정확히 구분한다. |
| 04 | 연산량과 파라미터 | ▸ 모델 파라미터 대부분이 FFN에 있다는 사실을 계산으로 확인한다(Embedding 제외). |

- **핵심 실습:** SwiGLU FFN을 구현하고 Qwen 0번 계층의 MLP 출력과 비교한다.
- **검증:** Hook 출력과 허용 오차 이내 일치, 파라미터 수 손계산 일치.

## 제18장. 정규화와 Residual Connection — `RMSNorm·잔차`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | 정규화가 필요한 이유 | ▸ 층이 깊어질수록 값의 크기가 흔들리는 문제를 정규화가 잡는다. |
| 02 | LayerNorm과 RMSNorm | ▸ RMSNorm은 평균을 빼지 않고 크기만 맞춘다. Qwen은 RMSNorm을 쓴다. |
| 03 | Residual Connection | ▸ 입력을 더해 주는 지름길이 깊은 모델의 학습을 가능하게 한다. |
| 04 | Pre-Norm과 Final Norm | ▸ Qwen은 블록 앞에 정규화하고 마지막에 한 번 더 정규화한다. |

- **핵심 실습:** RMSNorm을 구현하고 Attention·FFN을 조립해 Transformer Block 하나를 완성한다.
- **검증:** Qwen 0번 Decoder Layer 출력과 직접 조립 Block 출력 일치.

## 제19장. Qwen2-Tiny 조립과 순전파 검증 — `Qwen2-Tiny`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | Qwen2-Tiny 설계 | ▸ hidden 256·4계층·Q 4/KV 1·intermediate 768·어휘 151,936, Qwen2와 계층 이름·Shape를 맞춘다. |
| 02 | 전체 모델 조립 | ▸ Embedding → Block × 4 → Final Norm → LM Head의 순전파를 구현한다. |
| 03 | Weight Tying | ▸ LM Head와 Embedding이 같은 텐서를 공유하므로 파라미터는 한 번만 센다. |
| 04 | 차원 추적과 파라미터 수 | ▸ 입력부터 Logits까지 Shape를 추적하고 약 4,190만 개(Embedding 약 93%)를 손계산한다. |
| 05 | Hugging Face 형식 호환 | ▸ 직접 만든 가중치를 `Qwen2ForCausalLM`에 불러와 같은 Logits가 나오는지 확인한다. |

- **핵심 실습:** Qwen2-Tiny를 무작위 초기화해 저장하고 `Qwen2ForCausalLM`으로 다시 불러 순전파 결과를 비교한다.
- **검증:** 파라미터 수 일치(공유 텐서 중복 제거), 두 구현의 Logits 허용 오차 이내 일치.

## 제20장. 실제 Qwen 모델 구조와 추론 분석 — `Qwen 분석`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | AutoConfig·AutoTokenizer·AutoModel | ▸ Hugging Face가 설정·토크나이저·모델을 한 이름으로 불러오는 구조를 익힌다. |
| 02 | 계층 이름과 가중치 Shape | ▸ 0.5B 모델의 실제 계층 목록을 제2부 구조도와 하나씩 대응시킨다. |
| 03 | Forward Hook | ▸ 모델 내부 중간 출력을 꺼내 직접 구현과 비교하는 검증 도구를 만든다. |
| 04 | Sampling과 생성 설정 | ▸ Temperature·Top-k·Top-p와 `generation_config.json` 기본값, 재현을 위한 Greedy 고정을 정리한다. |
| 05 | KV Cache 메모리 | ▸ 2 × 계층 × KV 헤드 × head_dim × 자료형 × 토큰: 0.5B는 토큰당 12KiB, 32K 문맥에서 384MiB. |
| 06 | Qwen2-Tiny와 실제 모델 비교 | ▸ QKV Bias·Weight Tying·GQA·rope_theta·Final Norm 차이표로 2부를 마무리한다. |

- **핵심 실습:** Hook으로 0번 계층 Attention 출력을 꺼내 제13~18장 직접 구현과 비교하고, KV Cache 크기를 계산·측정한다.
- **검증:** Hook 출력과 직접 구현 일치, KV Cache 계산값과 측정값 비교표.

# 제3부. 전이학습 및 LoRA 파인튜닝

> 손실·기울기·업데이트의 학습 원리를 세운 뒤, 가중치를 얼려 두고 작은 행렬만 학습하는 LoRA를 직접 구현한다.

## 제21장. 사전학습·전이학습·파인튜닝 — `전이학습`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | 사전학습과 전이학습 | ▸ 대량의 일반 지식을 먼저 배우고 그 가중치를 새 과제에 재사용한다. |
| 02 | Base Model과 Instruct Model | ▸ 같은 구조라도 대화 형식 학습 여부에 따라 응답 방식이 달라진다. |
| 03 | 프롬프트·RAG·파인튜닝 | ▸ 무엇을 바꾸고 싶은지(형식·지식·행동)에 따라 방법을 고르는 기준을 세운다. |
| 04 | 실험용 고정 데이터셋 | ▸ 제3·4부 전체에서 같은 고정 토큰 데이터로 비교한다. |

- **핵심 실습:** Base와 Instruct 모델에 같은 질문을 Greedy로 넣어 응답 차이를 기록한다.
- **검증:** 생성 설정 고정 상태에서 두 결과 재현.

## 제22장. 손실함수와 Perplexity — `손실·PPL`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | Cross Entropy와 NLL | ▸ 정답 토큰의 확률에 −log를 취한 값이 손실이다. |
| 02 | 입력과 정답의 한 칸 이동 | ▸ 언어 모델은 위치 t의 출력으로 t+1의 토큰을 맞힌다. |
| 03 | Loss Masking 기초 | ▸ Padding처럼 학습하지 않을 위치는 −100으로 제외한다. |
| 04 | Perplexity | ▸ PPL = exp(전체 NLL 합 / 유효 토큰 수). 비교는 같은 데이터·문맥·마스킹 정책에서만 한다. |
| 05 | 기준값 저장 | ▸ 교육용 고정 데이터에서 기본 모델의 PPL을 측정해 제3·4부 비교 기준으로 저장한다. |

- **핵심 실습:** 손실을 직접 계산하고 Qwen2.5-0.5B의 `loss` 출력, PPL 계산을 맞춘다.
- **검증:** 직접 계산과 라이브러리 손실 일치, 기준 PPL 파일 저장.

## 제23장. 역전파와 Gradient — `역전파`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | 미분과 연쇄법칙 | ▸ 출력의 변화가 각 가중치에 얼마씩 책임이 있는지를 거꾸로 나눠 계산한다. |
| 02 | 계산 그래프와 Autograd | ▸ PyTorch가 순전파를 기록해 두었다가 역전파를 자동으로 수행하는 방식을 본다. |
| 03 | Gradient 누적과 초기화 | ▸ `.grad`는 더해지므로 매 단계 초기화해야 한다. |
| 04 | 수치 미분 검증 | ▸ FP64 수치 미분과 자동 미분을 비교해 구현을 검증한다. |

- **핵심 실습:** 작은 Linear 모델의 Gradient를 손계산·수치 미분·Autograd 세 방법으로 비교한다.
- **검증:** `gradcheck` 통과, 세 결과 비교표.

## 제24장. Optimizer와 학습 반복 — `Optimizer`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | 경사하강법과 SGD | ▸ 기울기의 반대 방향으로 조금씩 이동하는 것이 학습의 기본 동작이다. |
| 02 | Momentum·Adam·AdamW | ▸ 이동 방향과 크기를 기억해 보정하는 방법과 Weight Decay를 정리한다. |
| 03 | Learning Rate와 Batch·Epoch | ▸ 학습률과 묶음 크기가 수렴 속도와 안정성에 주는 영향을 본다. |
| 04 | Optimizer State와 메모리 | ▸ AdamW는 파라미터당 8바이트의 상태를 추가로 저장한다(FP32 기준). |
| 05 | Scheduler·Accumulation·Clipping 개념 | ▸ 세 기법의 목적만 정리하고 실제 적용은 제25장에서 한다. |

- **핵심 실습:** 같은 문제를 SGD·Adam·AdamW로 학습해 손실 곡선을 비교한다.
- **검증:** 손실 감소 확인, Optimizer 상태 메모리 계산과 측정값 비교.

## 제25장. Qwen2-Tiny 사전학습과 Full Fine-tuning — `Full FT`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | 학습 루프 구성 | ▸ Forward → Loss → Backward → Step → Zero의 반복을 하나의 함수로 만든다. |
| 02 | Scheduler·Accumulation·Clipping 적용 | ▸ Warmup·Cosine, 유효 배치 확대, Gradient 크기 제한을 실제 학습에 적용하고 기록한다. |
| 03 | 소규모 사전학습 | ▸ GT 1030 기준 FP32·시퀀스 128·Batch 2로 Qwen2-Tiny를 학습한다. |
| 04 | Hugging Face 형식 저장 | ▸ `config.json`·Safetensors·토크나이저로 저장해 이후 PEFT·TRL·GGUF에서 재사용한다. |
| 05 | Full Fine-tuning | ▸ 도메인 데이터로 전체 가중치를 다시 학습하고 전후 PPL을 비교한다. |
| 06 | 0.5B Full FT 메모리 계산 | ▸ 가중치·Gradient·Optimizer State로 약 8GB가 필요해 GT 1030에서 불가함을 계산으로 판정한다. |

- **핵심 실습:** Qwen2-Tiny를 사전학습 → 저장 → 재로딩 → Full Fine-tuning하고 손실 곡선을 그린다.
- **검증:** 손실 감소, 재로딩 전후 출력 일치, 최대 메모리가 1.2절 예산 이내.

## 제26장. 가중치 동결과 PEFT — `동결·PEFT`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | 가중치 동결 | ▸ `requires_grad=False`인 가중치는 Gradient도 Optimizer 상태도 만들지 않는다. |
| 02 | 부분 학습 | ▸ 어떤 계층만 학습할지에 따라 결과와 메모리가 달라진다. |
| 03 | PEFT의 발상 | ▸ 원본은 그대로 두고 작은 추가 파라미터만 학습하는 방법들의 공통점을 정리한다. |

- **핵심 실습:** Qwen2-Tiny의 마지막 Block만 학습하고 나머지 가중치가 바뀌지 않았음을 확인한다.
- **검증:** 동결 가중치의 학습 전후 완전 일치, 학습 파라미터 수 일치.

## 제27장. Rank와 저랭크 분해 — `Rank·SVD`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | 행렬의 Rank | ▸ 행렬이 실제로 담고 있는 독립 방향의 수가 정보량이다. |
| 02 | SVD와 저랭크 근사 | ▸ 큰 특잇값만 남겨 두 개의 작은 행렬로 근사할 수 있다. |
| 03 | 파라미터 수 절약 | ▸ `[out, in]`을 `[out, r] × [r, in]`으로 바꿀 때의 절약량을 계산한다. |
| 04 | LoRA와 SVD의 차이 | ▸ LoRA는 원본을 근사하는 것이 아니라 '변화량'을 저랭크로 학습한다. |

- **핵심 실습:** 실제 Qwen 가중치 하나를 Rank별로 근사해 복원 오차 곡선을 그린다.
- **검증:** Rank 증가에 따른 오차 감소, 파라미터 수 계산 일치.

## 제28장. LoRA의 수학적 원리 — `LoRA 원리`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | W와 ΔW | ▸ 원본 W는 얼리고 `ΔW = (α/r)·BA`만 학습한다. |
| 02 | A·B의 모양과 초기화 | ▸ A `[r, in]`, B `[out, r]`, B를 0으로 시작해 학습 첫 순간 출력이 원본과 같다. |
| 03 | Alpha와 Scaling | ▸ α/r이 학습률처럼 업데이트 크기를 조절하는 원리를 본다. |
| 04 | 파라미터 수 계산 | ▸ r·(in + out)이 원본 in·out에 비해 얼마나 작은지 실제 계층으로 계산한다. |

- **핵심 실습:** 작은 숫자 행렬로 LoRA 순전파를 손계산하고 병합 결과 `W + ΔW`와 비교한다.
- **검증:** 초기 출력이 원본과 일치(B = 0), 병합 전후 출력 일치.

## 제29장. PyTorch LoRA 직접 구현 — `LoRA 구현`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | LoRALinear 설계 | ▸ 기존 Linear를 감싸 원본은 동결하고 A·B만 학습하는 계층을 만든다. |
| 02 | 순전파와 역전파 | ▸ Gradient가 A·B에만 흐르는지 실제로 확인한다. |
| 03 | Qwen2-Tiny에 적용 | ▸ q_proj·v_proj를 LoRALinear로 바꿔 학습한다. |
| 04 | 가중치 병합 | ▸ 학습한 ΔW를 원본에 더해 추론 시 추가 연산을 없앤다. |

- **핵심 실습:** Qwen2-Tiny에 직접 구현 LoRA를 붙여 학습하고 병합한다.
- **검증:** 원본 가중치 불변, 병합 전후 Logits 일치.

## 제30장. PEFT 라이브러리 LoRA — `PEFT LoRA`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | LoraConfig와 get_peft_model | ▸ 직접 구현한 내용이 라이브러리에서 어떤 설정 이름이 되는지 연결한다. |
| 02 | Target Modules | ▸ Qwen 계층 이름으로 적용 대상을 고르고 학습 파라미터 수를 계산한다. |
| 03 | Qwen2-Tiny PEFT 학습 | ▸ 제25장 체크포인트에 PEFT LoRA를 적용해 학습한다(CPU·GT 1030 공통). |
| 04 | Adapter 저장과 재로딩 | ▸ 원본과 분리된 작은 Adapter 파일의 구조를 본다. |

- **핵심 실습:** 직접 구현 LoRA와 PEFT LoRA를 같은 조건으로 학습해 결과를 비교한다.
- **검증:** 학습 파라미터 수 일치, 두 구현의 가중치 이름·Shape 대응표, 재로딩 출력 일치.

# 제4부. 양자화 및 QLoRA 파인튜닝

> 숫자를 적은 비트로 저장하는 원리를 직접 구현하고, GT 1030 2GB에서 Qwen2.5-0.5B를 QLoRA로 학습한다.

## 제31장. 컴퓨터의 수 표현 — `수 표현`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | 정수와 2의 보수 | ▸ 같은 비트 패턴이 부호 유무에 따라 다른 수가 되는 원리를 본다. |
| 02 | 비트 폭과 표현 범위 | ▸ n비트로 표현할 수 있는 범위가 양자화의 출발점이다. |
| 03 | 고정소수점과 Q Format | ▸ 소수점 위치를 약속해 정수로 실수를 표현한다(FPGA 연계). |
| 04 | Overflow·Saturation·Rounding | ▸ 범위를 넘을 때와 끝자리를 처리할 때의 규칙을 정리한다. |

- **핵심 실습:** Python 비트 연산으로 정수·고정소수점 변환기를 만든다.
- **검증:** 경계값(최소·최대·오버플로)에서 기대 결과 일치.

## 제32장. FP32·FP16·BF16 — `부동소수점`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | IEEE 754 구조 | ▸ 부호·지수·가수의 비트 배분이 범위와 정밀도를 결정한다. |
| 02 | FP16과 BF16 | ▸ 같은 16비트라도 정밀도(FP16)와 범위(BF16) 중 무엇을 택했는지가 다르다. |
| 03 | 저장 자료형과 연산 자료형 | ▸ FP16으로 저장하고 FP32로 계산할 수 있다. GT 1030은 이 방식이 기본이다. |
| 04 | Mixed Precision과 GradScaler | ▸ 최신 GPU의 혼합 정밀도 원리를 이해하되 GT 1030에서는 쓰지 않는 이유를 정리한다. |

- **핵심 실습:** 같은 가중치를 세 자료형으로 저장해 오차와 용량을 비교하고, GPU에서 자료형별 행렬곱 속도를 측정한다.
- **검증:** 비트 분해 결과와 IEEE 754 계산 일치, GT 1030 FP16 속도 저하 실측 기록.

## 제33장. INT8 양자화 직접 구현 — `INT8`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | Scale과 Zero Point | ▸ 실수 구간을 정수 구간에 대응시키는 두 숫자가 양자화의 전부다. |
| 02 | 대칭·비대칭 양자화 | ▸ 0을 정확히 표현해야 하는지에 따라 방식을 고른다. |
| 03 | Per-Tensor와 Per-Channel | ▸ Scale을 얼마나 잘게 나누느냐가 오차를 좌우한다. |
| 04 | Clipping과 Rounding | ▸ 범위 밖 값과 반올림 방식이 결과에 주는 영향을 본다. |

- **핵심 실습:** Qwen 가중치 하나를 INT8로 양자화·복원하고 Per-Tensor와 Per-Channel 오차를 비교한다.
- **검증:** 복원 오차가 Scale/2 이내, 저장 용량 실측.

## 제34장. INT4와 Bit Packing — `INT4`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | 4비트 표현 범위 | ▸ 16단계뿐인 표현으로 가중치를 담는 대가를 계산한다. |
| 02 | Bit Packing | ▸ 4비트 두 개를 한 바이트에 담는 시프트·마스킹 연산을 구현한다. |
| 03 | 부호 있는 4비트 복원 | ▸ 꺼낸 4비트를 음수까지 올바르게 되돌리는 부호 확장을 다룬다. |
| 04 | 파일 생성과 FPGA 연계 | ▸ 패킹한 가중치 파일이 하드웨어 메모리에 어떻게 놓이는지 연결한다. |

- **핵심 실습:** INT4 가중치 파일을 만들고 실제 파일 크기가 INT8의 절반임을 확인한다.
- **검증:** 패킹→언패킹 왕복 완전 일치, 파일 크기 실측.

## 제35장. 역양자화와 오차 분석 — `양자화 오차`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | 역양자화 | ▸ 저장된 정수를 계산 직전에 다시 실수로 되돌린다. |
| 02 | MSE와 최대 절대오차 | ▸ 평균 오차와 최악 오차를 함께 봐야 하는 이유를 본다. |
| 03 | 이상치의 영향 | ▸ 값 하나가 Scale을 키워 나머지 전체의 정밀도를 떨어뜨린다. |
| 04 | 행렬곱 출력 오차 | ▸ 가중치 오차가 실제 계층 출력에서 얼마나 커지는지 측정한다. |

- **핵심 실습:** INT8·INT4로 양자화한 계층의 출력 오차를 원본과 비교하고 분포를 시각화한다.
- **검증:** 비트 수에 따른 오차 증가 확인, 비교표 제출.

## 제36장. NF4와 블록 단위 양자화 — `NF4`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | 가중치 분포와 NF4 | ▸ 가중치가 정규분포에 가깝다는 점을 이용해 값이 몰린 곳에 단계를 촘촘히 둔다. |
| 02 | Codebook 양자화 | ▸ 균일 간격 대신 미리 정한 16개 값 중 가장 가까운 것을 고른다. |
| 03 | Block-wise와 Double Quantization | ▸ 블록마다 Scale을 두고, 그 Scale까지 다시 양자화해 메타데이터를 줄인다. |
| 04 | 저장 비용 | ▸ 가중치 비트 외에 Scale 저장 비용까지 더해 실제 평균 비트를 계산한다. |

- **핵심 실습:** 같은 가중치를 INT4와 NF4로 양자화해 오차를 비교한다.
- **검증:** INT4 대비 NF4 오차 감소 확인, 평균 비트 계산.

## 제37장. bitsandbytes와 GPU 호환성 — `bitsandbytes`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | BitsAndBytesConfig | ▸ 4비트 로딩 설정 항목과 제36장 개념의 대응을 정리한다. |
| 02 | 하드웨어 조건 | ▸ NF4는 CC 6.0 이상(GT 1030 가능), LLM.int8은 CC 7.5 이상(GT 1030 불가)이다. |
| 03 | Compute Dtype과 torch_dtype | ▸ GT 1030은 FP32 연산, 양자화되지 않는 Embedding(약 520MiB)의 자료형도 정한다. |
| 04 | 버전 조합 확정 | ▸ PyTorch 2.14(cu126)·드라이버·bitsandbytes 조합을 실행으로 확인해 고정한다. |

- **핵심 실습:** Qwen2.5-0.5B를 4비트로 로딩해 계층별 자료형과 실제 VRAM 사용량을 측정한다.
- **검증:** 측정 VRAM과 1.2절 예산 비교, `requirements/gt1030.txt` 고정.

## 제38장. QLoRA 구조와 메모리 최적화 — `QLoRA 구조`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | QLoRA의 구성 | ▸ 4비트로 얼린 원본 + FP32 LoRA Adapter, 계산 순간에만 역양자화한다. |
| 02 | 학습 메모리 분해 | ▸ 가중치·Activation·Gradient·Optimizer·Logits가 각각 차지하는 양을 계산한다. |
| 03 | Gradient Checkpointing | ▸ 중간 결과를 버리고 다시 계산해 메모리를 시간과 바꾼다. |
| 04 | Paged Optimizer | ▸ GPU 메모리가 부족할 때 Optimizer 상태를 옮기는 원리를 본다. |

- **핵심 실습:** Gradient Checkpointing 사용 여부에 따른 최대 메모리를 비교한다.
- **검증:** 메모리 계산값과 측정값 비교표.

## 제39장. QLoRA 최소 학습 — `QLoRA 학습`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | 학습 준비 | ▸ 4비트 로딩 → `prepare_model_for_kbit_training` → LoRA 설정 순서로 준비한다. |

| 03 | 최소 학습 루프 | ▸ 제25장 학습 루프를 재사용해 고정 토큰 데이터로 학습한다. |
| 04 | 동결 검증과 Adapter 저장 | ▸ 4비트 원본이 바뀌지 않았는지 확인하고 Adapter만 저장한다. |
| 05 | CPU 경로 | ▸ CPU에서는 bitsandbytes CPU 지원 여부를 확인해 실제 QLoRA 또는 원리 모사로 진행한다. |

- **핵심 실습:** GT 1030에서 Qwen2.5-0.5B QLoRA를 실행해 학습 전후 PPL과 최대 VRAM을 기록한다.
- **검증:** PPL 감소, 최대 VRAM 1.2절 예산 이내, 동결 가중치 불변.

## 제40장. Full FT·LoRA·QLoRA 비교 — `학습 방식 비교`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|

- **핵심 실습:** 비교 A를 실행해 파라미터 수·저장 용량·최대 메모리·손실·PPL을 한 표로 만든다.
- **검증:** 비교 조건 기록표, 방식별 결과표 제출.

| 01 | 결측·오류·중복 제거 | ▸ 정규화·해시·N-gram으로 중복과 유사 후보를 찾는다. |
| 02 | 문장 임베딩 유사도 | ▸ 토큰 임베딩과 문장 임베딩을 구분하고, 유사 후보는 사람이 최종 검토한다. |
| 03 | 분할과 데이터 누출 | ▸ 주제·출처 단위로 나눠 비슷한 문항이 Train과 Test에 함께 들어가지 않게 한다. |
| 04 | 평가 지표 정의 | ▸ PPL·도메인 정답률(정확 일치·핵심어·채점 기준표)·지시 이행·일반 능력 유지를 정의한다. |
| 05 | 합격 기준 사전 기록 | ▸ 실험 전에 `configs/eval_criteria.yaml`에 기준을 적고 이후 장에서 그대로 쓴다. |

- **핵심 실습:** 중복·유사 검출 → 그룹 분할 → 누출 검사 → 평가 기준 파일 작성을 순서대로 실행한다.
- **검증:** 누출 검사표와 검출 한계 기록, `eval_criteria.yaml` 생성.

## 제44장. Chat Template — `Chat Template`

## 제45장. 토큰화와 Label Masking — `Label Masking`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | input_ids·attention_mask·labels | ▸ 학습 입력 세 가지의 역할을 실제 배열로 확인한다. |
| 02 | Attention Mask와 Loss Mask | ▸ 보지 않을 위치와 채점하지 않을 위치는 다른 개념이다. |
| 03 | Completion-only Loss | ▸ 질문 부분은 −100으로 가리고 답변만 학습한다(기본 경로). |
| 04 | Assistant-only Loss의 조건 | ▸ 템플릿에 생성 구간 표시가 필요하며, Qwen2.5 기본 템플릿에는 없다. |
| 05 | 종료 토큰과 PAD | ▸ 응답 끝 토큰이 학습 대상인지, PAD=EOS 설정(Base·직접 지정)에서 생기는 오류를 확인한다. |
| 06 | 길이 제한과 잘림 | ▸ 최대 시퀀스(GT 1030: 256)를 넘는 샘플의 손실을 측정한다. |

- **핵심 실습:** 샘플 하나의 input_ids와 labels를 나란히 출력해 학습 대상 토큰을 색으로 표시한다.
- **검증:** 답변·종료 토큰만 학습 대상, PAD 제외, 잘림 비율 기록.

## 제59장. Basys3 LLM 연산 블록 (선택) — `FPGA 연산 블록`

| 절 | 제목 | 핵심 맥락 |
|---|---|---|
| 01 | LLM 연산과 NPU | ▸ LLM 추론의 대부분은 행렬곱이며, 하드웨어 가속은 MAC 반복이다. |
| 02 | Basys3 자원과 탑재 범위 | ▸ BRAM 225KiB에 q_proj(INT8 784KiB)는 불가, k_proj(INT8 112KiB)는 이론상 가능하다. |
| 03 | 정수 MAC와 누산기 | ▸ INT8×INT8 896회 누산은 최소 25비트, 실습 권장 32비트로 설계한다. |
| 04 | RTL MatMul과 Testbench | ▸ Python 정수 기준값과 시뮬레이션 결과를 비트 단위로 비교한다. |

- **검증:** Python 기준값과 완전 일치, 합성 자원·타이밍 보고.
